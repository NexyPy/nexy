# Actions

`@Action` turns a Python function into a `POST` endpoint with a generated path, so a page can call
server code without declaring a route file.

## Define an action

```python filename="src/actions/user.py"
from nexy.decorators import Action


@Action
async def create_user(name: str) -> dict:
    return {"name": name}
```

## What Nexy does

- At startup it scans `src/` and imports every module, which registers each `@Action` function.
- Each function is mounted as `POST /_nx_<hash>`, where the hash is derived from
  `<module>.<function>`.
- The endpoint is a normal FastAPI route: parameters and body models follow the function signature.

## Call an action from a page

Inside a `.nexy` template, every action is exposed three ways:

| Variable | Content |
|---|---|
| `create_user` | the function itself, called directly in the template |
| `__actions["create_user"]` | the same function, by name |
| `__actions_path["create_user"]` | the generated URL |

```nexy filename="src/routes/index.nexy"
<form method="post" action="{{ __actions_path['create_user'] }}">
  <input name="name">
  <button type="submit">Create</button>
</form>
```

## Security

The action path is deterministic: a hash of the function's module and name. It hides the endpoint
from casual discovery, but it is not a secret - do not rely on it for authorization.

There is no typed TypeScript client generated by the current build; call the URL from your own code.
