# কোডিং এজেন্ট

`nx new` দিয়ে তৈরি একটি প্রজেক্টের নিয়মগুলি বহন করে যেগুলি কোডিং এজেন্টকে আপনার উপায়ে Nexy কোড লিখতে হবে:
কাজের ক্রম, কোড এবং লেখার নিয়ম এবং প্রতি বিষয়ে একটি দক্ষতা। এই পৃষ্ঠাটি বলে আপনি যা পান,
এটি কোথায় যায় এবং কীভাবে এটি বর্তমান রাখা যায়। নেক্সিতে কাজ করা নিজেই একটি ভিন্ন কাজ: পড়ুন
সংগ্রহস্থলের মূল `AGENTS.md`।

## কি `nx new` যোগ করে

| ফাইল | পঠিত | ধরে রাখে |
|---|---|---|
| `AGENTS.md` | কোডেক্স, ওপেনকোড | প্রকল্পের স্ট্যাক, কাজের ক্রম, নিয়ম, দক্ষতার তালিকা |
| `CLAUDE.md` | ক্লদ কোড | এক লাইন, `@AGENTS.md`, তাই উভয়ই একই পাঠ্য পড়ে |
| `.agents/skills/` | কোডেক্স, ওপেনকোড | দক্ষতা |
| `.claude/skills/` | ক্লদ কোড, ওপেনকোড | একই দক্ষতা |

`AGENTS.md` সংক্ষিপ্ত এবং উপযোগী। একটি ক্লায়েন্ট-রাউটেড Vue প্রোজেক্ট পড়ে "ক্লায়েন্ট-রাউটেড, Vue, স্টাইল করা
Tailwind সহ"; একটি API প্রকল্প বলা হয় কোন ভিউ নেই। শুধুমাত্র উপযুক্ত দক্ষতা অনুলিপি করা হয়: ক
প্রতিক্রিয়া প্রকল্প পায় `nexy-react` এবং কোন Vue দক্ষতা নেই, একটি সার্ভার প্রকল্প পায় `.nexy` এবং মার্কডাউন
দক্ষতা, একটি API প্রকল্প ভিউ সম্পর্কে কোন দক্ষতা পায় না।

এটি সব বাদ দিতে, `nx new --no-agents` দিয়ে প্রকল্পটি তৈরি করুন।

## দক্ষতা

| দক্ষতা | কভার |
|---|---|
| `nexy-principles` | কাজের ক্রম, কোডের নিয়ম, লেখার নিয়ম |
| `nexy-ux-audit` | অভিজ্ঞতা এবং তথ্য-স্থাপত্য নিরীক্ষা যে কোনো দৃশ্যের আগে চালানোর জন্য |
| `nexy-project` | মোড, ফোল্ডার, ফাইল কনভেনশন, কনফিগারেশন, কমান্ড |
| `nexy-file` | `.nexy` পৃষ্ঠা, প্রপস, হুক, দ্বীপ |
| `nexy-markdown` | `.md` এবং `.mdx` বিষয়বস্তু |
| `nexy-react`, `nexy-preact`, `nexy-solid`, `nexy-vue`, `nexy-svelte` | ক্লায়েন্ট ফ্রেমওয়ার্কের জন্য ইডিওম্যাটিক কোড |
| `nexy-styling` | Tailwind, UnoCSS বা প্লেইন CSS, এবং ডিজাইন টোকেন |
| `nexy-backend` | API হ্যান্ডলার, অ্যাকশন, ওয়েবসকেট, আইএসআর, মিডলওয়্যার |
| `nexy-modular` | মডুলার রাউটারের কন্ট্রোলার, মডিউল, ইনজেকশন এবং গার্ড |
| `nexy-security` | নির্ভরতা, ইনপুট, সেশন, অনুমোদন, গোপনীয়তা |
| `nexy-testing` | টেস্ট-ফার্স্ট লুপ এবং গেটস |
| `nexy-framework-dev` | নেক্সির সাথে নির্মিত একটি প্রকল্পের পরিবর্তে নেক্সি নিজেই পরিবর্তন করে |

তারা যে নিয়মগুলি প্রয়োগ করে: একটি দৃশ্য তৈরি করার আগে অভিজ্ঞতা নিরীক্ষণ করুন, প্রথমে ব্যর্থ পরীক্ষা লিখুন,
একটি ফাংশন একটি চিকিত্সা করে, একটি ক্লাস একটি উদ্দেশ্য বহন করে, একটি ফোল্ডার এক সেট ধারণ করে
সম্পর্কিত উদ্দেশ্য, কোন ইমোজি, বাস্তব SVG আইকন, সাধারণ পাঠ্য লোকেদের জন্য লেখা, এবং হাতে লেখা নেই
DOM স্ক্রিপ্ট প্রতিক্রিয়া, Vue, Svelte, সলিড বা প্রেক্টে।

## একটি বিদ্যমান প্রকল্পে তাদের যোগ করুন

```bash
nx skills
```

প্রকল্পের মূলে এটি চালান। স্ট্যাক খুঁজে পেতে এটি পড়ে `nexyconfig.py` এবং `package.json`,
ম্যাচিং দক্ষতা অনুলিপি করে, এবং যখন তারা অনুপস্থিত থাকে তখন `AGENTS.md` এবং `CLAUDE.md` লিখে।

এটি কখনই আপনার লেখা একটি ফাইলকে ওভাররাইট করে না: একটি বিদ্যমান `AGENTS.md` বা `CLAUDE.md` রাখা হয়, এবং
আদেশ আপনাকে তাই বলে। আপনার নিজের ফাইলে দক্ষতার তালিকা যোগ করুন যদি আপনি এটি সেখানে চান। একটি দক্ষতা
আপনার নিজের `.claude/skills/` বা `.agents/skills/` এ একা রয়ে গেছে; শুধুমাত্র `nexy-*` দক্ষতা
রিফ্রেশ

অনুলিপিগুলি রিফ্রেশ করতে Nexy আপগ্রেড করার পরে আবার `nx skills` চালান এবং ফলাফলটি কমিট করুন যাতে
পুরো দল এটা শেয়ার করে।

## কীভাবে একজন এজেন্ট তাদের খুঁজে পায়

- `AGENTS.md` (বা `CLAUDE.md`, যা এটি আমদানি করে) প্রতিটি সেশনের শুরুতে পড়া হয়। এটা নাম
  দক্ষতা
- প্রতিটি দক্ষতা একটি নাম এবং একটি বিবরণ দিয়ে শুরু হয় যা বলে যে এটি কী কভার করবে এবং কখন এটি লোড করতে হবে। দ
  এজেন্ট প্রথমে সেগুলি পড়ে এবং কাজটি মেলে তবেই একটি দক্ষতা খোলে।

দক্ষতা উন্মুক্ত [এজেন্ট দক্ষতা বিন্যাস](https://agentskills.io/specification) অনুসরণ করে, তাই অন্যান্য
যে এজেন্ট `SKILL.md` ফোল্ডার পড়ে তারাও সেগুলো ব্যবহার করতে পারে।

## তারা যা করে না

দক্ষতা একজন এজেন্টকে কীভাবে কাজ করতে হয় তা বলে; তারা এর আউটপুট সঠিক করে না। আপনার নিজের চেক রাখুন:

- এজেন্ট কি পরিবর্তন হয়েছে পড়ুন.
- রান `nx check`, `nx test` এবং `nx build`। দক্ষতা এই জন্য এবং আউটপুট হতে জিজ্ঞাসা
  রিপোর্ট করা হয়েছে, সংক্ষিপ্ত নয়।
- অডিট নির্ভরতা এজেন্ট যোগ করে (`nexy-security` কীভাবে ব্যাখ্যা করে)।

দক্ষতার উদাহরণগুলি নেক্সির নিজস্ব পরীক্ষা দ্বারা পরীক্ষা করা হয়: আমদানি বিদ্যমান, কনফিগারেশন
ক্ষেত্র বিদ্যমান, কমান্ড বিদ্যমান, পাইথন পার্স। যে ড্রিফট ক্যাচ, ভুল বিচার না.

## প্রজেক্ট ইনভেরিয়েন্টস

1. `__nexy__/` তৈরি হয়। এটি কখনই সম্পাদনা করবেন না, এটি কখনই কমিট করবেন না। একটি পরিষ্কার বিল্ড জোর করে এটি মুছুন.
2. ইউআরএল প্রতি একটি ফাইল। একই পথের জন্য `index.nexy` এবং `index.py` একটি বাগ, অগ্রাধিকারের নিয়ম নয়।
3.  ভিতরে সংরক্ষিত নাম `src/routes/`: `layout.nexy`, `loading.nexy`, `errors.nexy`,
   `notfound.nexy`, `dependencies.py`, `__init__.py`। বিষয়বস্তুর জন্য তাদের ব্যবহার করবেন না.
4. `.nexy` ফ্রন্টম্যাটার হল পাইথন যা প্রতি অনুরোধে চলে। কোনো মডিউল-স্তরের পার্শ্বপ্রতিক্রিয়া নেই: কোনো ফাইল নেই
   হ্যান্ডেল, কোনো ডাটাবেস সংযোগ নেই, আমদানিতে কোনো নেটওয়ার্ক কল নেই।
5. `.py` `src/routes/` একটি API হ্যান্ডলার। পদ্ধতি হল ফাংশনের নাম (`GET`, `POST`, ...)।
6. কনফিগারেশন থাকে `nexyconfig.py`, পরিবেশের ভেরিয়েবলে নয় এবং বিক্ষিপ্ত নয়
   ধ্রুবক
7.  `.nexy` টেমপ্লেটগুলিতে অটোস্কেপিং বন্ধ রয়েছে: `| e` সহ অবিশ্বস্ত মানগুলি এস্কেপ করুন৷

```bash
nx dev      # development
nx build    # production build
nx start    # production server
nx test     # pytest, --client adds vitest
```

যখন ডক্স এবং কোড একমত না হয়, তখন কোডটি বিশ্বাস করুন এবং বলুন: `nexy/core/config.py` প্রতিটি
বিকল্প, `nexy/modules/routers/fbrouter/` রাউটিং নিয়ম, `nexy/modules/compiler/` কিভাবে `.nexy`
ফাইলগুলি মডিউল হয়ে যায়।
