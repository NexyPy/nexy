# কোডিং এজেন্ট

`nx new` দিয়ে তৈরি একটি প্রজেক্টে কোডিং এজেন্টকে আপনার মত করে Nexy কোড লিখতে প্রয়োজনীয় নিয়মগুলি বহন করে: কাজের ক্রম, কোড এবং লেখার নিয়ম এবং প্রতি বিষয়ের জন্য একটি দক্ষতা। এই পৃষ্ঠাটি আপনি কী পান, এটি কোথায় যায় এবং কীভাবে এটি বর্তমান রাখা যায় তা বলে। নেক্সিতে কাজ করা নিজেই একটি ভিন্ন কাজ: রিপোজিটরির রুট পড়ুন `AGENTS.md`।

## যা `nx new` যোগ করে

| ফাইল | পঠিত | ধরে রাখে |
|---|---|---|
| `AGENTS.md` | Codex, OpenCode [| প্রকল্পের স্ট্যাক, কাজের ক্রম, নিয়ম, দক্ষতার তালিকা |
| `CLAUDE.md` | Claude Code | একটি লাইন, `@AGENTS.md`, তাই উভয়ই একই পাঠ্য পড়ে |
| `.agents/skills/` | Codex, OpenCode | দক্ষতা |
| `.claude/skills/` | Claude Code, OpenCode | একই দক্ষতা |

`AGENTS.md` সংক্ষিপ্ত এবং উপযোগী। একটি ক্লায়েন্ট-রাউটেড Vue প্রজেক্ট পড়ে "ক্লায়েন্ট-রাউটেড, Vue, Tailwind এর সাথে স্টাইল করা"; একটি API প্রকল্প বলা হয় কোন ভিউ নেই। শুধুমাত্র মানানসই দক্ষতাগুলি অনুলিপি করা হয়: একটি React প্রকল্প `nexy-react` এবং Vue দক্ষতা পায় না, একটি সার্ভার প্রকল্প `.nexy` এবং Markdown দক্ষতা পায়, একটি API প্রকল্প ভিউ সম্পর্কে কোনও দক্ষতা পায় না।

এটি সব বাদ দিতে, `nx new --no-agents` দিয়ে প্রকল্পটি তৈরি করুন।

## দক্ষতা

| দক্ষতা | কভার |
|---|---|
| `nexy-principles` | কাজের ক্রম, কোডের নিয়ম, লেখার নিয়ম |
| `nexy-ux-audit` | অভিজ্ঞতা এবং তথ্য-আর্কিটেকচার অডিট যে কোনো দৃশ্যের আগে চালানোর জন্য |
| `nexy-project` | মোড, ফোল্ডার, ফাইল কনভেনশন, কনফিগারেশন, কমান্ড |
| `nexy-file` | `.nexy` পৃষ্ঠা, প্রপস, হুক, দ্বীপ |
| `nexy-markdown` | `.md` এবং `.mdx` বিষয়বস্তু |
| `nexy-react`, `nexy-preact`, `nexy-solid`, `nexy-vue`, `nexy-svelte` | ক্লায়েন্ট ফ্রেমওয়ার্কের জন্য ইডিওম্যাটিক কোড |
| `nexy-styling` | Tailwind, UnoCSS বা প্লেইন CSS, এবং ডিজাইন টোকেন |
| `nexy-backend` | API হ্যান্ডলার, অ্যাকশন, WebSocket, ISR, মিডলওয়্যার |
| `nexy-modular` | মডুলার রাউটারের কন্ট্রোলার, মডিউল, ইনজেকশন এবং গার্ড |
| `nexy-security` | নির্ভরতা, ইনপুট, সেশন, অনুমোদন, গোপনীয়তা |
| `nexy-testing` | টেস্ট-ফার্স্ট লুপ এবং গেটস |
| `nexy-framework-dev` | নেক্সির সাথে নির্মিত একটি প্রকল্পের পরিবর্তে নেক্সি নিজেই পরিবর্তন করে |

তারা যে নিয়মগুলি প্রয়োগ করে: একটি ভিউ তৈরি করার আগে অভিজ্ঞতার অডিট করুন, প্রথমে ব্যর্থ পরীক্ষা লিখুন, একটি ফাংশন একটি চিকিত্সা করে, একটি ক্লাস একটি উদ্দেশ্য বহন করে, একটি ফোল্ডারে সম্পর্কিত উদ্দেশ্যগুলির একটি সেট ধারণ করে, কোনো ইমোজি নেই, বাস্তব SVG আইকন, মানুষের জন্য লেখা সাধারণ পাঠ্য, এবং React-এ হাতে লেখা DOM স্ক্রিপ্ট নেই, Vue, Svelte, Solid বা Preact।

## একটি বিদ্যমান প্রকল্পে তাদের যোগ করুন

```bash
nx skills
```

প্রকল্পের মূলে এটি চালান। এটি স্ট্যাক খুঁজে পেতে `nexyconfig.py` এবং `package.json` পড়ে, ম্যাচিং দক্ষতা অনুলিপি করে এবং যখন তারা অনুপস্থিত থাকে তখন `AGENTS.md` এবং `CLAUDE.md` লিখে।

এটি কখনই আপনার লেখা একটি ফাইলকে ওভাররাইট করে না: একটি বিদ্যমান `AGENTS.md` বা `CLAUDE.md` রাখা হয়, এবং কমান্ড আপনাকে তাই বলে। আপনার নিজের ফাইলে দক্ষতার তালিকা যোগ করুন যদি আপনি এটি সেখানে চান। আপনার নিজের একটি দক্ষতা `.claude/skills/` বা `.agents/skills/` একা বাকি আছে; শুধুমাত্র `nexy-*` দক্ষতা রিফ্রেশ হয়.

আপনি অনুলিপিগুলি রিফ্রেশ করতে Nexy আপগ্রেড করার পরে আবার `nx skills` চালান, এবং ফলাফলের প্রতিশ্রুতি দিন যাতে পুরো দল এটি ভাগ করে।

## কিভাবে একজন এজেন্ট তাদের খুঁজে বের করে

- `AGENTS.md` (বা `CLAUDE.md`, যা এটি আমদানি করে) প্রতিটি সেশনের শুরুতে পড়া হয়। এটি দক্ষতার নাম দেয়।
- প্রতিটি দক্ষতা একটি নাম এবং একটি বিবরণ দিয়ে শুরু হয় যা বলে যে এটি কী কভার করে এবং কখন এটি লোড করতে হবে। এজেন্ট প্রথমে সেগুলি পড়ে এবং কাজটি মেলে তবেই একটি দক্ষতা খোলে।

দক্ষতাগুলি খোলা [এজেন্ট দক্ষতা বিন্যাস](https://agentskills.io/specification) অনুসরণ করে, তাই অন্যান্য এজেন্ট যারা `SKILL.md` ফোল্ডারগুলি পড়ে তারাও সেগুলি ব্যবহার করতে পারে।

## যা তারা করে না

দক্ষতা একজন এজেন্টকে কীভাবে কাজ করতে হয় তা বলে; তারা এর আউটপুট সঠিক করে না। আপনার নিজের চেক রাখুন:

- এজেন্ট পরিবর্তন কি পড়ুন.
- রান `nx check`, `nx test` এবং `nx build`। দক্ষতা এটির জন্য এবং আউটপুট রিপোর্ট করার জন্য জিজ্ঞাসা করে, সংক্ষিপ্ত নয়।
- এজেন্ট যোগ করে নিরীক্ষা নির্ভরতা (`nexy-security` কীভাবে ব্যাখ্যা করে)।

দক্ষতার উদাহরণগুলি Nexy-এর নিজস্ব পরীক্ষা দ্বারা পরীক্ষা করা হয়: আমদানি বিদ্যমান, কনফিগারেশন ক্ষেত্র বিদ্যমান, কমান্ড বিদ্যমান, Python পার্স। যে ড্রিফট ক্যাচ, ভুল বিচার না.

## প্রকল্প invariants

1. `__nexy__/` তৈরি হয়। এটি কখনই সম্পাদনা করবেন না, এটি কখনই কমিট করবেন না। একটি পরিষ্কার বিল্ড জোর করে এটি মুছুন.
2. URL প্রতি একটি ফাইল। একই পথের জন্য `index.nexy` এবং `index.py` একটি বাগ, অগ্রাধিকারের নিয়ম নয়।
3. ভিতরে সংরক্ষিত নাম `src/routes/`: `layout.nexy`, `loading.nexy`, `errors.nexy`, `notfound.nexy`, `dependencies.py`, `__init__.py`। বিষয়বস্তুর জন্য তাদের ব্যবহার করবেন না.
4. `.nexy` ফ্রন্টম্যাটার হল Python যা প্রতি অনুরোধে চলে। কোনও মডিউল-স্তরের পার্শ্ব প্রতিক্রিয়া নেই: কোনও ফাইল হ্যান্ডেল নেই, কোনও ডাটাবেস সংযোগ নেই, আমদানিতে কোনও নেটওয়ার্ক কল নেই।
5. `.py` `src/routes/` একটি এপিআই হ্যান্ডলার। পদ্ধতি হল ফাংশনের নাম (`GET`, `POST`, ...)।
6. কনফিগারেশন থাকে `nexyconfig.py`, পরিবেশের ভেরিয়েবলে নয় এবং বিক্ষিপ্ত ধ্রুবকগুলিতে নয়।
7. `.nexy` টেমপ্লেটগুলিতে অটোএসকেপিং বন্ধ রয়েছে: `| e` সহ অবিশ্বস্ত মানগুলি এস্কেপ করুন।

```bash
nx dev      # development
nx build    # production build
nx start    # production server
nx test     # pytest, --client adds vitest
```

যখন ডক্স এবং কোড অসম্মত হয়, কোডটি বিশ্বাস করুন এবং বলুন: `nexy/core/config.py` প্রতিটি বিকল্প ধারণ করে, `nexy/modules/routers/fbrouter/` রাউটিং নিয়ম, `nexy/modules/compiler/` কীভাবে `.nexy` ফাইলগুলি মডিউল হয়ে যায়।
