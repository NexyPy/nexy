# Nexy কিভাবে কাজ করে

এক পৃষ্ঠায় মানসিক মডেল: Nexy কী তৈরি করে, কী Vite তৈরি করে এবং আপনার ব্রাউজারে একটি ফাইল এবং একটি পৃষ্ঠার মধ্যে কী ঘটে। একবার পড়ুন; বাকি ডকুমেন্টেশন তারপর বিবরণ একটি সেট.

## নেক্সি আর্কিটেকচার

একটি অনুরোধ পাঁচটি স্তর অতিক্রম করে: Uvicorn এটি গ্রহণ করে, মিডলওয়্যার এটিকে সজ্জিত করে, রাউটার একটি ফাইল বাছাই করে, রেন্ডারার সেই ফাইলটিকে HTML বা JSON-এ পরিণত করে এবং পৃষ্ঠাটিতে JavaScript থাকলে ক্লায়েন্ট স্তরটি গ্রহণ করে। নেক্সি মধ্যম তিনটির মালিক; Vite এবং আপনার ফ্রেমওয়ার্ক ক্লায়েন্টের মালিক; আপনার অ্যাপ্লিকেশন ডেটা, প্রমাণীকরণ এবং অনুমোদনের মালিক।

প্রতিটি স্তর, এবং এটি যা করতে অস্বীকার করে তা [স্থাপত্যে](../architecture.md)। Nexy-এর প্যাকেজগুলির জন্য, রিপোজিটরি রুটে `ARCHITECTURE.md` দেখুন - এটি অবদানকারীদের জন্য লেখা।

## অ্যাপ্লিকেশন জীবনচক্র

`nx dev` প্রথম অনুরোধের আগে ছয়টি কাজ করে:

1. বৈধ করে `nexyconfig.py`, এবং একটি অবৈধ কনফিগারে থামে;
2. প্রকল্পের Python প্যাকেজগুলি আমদানিযোগ্য তা নিশ্চিত করে;
3. পোর্টগুলি সমাধান করে, এবং বাসি `__nexy__/nexy.prod` মার্কার মুছে দেয়;
4. ক্লায়েন্ট ফাইল তৈরি করে এবং সমান্তরালে রুটগুলি কম্পাইল করে;
5. শুরু হয় Vite এবং এটি উত্তর না হওয়া পর্যন্ত অপেক্ষা করে;
6. ফাইল প্রহরী ইনস্টল করে, তারপর ইউভিকর্ন আমদানি করতে দেয় `nexy.modules.routers.app:_server`।

সেই আমদানি অ্যাপ্লিকেশনটিকে একত্রিত করে - মিডলওয়্যার, অ্যাকশন, রাউটার, ত্রুটি হ্যান্ডলার - এবং প্রথম অনুরোধটি সেই সমাবেশ দ্বারা পরিবেশিত হয়। যখন আপনি সংরক্ষণ করেন, পর্যবেক্ষক ইউভিকর্ন পুনরায় চালু করে; একটি পৃষ্ঠা যা প্রদর্শিত, অদৃশ্য বা সরানো হয়েছে তাও ক্লায়েন্ট রুট তালিকা পুনরায় তৈরি করে।

## রাউটিং সিস্টেম

`src/routes/` এর অধীনে একটি পাথ চারটি নিয়ম দ্বারা একটি URL হয়ে যায়:

| ফাইল | URL |
|---|---|
| `blog/index.nexy` | `/blog` |
| `blog/[slug].nexy` | `/blog/hello` |
| `blog/[...parts].nexy` | `/blog/a/b` |
| `(marketing)/about.nexy` | `/about` |

এক্সটেনশন কখনই দেখা যায় না; `index` হল এর ফোল্ডারের রুট; বন্ধনীতে থাকা একটি ফোল্ডার একটি সেগমেন্ট যোগ না করে ফাইলগুলিকে গোষ্ঠীভুক্ত করে।

যখন দুটি জিনিস একই URL এর উত্তর দিতে পারে, **প্রথমটি নিবন্ধিত জয়ী হয়**, এবং Nexy সর্বদা এই ক্রমে নিবন্ধন করে:

1. অ্যাকশন এন্ডপয়েন্ট;
2. স্ট্যাটিক ফাইল: `/public`, `/assets`, `/favicon.ico`;
3. একটি মডুলার `APIRouter` (`useRouter`);
4. ফাইল রুট, সবচেয়ে নির্দিষ্ট প্রথম: স্ট্যাটিক পাথ, তারপর সবচেয়ে নির্দিষ্ট সেগমেন্ট সহ গতিশীল পাথ, তারপর ক্যাচ-অল।

সমান নির্দিষ্টতার দুটি ফাইল রুট বর্ণানুক্রমিক পাথ ক্রমানুসারে নিবন্ধিত, তাই `[id].nexy` `[slug].nexy` এর আগে উত্তর দেয়। একটি মডুলার রুট তাই একই পথের সাথে একটি পৃষ্ঠাকে বীট করে। এটি একটি অগ্রাধিকার আদেশ যা আপনি নির্ভর করতে পারেন, খেলার জন্য টাই-ব্রেক নিয়ম নয়: একটি URL একটি ফাইল দিন৷

## ভিউ সিস্টেম

একটি ফাইলের এক্সটেনশন নির্ধারণ করে যে এটি কী, এবং প্রকল্প কনফিগ সিদ্ধান্ত নেয় কোন এক্সটেনশনগুলি সক্রিয়।

| এক্সটেনশন | সক্রিয় যখন | | দ্বারা সংকলিত | হিসাবে পরিবেশিত
|---|---|---|---|
| `.nexy` | সার্ভার মোড | নেক্সি: ফ্রন্টম্যাটার হয়ে যায় Python, মার্কআপ হয়ে যায় Jinja2 | একটি পৃষ্ঠা |
| `.md` | সর্বদা | নেক্সি: গিটহাব-স্বাদযুক্ত Markdown, শিরোনাম আইডি, বিষয়বস্তুর সারণী | একটি পৃষ্ঠা, নিকটতম লেআউটের ভিতরে |
| `.mdx` | সর্বদা | Vite, React বা Preact | একটি উপাদান রুট |
| `.tsx` | `useFF` হল React, Solid বা Preact | Vite এবং কাঠামো | একটি উপাদান রুট |
| `.vue` | `useFF` হল Vue | Vite এবং Vue | একটি উপাদান রুট |
| `.svelte` | `useFF` হল Svelte | Vite এবং Svelte | একটি উপাদান রুট |
| `.py` | সর্বদা | Python | একটি API হ্যান্ডলার: `GET`, `POST`, ... হল পদ্ধতি |

একটি ফাইল যার এক্সটেনশন সক্রিয় নয় একটি সতর্কতা সহ বাদ দেওয়া হয়, পরিবেশন করা হয় না। ক্লায়েন্ট মোডে, সার্ভার শুরু হওয়ার আগে `.nexy` প্রত্যাখ্যান করা হয়। [ফাইল কনভেনশন](../reference/file-conventions.md) দেখুন।

## রেন্ডারিং জীবনচক্র

তিনটি প্রশ্ন একটি পাঠক নোটিশ সবকিছু নির্ধারণ:

| প্রশ্ন | উত্তর | পৃষ্ঠা |
|---|---|---|
| এইচটিএমএল কে তৈরি করে? | সার্ভার, অথবা একটি ক্লায়েন্ট রুটের জন্য ব্রাউজার | [রেন্ডারিং](../rendering/README.md) |
| ডেটা কখন পড়া হয়? | প্রতিটি অনুরোধে, প্রতিটি পুনর্জন্মে, বা ব্রাউজারে | [SSR](../rendering/ssr.md), [ISR](../rendering/isr.md) |
| কখন JavaScript আসে? | শুধুমাত্র একটি দ্বীপের জন্য, অথবা পুরো নথির জন্য | [দ্বীপগুলি](../rendering/islands.md), [CSR](../rendering/csr.md) |

সার্ভার মোডে সার্ভার প্রতিটি পৃষ্ঠা রেন্ডার করে, `revalidate` প্রতি ইউআরএলে একটি পৃষ্ঠা ক্যাশ করে এবং দ্বীপগুলি একটি উপাদানে JavaScript যোগ করে। ক্লায়েন্ট মোডে প্রথম নথিটি নোডে রেন্ডার করা হয় এবং নেভিগেশন তারপর ব্রাউজারে ঘটে।

`__nexy__/` উত্পন্ন সবকিছু ধারণ করে: সংকলিত পৃষ্ঠা, ক্লায়েন্ট এন্ট্রি, বিল্ড আউটপুট। এটি কখনই সম্পাদনা করবেন না, এটি কখনও করবেন না; একটি পরিষ্কার বিল্ড জোর করে এটি মুছুন.

## ফ্রন্টএন্ড ইন্টিগ্রেশন

**Vite প্রতিস্থাপন করে না নেক্সি।** Vite ক্লায়েন্ট কোড বান্ডিল এবং পরিবেশন করে। এটি একটি অনুরোধ রুট করে না, একটি `.nexy` পৃষ্ঠা রেন্ডার করে না, একটি অ্যাকশন চালায় বা মূলের মালিক হয় না। ব্রাউজারটি একটি মূলের সাথে কথা বলে - Nexy এর - এবং বিকাশে Nexy proxies Vite এর এন্ডপয়েন্ট এর মাধ্যমে, তাই কনফিগার করার জন্য কোন CORS নেই।

**Nexy প্রতিস্থাপন না React.** Nexy সিদ্ধান্ত নেয় কোন উপাদান রেন্ডার করে, কখন, এবং কোন প্রপস দিয়ে; কাঠামোটি উপাদান মডেল, প্রতিক্রিয়াশীলতা এবং বাস্তুতন্ত্রের মালিক। একটি `.nexy` পৃষ্ঠা একটি দ্বীপ হিসাবে একটি উপাদান আমদানি করে; ক্লায়েন্ট মোডে একটি রুট * একটি উপাদান।

একটি কম্পোনেন্ট রুটের জন্য, Python শুধুমাত্র একটি পাতলা মোড়ক মডিউল লেখে যা ফাইলের দিকে নির্দেশ করে। সংকলন এবং সার্ভার-সাইড রেন্ডারিং হল Vite এর কাজ।

## উন্নয়ন এবং উৎপাদন

| | `nx dev` | `nx build` তারপর `nx start` |
|---|---|---|
| পৃষ্ঠাগুলি | সংকলিত হয় যখন আপনি সংরক্ষণ করেন | একবার সংকলিত, সময়ের আগে |
| ক্লায়েন্ট কোড | Vite হট রিলোড সহ ডেভ সার্ভার, নেক্সির নিজস্ব মূল | বান্ডেলের পিছনে `__nexy__/client/`, প্রাক-রেন্ডার করা HTML |
| Node.js | রানের পাশে Python | পরিবেশনের প্রয়োজন নেই |
| ত্রুটিগুলি | ব্রাউজারে ওভারলে, প্রতিটি পৃষ্ঠায় টুলবারে | বিশদ বিবরণ ছাড়াই স্ট্যাটাস পৃষ্ঠাগুলি |
| উৎপত্তি | একটি বন্দর, `3000` | একটি বন্দর |

কি পরিবর্তন হয় না: একই রাউটিং নিয়ম, একই পৃষ্ঠা ফাইল, একই `nexyconfig.py`। একটি পৃষ্ঠা যা উভয়ের মধ্যে ভিন্নভাবে আচরণ করে সেটি একটি বাগ, একটি মোড নয়।
