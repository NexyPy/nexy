# মূল ধারণা

মানসিক মডেল, API-এর আগে: পড়ার চারটি স্তর, তারপরে প্রতিটি পৃষ্ঠায় ফিরে আসা ধারণা। প্রতিটি ধারণা এখানে একটি লাইন এবং পৃষ্ঠার একটি লিঙ্ক পায় যা আরও গভীরে যায়।

## কিভাবে এই ডক্স পড়া

| স্তর | এটি যে প্রশ্নের উত্তর দেয় | দিয়ে শুরু করুন |
|---|---|---|
| অ্যাপ্লিকেশন আর্কিটেকচার | কোন স্তরটি একটি অনুরোধের উত্তর দেয় এবং এটি কি করতে অস্বীকার করে | [আর্কিটেকচার](../architecture.md) |
| অ্যাপ্লিকেশন কাঠামো | কোডটি কোথায় থাকে এবং একটি ফাইল কী হয়ে যায় | [প্রকল্প কাঠামো](project-structure.md) |
| উপস্থাপনা এবং রেন্ডারিং | পাঠক যা দেখেন এবং কে HTML তৈরি করে | [দর্শন](../views/README.md), [রেন্ডারিং](../rendering/README.md) |
| অ্যাপ্লিকেশন মিথস্ক্রিয়া | পাঠক কী করে, এবং প্রতিক্রিয়ায় কী চলে | [ক্রিয়াগুলি](../guides/actions.md) |

স্তরগুলি একবার সেই ক্রমে পড়া হয়। এর পরে, আপনার প্রয়োজন একটি পৃষ্ঠা একটি অনুসন্ধান, একটি কোর্স নয়.

## অ্যাপ্লিকেশন আর্কিটেকচার

কোন কোড কোন URL এর উত্তর দেয় তা নির্ধারণ করার তিনটি উপায়। তারা বিকল্প, স্তর নয়:

- **ফাইল-ভিত্তিক রাউটিং (FBR)**: `src/routes/` এর অধীনে একটি ফাইল একটি রুট। ডিফল্ট।
- **মডুলার রাউটার**: একটি NestJS-স্টাইল কোডবেসের জন্য `src/apps/` এর অধীনে কন্ট্রোলার এবং মডিউল, ডেকোরেটরদের সাথে ঘোষিত।
- **কাস্টম রাউটার**: একটি বিদ্যমান FastAPI `APIRouter` অ্যাপ্লিকেশন অন্তর্ভুক্ত।

তিনটির মধ্যে একটি বেছে নেওয়া একটি সিদ্ধান্ত। ফ্রন্টএন্ড ফ্রেমওয়ার্ক বেছে নেওয়া আরেকটি, আলাদা আলাদা: [একটি রাউটার চয়ন করুন](../routing/README.md) এবং [ভিউ](../views/README.md) দেখুন।

## আবেদন কাঠামো

পাঁচটি ধারণা যে Next.js থেকে আসা একজন পাঠক সাধারণত এক হয়ে যায়। তারা একই জিনিস নয়, এবং পার্থক্য সবচেয়ে ব্যাখ্যা করে "কেন আমার পৃষ্ঠা রেন্ডার হচ্ছে না" প্রশ্ন।

| ধারণা | এটি কী | এটি কী নয় |
|---|---|---|
| **রুট** | একটি URL প্যাটার্ন, একটি ফাইলের পাথ দ্বারা উত্পাদিত | একটি ফাইল: একটি ফাইল বেশ কয়েকটি URL এর উত্তর দিতে পারে (`[slug]`) |
| **পৃষ্ঠা** | একটি রুট ফাইল যা একটি ভিউ রেন্ডার করে: `.nexy`, `.md`, `.mdx`, `.tsx`, `.vue`, `.svelte` | একটি শেষ পয়েন্ট: এটি একটি নথির উত্তর দেয়, ডেটা নয় |
| **দেখুন** | একটি পৃষ্ঠার মূল অংশ কী তৈরি করে: Jinja2 এবং Python, Markdown, বা একটি ক্লায়েন্ট উপাদান | একটি রুট: একই দৃশ্য বেশ কয়েকটি পৃষ্ঠা পরিবেশন করতে পারে |
| **কম্পোনেন্ট** | একটি পুনঃব্যবহারযোগ্য অংশ একটি পৃষ্ঠা আমদানি করে | একটি রুট: সার্ভার মোডে একটি উপাদান কখনই নিজে থেকে পরিবেশিত হয় না |
| **রুট হ্যান্ডলার** | একটি `.py` রুট ফাইলের ফাংশন, HTTP পদ্ধতির নামে নামকরণ করা হয়েছে (`GET`, `POST`, …) | একটি পৃষ্ঠা: এটি JSON, একটি ফাইল বা একটি `Response` |
| **এন্ডপয়েন্ট** [| জোড়া (URL, পদ্ধতি) যা একজন হ্যান্ডলার উত্তর দেয় | একটি হ্যান্ডলার: একটি ফাইল বেশ কয়েকটি শেষ পয়েন্টের উত্তর দিতে পারে |

একটি বাক্যে: **একটি পৃষ্ঠা হল একটি রুট ফাইল, একটি ভিউ হল যা এটিকে রেন্ডার করে, একটি উপাদান হল যা একটি পৃষ্ঠা পুনঃব্যবহার করে, একটি হ্যান্ডলার একটি শেষ পয়েন্টের উত্তর দেয়।**

আরও দুটি শব্দ যা সর্বত্র ফিরে আসে:

- **লেআউট**: একটি `layout.*` ফাইল যা তার ফোল্ডারের নিচের পৃষ্ঠাগুলিকে মোড়ানো করে; এইচটিএমএল ডকুমেন্টের মালিক রুট। [লেআউটস](../routing/fbr/layouts/README.md) দেখুন।
- **নির্ভরতা**: একটি ফাংশন যা একটি হ্যান্ডলারের আগে চলে, প্রতি রুট বা প্রতি ফোল্ডারে প্রয়োগ করা হয়। দেখুন [নির্ভরতা](../routing/fbr/dependencies/README.md)।

## উপস্থাপনা এবং রেন্ডারিং

দুটি স্বাধীন সিদ্ধান্ত, প্রায়ই বিভ্রান্ত হয়:

- **বিন্যাস** সিদ্ধান্ত নেয় কোন ফাইলটি পৃষ্ঠাটিকে রেন্ডার করবে: [দর্শন](../views/README.md)।
- **মোড** নির্ধারণ করে কে এইচটিএমএল তৈরি করে এবং কখন: [রেন্ডারিং](../rendering/README.md)।

| ধারণা | এক লাইন |
|---|---|
| সার্ভার মোড | সার্ভার রেন্ডার করে `.nexy` এবং `.md` পৃষ্ঠা; উপাদান হল দ্বীপ ([মোড](../routing/fbr/modes.md)) |
| ক্লায়েন্ট মোড | `useCSR = True`: ফ্রেমওয়ার্ক ফাইলগুলি হল রুট, এবং নেভিগেশন ব্রাউজারে ঘটে |
| SSR, ISR, CSR, দ্বীপপুঞ্জ | চারটি রেন্ডারিং মোড, সিএসআর ব্যতীত প্রতি পৃষ্ঠায় সিদ্ধান্ত নেওয়া হয়েছে, যা প্রতি প্রকল্প ([রেন্ডারিং](../rendering/README.md)) |
| হাইড্রেশন | ব্রাউজারটি HTML এর সাথে একটি ফ্রেমওয়ার্ক সংযুক্ত করছে যা সার্ভার ইতিমধ্যেই পাঠিয়েছে ([দ্বীপগুলি](../rendering/islands.md)) |
| প্রপস | মানগুলি একজন অভিভাবক একটি উপাদানে পাস করেন, একটি `.nexy` ফাইলে `name: prop[type]` ঘোষণা করা হয় ([.nexy ফাইল](../views/nexy/README.md)) |

## অ্যাপ্লিকেশন মিথস্ক্রিয়া

| ধারণা | এক লাইন |
|---|---|
| ক্রিয়া | একটি Python ফাংশন চিহ্নিত `@Action`, একটি `POST` হিসাবে পরিবেশিত, একটি ফর্ম থেকে কলযোগ্য বা একটি টাইপ করা ফাংশন ([কর্ম](../guides/actions.md)) |
| ফর্ম | একটি এইচটিএমএল ফর্ম যা একটি অ্যাকশনে পোস্ট করে, যাচাইকরণের ত্রুটিগুলি পৃষ্ঠায় ফিরে আসে ([কর্ম](../guides/actions.md)) |
| নেভিগেশন | লিঙ্ক যা প্রিফেচ করে, এবং হুকগুলি যা পথ, ক্যোয়ারী, কুকিজ এবং সেশন ([হুকস](../routing/fbr/navigation/hooks.md)) |
| ডেটা আনয়ন | পৃষ্ঠা বা হ্যান্ডলার দ্বারা করা হয় যার এটি প্রয়োজন; Nexy কোনো ক্লায়েন্ট ডেটা লেয়ার পাঠায় না ([হ্যান্ডলার](../routing/fbr/handlers/README.md)]) |

## নেক্সি যা করে না

প্রমাণীকরণ, অনুমোদন, ডাটাবেস, আন্তর্জাতিকীকরণ, ব্যাকগ্রাউন্ড জব, ইমেল, অর্থপ্রদান এবং অনুসন্ধান **আপনার আবেদনের দায়িত্ব**, কাঠামোর নয়। Nexy এক্সটেনশন পয়েন্ট দেয় এবং বলে যে প্রতিটিকে কোথায় প্লাগ করতে হবে: দেখুন [সীমানাগুলি](../architecture.md#boundaries)।

কারণটি তার নিজের স্বার্থে ন্যূনতমতা নয়: একটি কাঠামো যা আপনার ORM বা আপনার প্রমাণীকরণ লাইব্রেরি বাছাই করে এমন কিছু সিদ্ধান্ত নিয়েছে শুধুমাত্র আপনার অ্যাপ্লিকেশন সিদ্ধান্ত নিতে পারে।
