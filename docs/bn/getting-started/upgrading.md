# 2.2-এ আপগ্রেড করা হচ্ছে

আপনি যখন 2.1 থেকে 2.2 এ যান তখন বিদ্যমান প্রকল্পের জন্য কী পরিবর্তন হয় এবং এটি সম্পর্কে কী করতে হবে। দ
সম্পূর্ণ তালিকা [চেঞ্জলগ](../../CHANGELOG.md) এ রয়েছে।

```bash
uv add "nexy>=2.2"            # or: uv tool upgrade nexy
nx build
nx test
```

## আপনাকে কি পরিবর্তন করতে হতে পারে

| পরিবর্তন | এটি করুন |
|---|---|
| **`.mdx` Vite দ্বারা সংকলিত শুধুমাত্র** পাইথন কম্পাইলার আর এটিকে | রেন্ডার করে না `useFF` এ রিঅ্যাক্ট বা প্র্যাক্ট রাখুন এবং `@mdx-js/rollup`, `remark-gfm` এবং `@mdx-js/react` ইনস্টল করুন। কোন উপাদান ছাড়া একটি পৃষ্ঠা পরিবর্তে একটি `.md` ফাইল হতে পারে |
| **`useBadge` হল চলে গেছে** "Built with Nexy" ট্যাগটি আর বিদ্যমান নেই | `nexyconfig.py` থেকে লাইনটি মুছুন। একটি অবশিষ্ট লাইন উপেক্ষা করা হয় |
| **`nx check` আর কম্পাইল করে না `.mdx`** | কিছুই নয়: Vite বিল্ডে MDX ত্রুটির রিপোর্ট করে |

## কি একই থাকে

- আপনার রুট, লেআউট, অ্যাকশন এবং কনফিগারেশন।
- বিদ্যমান প্রকল্পগুলি তাদের নিজস্ব স্টার্টার পেজ রাখে। নতুন স্টার্টার ডিজাইন শুধুমাত্র প্রকল্পের জন্য প্রযোজ্য
  আপগ্রেড করার পরে তৈরি।
- ডেভেলপমেন্ট টুলবার এবং `useDevTools`।

## ২.২-এ নতুন

- **এজেন্ট ফাইল** `nx new` লিখেছেন `AGENTS.md`, `CLAUDE.md` এবং কোডিং এজেন্টের দক্ষতা। একটি জন্য
  আপনার ইতিমধ্যেই রয়েছে প্রজেক্ট, চালান `nx skills`। এটি কখনোই আপনার লেখা একটি ফাইল ওভাররাইট করে না। দেখুন
  [কোডিং এজেন্ট](../guides/ai-agents.md)।
- **একটি ডেভ সার্ভার যা রাখে চলমান** যখন আপনার আবেদন শুরু হতে পারে না, `nx dev` রিপোর্ট করে কেন এবং
  প্রস্থান করার পরিবর্তে পরবর্তী পরিবর্তনের জন্য অপেক্ষা করে।
- **একটি নতুন স্টার্টার** টেলউইন্ড বা ইউনোসিএসএস-এর প্রতিটি ফ্রেমওয়ার্কের জন্য, একই পৃষ্ঠা এবং উপাদান সহ।
- **UnoCSS একটি সার্ভার প্রকল্পে `.nexy` ফাইল** পড়ে। আপনি যদি `.nexy` পৃষ্ঠাগুলির সাথে UnoCSS ব্যবহার করেন তবে যোগ করুন
  `content` ব্লক [সমস্যা সমাধান](../guides/troubleshooting.md) এ দেখানো হয়েছে।

## সংশোধিত ডকুমেন্টেশন

তিনটি পৃষ্ঠা এমন কিছু বলেছে যা কোডটি করে না। আপনি যদি তাদের অনুসরণ করেন তবে আপনার ফাইলগুলি পরীক্ষা করুন:

- একটি `.nexy` উপাদান তার সন্তানদের `<Slot />` (ক্যাপিটাল এস) দিয়ে রাখে, `<slot />` নয়।
- একটি `.nexy` কম্পোনেন্ট ফাইলের নাম PascalCase এ রাখা হয়েছে: এটি একটি পাইথন মডিউল হিসেবে আমদানি করা হয়, তাই একটি হাইফেন
  কম্পাইল করে না।
-  `.mdx` এর জন্য, ফ্রেমওয়ার্ক হল Preact যখন ফাইলটি আমদানি করে `preact`, অন্যথায় প্রতিক্রিয়া দেখায়।
