# রেন্ডারিং

রেন্ডারিং একটি প্রশ্নের উত্তর দেয়: **কে HTML তৈরি করে এবং কখন**। Nexy এর চারটি উত্তর এবং একটি আছে
ডিফল্ট

**নিশ্চিত নন? রাখা এসএসআর।** একটি পৃষ্ঠা পরিবর্তন করুন যখন আপনি কারণটির নাম দিতে পারেন: কন্টেন্ট যা খুব কমই পরিবর্তিত হয়
(ISR), একটি উইজেট যার প্রয়োজন ব্রাউজার (দ্বীপ), বা অ্যাপের মতো নেভিগেশন (CSR)।
## এটি কিভাবে কাজ করে

```diagram filename="কে এইচটিএমএল তৈরি করে এবং কখন"
SSR       request ──► server renders ────────────────► HTML ──► browser
ISR       request ──► cached HTML? ──► browser, regenerated in the background
CSR       request ──► document rendered by the server ──► browser takes over navigation
Islands   request ──► server renders the page ──► one widget hydrates on demand
```

## চারটি মোড

| | SSR | ISR | CSR | দ্বীপপুঞ্জ |
|---|---|---|---|---|
| প্রতিটি অনুরোধে | ডেটা পড়া হয় | প্রতিটি রিজেনারেশনে | ব্রাউজারে | প্রতিটি অনুরোধে |
| HTML আসে | সার্ভার | সার্ভার থেকে, তারপর একটি ক্যাশে | প্রথম নথির জন্য সার্ভার, পরে ব্রাউজার | সার্ভার |
| জাভাস্ক্রিপ্ট | শুধুমাত্র দ্বীপগুলির জন্য | শুধুমাত্র দ্বীপগুলির জন্য | ফ্রেমওয়ার্ক বান্ডিল | শুধুমাত্র দ্বীপ |
| হাইড্রেশন | কোনোটিই | কোনোটিই | পুরো নথি | দ্বীপ |
| ক্যাশে | কোনোটিই | প্রতি URL, মেমরিতে | কোনোটিই | কোনোটিই |
| পৃষ্ঠায় | ডিফল্ট | `revalidate = N` দ্বারা সিদ্ধান্ত নেওয়া হয়েছে | `useCSR = True` প্রকল্পে | `directive` উপাদানের উপর |
| শস্য | পৃষ্ঠা | পৃষ্ঠা | **প্রকল্প ** | উপাদান |

## রেন্ডারিং জীবনচক্র

দুটি তথ্য সবচেয়ে বিস্ময় ব্যাখ্যা করে।

1. **একটি প্রকল্প এক মোডে রয়েছে।** `useCSR` সার্ভার মোড (SSR, ISR, দ্বীপপুঞ্জ, `.nexy`,
   `.md`, `.mdx` রুট) এবং ক্লায়েন্ট মোড (ফ্রেমওয়ার্ক রুট এবং একটি ক্লায়েন্ট রাউটার)। দুটো হতে পারে না
   মিশ্র: [সার্ভার মোড এবং ক্লায়েন্ট মোড](../routing/fbr/modes.md) দেখুন।
2. **সার্ভার মোডের ভিতরে, মোডটি প্রতি পৃষ্ঠা** একটি পৃষ্ঠা `revalidate` দিয়ে ক্যাশে করা যায়, আরেকটি
   একটি দ্বীপ ধরে রাখতে পারে, তৃতীয় কেউ পারে না।

ক্লায়েন্ট মোড এখনও একটি বাস্তব নথি পাঠায়: Nexy এটিকে প্রথম প্রতিক্রিয়ার জন্য নোডে রেন্ডার করে, তারপরে
ব্রাউজার নেভিগেশন গ্রহণ করে। একটি সিএসআর পৃষ্ঠা একটি বান্ডিলের জন্য অপেক্ষা করা একটি ফাঁকা পৃষ্ঠা নয়।

## কখন ব্যবহার করতে হবে

- **কন্টেন্ট, মার্কেটিং, ডকুমেন্টেশন**: SSR, প্লাস ISR যখন কন্টেন্ট খুব কমই পরিবর্তিত হয়।
- **একটি ইন্টারেক্টিভ উইজেট সহ একটি বেশিরভাগ স্ট্যাটিক পৃষ্ঠা**: একটি দ্বীপের সাথে SSR।
- **ড্যাশবোর্ড, সম্পাদক, অ্যাপের মতো নেভিগেশন**: CSR।
- **একটি পৃষ্ঠা ক্রমাগত পঠিত এবং খুব কমই পরিবর্তিত হয়**: আইএসআর।

## কনফিগারেশন

| মোড | যেখানে |
|---|---|
| SSR | কোথাও নেই: এটি ডিফল্ট |
| আইএসআর | `revalidate = 60` একটি `.nexy` পৃষ্ঠার সামনের অংশে |
| সিএসআর | `useCSR = True` `nexyconfig.py` মধ্যে, `useFF` সেট | সহ
| দ্বীপপুঞ্জ | `directive="client:visible"` উপাদান ট্যাগে |

## উদাহরণ

```nexy filename="src/routes/blog/index.nexy"
---
revalidate = 60
---
<h1>Rendered at most once per minute</h1>
```

ফ্রন্টম্যাটার লাইন ছাড়া একই পৃষ্ঠা হল SSR।

## সীমাবদ্ধতা

- **কোন SSG নেই মোড** Nexy বিল্ড টাইমে HTML প্রি-রেন্ডার করে (কম্পোনেন্ট HTML, ক্লায়েন্ট ডকুমেন্ট),
  কিন্তু সর্বদা সার্ভারের মাধ্যমে এটি পড়ে: কোন এক্সপোর্ট কমান্ড নেই, হোস্ট করার জন্য কোন স্বতন্ত্র ফোল্ডার নেই
  স্থিতিশীলভাবে হিমায়িত সামগ্রীর জন্য, একটি দীর্ঘ উইন্ডো সহ ISR ব্যবহার করুন।
- **ISR একটি নয় সিডিএন।** ক্যাশে সেই প্রক্রিয়ায় থাকে যা পৃষ্ঠাটিকে রেন্ডার করে; বেশ কয়েকজন কর্মী রাখে
  বেশ কিছু ক্যাশে। [ISR](isr.md) দেখুন।
- **CSR একটি প্রকল্প সিদ্ধান্ত** আপনি এক পৃষ্ঠার CSR করতে পারবেন না এবং বাকি SSR রাখতে পারবেন না।
- **দ্বীপগুলি দ্বীপটিকে হাইড্রেট করে, নয় পৃষ্ঠা** একটি পৃষ্ঠা যার সমস্ত দ্বীপ একে অপরের উপর নির্ভরশীল
  ছদ্মবেশে CSR পাতা।
