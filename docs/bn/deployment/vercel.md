# আমি কিভাবে Vercel এ একটি Nexy অ্যাপ স্থাপন করব?

`nx add vercel` চালান, আপনার `nx build` আউটপুটের সাথে জেনারেট করা ফাইলগুলিকে একত্রে কমিট করুন এবং Vercel Python রানটাইমকে `src/server.py:app` এ নির্দেশ করুন।

## প্ল্যাটফর্ম ফাইল যোগ করুন

একটি Nexy প্রকল্পের মূল থেকে:

```bash
nx add vercel
nx build
```

`nx add vercel` লিখেছেন `src/server.py` এবং `vercel.json`। অ্যাপটি চালানোর সময় পরিবর্তন হওয়া ফাইলগুলির জন্য উপেক্ষা করার নিয়মগুলিও যুক্ত করে: `__nexy__/build-cache.json`, `__nexy__/server.port`, `__nexy__/.temp/` এবং `__pycache__/`। কমান্ডটি আবার চালানোর ফলে ফাইলগুলি ইতিমধ্যেই বিদ্যমান থাকে এবং উপেক্ষা করার নিয়মগুলি নকল করে না।

## অ্যাপে Vercel পয়েন্ট করুন

Vercel প্রজেক্ট সেটিংসে, Python রানটাইম নির্বাচন করুন এবং এন্ট্রি পয়েন্ট হিসেবে `src/server.py:app` ব্যবহার করুন। ভার্সেল সেই মডিউলে `app` নামটি আবিষ্কার করে; `nx start` জড়িত নয়।

তৈরি করা `src/server.py` অলসকে আমদানি করে `nexy.app.app` এটি কার্যকরী ফোল্ডার প্রস্তুত করার পরে। আপনি স্থানীয়ভাবে `uvicorn src.server:app` এর সাথে একই এন্ট্রি পয়েন্ট ব্যবহার করতে পারেন।

## বিল্ড আউটপুট কমিট

যখন ভার্সেলের কোন বিল্ড কমান্ড থাকে না, তখন এটি শুধুমাত্র সংগ্রহস্থলে যা থাকে তা গ্রহণ করে। প্রতি `__nexy__/` পরে প্রতি `nx build`, সংকলিত রুট সহ, `__nexy__/client/` এর অধীনে ক্লায়েন্ট বান্ডিল এবং `__nexy__/client/.vite/manifest.json` এ ম্যানিফেস্ট করুন।

প্রজেক্ট রুটে `vite.config.ts` রাখুন এবং এটি কমিট করুন। প্রোডাকশনে Nexy স্টাইলশীট এবং স্ক্রিপ্ট ট্যাগ লেখার জন্য Vite ম্যানিফেস্ট পড়ে, কিন্তু এটি সেই ট্যাগগুলিকে নির্গত করে যখন `vite.config.ts` বিদ্যমান থাকে। সেই ফাইলটি ছাড়া পৃষ্ঠাটি এখনও 200 উত্তর দেয় এবং CSS বা ক্লায়েন্ট ছাড়াই আসে JavaScript।

প্রতিশ্রুতি দেবেন না `__nexy__/build-cache.json`: এতে মেশিনের পরম পাথ রয়েছে যা বিল্ড চালায়। `__nexy__/server.port` `nx start` এর অন্তর্গত, এবং `__nexy__/.temp/` হল স্ক্র্যাচ স্পেস।

## একটি শুধুমাত্র পঠনযোগ্য ফাইল সিস্টেম গ্রহণ করুন

একটি Python অ্যাপ্লিকেশন শুরু হওয়ার সময় Vercel শুধুমাত্র পঠনযোগ্য প্রকল্পটিকে মাউন্ট করে। Nexy স্টার্টআপের সময় জেনারেট করা ফাইল লেখে, তাই একটি বেয়ার `from nexy.app import app` `OSError: [Errno 30] Read-only file system` এর সাথে ব্যর্থ হতে পারে।

জেনারেটেড এন্ট্রি পয়েন্ট অ্যাপটি আমদানি করার আগে ছয়টি প্রকল্পের আইটেম একটি লেখার অস্থায়ী ফোল্ডারে অনুলিপি করে: `src`, `__nexy__`, `public`, `nexyconfig.py`, `pyproject.toml` এবং `vite.config.ts`। এটি কার্যকরী ডিরেক্টরি পরিবর্তন করে এবং অনুলিপিটিকে প্রথমে `sys.path` এ রাখে, কারণ Nexy বর্তমান ডিরেক্টরি থেকে রুটগুলি সমাধান করে। আপনার অ্যাপ রানটাইমে পড়া অন্য কোনো ফাইল হাত দিয়ে সেই তালিকায় যোগ করুন।

## ক্যাশে স্ট্যাটিক সম্পদ

জেনারেট করা `vercel.json`-এ দুটি ক্যাশে নিয়ম রয়েছে যা একটি স্থাপন করা Nexy সাইট ব্যবহার করে: `/assets/` এর অধীনে ফাইলগুলি এক বছরের জন্য অপরিবর্তনীয়, এবং `public/` এর অধীনে থাকা ছবি এবং ফন্টগুলি এক সপ্তাহের স্থির থাকাকালীন-পুনঃপ্রমাণ উইন্ডোর সাথে একদিনের জন্য তাজা থাকে। আপনার প্রকল্পের প্রয়োজন হলে একই ফাইলে অন্যান্য নিয়ম যোগ করুন।

## স্থাপনা চেক করুন

পুশ করার আগে, এন্ট্রি পয়েন্টটি আমদানি করুন এবং এটি একটি পৃষ্ঠার জন্য জিজ্ঞাসা করুন:

```bash
uv run python -c "from src.server import app; print(type(app).__name__)"
uv run uvicorn src.server:app
```

তারপর `/` খুলুন, একটি উত্পন্ন রুট এবং `/assets/` এর অধীনে একটি ফাইল। স্থানীয়ভাবে `nx start` এর সাথে প্রতিক্রিয়ার তুলনা করুন: অবস্থা, বিষয়বস্তুর ধরন এবং আকার মেলে। একটি পৃষ্ঠা যা স্থানীয় একের চেয়ে ছোট দুটি ক্লায়েন্ট ট্যাগের অর্থ হল `vite.config.ts` অনুলিপি করা প্রকল্প থেকে অনুপস্থিত।
