# Markdown و MDX

هناك تنسيقان لصفحات المحتوى: `.md` عندما تحتاج فقط إلى Markdown، `.mdx` عندما تحتاج إلى مكونات.

## `.md`: طاهر Markdown

الملف `.md` هو محتوى خالص. يعرضه Nexy باستخدام `cmarkgfm` (GFM)، ويضيف معرفات العناوين، ويشتق جدول محتويات، ويغلفه في أقرب `layout.*`.

```md filename="src/routes/about.md"
# About

Nexy is a fullstack Python meta-framework.
```

- لا يتم استخدام Frontmatter في `.md` كمنطق Python. إذا كنت بحاجة إلى منطق الخادم، فاستخدم `.nexy`.
- يعمل التفاف التخطيط وصفحات الخطأ والشرائح الديناميكية بنفس الطريقة التي تعمل بها الصفحات الأخرى.

## `.mdx`: Markdown بالمكونات

`.mdx` يتم تجميع الملفات بواسطة **Vite**، من خلال مسار مسار الإطار (React أو Preact). Python لا يكتب إلا الغلاف الرقيق الذي يخدم الطريق؛ لا يقوم أبدًا بتجميع أو عرض MDX بنفسه. يتم عرض المكونات بواسطة إطار العمل، ويتم عرضها بواسطة الخادم مثل مسارات المكونات الأخرى، ويتم عرضها مسبقًا إلى HTML بواسطة `nx build`.

- يتطلب `useFF` أن يكون React أو Preact.
- يتطلب الحزم الاختيارية `@mdx-js/rollup` و `remark-gfm` و `@mdx-js/react` (و `@mdx-js/esbuild` للإنشاء). Vite يخبرك أيهما مفقود.
- يتم اكتشاف إطار العمل تلقائيًا من الواردات: Preact عندما يستورد الملف `preact`، React بخلاف ذلك.

> [!NOTE]
> استخدم `.nexy` إذا كنت بحاجة إلى منطق Python في المادة الأمامية.
