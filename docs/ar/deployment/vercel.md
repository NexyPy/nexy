# كيف أقوم بنشر تطبيق Nexy على Vercel؟

قم بتشغيل `nx add vercel`، وقم بتنفيذ الملفات التي تم إنشاؤها مع مخرجات `nx build` الخاصة بك، وقم بتوجيه وقت تشغيل Vercel Python إلى `src/server.py:app`.

## أضف ملفات النظام الأساسي

من جذر مشروع Nexy:

```bash
nx add vercel
nx build
```

`nx add vercel` يكتب `src/server.py` و `vercel.json`. كما أنه يُلحق قواعد تجاهل للملفات التي تتغير أثناء تشغيل التطبيق: `__nexy__/build-cache.json`، `__nexy__/server.port`، `__nexy__/.temp/` و `__pycache__/`. يؤدي تشغيل الأمر مرة أخرى إلى الاحتفاظ بالملفات الموجودة بالفعل ولا يكرر قواعد التجاهل.

## نقطة Vercel في التطبيق

في إعدادات مشروع Vercel، حدد وقت التشغيل Python واستخدم `src/server.py:app` كنقطة إدخال. يكتشف Vercel الاسم `app` في تلك الوحدة؛ `nx start` لا يدخل فيه.

يقوم `src/server.py` الذي تم إنشاؤه باستيراد `nexy.app.app` البطيء بعد أن يقوم بإعداد مجلد العمل. يمكنك استخدام نفس نقطة الإدخال مع `uvicorn src.server:app` محليًا.

## الالتزام بمخرجات البناء

عندما لا يكون لدى Vercel أمر بناء، فإنه يتلقى فقط ما يحتوي عليه المستودع. قم بتنفيذ `__nexy__/` بعد كل `nx build`، مع المسارات المجمعة، وحزمة العميل ضمن `__nexy__/client/` والبيان في `__nexy__/client/.vite/manifest.json`.

احتفظ بـ `vite.config.ts` في جذر المشروع وقم بتنفيذه. في الإنتاج، يقرأ Nexy بيان Vite لكتابة ورقة الأنماط وعلامات البرنامج النصي، ولكنه يصدر تلك العلامات فقط عند وجود `vite.config.ts`. بدون هذا الملف، ستظل الصفحة تجيب على 200 وتصل بدون CSS أو عميل JavaScript.

لا تلتزم `__nexy__/build-cache.json`: فهو يحتوي على مسارات مطلقة من الجهاز الذي قام بتشغيل البناء. `__nexy__/server.port` ينتمي إلى `nx start`، و `__nexy__/.temp/` هو مساحة الصفر.

## قبول نظام ملفات للقراءة فقط

يقوم Vercel بتحميل المشروع للقراءة فقط أثناء بدء تشغيل التطبيق Python. يكتب Nexy الملفات التي تم إنشاؤها أثناء بدء التشغيل، لذلك يمكن أن يفشل `from nexy.app import app` مع `OSError: [Errno 30] Read-only file system`.

تقوم نقطة الإدخال التي تم إنشاؤها بنسخ ستة عناصر مشروع في مجلد مؤقت قابل للكتابة قبل استيراد التطبيق: `src`، `__nexy__`، `public`، `nexyconfig.py`، `pyproject.toml` و `vite.config.ts`. يقوم بتغيير دليل العمل ويضع النسخة أولاً على `sys.path`، لأن Nexy يحل المسارات من الدليل الحالي. أضف أي ملف آخر يقرأه تطبيقك في وقت التشغيل إلى تلك القائمة يدويًا.

## تخزين الأصول الثابتة مؤقتًا

يحتوي `vercel.json` الذي تم إنشاؤه على قاعدتي ذاكرة التخزين المؤقت التي يستخدمها موقع Nexy المنشور: الملفات الموجودة ضمن `/assets/` غير قابلة للتغيير لمدة عام واحد، والصور والخطوط الموجودة ضمن `public/` تظل محدثة لمدة يوم واحد مع نافذة لا معنى لها لمدة أسبوع واحد أثناء إعادة التحقق. أضف قواعد أخرى في نفس الملف إذا كان مشروعك يحتاج إليها.

## تحقق من النشر

قبل الدفع، قم باستيراد نقطة الإدخال واطلب منها صفحة واحدة:

```bash
uv run python -c "from src.server import app; print(type(app).__name__)"
uv run uvicorn src.server:app
```

ثم افتح `/`، مسارًا واحدًا تم إنشاؤه وملفًا واحدًا ضمن `/assets/`. قارن الاستجابة بـ `nx start` محليًا: يجب أن تتطابق الحالة ونوع المحتوى والحجم. الصفحة الأصغر من الصفحة المحلية بعلامتي العميل بالضبط تعني أن `vite.config.ts` كان مفقودًا من المشروع المنسوخ.
