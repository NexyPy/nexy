# الهندسة المعمارية

## التعريف

Nexy عبارة عن خمس طبقات، ولكل واحدة منها وظيفة لا يقوم بها الآخرون. معرفة الحدود تجيب على معظم أسئلة "لماذا تعمل بهذه الطريقة": الصفحة البطيئة هي سؤال العارض، والصفحة الخاطئة هي سؤال جهاز التوجيه، والصفحة التي لا تظهر أبدًا هي سؤال العميل.

هذه الصفحة مخصصة للأشخاص الذين يكتبون طلبًا. حزم Nexy نفسها، والآليات التي تقف وراءها، موصوفة في `ARCHITECTURE.md` في جذر المستودع، للمساهمين.

## الطبقات

```diagram filename="طلب واحد، خمس طبقات"
Browser
   │
   ▼
Uvicorn ───── ASGI transport
   │
   ▼
Middleware ── sessions, CORS, gzip, trusted hosts, your own
   │
   ▼
Router ────── FBR | Modular | Custom ── picks the file that answers
   │
   ▼
Renderer ──── HTML (Jinja2, Markdown, Node) or JSON
   │
   ▼
Response
```

| طبقة | المسؤولية | لا |
|---|---|---|
| Uvicorn | قبول الاتصال، والتحدث بـ ASGI | معرفة ما هي الصفحة |
| البرامج الوسيطة | تزيين الطلب: الجلسة، CORS، gzip، المضيفين الموثوقين، إعادة توجيه HTTPS، لك | اختر طريقًا |
| يقوم جهاز التوجيه | بمطابقة عنوان URL للملف، مع تخطيطاته وتبعياته وصفحات الأخطاء | التي تنتج المحتوى |
| يقوم العارض | بتشغيل الصفحة وتحويل نتيجتها إلى HTML أو JSON | جلب بياناتك |
| العميل | Vite وإطار العمل الخاص بك: الحزم، والترطيب، وملاحة العميل | الإجابة على طلب الخادم |

## من يبني ماذا

| الفاعل | يملك | لا يملك |
|---|---|---|
| توجيه Nexy |، عرض الخادم، الإجراءات، `.nexy` التجميع، أصل واحد | المكونات، التفاعل، البيانات |
| Vite | حزم العميل، خادم التطوير، إعادة التحميل السريع | التوجيه، عرض الخادم، الإجراءات |
| مكونات إطار العمل الخاص بك |، والتفاعل، وتوجيه النظام البيئي |، والمستند (يطلب Nexy تخطيطه له) |
| تطبيقك | البيانات، المصادقة، الترخيص، قواعد العمل | النقل، العرض |

القاعدة وراء الجدول: **يبني Nexy ما يملكه، ولا يجمع أبدًا ما يجمعه Vite.** بالنسبة لمسار المكون، يكتب Python وحدة مجمعة رفيعة تشير إلى الملف.

## حيث يتم تحديد الطلب

1. تعمل البرامج الوسيطة وقد تغير الطلب أو توقفه.
2. يختار جهاز التوجيه ملفًا واحدًا والتخطيطات المحيطة به.
3. يقوم العارض بتشغيل هذا الملف بالبيانات التي يقرأها بنفسه.
4. تعود الاستجابة، وتتولى طبقة العميل المسؤولية إذا كانت الصفحة تحتوي على JavaScript.

كل خطوة، مع الأسبقية الدقيقة بين أجهزة التوجيه وترتيب `nx dev`، موجودة في [كيف يعمل Nexy](getting-started/how-nexy-works.md). هذه الصفحة لا تكرر ذلك.

## التطوير والإنتاج

نفس الطبقات الخمس، مجمعة مرتين:

| طبقة | `nx dev` | `nx build` ثم `nx start` |
|---|---|---|
| يتم تشغيل المترجم | عند حفظ | مرة واحدة، قبل الموعد المحدد |
| Vite | خادم التطوير، إعادة التحميل السريع، الوكيل من خلال أصل Nexy | الحزمة المكتوبة إلى `__nexy__/client/`، لا يوجد خادم مطور |
| العقدة | تعرض مستندات العميل عند الطلب | تعرضها عند الإنشاء، وليس أثناء الخدمة |
| المراقب | يعيد تشغيل اليوفيكورن عند التغيير | غياب |
| الأصل | منفذ واحد | منفذ واحد |

ما يتغير هو *متى* يحدث العمل، وليس *من* يقوم به. الصفحة التي تتصرف بشكل مختلف بين الاثنين هي خطأ في الصفحة، وليست خاصية للوضع.

## الحدود

يتوقف Nexy عند حافة التطبيق الخاص بك، عن قصد:

| اهتمام | ما يقدمه النكسي | ما تكتبه |
|---|---|---|
| المصادقة | البرامج الوسيطة للجلسة، `AuthenticationMiddleware` عند تمكين | تسجيل الدخول، بحث المستخدم، سياسة ملفات تعريف الارتباط |
| التفويض | `dependencies.py`، الحراس، وراثة كل مجلد | القاعدة نفسها |
| قاعدة البيانات | لا شيء: لا يوجد ORM، لا توجد عمليات ترحيل | طبقة النموذج ([قواعد البيانات](guides/databases.md)) |
| التدويل | لا شيء لصفحاتكم؛ يتم ترجمة سطر الأوامر فقط | المكتبة والرسائل ([i18n](guides/i18n.md)) |
| وظائف الخلفية | لا شيء: لا توجد قائمة انتظار، لا يوجد جدولة | عملية عاملة |
| البريد الإلكتروني، المدفوعات، البحث | لا شيء | الخدمة التي تختارها |

السبب هو نفسه بالنسبة لجميع الستة: إطار العمل الذي يختار ORM الخاص بك أو مكتبة المصادقة الخاصة بك تقرر الأشياء التي يمكن لتطبيقك فقط أن يقررها. التكلفة واضحة: لا يوجد شيء موصل لك، وصفحات الدليل أعلاه توضح مكان توصيل كل منها.
