# التقديم

العرض يجيب على سؤال واحد: **من يقوم بإنتاج HTML، ومتى**. لدى Nexy أربع إجابات وافتراضي واحد.

**لست متأكدا؟ احتفظ بـ SSR.** قم بتغيير الصفحة فقط عندما يمكنك تسمية السبب: المحتوى الذي نادرًا ما يتغير (ISR)، أو عنصر واجهة المستخدم الذي يحتاج إلى المتصفح (الجزيرة)، أو التنقل الشبيه بالتطبيق (CSR).

## كيف يعمل

```diagram filename="من ينتج HTML ومتى"
SSR       request ──► server renders ────────────────► HTML ──► browser
ISR       request ──► cached HTML? ──► browser, regenerated in the background
CSR       request ──► document rendered by the server ──► browser takes over navigation
Islands   request ──► server renders the page ──► one widget hydrates on demand
```

## الأوضاع الأربعة

| | SSR | ISR | المسؤولية الاجتماعية للشركات | الجزر |
|---|---|---|---|---|
| تتم قراءة البيانات | في كل طلب | في كل تجديد | في المتصفح | في كل طلب |
| يأتي HTML من | الخادم | الخادم، ثم ذاكرة التخزين المؤقت | الخادم للمستند الأول، ثم المتصفح بعد ذلك | الخادم |
| JavaScript | فقط للجزر | فقط للجزر | حزمة الإطار | الجزيرة فقط |
| الترطيب | لا شيء | لا شيء | الوثيقة كاملة | الجزيرة |
| ذاكرة التخزين المؤقت | لا شيء | لكل عنوان URL، في الذاكرة | لا شيء | لا شيء |
| تقرر | افتراضيا | `revalidate = N` في صفحة | `useCSR = True` في المشروع | `directive` على المكون |
| الحبوب | صفحة | صفحة | **المشروع** | مكون |

## تقديم دورة الحياة

هناك حقيقتان تفسران معظم المفاجآت.

1. **المشروع في وضع واحد.** `useCSR` يختار بين وضع الخادم (SSR، ISR، الجزر، `.nexy`، `.md`، `.mdx` المسارات) ووضع العميل (مسارات إطار العمل وجهاز توجيه العميل). ولا يمكن الخلط بين الاثنين: انظر [وضع الخادم ووضع العميل](../routing/fbr/modes.md).
2. **داخل وضع الخادم، يكون الوضع لكل صفحة.** يمكن تخزين صفحة واحدة مؤقتًا باستخدام `revalidate`، ويمكن لصفحة أخرى الاحتفاظ بجزيرة، ولا يمكن لصفحة ثالثة القيام بأي منهما.

لا يزال وضع العميل يرسل مستندًا حقيقيًا: يعرضه Nexy في Node للاستجابة الأولى، ثم يتولى المتصفح التنقل. صفحة المسؤولية الاجتماعية للشركات ليست صفحة فارغة تنتظر حزمة.

## متى تستخدم

- **المحتوى والتسويق والتوثيق**: SSR، بالإضافة إلى ISR عندما يتغير المحتوى نادرًا.
- **صفحة ثابتة في الغالب مع عنصر واجهة مستخدم تفاعلي واحد**: SSR مع جزيرة.
- **لوحات المعلومات، والمحررين، والتنقل الشبيه بالتطبيقات**: المسؤولية الاجتماعية للشركات.
- **صفحة تقرأ باستمرار ونادرا ما تتغير**: ISR.

## التكوين

| الوضع | حيث |
|---|---|
| SSR | ليس في أي مكان: إنه الافتراضي |
| ISR | `revalidate = 60` في مقدمة صفحة `.nexy` |
| المسؤولية الاجتماعية للشركات | `useCSR = True` في `nexyconfig.py`، مع تعيين `useFF` |
| الجزر | `directive="client:visible"` على علامة المكون |

## مثال

```nexy filename="src/routes/blog/index.nexy"
---
revalidate = 60
---
<h1>Rendered at most once per minute</h1>
```

نفس الصفحة بدون السطر الأمامي هي SSR.

## القيود

- **لا يوجد وضع SSG.** يقوم Nexy بعرض HTML مسبقًا في وقت الإنشاء (HTML المكون، مستندات العميل)، ولكنه يقرأها دائمًا مرة أخرى من خلال الخادم: لا يوجد أمر تصدير، ولا يوجد مجلد مستقل لاستضافته بشكل ثابت. بالنسبة للمحتوى المجمد، استخدم ISR مع نافذة طويلة.
- **ISR ليس CDN.** توجد ذاكرة التخزين المؤقت في العملية التي تعرض الصفحة؛ يحتفظ العديد من العمال بالعديد من المخابئ. انظر [ISR](isr.md).
- **المسؤولية الاجتماعية للشركات هي قرار مشروع.** لا يمكنك إنشاء صفحة واحدة للمسؤولية الاجتماعية للشركات والاحتفاظ بالباقي SSR.
- **الجزر هي التي ترطب الجزيرة، وليس الصفحة.** الصفحة التي تعتمد جميع جزرها على بعضها البعض هي صفحة مقنعة للمسؤولية الاجتماعية للشركات.
