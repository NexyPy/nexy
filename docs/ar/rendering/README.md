# التقديم

العرض يجيب على سؤال واحد: **من يقوم بإنتاج HTML، ومتى**. لدى Nexy أربع إجابات وواحدة
default.

**لست متأكدا؟ احتفظ بـ SSR.** قم بتغيير الصفحة فقط عندما تتمكن من تسمية السبب: المحتوى الذي نادرًا ما يتغير
(ISR)، أداة واحدة تحتاج إلى المتصفح (الجزيرة)، أو التنقل الشبيه بالتطبيق (CSR).

## كيفية العمل

```diagram filename="من ينتج HTML ومتى"
SSR       request ──► server renders ────────────────► HTML ──► browser
ISR       request ──► cached HTML? ──► browser, regenerated in the background
CSR       request ──► document rendered by the server ──► browser takes over navigation
Islands   request ──► server renders the page ──► one widget hydrates on demand
```

## الأوضاع الأربعة

| | SSR | ISR | المسؤولية الاجتماعية للشركات | الجزر |
|---|---|---|---|---|
| تتم قراءة البيانات | في كل طلب | في كل تجديد | في المتصفح | في كل طلب |
| يأتي HTML من | الخادم | الخادم، ثم ذاكرة التخزين المؤقت | الخادم للمستند الأول، ثم المتصفح بعد ذلك | الخادم |
| جافا سكريبت | فقط للجزر | فقط للجزر | حزمة الإطار | الجزيرة فقط |
| الترطيب | لا شيء | لا شيء | الوثيقة كاملة | الجزيرة |
| ذاكرة التخزين المؤقت | لا شيء | لكل عنوان URL، في الذاكرة | لا شيء | لا شيء |
| مقرر | افتراضيا | `revalidate = N` في صفحة | `useCSR = True` في المشروع | `directive` على المكون |
| الحبوب | صفحة | صفحة | **المشروع** | المكون |

## دورة حياة العرض

هناك حقيقتان تفسران معظم المفاجآت.

1. **المشروع في وضع واحد.** `useCSR` يختار بين وضع الخادم (SSR، ISR، الجزر، `.nexy`،
   `.md`، `.mdx` المسارات) ووضع العميل (مسارات إطار العمل وجهاز توجيه العميل). لا يمكن أن يكون الاثنان
   مختلط: راجع [وضع الخادم ووضع العميل](../routing/fbr/modes.md).
2. **داخل وضع الخادم، يكون الوضع لكل صفحة.** يمكن تخزين صفحة واحدة مؤقتًا باستخدام `revalidate`، وأخرى
   يمكن أن يحتفظ بجزيرة، وثالث لا يمكنه فعل أي منهما.

لا يزال وضع العميل يرسل مستندًا حقيقيًا: يعرضه Nexy في Node للاستجابة الأولى، ثم
يتولى المتصفح مهمة التنقل. صفحة المسؤولية الاجتماعية للشركات ليست صفحة فارغة تنتظر حزمة.

## متى يستخدم

- **المحتوى والتسويق والتوثيق**: SSR، بالإضافة إلى ISR عندما يتغير المحتوى نادرًا.
- **صفحة ثابتة في الغالب مع عنصر واجهة مستخدم تفاعلي واحد**: SSR مع جزيرة.
- **لوحات المعلومات، والمحررين، والتنقل الشبيه بالتطبيق**: المسؤولية الاجتماعية للشركات.
- **صفحة تقرأ باستمرار ونادرا ما تتغير**: ISR.

##  التكوين

| الوضع | حيث |
|---|---|
| SSR | في لا مكان: إنه الافتراضي |
| ISR | `revalidate = 60` في مقدمة صفحة `.nexy` صفحة |
| المسؤولية الاجتماعية للشركات | `useCSR = True` في `nexyconfig.py`، مع تعيين `useFF` |
| الجزر | `directive="client:visible"` على علامة المكون |

## مثال

```nexy filename="src/routes/blog/index.nexy"
---
revalidate = 60
---
<h1>Rendered at most once per minute</h1>
```

نفس الصفحة بدون السطر الأمامي هي SSR.

## القيود

- **لا يوجد وضع SSG.** يعرض Nexy HTML مسبقًا في وقت الإنشاء (HTML المكون، مستندات العميل)،
  ولكن دائمًا ما يقرأها مرة أخرى من خلال الخادم: لا يوجد أمر تصدير، ولا يوجد مجلد مستقل لاستضافته
  بشكل ثابت. بالنسبة للمحتوى المجمد، استخدم ISR مع نافذة طويلة.
- **ISR ليس CDN.** توجد ذاكرة التخزين المؤقت في العملية التي تعرض الصفحة؛ يحتفظ العديد من العمال
  عدة مخابئ. انظر [ISR](isr.md).
- **المسؤولية الاجتماعية للشركات هي قرار مشروع.** لا يمكنك إنشاء صفحة واحدة للمسؤولية الاجتماعية للشركات والاحتفاظ بباقي المسؤولية الاجتماعية للشركات.
- **الجزر هي التي ترطب الجزيرة وليس الصفحة.** الصفحة التي تعتمد جزرها جميعها على بعضها البعض هي صفحة
  صفحة المسؤولية الاجتماعية للشركات مقنعة.
