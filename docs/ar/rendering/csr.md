# المسؤولية الاجتماعية للشركات (العرض من جانب العميل)

## التعريف

يقوم CSR بتسليم التنقل إلى المتصفح: بعد المستند الأول، لم يعد التنقل بين الصفحات مطلوبًا
الخادم لHTML. في Nexy هو قرار **مشروع**، وليس صفحة واحدة - `useCSR = True` يحول
توجيه العميل للتطبيق بأكمله.

## كيفية العمل

```python filename="nexyconfig.py"
from nexy.core.models import NexyConfigModel
from nexy.frontend import react


class NexyConfig(NexyConfigModel):
    useFF = react()
    useCSR = True
```

ثم يتغير شكل المشروع:

| | وضع الخادم (`False`) | وضع العميل (`True`) |
|---|---|---|
| الطرق | `.nexy`، `.md`، `.mdx` | `.tsx`، `.jsx`، `.vue`، `.svelte` |
| المستند | `layout.nexy` | الجذر `layout.tsx` / `.vue` / `.svelte` يملك `<html>`، `<head>`، `<body>` |
| مكونات العميل | الجزر داخل الصفحة | الصفحات نفسها |
| `.nexy` تحت `src/routes/` | تنسيق الصفحة | مرفوض قبل `nx dev`، `nx start` و `nx build` |
| التنقل | طلب كامل لكل رابط | جهاز توجيه العميل |

`.md` و`.mdx` يظلان صالحين: يعرضهما Nexy على الخادم داخل تخطيط العميل، و
يتولى جهاز توجيه العميل المسؤولية من هناك. `.py` توجد المعالجات بجوار المسارات ويتم خدمتها بواسطة FastAPI.

## دورة حياة العرض

1.  يصل الطلب إلى جهاز التوجيه القائم على الملف، والذي يجد المسار المطابق وتخطيطاته.
2. يعرض التخطيط الجذر **المستند بأكمله** في العقدة - الاستجابة الأولى تحمل بالفعل
   حقيقي `<html>`، وليس قوقعة فارغة.
3. يقوم Nexy بإدخال أصول العميل ووصف JSON للصفحة قبل `</body>`.
4. يقوم المتصفح بترطيب تلك الوثيقة. تحافظ التخطيطات المتداخلة على حالتها من الآن فصاعدًا.
5. يتم التعامل مع الارتباط إلى مسار آخر بواسطة جهاز توجيه العميل: لا يوجد طلب مستند، الصفحة موجودة
   المقدمة في المتصفح.

أثناء التطوير، يتم تقديم المستند عند الطلب بواسطة خادم Vite dev. في الإنتاج هو
يتم تقديمه مرة واحدة عند الإنشاء: يحصل المسار الثابت على وثيقته، بينما يحصل المسار الديناميكي على واحد لكل إعلان
المعلمة الثابتة، أو الصدفة - التخطيطات المحيطة بصفحة فارغة - عندما لا تعلن شيئًا.

## متى يستخدم

- لوحات المعلومات، والمحررين، وأي شيء يتصرف مثل التطبيق.
- واجهة برمجة تطبيقات Python مع تطبيق العميل في الأعلى.
- صفحة يكون فيها كل تفاعل محليًا وستشعر برحلة ذهابًا وإيابًا.

##  التكوين

| الإعداد | القيمة |
|---|---|
| `useFF` | مطلوب: `useCSR` يتم رفض بدون إطار عمل العميل |
| `useCSR` | `True` |
| `useRouter` | يجب أن يظل بعيدًا: تم رفض جهاز التوجيه المعياري في وضع العميل |

يتم تجاهل الملفات والمجلدات التي تبدأ بـ `_` أو `.` من خلال عمليات التحقق هذه.

## مثال

```tsx filename="src/routes/layout.tsx"
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <head><title>My app</title></head>
      <body>{children}</body>
    </html>
  )
}
```

```tsx filename="src/routes/index.tsx"
export default function Home() {
  return <h1>Home</h1>
}
```

## القيود

- **المشروع بأكمله.** لا يمكنك دمج صفحة CSR واحدة في مشروع في وضع الخادم: اختر الوضع لـ
  التطبيق، ثم استخدم [الجزر](islands.md) للأجزاء التفاعلية لصفحة وضع الخادم.
- **لا يوجد `.nexy` طرق.** أي شيء كتبته في `.nexy` يجب أن يصبح مكون إطار عمل.
- **تمر بيانات الخادم عبر نقاط النهاية.** لا يمكن لمسار العميل قراءة قاعدة البيانات في وقت العرض؛ ذلك
  يستدعي معالج `.py` أو [إجراء](../guides/actions.md).
- **يحتاج المسار الديناميكي إلى معلمة ثابتة معلنة، أو يبدأ من الصدفة.** تصدير
  `getStaticParams()` من الصفحة - أسماء Next.js `getStaticPaths` و `generateStaticParams`
  يتم قبولها أيضًا - للحصول على مستند واحد لكل قيمة. بدونها، تحمل القشرة التخطيطات و
  ليست الصفحة: تظهر الصفحة بمجرد تشغيل المتصفح.
- **المسؤولية الاجتماعية للشركات ليست صفحة فارغة، وليست SPA أيضًا.** يتم تقديم المستند الأول بواسطة الخادم؛ ذلك
  هو التنقل الذي يحدث في المتصفح.
