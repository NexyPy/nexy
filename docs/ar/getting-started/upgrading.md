# الترقية إلى 2.2

ما الذي يتغير لمشروع موجود عند الانتقال من 2.1 إلى 2.2، وماذا تفعل حيال ذلك. القائمة الكاملة موجودة في [سجل التغيير](../../CHANGELOG.md).

```bash
uv add "nexy>=2.2"            # or: uv tool upgrade nexy
nx build
nx test
```

## ما قد تضطر إلى تغييره

| تغيير | افعل هذا |
|---|---|
| **تم تجميع `.mdx` بواسطة Vite فقط.** لم يعد المترجم Python يعرضه | احتفظ بـ React أو Preact في `useFF` وقم بتثبيت `@mdx-js/rollup`، `remark-gfm` و `@mdx-js/react`. يمكن للصفحة التي لا تحتوي على مكونات أن تكون ملف `.md` بدلاً من |
| **`useBadge` اختفى.** لم تعد علامة "Built with Nexy" موجودة | احذف السطر من `nexyconfig.py`. يتم تجاهل السطر المتبقي |
| **`nx check` لم يعد يجمع `.mdx`** | لا شيء: Vite يُبلغ عن MDX أخطاء في البناء |

## ما يبقى على حاله

- مساراتك وتخطيطاتك وإجراءاتك وتكوينك.
- تحتفظ المشاريع الحالية بصفحاتها الأولية. ينطبق التصميم المبدئي الجديد فقط على المشاريع التي تم إنشاؤها بعد الترقية.
- شريط أدوات التطوير و `useDevTools`.

## جديد في 2.2

- **ملفات الوكلاء.** `nx new` يكتب `AGENTS.md`، `CLAUDE.md` ومهارات وكلاء الترميز. بالنسبة لمشروع لديك بالفعل، قم بتشغيل `nx skills`. لا يقوم أبدًا بالكتابة فوق الملف الذي كتبته. انظر [وكلاء الترميز](../guides/ai-agents.md).
- **خادم تطوير يستمر في العمل.** عندما لا يمكن بدء تشغيل التطبيق الخاص بك، `nx dev` يبلغ عن السبب وينتظر التغيير التالي بدلاً من الخروج.
- **بداية جديدة** لكل إطار عمل في Tailwind أو UnoCSS، بنفس الصفحات والمكونات.
- **UnoCSS يقرأ `.nexy` الملفات** في مشروع الخادم. إذا كنت تستخدم UnoCSS مع صفحات `.nexy`، أضف الكتلة `content` الموضحة في [استكشاف الأخطاء وإصلاحها](../guides/troubleshooting.md).

## الوثائق المصححة

قالت ثلاث صفحات شيئًا لا يفعله الكود. إذا تابعتهم، تحقق من ملفاتك:

- المكون `.nexy` يضع أبناءه بـ `<Slot />` (الحرف الكبير S)، وليس `<slot />`.
- تتم تسمية ملف المكون `.nexy` في PascalCase: يتم استيراده كوحدة Python، لذلك لا يتم تجميع الواصلة.
- بالنسبة لـ `.mdx`، يكون الإطار Preact عندما يستورد الملف `preact`، React بخلاف ذلك.
