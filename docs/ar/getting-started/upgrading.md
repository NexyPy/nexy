# الترقية إلى 2.2

ما الذي يتغير لمشروع موجود عند الانتقال من 2.1 إلى 2.2، وماذا تفعل حيال ذلك. ال
القائمة الكاملة موجودة في [سجل التغيير](../../CHANGELOG.md).

```bash
uv add "nexy>=2.2"            # or: uv tool upgrade nexy
nx build
nx test
```

## ما قد يتعين عليك تغييره

| تغيير | افعل هذا |
|---|---|
| **`.mdx` يتم تجميعه بواسطة Vite فقط.** لم يعد مترجم Python يعرضه | احتفظ بـ React أو Preact في `useFF` وقم بتثبيت `@mdx-js/rollup`، `remark-gfm` و `@mdx-js/react`. يمكن للصفحة التي لا تحتوي على مكونات أن تكون ملف `.md` بدلاً من |
| **`useBadge` اختفى.** لم تعد علامة "Built with Nexy" موجودة | احذف السطر من `nexyconfig.py`. يتم تجاهل السطر المتبقي |
| **`nx check` لم يعد يجمع `.mdx`** | لا شيء: أبلغ Vite عن أخطاء MDX عند الإنشاء |

## ما يبقى على حاله

- المسارات والتخطيطات والإجراءات والتكوينات الخاصة بك.
- تحتفظ المشاريع الحالية بصفحاتها الأولية. ينطبق التصميم المبدئي الجديد على المشاريع فقط
  تم إنشاؤها بعد الترقية.
- شريط أدوات التطوير و`useDevTools`.

## جديد في 2.2

- **ملفات الوكلاء.** `nx new` يكتب `AGENTS.md`، `CLAUDE.md` ومهارات وكلاء الترميز. ل
  المشروع الذي لديك بالفعل، قم بتشغيل `nx skills`. لا يقوم أبدًا بالكتابة فوق الملف الذي كتبته. انظر
  [وكلاء الترميز](../guides/ai-agents.md).
- **خادم تطوير يستمر في العمل.** عندما لا يمكن بدء تشغيل التطبيق الخاص بك، `nx dev` يبلغ عن السبب و
  ينتظر التغيير التالي بدلاً من الخروج.
- **بداية جديدة** لكل إطار عمل في Tailwind أو UnoCSS، بنفس الصفحات والمكونات.
- **يقرأ UnoCSS `.nexy` الملفات** في مشروع الخادم. إذا كنت تستخدم UnoCSS مع `.nexy` من الصفحات، فقم بإضافة ملف
  `content` كتلة تظهر في [استكشاف الأخطاء وإصلاحها](../guides/troubleshooting.md).

## التوثيق المصحح

قالت ثلاث صفحات شيئًا لا يفعله الكود. إذا تابعتهم، تحقق من ملفاتك:

- المكون `.nexy` يضع أبناءه بـ `<Slot />` (الحرف الكبير S)، وليس `<slot />`.
- تمت تسمية ملف المكون `.nexy` في PascalCase: يتم استيراده كوحدة نمطية لـ Python، لذلك يتم استخدام واصلة
  لا يجمع.
- بالنسبة إلى `.mdx`، يكون إطار العمل Preact عندما يستورد الملف `preact`، ويكون React بخلاف ذلك.
