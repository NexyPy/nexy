# المفاهيم الأساسية

النموذج العقلي قبل API: أربعة مستويات للقراءة، ثم المفاهيم التي تعود على كل منها
الصفحة. تحصل كل فكرة على سطر واحد هنا ورابط للصفحة التي تتعمق أكثر.

## كيفية قراءة هذه المستندات

| المستوى | السؤال الذي يجيب عليه | ابدأ بـ |
|---|---|---|
| بنية التطبيق | أي طبقة تجيب على الطلب، وما ترفض القيام به | [الهندسة المعمارية](../architecture.md) |
| بنية التطبيق | حيث يعيش الكود، وما هو الملف | [بنية المشروع](project-structure.md) |
| العرض والتقديم | ما يراه القارئ، ومن ينتج HTML | [المشاهدات](../views/README.md)، [العرض](../rendering/README.md) |
| التفاعل التطبيقي | ما يفعله القارئ، وما يجري استجابة له | [الإجراءات](../guides/actions.md) |

تتم قراءة المستويات بهذا الترتيب مرة واحدة. بعد ذلك، الصفحة التي تحتاجها هي صفحة بحث وليست دورة تدريبية.

## بنية التطبيق

ثلاث طرق لتحديد الرمز الذي يجيب على عنوان URL. إنها بدائل وليست طبقات:

- **التوجيه القائم على الملف (FBR)**: الملف الموجود ضمن `src/routes/` هو مسار. الافتراضي.
- **جهاز التوجيه المعياري**: وحدات التحكم والوحدات ضمن `src/apps/`، المُعلن عنها باستخدام أدوات الديكور، لـ
  قاعدة بيانات على نمط NestJS.
- **جهاز توجيه مخصص**: واجهة FastAPI موجودة `APIRouter` مضمنة في التطبيق.

اختيار واحد من الثلاثة هو قرار واحد. يعد اختيار إطار عمل الواجهة الأمامية أمرًا منفصلاً آخر:
راجع [اختيار جهاز توجيه](../routing/README.md) و[طرق العرض](../views/README.md).

## هيكل التطبيق

خمس مفاهيم عادة ما يدمجها القارئ القادم من Next.js في فكرة واحدة. إنهم ليسوا نفس الشيء،
والفرق يفسر معظم أسئلة "لماذا لا يتم عرض صفحتي".

| المفهوم | ما هو | ما ليس هو |
|---|---|---|
| **الطريق** | نمط عنوان URL، يتم إنتاجه بواسطة مسار ملف | ملف: يمكن لملف واحد الإجابة على عدة عناوين URL (`[slug]`) |
| **صفحة** | ملف مسار يعرض طريقة عرض: `.nexy`، `.md`، `.mdx`، `.tsx`، `.vue`، `.svelte` | نقطة نهاية: فهو يجيب على مستند، وليس بيانات |
| **عرض** | ما ينتج نص الصفحة: Jinja2 وPython أو Markdown أو مكون العميل | الطريق: نفس العرض يمكن أن يخدم عدة صفحات |
| **المكون** | قطعة قابلة لإعادة الاستخدام تستوردها الصفحة | المسار: في وضع الخادم، لا يتم تقديم المكون بمفرده |
| **معالج المسار** | وظيفة ملف المسار `.py`، المسمى على اسم طريقة HTTP (`GET`، `POST`، …) | صفحة: تقوم بإرجاع JSON أو ملف أو `Response` |
| **نقطة النهاية** | الزوج (عنوان URL، الطريقة) الذي يجيب عليه المعالج | المعالج: يمكن لملف واحد الإجابة على عدة نقاط نهاية |

في جملة واحدة: **الصفحة هي ملف توجيه، والعرض هو ما يعرضه، والمكون هو ما هي الصفحة
إعادة الاستخدام، يجيب المعالج على نقطة النهاية.**

كلمتان أخريان تعودان في كل مكان:

- **التخطيط**: ملف `layout.*` يغلف الصفحات الموجودة أسفل المجلد الخاص به؛ الجذر يمتلك HTML
  وثيقة. انظر [التخطيطات](../routing/fbr/layouts/README.md).
- **التبعية**: دالة يتم تشغيلها قبل المعالج، ويتم تطبيقها لكل مسار أو لكل مجلد. انظر
  [التبعيات](../routing/fbr/dependencies/README.md).

## العرض والتقديم

قراران مستقلان، غالبًا ما يتم الخلط بينهما:

- **التنسيق** هو الذي يحدد الملف الذي يعرض الصفحة: [المشاهدات](../views/README.md).
- **يقرر الوضع** من يقوم بإنتاج HTML ومتى: [العرض](../rendering/README.md).

| مفهوم | سطر واحد |
|---|---|
| وضع الخادم | يعرض الخادم `.nexy` و `.md` الصفحات؛ المكونات هي جزر ([أوضاع](../routing/fbr/modes.md)) |
| وضع العميل | `useCSR = True`: ملفات إطار العمل هي المسارات، ويتم التنقل في المتصفح |
| SSR، ISR، CSR، الجزر | أربعة أوضاع عرض، يتم تحديدها لكل صفحة باستثناء CSR، والتي تكون لكل مشروع ([تقديم](../rendering/README.md)) |
| الترطيب | المتصفح الذي يرفق إطار عمل بـ HTML الذي أرسله الخادم بالفعل ([الجزر](../rendering/islands.md)) |
| الدعائم | القيم التي يمررها أحد الوالدين إلى المكون، المعلن عنها `name: prop[type]` في ملف `.nexy` ([.nexy files](../views/nexy/README.md)) |

## تفاعل التطبيق

| مفهوم | سطر واحد |
|---|---|
| الإجراء | دالة بايثون تحمل علامة `@Action`، بمثابة `POST`، قابلة للاستدعاء من نموذج أو كدالة مكتوبة ([إجراءات](../guides/actions.md)) |
| النموذج | نموذج HTML يُنشر إلى إجراء، مع عودة أخطاء التحقق إلى الصفحة ([الإجراءات](../guides/actions.md)) |
| روابط التنقل | التي تجلب مسبقًا، والخطافات التي تقرأ المسار والاستعلام وملفات تعريف الارتباط والجلسة ([الخطافات](../routing/fbr/navigation/hooks.md)) |
| جلب البيانات | يتم عن طريق الصفحة أو المعالج الذي يحتاجها؛ لا يقوم Nexy بشحن طبقة بيانات العميل ([معالجات](../routing/fbr/handlers/README.md)) |

## ما لا يفعله نكسي

المصادقة، والترخيص، وقاعدة البيانات، والتدويل، والوظائف الأساسية، والبريد الإلكتروني، والمدفوعات، و
البحث هو **مسؤولية تطبيقك**، وليس إطار العمل. Nexy يعطي التمديد
ويشير إلى مكان توصيل كل منها: انظر [الحدود](../architecture.md#boundaries).

السبب ليس البساطة في حد ذاتها: إطار عمل يختار ORM الخاص بك أو مكتبة المصادقة الخاصة بك
لقد قرر شيئًا لا يمكن لأحد أن يقرره إلا طلبك.
