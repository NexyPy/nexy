# سطر الأوامر

الثنائي هو `nx` (مثبت أيضًا كـ `nexy`). `uvx nexy new` ينشئ مشروعًا (`uvx` يأتي معه
الأشعة فوق البنفسجية). قم بتشغيل كل الأوامر الأخرى داخل البيئة الافتراضية للمشروع، أو من خلال `uv run`، لـ
مثال `uv run nexy dev`: هذا هو المكان الذي توجد فيه الحزم الخاصة بك.

## الأوامر

| الأمر | الاسم المستعار | ماذا يفعل |
|---|---|---|
| `nx dev` | `nx d` | خادم التطوير: ترجمة عند التغيير، Vite، HMR |
| `nx start` | `nx s` | خادم الإنتاج على الإخراج المترجم |
| `nx build` | `nx b` | بناء الإنتاج |
| `nx new` | `nx n` | مشروع سقالة |
| `nx init` | `nx i` | إضافة Nexy إلى مشروع موجود |
| `nx add` | - | إضافة مكون واجهة المستخدم من السجل أو عنوان URL إلى `src/components/ui` |
| `nx migrate` | `nx m` | إنشاء أو تطبيق عمليات ترحيل قاعدة البيانات باستخدام Alembic أو Aerich |
| `nx check` | `nx c` | التحقق من النوع: mypy على بايثون، `tsc` على TypeScript |
| `nx format` | `nx f` | تنسيق بايثون (روف)، JS/TS (أجمل)، `.nexy` ملفات |
| `nx test` | - | تشغيل pytest؛ `--client` يضيف الأقوى |
| `nx skills` | - | إضافة أو تحديث المهارات، `AGENTS.md` و `CLAUDE.md` لوكلاء الترميز |

## أعلام

| الأمر | العلم | الافتراضي |
|---|---|---|
| `dev`, `start` | `--port` | `usePort`, `3000` |
| `dev`, `start` | `--host` | `useHost`, `0.0.0.0` |
| `build` | `--check` | إيقاف - يعمل ruff و mypy بعد البناء |
| `format` | `--check` | إيقاف - تقرير بدلاً من إعادة الكتابة |
| `test` | `--client` | إيقاف - قم أيضًا بتشغيل vitest بدلاً من pytest وحده |
| `test` | `--no-server` | on - تخطي pytest عندما تريد فقط اختبارات العميل |
| `new` | `--template`، `-t` | لا شيء - استنساخ قالب مسجل بدون مطالبات |
| `new` | `--no-agents` | الوكلاء - تخطي `AGENTS.md` ومهارات الوكيل |
| `add` | `--ui`، `--url` | إيقاف - فرض اسم التسجيل أو عنوان URL عندما يكون غامضًا |
| `add` | `--all`، `-a` | إيقاف - إضافة كل مكون من مكونات التسجيل |
| `add` | `--sha256` | لا شيء - الملخص المتوقع لمكون بعيد؛ عدم التطابق إجهاض |
| `migrate` | `--init` | إيقاف - اكتب إعداد Alembic أو Aerich |
| `migrate` | `--upgrade`، `-u` | إيقاف - تطبيق الهجرات بدلاً من كتابة واحدة جديدة |
| `migrate` | `--message`، `-m` | فارغ - اسم المراجعة الجديدة |

## الإخراج

تُظهر الخطوات الطويلة (تثبيت الحزم، والتجميع، والتجميع) قرصًا دوارًا مع الوقت المنقضي، ثم
واترك سطرًا واحدًا: `✔ uv sync .venv  1.4s`. تظهر مجموعة الخطوات (تثبيتات `nx new`) أ
شريط التقدم مع عدد الخطوات المكتملة، `━━━━────  2/5`؛ خطوة واحدة (`nx add`) تظهر أ
الشريط الذي ينبض أثناء تشغيله. تقرأ سجلات التطوير `GET » /about 200 in 12ms` للطلبات و
`vite » ...` لفيت. الخطوة الفاشلة تطبع الخطوة الأخيرة
أسطر إخراج الأمر بدلاً من إخفائه. المحطات الطرفية التي لا يمكنها تقديم Unicode تحصل عليها
`+` و `x`.

## أخطاء أثناء تشغيل `nx dev`

حفظ ملف معطل لا يوقف الخادم أبدًا. تم الإبلاغ عن ملف `.py` يحتوي على خطأ في بناء الجملة مع ملف
الملف والسطر، ويستمر الخادم في تقديم آخر إصدار عامل حتى تقوم بإصلاحه:

```text
  nexy » error  src/routes/users.py:3
  SyntaxError: invalid syntax

    1 | import json
    2 |
  > 3 | def GET(:
                ^
    4 |     x = 1
    5 |     return {"v": 2}

  Fix it and save: the server keeps its last working version.
```

ملف يتم تحليله لكنه يفشل عند تحميل التطبيق (استيراد مفقود، خطأ في الوحدة النمطية
Level) بنفس الطريقة وينتظر `nx dev` عملية الحفظ التالية؛ لا يتم تقديم أي شيء حتى
يتم تحميل التطبيق مرة أخرى. يقرأ الحفظ الصالح `nexy » update <file>` أثناء إعادة تحميل الخادم. ملفات تخفيض السعر في الخارج
`src/routes`، مثل `README.md`، ليست صفحات ولا تؤدي إلى أي شيء.
`nx start` أكثر صرامة: يخرج بالرمز 1، ولا يبدأ بأي شيء، إذا تعذر تحميل ملف المسار.

## أسئلة `nx new`

`nx new` يسأل، بهذا الترتيب: جهاز التوجيه المستند إلى الملف، ونوع المشروع (الويب أو واجهة برمجة التطبيقات)، والتوجيه من جانب العميل،
إطار عمل العميل، وكيفية تصميم التطبيق، واستيراد الاسم المستعار، وORM، وقاعدة البيانات، وعنوان URL لقاعدة البيانات. كل خيار لديه قصيرة
يتم تسليط الضوء على الوصف والحالي. يتم تخطي الأسئلة التي لا تنطبق (API
المشروع ليس له إطار أو أسلوب؛ اختيار **لا توجد قاعدة بيانات** حيث يتخطى ORM قاعدة البيانات وعنوان URL).
تحرك باستخدام مفاتيح الأسهم (أو `j`/`k`، أو رقم)، أكد باستخدام `enter`، ارجع إلى السابق
سؤال مع `←` أو `esc`، إنهاء مع `ctrl+c`.

| سؤال | الاختيارات |
|---|---|
| استيراد الاسم المستعار | `@` (`@/components/...` يشير إلى `src/`)، أو بادئة أخرى مثل `~` أو `#app` |
| النمط | Tailwind CSS، UnoCSS، Vanilla CSS، أخرى (لا توجد أداة CSS، نفس ورقة الأنماط البسيطة مثل Vanilla) |
| ORM | SQLModel، SQLAlchemy، Tortoise-ORM، لا توجد قاعدة بيانات |
| قاعدة البيانات (مع ORM) | SQLite، PostgreSQL، Neon، MySQL / MariaDB، أخرى (اكتب عنوان URL) |

يتم تثبيت برنامج تشغيل قاعدة البيانات لـ ORM المختار معه (`psycopg` أو `pymysql` أو `asyncpg` أو
`aiomysql`)، ويتم كتابة الرابط إلى `.env`.

قبل تثبيت الحزم، `nx new` يتحقق من الاتصال. بدون واحد، فإنه يتخطى عمليات التثبيت و
يخبرك بتشغيل `uv sync` وتثبيت مدير الحزم الخاص بك لاحقًا. مع واحد، فإنه يطبع
زمن الوصول وسرعة التنزيل، ويحذر عندما يكون الاتصال بطيئًا (أكثر من 400 مللي ثانية، أو أقل
100 كيلو بايت/ثانية). على سبيل المثال، يقوم كل سطر تثبيت بتسمية الأداة والمجلد الذي تملأه
`pnpm install node_modules` أو `uv sync .venv`.

## ما يخلق `dev` و `build` و `start`

قبل تشغيلها، تقوم الأوامر الثلاثة بإنشاء `__init__.py` فارغة في `src/` وفي كل مجلد
تحته يحتوي على ملف `.py` أو `.nexy`، لذا فإن مسارًا مثل `src/routes/users.py` يستورد
بنفس الطريقة في كل منهم. لا يتم لمس الملفات الموجودة أبدًا، و`nx dev` يفعل الشيء نفسه مرة أخرى عندما
قمت بإضافة مجلد. ينتقل كود Python الثانوي إلى `__nexy__/__pycache__`، لذا لا يوجد مجلد `__pycache__`
يظهر بجوار مصادرك.

## اللغة

يتحدث سطر الأوامر الإنجليزية والصينية والهندية والإسبانية والبرتغالية والفرنسية والألمانية واليابانية،
الروسية والكورية والإندونيسية والعربية. يستخدم أول ما يدعمه:

1. متغير البيئة `NEXY_LANG` (`NEXY_LANG=ja nx dev`)؛
2. المتغيرات المحلية لقوقعتك (`LC_ALL`، `LC_MESSAGES`، `LANG`، ثم `LANGUAGE`)؛
3. لغة نظام التشغيل الخاص بك.

أي شيء آخر هو الإنجليزية، وكذلك أي رسالة لم تصلها لغة ما بعد. إلا ما `nx`
تتم ترجمة المطبوعات: تظل أخطاء المترجم وعمليات التتبع ومخرجات الأدوات التي يتم تشغيلها كما هي
هي. لم تتم مراجعة الترجمات من قبل الناطقين بها حتى الآن:
التصحيحات مرحب بها كطلبات سحب إلى `nexy/modules/i18n/<language>.json`.

## بناء السلوك

`nx build` يجمع المسارات، ثم يجمع العميل عندما يكون `useVite` قيد التشغيل.

> [!ملاحظة]
> لا يوجد `--static` علم. الاستضافة الثابتة هي خيار نشر وليست بناء
> الوضع - راجع [نشر](../deployment/README.md).

## العمل على جهاز Nexy نفسه

داخل هذا المستودع البوابات هي:

```bash
python scripts/verify.py             # lint, format, typecheck, tests
python scripts/audit_dependencies.py # supply-chain audit against the lock
```
