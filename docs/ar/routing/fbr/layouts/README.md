# التخطيطات

يقوم التخطيط بتغليف كل صفحة أسفل الدليل الخاص بها. تداخل التخطيطات: يتم عرض الصفحة داخل تخطيط
الدليل الخاص به، والذي يتم عرضه داخل تخطيط الدليل الأصلي، حتى التخطيط الجذري.

توجد صفحة واحدة لكل نوع ملف تخطيط:

| الملف | الوضع | يمتلك مستند HTML | الصفحة |
|---|---|---|---|
| `layout.nexy` | الخادم (`useCSR = False`) | نعم، في الجذر | [layout.nexy](../../../views/nexy/layouts.md) |
| `layout.tsx` | العميل (`useCSR = True`) | نعم، عند الجذر (React، Solid، Preact) | [React](../../../views/react/differences.md)، [Solid](../../../views/solid/differences.md)، [Preact](../../../views/preact/differences.md) |
| `layout.vue` | العميل | نعم، في الجذر | [layout.vue](../../../views/vue/differences.md) |
| `layout.svelte` | العميل | نعم، في الجذر | [layout.svelte](../../../views/svelte/differences.md) |

يستخدم المشروع عائلة واحدة. `layout.nexy` و `layout.tsx` لا يمكن أن يعيشا في نفس المشروع: الخادم
يحتوي الوضع على `.nexy` تخطيطات ووضع العميل يحتوي على تخطيطات إطارية. انظر
[وضع الخادم ووضع العميل](../modes.md).

## كيفية سيطرة المتصفح على الوثيقة

في وضع العميل، يعرض Nexy التخطيط الجذري في Node، وبالتالي فإن الاستجابة الأولى تكون مستندًا كاملاً. ال
ثم يتولى المتصفح الأمر بإحدى طريقتين:

| الإطار | الاستحواذ | ماذا يعني |
|---|---|---|
| التفاعل، الصلبة | **ترطيب** المستند بأكمله | تتم إعادة استخدام HTML للخادم كما هو |
| Preact, Vue, Svelte | **body takeover** | يقوم إطار العمل ببناء نص الصفحة واستبداله بالنص الذي أرسله الخادم |

لا يمكن لـ Preact وVue وSvelte ترطيب مستند كامل: يقوم Preact `hydrate` ببناء مستند ثانٍ `<html>`
عنصر، يقوم مترجم Vue بإسقاط `<script>` من قالب العميل، ولا يمكن لـ Svelte إنشاء `<html>`،
`<head>` أو `<body>` في المتصفح. فلهم `<html>` و`<head>` والصفات `<body>`
تلك التي أرسلها الخادم، ويتم إنشاء النص فقط بواسطة المتصفح. في الممارسة العملية:

- ضع العنوان والعلامات الوصفية والخطوط والبرنامج النصي للموضوع في تخطيط الجذر: يتم تقديمها بواسطة الخادم
  والبقاء كما هم.
- يتم تطبيق الارتباط على `<html>` أو `<head>` أو `<body>` (على سبيل المثال فئة تفاعلية) بواسطة الخادم
  ولكن لا يتم التحديث في المتصفح قم بتغييرها من برنامج نصي، كما يفعل البرنامج النصي للموضوع.
- يعرض المتصفح النص من الصفر بدلاً من إعادة استخدام ترميز الخادم، وبالتالي يكون النص
  تم استبداله مرة واحدة، في نفس مهمة العرض الأول.

## تخطيط الجذر

تخطيط الجذر هو `src/routes/layout.<ext>`. وهو من خلق `nx new` وهو المكان الوحيد الذي
يكتب `<!DOCTYPE html>`، `<html>`، `<head>` و `<body>` (كل إطار و`.nexy`). الصفحات ومتداخلة
التخطيطات لا تكررها أبدًا.

```text
src/routes/
├─ layout.*              root: the document
├─ index.*
└─ dashboard/
   ├─ layout.*           nested: UI only
   ├─ index.*
   └─ settings.*
```

`dashboard/index` يظهر كـ `root layout > dashboard layout > page`.

## مجموعات الطريق

يمكن أن يكون للدليل الموجود بين قوسين تخطيط خاص به دون تغيير عناوين URL:

```text
src/routes/
├─ layout.nexy
├─ (marketing)/
│  ├─ layout.nexy        wraps /pricing and /about only
│  ├─ pricing.nexy
│  └─ about.nexy
└─ (app)/
   └─ dashboard.nexy     only the root layout
```

##  الثبات

في وضع العميل، يظل التخطيط مثبتًا أثناء تنقل المستخدم بين الصفحات التي تشاركه: إنه
يتم الاحتفاظ بـ DOM والحالة وموضع التمرير. في وضع الخادم، كل تنقل هو مستند جديد.
