# تكامل التوجيه المخصص

يتيح لك Nexy تضمين تطبيق FastAPI موجود كجهاز توجيه في مشروعك. يعد هذا مفيدًا عندما تريد إعادة استخدام منطق الواجهة الخلفية من خدمة أخرى، أو التكامل مع واجهات برمجة التطبيقات التابعة لجهات خارجية، أو إنشاء تطبيق مركب يتضمن مشكلات توجيه متعددة.

على عكس أجهزة التوجيه المستندة إلى الملفات والموحدة، والتي تعتبر جوهرية في Nexy، فإن جهاز التوجيه المخصص هو ببساطة `APIRouter` الذي تقوم بتثبيته في التطبيق الخاص بك.

## متى يجب استخدام جهاز توجيه مخصص

- **خدمات الطرف الثالث**: لديك تطبيق FastAPI موجود وتريد الكشف عنه من خلال عميل Nexy.
- **إعادة استخدام الكود**: استخراج منطق الواجهة الخلفية من مشروع آخر إلى جهاز التوجيه وإدراجه في جهاز جديد.
- **أنماط الواجهة الأمامية متعددة المستأجرين أو الصغيرة**: يوفر كل مستأجر أو وحدة جهاز التوجيه الخاص به.
- **الترحيل التدريجي**: ابدأ بـ `APIRouter` وقم بتطويره إلى وحدة Nexy كاملة لاحقًا.

## كيفية العمل

```python
from fastapi import APIRouter
from nexy import useRouter

# An existing FastAPI router (from another service)
third_party = APIRouter()
@third_party.get("/info")
async def info():
    return {"name": "Foo"}

# In your nexyconfig.py:
useRouter = third_party
```

يتم تثبيت جهاز التوجيه تلقائيًا بواسطة محلل جهاز التوجيه الخاص بـ Nexy. تتوفر مساراتها ضمن نفس نمط عنوان URL كما في التطبيق الأصلي. ليس هناك حاجة إلى تكوين إضافي.

## بناء جهاز توجيه مخصص

1. **إنشاء جهاز التوجيه**
   ```بيثون
   من fastapi استيراد APIRouter

   واجهة برمجة التطبيقات = APIRouter ()
   @api.get("/الحالة")
   حالة التعريف غير المتزامنة ():
       إرجاع {"الحالة": "موافق"}
   ```

2. **راجعه في `nexyconfig.py`**
   ```بيثون
   من .my_backend استيراد واجهة برمجة التطبيقات

   useRouter = api
   ```

3. **طرق الوصول**
   - يمكن للصفحات المستندة إلى الملفات (`.nexy`، `.md`) والمعالجات المعيارية الإشارة إلى `/status` كما تفعل مع أي مسار آخر.
   - يعمل جهاز التوجيه في نفس العملية، لذا تعمل التبعيات واتصالات قاعدة البيانات والمصادقة تمامًا كما في التطبيق الأصلي.

## التكامل مع أجهزة التوجيه الأخرى

يمكن لمشروع Nexy الجمع بين:

- **التوجيه المعتمد على الملف** (`src/routes/`) للصفحات ونقاط النهاية البسيطة
- **التوجيه المعياري** (`useRouter = AppModule`) للواجهات الخلفية المنظمة
- **توجيه مخصص** (`useRouter = APIRouter`) لرمز الجهة الخارجية

الثلاثة يتعايشون. يتم تسجيل كل مسار مرة واحدة فقط. يتم دائمًا فحص جهاز التوجيه المعتمد على الملف عند وجود `src/routes/`.

## وصول CLI إلى التطبيق المضمن

تعمل الأوامر `nexy dev` و `nx` على جهاز التوجيه المثبت تمامًا مثل جهاز التوجيه المدمج. تحصل على:

- إعادة التحميل السريع لنقاط النهاية المحددة في جهاز التوجيه المخصص (إذا كان يستخدم `nexy` أو ميزات خادم التطوير المعتادة لـ FastAPI)
- التصديق في `nexyconfig.py` (أي `APIRouter` أعمال)
- المستندات التي تم إنشاؤها تلقائيًا للمسارات المضمنة (إذا قمت بتمكينها)

##  الأمن والعزلة

نظرًا لأن جهاز التوجيه مضمن، وليس مثبتًا عبر `app.mount`، فلا توجد طبقة ASGI إضافية. يعيش جهاز التوجيه في نفس كائن التطبيق مثل المسارات المعيارية والقائمة على الملفات. هذا يعني:

- تنطبق البرامج الوسيطة المضافة بواسطة جهاز التوجيه المخصص على جميع الطلبات.
- يمكن للحراسات وحقن التبعية المحددة في جهاز التوجيه المخصص الوصول إلى نفس الحاوية مثل الكود الخاص بك (إذا كنت تستخدم الحقن المعياري).
- لا توجد بادئة URL بخلاف ما يحدده جهاز التوجيه نفسه.

إذا كنت بحاجة إلى العزل، فقم بتغليف جهاز التوجيه في تطبيق فرعي قبل تضمينه، أو استخدم تقنيات FastAPI القياسية.

## مثال: تضمين مشروع FastAPI موجود

لنفترض أن لديك `auth.py` في حزمة أخرى:

```python
from fastapi import FastAPI, APIRouter

auth = FastAPI(title="Auth service")
api = APIRouter()

@api.get("/login")
async def login():
    return {"msg": "Login"}

auth.include_router(api)
```

وفي `nexyconfig.py`:

```python
from other_package.auth import api

useRouter = api
```

يمكن الآن الوصول إلى نقطة النهاية `/login` من موقع Nexy الخاص بك دون نقل سطر من التعليمات البرمجية.

## كيف تبدأ

1. قم بإنشاء `APIRouter` الخاص بك (أو ابحث عن واحد في حزمة موجودة).
2. أشر إليه `useRouter` عليه في `nexyconfig.py`.
3. الوصول إلى مساراتها من خلال صفحاتك أو معالجاتك أو أطر عمل العميل.
4. إذا كنت بحاجة إلى مزيد من التحكم، قم بتحويل جهاز التوجيه المخصص إلى جهاز توجيه معياري باستخدام `AppModule`.
