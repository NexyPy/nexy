# كيف أنشر وحدة نمطية في سجل Nexy؟

قم بتشغيل `nx publish` من دليل الوحدة النمطية باستخدام `nx.toml` صالح، ورمز تسجيل مميز، وكل ملف يعلنه البيان؛ يقوم الأمر بالتحقق من الإصدار وإنشاء أرشيف واحد وتحميل نسخة غير قابلة للتغيير.

## قم بإعداد البيان

تسرد الوحدة المصدرية كل ملف يتم شحنه. يحتوي الأرشيف على `nx.toml` وهذه الملفات بالضبط.

```toml filename="nx.toml"
name = "@acme/auth"
version = "1.2.0"
kind = "source"

[compatibility]
nexy = ">=2.0.0"
python = ">=3.12"

[dependencies]
python = []
node = []

[source]
files = ["src/auth.py", "src/helpers.py"]
```

يجب أن يكون الحقل `name` بأحرف صغيرة `@scope/name`. يجب أن يتكون الحقل `version` من ثلاثة أرقام مفصولة بنقاط. يجب أن تكون الملفات مسارات نسبية داخل الوحدة. تعلن وحدة الحزمة عن `source.package` بدلاً من `source.files`.

## تحقق قبل التحميل

استخدم `--dry-run` للتحقق من صحة البيان وأرشفة الملفات المعلنة وطباعة المجموع الاختباري دون تحميل:

```bash
nx publish --dry-run
```

التشغيل الجاف لا يحتاج إلى رمز مميز. يقوم بطباعة سطر `warning:` لكل استيراد نسبي يشير إلى ملف لم يعلن عنه البيان. على سبيل المثال، يحتاج `from .helpers import token` في `src/auth.py` إلى `src/helpers.py` في `source.files`، وإلا فسيحصل التثبيت على استيراد معطل.

## قم بتعيين الرمز المميز

`nx publish` يقرأ `NEXY_REGISTRY_TOKEN`، ثم `~/.config/nexy/registry-token`. يتم إرسال الرمز المميز في رأس `Authorization` ولا تتم طباعته مطلقًا.

```bash
export NEXY_REGISTRY_TOKEN="your-token"
nx publish
```

يتيح ملف الرمز المميز `nx login` المستقبلي كتابة نفس بيانات الاعتماد. بدون أي مصدر، يطبع الأمر `error: No registry token` ويخرج بالحالة 1.

## نشر

```bash
nx publish
```

يقوم الأمر بطباعة الاسم والإصدار والمجموع الاختباري SHA-256 للإصدار الذي نشره. الاسم وزوج الإصدار غير قابلين للتغيير: يؤدي نشره مرة أخرى إلى ظهور خطأ تعارض. نشر نسخة جديدة بدلا من ذلك.

## استخدام سجل آخر

بشكل افتراضي، يرسل الأمر إلى `https://registry.nexypy.dev`. استخدم `--registry` لسجل آخر، على سبيل المثال سجل محلي أثناء التطوير:

```bash
nx publish --registry http://localhost:8000
```

يتم قبول عناوين URL https فقط، بالإضافة إلى http العادي في `localhost` و `127.0.0.1` و `::1`. تتم إعادة محاولة الإجابات العابرة `429` و `5xx` مرتين؛ لا تتم إعادة محاولة بيان سيئ أو رمز مفقود أو تعارض.

## التحقق من الإصدار

```bash
nx add @acme/auth@1.2.0
```

راجع [تثبيت الوحدات](install-modules.md) للحصول على الترقيات والدبابيس وإعدادات الثقة.
