# الواجهة الأمامية

لا تقوم Nexy بشحن نظام المكونات الخاص بها للعميل. إنه يعتمد على Vite: React، Vue، Svelte، Solid و Preact كلها مدعومة، وتعمل صفحات الفانيليا بدون إطار عمل للعميل على الإطلاق.

## تمكين الإطار

```python filename="nexyconfig.py"
from nexy.core.models import NexyConfigModel
from nexy.frontend import react


class NexyConfig(NexyConfigModel):
    useFF = react()   # vue(), svelte(), solid(), preact()
```

`useVite` الإعدادات الافتراضية هي `True`؛ احتفظ بها عند تكوين الإطار.

## ملفات الطريق

| ملحق | المقدمة |
|---|---|
| `.nexy`، `.md` | بواسطة Nexy في وقت الطلب |
| `.mdx`، `.tsx`، `.jsx`، `.vue`، `.svelte` | بواسطة إطار العميل؛ يتم عرضه مسبقًا إلى HTML في وقت الإنشاء، ثم يتم الاستيلاء عليه بواسطة حزمة العميل |

مسار إطار العمل عبارة عن صفحة عادية، وليست جزيرة للعميل فقط: يوجد HTML قبل تشغيل الحزمة، لذا فإن الطلاء الأول لا ينتظر JavaScript.

الإعداد لكل إطار: [React ](../views/react/differences.md)، [Vue ](../views/vue/differences.md)، [Svelte ](../views/svelte/differences.md)، [Solid ](../views/solid/differences.md)، [Preact ](../views/preact/differences.md).

## التنمية

`nx dev` يبدأ تشغيل خادم واحد على منفذ واحد:

1. يقوم التطبيق بإعادة ترجمة المسارات التي قمت بتغييرها، الخادم والعميل؛
2. Vite يعمل على منفذ داخلي ويخدم وحدات الإطار؛
3. نقاط نهاية وكلاء Nexy Vite من خلال أصلها.

المتصفح يتحدث فقط إلى المنفذ `3000`. لا يوجد عنوان URL ثانٍ لفتحه ولا يوجد CORS لتكوينه.

## بناء

`nx build` ينتج:

- HTML معروض مسبقًا لمسارات إطار العمل؛
- حزمة العميل، مع الأصول تحت `__nexy__/client/`؛
- الطرق المجمعة Python .

Vite يبني حزمة العميل؛ تتم كتابة HTML الخاص بالخادم لكل صفحة مكونة في وقت الإنشاء.

> [!NOTE]
> يتم الإبلاغ عن المسار الذي فشل عرض الخادم الخاص به كمسار للعميل فقط بدلاً من فشل الإنشاء بالكامل.

## التصميم

`nexy new` يطلب وضع النمط ويقوم بإعداده لإطار عمل العميل الذي تختاره: Tailwind، UnoCSS أو CSS عادي. رموز التصميم (الألوان، الخطوط، المظهر الداكن) هي متغيرات CSS في `src/globale.css`، الملف الذي تنشئه السقالة.

| الوضع | تتم كتابة صفحات البداية باستخدام |
|---|---|
| Tailwind، UnoCSS | فئات المرافق في العلامات، مع تعيين الرموز المميزة لأسماء الفئات |
| CSS عادي | أسماء الفئات الدلالية وCSS في `src/globale.css` |

اتبع نمط مشروعك عند إضافة صفحة: فئات الأدوات المساعدة في مشروع أدوات مساعدة، وفئات CSS في مشروع CSS عادي. احتفظ بالمكون CSS الذي لا تستطيع الأدوات المساعدة التعبير عنه في كتلة `<style>` الخاصة بالمكون. في مشروع الخادم (`.nexy` صفحة) يقرأ UnoCSS الملفات `.nexy` للفئات؛ Tailwind يجدهم بنفسه.

## الخطوط والصور والنصوص

ضع الملفات الثابتة في `public/` - يتم تقديمها من `/` في كل من التطوير والإنتاج.
