# الواجهة الأمامية

لا تقوم Nexy بشحن نظام المكونات الخاص بها للعميل. إنه يعتمد على Vite: React، Vue، Svelte،
يتم دعم كل من Solid وPreact، وتعمل صفحات الفانيليا بدون إطار عمل للعميل على الإطلاق.

## تمكين الإطار

```python filename="nexyconfig.py"
from nexy.core.models import NexyConfigModel
from nexy.frontend import react


class NexyConfig(NexyConfigModel):
    useFF = react()   # vue(), svelte(), solid(), preact()
```

`useVite` الإعدادات الافتراضية هي `True`؛ احتفظ بها عند تكوين الإطار.

## ملفات التوجيه

| الامتداد | تم تقديمه |
|---|---|
| `.nexy`، `.md` | بواسطة Nexy في وقت الطلب |
| `.mdx`، `.tsx`، `.jsx`، `.vue`، `.svelte` | بواسطة إطار عمل العميل؛ تم عرضه مسبقًا إلى HTML في وقت الإنشاء، ثم تم الاستيلاء عليه بواسطة حزمة العميل |

مسار إطار العمل عبارة عن صفحة عادية، وليست جزيرة للعميل فقط: يوجد HTML قبل تشغيل الحزمة،
لذلك فإن الطلاء الأول لا ينتظر جافا سكريبت.

الإعداد لكل إطار عمل: [React](../views/react/differences.md)، [Vue](../views/vue/differences.md)،
[رشيق](../views/svelte/differences.md)، [صلب](../views/solid/differences.md)،
[Preact](../views/preact/differences.md).

##  التنمية

`nx dev` يبدأ تشغيل خادم واحد على منفذ واحد:

1. يقوم التطبيق بإعادة ترجمة المسارات التي قمت بتغييرها، الخادم والعميل؛
2. يعمل Vite على منفذ داخلي ويخدم وحدات إطار العمل؛
3.  نقاط نهاية وكلاء Nexy Vite من خلال أصلها.

المتصفح يتحدث فقط إلى المنفذ `3000`. لا يوجد عنوان URL ثانٍ لفتحه ولا يوجد CORS لتكوينه.

##  البناء

`nx build` ينتج:

- HTML معروض مسبقًا لمسارات إطار العمل؛
- حزمة العميل، مع أصول ضمن `__nexy__/client/`؛
- طرق بايثون المجمعة.

يتعامل Vite مع حزمة العميل؛ يتم إنتاج SSR HTML لكل ملف بواسطة esbuild.

> [!ملاحظة]
> يتم الإبلاغ عن المسار الذي فشل عرض الخادم الخاص به كمسار للعميل فقط بدلاً من
> فشل البناء كله.

##  التصميم

`nexy new` يطلب وضع النمط ويقوم بإعداده لإطار عمل العميل الذي تختاره: Tailwind،
UnoCSS أو CSS عادي. رموز التصميم (الألوان، الخطوط، المظهر الداكن) هي متغيرات CSS
`src/globale.css`، الملف الذي تنشئه السقالة.

| الوضع | تتم كتابة صفحات البداية بـ |
|---|---|
| فئات الأداة المساعدة Tailwind، UnoCSS | في الترميز، مع تعيين الرموز المميزة لأسماء الفئات |
| أسماء الفئات الدلالية في CSS | و CSS في `src/globale.css` |

اتبع وضع مشروعك عند إضافة صفحة: فئات الأداة المساعدة في مشروع الأداة المساعدة، وCSS في ملف
عادي CSS واحد. احتفظ بالمكون CSS الذي لا تستطيع الأدوات المساعدة التعبير عنه في كتلة `<style>` للمكون.
في مشروع الخادم (`.nexy` صفحة) يقرأ UnoCSS الملفات `.nexy` للفئات؛ تجدهم الريح الخلفية
من تلقاء نفسها.
