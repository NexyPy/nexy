# وكلاء الترميز

يحمل المشروع الذي تم إنشاؤه باستخدام `nx new` القواعد التي يحتاجها وكيل الترميز لكتابة كود Nexy بطريقتك: ترتيب العمل، والكود وقواعد الكتابة، ومهارة واحدة لكل موضوع. توضح هذه الصفحة ما تحصل عليه، وأين تذهب، وكيفية الحفاظ على تحديثه. يعد العمل على Nexy في حد ذاته مهمة مختلفة: اقرأ جذر المستودع `AGENTS.md`.

## ما يضيف `nx new`

| ملف | قرأه | يحمل |
|---|---|---|
| `AGENTS.md` | Codex، OpenCode | كومة المشروع، ترتيب العمل، القواعد، قائمة المهارات |
| `CLAUDE.md` | Claude Code | سطر واحد، `@AGENTS.md`، فكلاهما يقرأ نفس النص |
| `.agents/skills/` | Codex، OpenCode | المهارات |
| `.claude/skills/` | Claude Code، OpenCode | نفس المهارات |

`AGENTS.md` قصير ومفصل. يقرأ المشروع Vue الموجه من قبل العميل "موجه من قبل العميل، Vue، مصممًا بـ Tailwind"؛ يتم إخبار مشروع API بعدم وجود طرق عرض. يتم نسخ المهارات المناسبة فقط: يحصل المشروع React على `nexy-react` ولا توجد مهارة Vue، ويحصل مشروع الخادم على المهارات `.nexy` و Markdown، ولا يحصل مشروع واجهة برمجة التطبيقات على أي مهارة حول طرق العرض.

لتخطي كل ذلك، قم بإنشاء المشروع باستخدام `nx new --no-agents`.

## المهارات

| المهارة | الأغلفة |
|---|---|
| `nexy-principles` | ترتيب العمل، قواعد الكود، قواعد الكتابة |
| `nexy-ux-audit` | تدقيق الخبرة وبنية المعلومات ليتم تشغيله قبل أي عرض |
| `nexy-project` | الأوضاع، المجلدات، اصطلاحات الملفات، التكوين، الأوامر |
| `nexy-file` | `.nexy` الصفحات، الدعائم، الخطافات، الجزر |
| `nexy-markdown` | `.md` و `.mdx` المحتوى |
| `nexy-react`، `nexy-preact`، `nexy-solid`، `nexy-vue`، `nexy-svelte` | الكود الاصطلاحي لإطار عمل العميل |
| `nexy-styling` | Tailwind، UnoCSS أو CSS عادي، ورموز التصميم |
| `nexy-backend` | معالجات واجهة برمجة التطبيقات، الإجراءات، WebSocket، ISR، البرامج الوسيطة |
| `nexy-modular` | وحدات التحكم والوحدات والحقن والحماية لجهاز التوجيه المعياري |
| `nexy-security` | التبعيات، المدخلات، الجلسات، التفويض، الأسرار |
| `nexy-testing` | حلقة الاختبار الأول والبوابات |
| `nexy-framework-dev` | تغيير Nexy نفسه، بدلاً من مشروع تم إنشاؤه باستخدام Nexy |

القواعد التي يفرضونها: تدقيق التجربة قبل إنشاء عرض، وكتابة اختبار الفشل أولاً، ووظيفة واحدة تقوم بمعالجة واحدة، وفئة واحدة تحمل نية واحدة، ومجلد واحد يحتوي على مجموعة واحدة من النوايا ذات الصلة، ولا توجد رموز تعبيرية، وأيقونات SVG حقيقية، ونص عادي مكتوب للأشخاص، ولا توجد نصوص DOM مكتوبة بخط اليد في React، Vue، Svelte، Solid أو Preact.

## إضافتها إلى مشروع موجود

```bash
nx skills
```

قم بتشغيله في جذر المشروع. يقرأ `nexyconfig.py` و `package.json` للعثور على المكدس، وينسخ مهارات المطابقة، ويكتب `AGENTS.md` و `CLAUDE.md` عندما تكون مفقودة.

لا يقوم أبدًا بالكتابة فوق الملف الذي كتبته: يتم الاحتفاظ بـ `AGENTS.md` أو `CLAUDE.md` الموجود، ويخبرك الأمر بذلك. أضف قائمة المهارات إلى ملفك الخاص يدويًا إذا كنت تريد ذلك هناك. مهارة خاصة بك في `.claude/skills/` أو `.agents/skills/` تُترك وحدها؛ يتم تحديث المهارات `nexy-*` فقط.

قم بتشغيل `nx skills` مرة أخرى بعد ترقية Nexy لتحديث النسخ، والالتزام بالنتيجة حتى يشاركها الفريق بأكمله.

## كيف يجدهم الوكيل

- تتم قراءة `AGENTS.md` (أو `CLAUDE.md`، الذي يستورده) في بداية كل جلسة. ويسمي المهارات.
- تبدأ كل مهارة باسم ووصف يوضح ما تغطيه ومتى يتم تحميله. يقرأ الوكيل تلك المهارات أولاً ولا يفتح المهارة إلا عندما تتطابق المهمة.

تتبع المهارات [تنسيق مهارات الوكيل](https://agentskills.io/specification) المفتوح، لذا يمكن للوكلاء الآخرين الذين يقرأون مجلدات `SKILL.md` استخدامها أيضًا.

## ما لا يفعلون

المهارات تخبر الوكيل بكيفية العمل؛ لا يجعلون مخرجاته صحيحة. احتفظ بالشيكات الخاصة بك:

- اقرأ ما تغير الوكيل.
- تشغيل `nx check`، `nx test` و `nx build`. تطلب المهارات ذلك والإبلاغ عن المخرجات، وليس تلخيصها.
- تبعيات التدقيق التي يضيفها الوكيل (`nexy-security` يشرح كيف).

يتم التحقق من الأمثلة الموجودة في المهارات من خلال اختبارات Nexy الخاصة: الواردات موجودة، وحقول التكوين موجودة، والأوامر موجودة، والتحليلات Python. وهذا يلفت النظر إلى الانجراف، وليس سوء التقدير.

## ثوابت المشروع

1. `__nexy__/` يتم إنشاؤه. لا تقم بتحريره أبدًا، ولا تلتزم به أبدًا. احذفه لفرض بناء نظيف.
2. ملف واحد لكل عنوان URL. `index.nexy` و `index.py` لنفس المسار خطأ، وليس قاعدة أولوية.
3. الأسماء المحجوزة داخل `src/routes/`: `layout.nexy`، `loading.nexy`، `errors.nexy`، `notfound.nexy`، `dependencies.py`، `__init__.py`. لا تستخدمها للمحتوى.
4. `.nexy` المادة الأمامية هي Python التي يتم تشغيلها لكل طلب. لا توجد آثار جانبية على مستوى الوحدة: لا توجد معالجات للملفات، ولا توجد اتصالات بقاعدة البيانات، ولا توجد مكالمات شبكة عند الاستيراد.
5. `.py` في `src/routes/` هو معالج API. الأساليب هي أسماء الوظائف (`GET`، `POST`، ​​...).
6. التكوين يعيش في `nexyconfig.py`، وليس في متغيرات البيئة وليس في ثوابت متفرقة.
7. يتم إيقاف الهروب التلقائي في قوالب `.nexy`: الهروب من القيم غير الموثوق بها باستخدام `| e`.

```bash
nx dev      # development
nx build    # production build
nx start    # production server
nx test     # pytest, --client adds vitest
```

عندما تختلف المستندات والكود، ثق في الكود وقل ذلك: `nexy/core/config.py` يحمل كل خيار، `nexy/modules/routers/fbrouter/` قواعد التوجيه، `nexy/modules/compiler/` كيف تصبح الملفات `.nexy` وحدات.
