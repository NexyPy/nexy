# وكلاء الترميز

يحمل المشروع الذي تم إنشاؤه باستخدام `nx new` القواعد التي يحتاجها وكيل الترميز لكتابة كود Nexy بطريقتك:
ترتيب العمل، الكود وقواعد الكتابة، ومهارة واحدة لكل موضوع. هذه الصفحة تقول ما تحصل عليه،
أين تذهب، وكيفية الحفاظ عليها الحالية. يعد العمل على Nexy في حد ذاته مهمة مختلفة: اقرأ
جذر المستودع `AGENTS.md`.

## ما يضيفه `nx new`

| ملف | قرأه | يحمل |
|---|---|---|
| `AGENTS.md` | Codex, OpenCode | حزمة المشروع، ترتيب العمل، القواعد، قائمة المهارات |
| `CLAUDE.md` | كلود كود | سطر واحد، `@AGENTS.md`، فكلاهما يقرأ نفس النص |
| `.agents/skills/` | Codex، OpenCode | المهارات |
| `.claude/skills/` | كلود كود، OpenCode | نفس المهارات |

`AGENTS.md` قصير ومفصل. يقرأ مشروع Vue الموجه من قبل العميل "client-routed، Vue، styled
مع الريح الخلفية"; يتم إخبار مشروع API بعدم وجود طرق عرض. يتم نسخ المهارات المناسبة فقط: أ
يحصل مشروع React على `nexy-react` ولا توجد مهارة Vue، بينما يحصل مشروع الخادم على `.nexy` وMarkdown
المهارات، لا يحصل مشروع واجهة برمجة التطبيقات (API) على أي مهارة بشأن طرق العرض.

لتخطي كل ذلك، قم بإنشاء المشروع باستخدام `nx new --no-agents`.

## المهارات

| المهارة | الأغلفة |
|---|---|
| `nexy-principles` | ترتيب العمل، قواعد الكود، قواعد الكتابة |
| `nexy-ux-audit` | تدقيق الخبرة وبنية المعلومات ليتم تشغيله قبل أي عرض |
| `nexy-project` | الأوضاع، المجلدات، اصطلاحات الملفات، التكوين، الأوامر |
| `nexy-file` | `.nexy` صفحات، دعائم، خطافات، جزر |
| `nexy-markdown` | `.md` و`.mdx` المحتوى |
| `nexy-react`، `nexy-preact`، `nexy-solid`، `nexy-vue`، `nexy-svelte` | الكود الاصطلاحي لإطار عمل العميل |
| `nexy-styling` | Tailwind أو UnoCSS أو CSS العادي ورموز التصميم |
| `nexy-backend` | معالجات API، الإجراءات، WebSocket، ISR، البرامج الوسيطة |
| `nexy-modular` | وحدات التحكم والوحدات والحقن والحماية لجهاز التوجيه المعياري |
| `nexy-security` | التبعيات، المدخلات، الجلسات، التفويض، الأسرار |
| `nexy-testing` | حلقة الاختبار الأول والبوابات |
| `nexy-framework-dev` | تغيير Nexy نفسه، بدلاً من مشروع تم إنشاؤه باستخدام Nexy |

القواعد التي يفرضونها: تدقيق التجربة قبل بناء العرض، وكتابة اختبار الفشل أولاً،
وظيفة واحدة تقوم بمعالجة واحدة، وفئة واحدة تحمل نية واحدة، ومجلد واحد يحمل مجموعة واحدة من
نوايا ذات صلة، لا توجد رموز تعبيرية، أيقونات SVG حقيقية، نص عادي مكتوب للأشخاص، ولا يوجد مكتوب بخط اليد
نصوص DOM النصية في React أو Vue أو Svelte أو Solid أو Preact.

## إضافتها إلى مشروع موجود

```bash
nx skills
```

قم بتشغيله في جذر المشروع. يقرأ `nexyconfig.py` و `package.json` للعثور على المكدس،
ينسخ مهارات المطابقة، ويكتب `AGENTS.md` و`CLAUDE.md` عند فقدانها.

لا يقوم أبدًا بالكتابة فوق الملف الذي كتبته: يتم الاحتفاظ بـ `AGENTS.md` أو `CLAUDE.md` الموجود، ويتم الاحتفاظ بالملف
الأمر يخبرك بذلك. أضف قائمة المهارات إلى ملفك الخاص يدويًا إذا كنت تريد ذلك هناك. مهارة
خاصتك في `.claude/skills/` أو `.agents/skills/` تُركت وحدها؛ فقط `nexy-*` المهارات هي
منتعش.

قم بتشغيل `nx skills` مرة أخرى بعد ترقية Nexy لتحديث النسخ، وتنفيذ النتيجة حتى يتم
الفريق بأكمله يشاركه.

## كيف يجدهم الوكيل

تتم قراءة -  `AGENTS.md` (أو `CLAUDE.md` التي تستورده) في بداية كل جلسة. انها أسماء
  المهارات.
- تبدأ كل مهارة باسم ووصف يوضح ما تغطيه ومتى يتم تحميلها. ال
  يقرأها الوكيل أولاً ولا يفتح المهارة إلا عندما تتطابق المهمة.

تتبع المهارات تنسيق [تنسيق مهارات الوكيل](https://agentskills.io/specification) المفتوح، وغير ذلك
يمكن للوكلاء الذين يقرأون المجلدات `SKILL.md` استخدامها أيضًا.

##  ما لا يفعلون

المهارات تخبر الوكيل بكيفية العمل؛ لا يجعلون مخرجاته صحيحة. احتفظ بالشيكات الخاصة بك:

- اقرأ ما غيره الوكيل.
- تشغيل `nx check`، `nx test` و `nx build`. المهارات تطلب هذا وأن يكون الإخراج
  ذكرت ولم تلخّص.
- تبعيات التدقيق التي يضيفها الوكيل (`nexy-security` يشرح كيفية ذلك).

يتم التحقق من الأمثلة الموجودة في المهارات من خلال اختبارات Nexy الخاصة: الواردات موجودة، والتكوين
الحقول موجودة، الأوامر موجودة، تحليلات بايثون. وهذا يلفت النظر إلى الانجراف، وليس سوء التقدير.

## ثوابت المشروع

1. `__nexy__/` يتم إنشاؤه. لا تقم بتحريره أبدًا، ولا تلتزم به أبدًا. احذفه لفرض بناء نظيف.
2. ملف واحد لكل عنوان URL. `index.nexy` و`index.py` لنفس المسار هو خطأ، وليس قاعدة أولوية.
3. الأسماء المحجوزة داخل `src/routes/`: `layout.nexy`، `loading.nexy`، `errors.nexy`،
   `notfound.nexy`، `dependencies.py`، `__init__.py`. لا تستخدمها للمحتوى.
4.  `.nexy` الواجهة الأمامية هي لغة بايثون التي يتم تشغيلها لكل طلب. لا توجد آثار جانبية على مستوى الوحدة: لا يوجد ملف
   مقابض، لا اتصالات قاعدة البيانات، لا توجد مكالمات الشبكة عند الاستيراد.
5.  `.py` في `src/routes/` هو معالج API. الأساليب هي أسماء الوظائف (`GET`، `POST`، ...).
6. يعيش التكوين في `nexyconfig.py`، وليس في متغيرات البيئة وليس في أماكن متفرقة
   الثوابت.
7. يتم إيقاف الهروب التلقائي في قوالب `.nexy`: الهروب من القيم غير الموثوق بها باستخدام `| e`.

```bash
nx dev      # development
nx build    # production build
nx start    # production server
nx test     # pytest, --client adds vitest
```

عندما تختلف المستندات والكود، ثق في الكود وقل ذلك: `nexy/core/config.py` يحمل كل
الخيار، `nexy/modules/routers/fbrouter/` قواعد التوجيه، `nexy/modules/compiler/` كيف `.nexy`
تصبح الملفات وحدات.
