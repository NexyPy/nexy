# كيف أقوم بتثبيت وحدة من التسجيل؟

قم بتشغيل `nx add @scope/name` في مشروع Nexy لتنزيل إصدار واحد من سجل الوحدة النمطية، والتحقق منه، وتطبيق التغييرات المعلنة الخاصة به. أضف `@1.2.0` لتثبيت الإصدار الدقيق.

## تثبيت وحدة

من جذر مشروع Nexy:

```bash
nx add @acme/auth
nx add @acme/auth@1.2.0
```

`nx add` يقرأ بيانات تعريف الإصدار والأرشيف من `useModuleRegistry`، ويتحقق من المجموع الاختباري SHA-256، ويتحقق من نطاقات التوافق `nexy` و `python` للوحدة النمطية. ثم يكتب فقط الملفات التي يعلنها البيان، ويضيف حزم Python المعلنة مع `uv add`، ويضيف حزم العقد مع مدير حزم المشروع، ويطبق خطافات التكوين على `nexyconfig.py` و `package.json`. تظل الإعدادات والملفات الموجودة كما هي: يتم تخطي الملف المعلن الموجود بالفعل بسطر `warning:`.

يتم تسجيل كل تثبيت ناجح في `.nexy/modules.json`. قم بتنفيذ هذا الملف حتى يحصل أحد أعضاء الفريق على نفس إصدار الوحدة.

## ترقية وحدة

للترقية، قم بتشغيل `nx add @acme/auth` مرة أخرى بعد حصول السجل على إصدار أحدث، أو قم بتعيين دبوس جديد مثل `@acme/auth@1.3.0`. يحدد الاسم غير المثبت الإصدار الأحدث من استجابة التسجيل `/versions`. يؤدي تشغيل نفس الإصدار مرة أخرى إلى طباعة `is already installed` ولا يغير شيئًا.

## تثبيت الإصدار

الدبوس دقيق: `nx add @acme/auth@1.2.0` يقوم بتثبيت `1.2.0` ولا يوجد إصدار آخر. استخدم دبوسًا في CI وفي `.nexy/modules.json` ملتزمًا بحيث تقوم كل عملية دفع بتثبيت نفس الرمز. بدون دبوس، يغير الإصدار الجديد عملية التثبيت التالية.

## تشغيل الهجرات

يتم إيقاف عمليات الترحيل بشكل افتراضي. أضف `--migrate` عندما تريد تشغيل الأوامر المعلنة للإصدار بعد وضع ملفاته وتبعياته في مكانها الصحيح:

```bash
nx add @acme/auth@1.2.0 --migrate
```

تتم طباعة كل أمر قبل تشغيله. يحتاج المشروع إلى تثبيت أداة الترحيل الخاصة به قبل أن تتمكن الوحدة من الإعلان عنها.

## قم بتعيين السجل وقواعد الثقة الخاصة به

الإعدادات الافتراضية موجودة في `nexyconfig.py`:

```python filename="nexyconfig.py"
class NexyConfig(NexyConfigModel):
    useModuleRegistry = "https://registry.nexypy.dev"
    useRequireSignedModules = False
```

`useModuleRegistry` هو عنوان URL الأساسي الذي تقرأه واجهة سطر الأوامر (CLI). يتم قبول عناوين URL الخاصة بـ https فقط، باستثناء الاسترجاع http للتسجيل المحلي أثناء التطوير. `useRequireSignedModules = True` يرفض الإصدار غير الموقع. يتم أيضًا رفض الإصدار الذي يحمل توقيعًا حتى يتوفر أداة التحقق؛ بمجرد التحقق من ذلك، `nx add` يطبع `Verified by` بهوية الموقع. احتفظ بالإعداد الافتراضي `False` للسجلات التي تثق بها فقط.
