# कोडिंग एजेंट

`nx new` के साथ बनाया गया एक प्रोजेक्ट उन नियमों को लागू करता है जो एक कोडिंग एजेंट को आपके तरीके से नेक्सी कोड लिखने के लिए आवश्यक होते हैं:
कार्य का क्रम, कोड और लेखन नियम, और प्रति विषय एक कौशल। यह पेज बताता है कि आपको क्या मिलता है,
यह कहां जाता है, और इसे कैसे चालू रखा जाए। नेक्सी पर काम करना अपने आप में एक अलग काम है: पढ़ें
भंडार की जड़ `AGENTS.md`।

## क्या `nx new` जोड़ता है

| फ़ाइल | | होल्ड्स द्वारा पढ़ें |
|---|---|---|
| `AGENTS.md` | कोडेक्स, ओपनकोड | परियोजना का ढेर, काम का क्रम, नियम, कौशल की सूची |
| `CLAUDE.md` | क्लाउड कोड | एक पंक्ति, `@AGENTS.md`, इसलिए दोनों एक ही पाठ पढ़ते हैं |
| `.agents/skills/` | कोडेक्स, ओपनकोड | कौशल |
| `.claude/skills/` | क्लाउड कोड, ओपनकोड | वही कौशल |

`AGENTS.md` संक्षिप्त और अनुरूप है। क्लाइंट-रूटेड Vue प्रोजेक्ट में लिखा है "क्लाइंट-रूटेड, Vue, स्टाइल
टेलविंड के साथ"; एक एपीआई प्रोजेक्ट में बताया गया है कि कोई विचार नहीं हैं। केवल वही कौशल कॉपी किए जाते हैं जो उपयुक्त होते हैं: a
रिएक्ट प्रोजेक्ट को `nexy-react` मिलता है और कोई Vue कौशल नहीं मिलता है, एक सर्वर प्रोजेक्ट को `.nexy` और मार्कडाउन मिलता है
कौशल, एक एपीआई परियोजना को विचारों के बारे में कोई कौशल नहीं मिलता है।

यह सब छोड़ने के लिए, `nx new --no-agents` के साथ प्रोजेक्ट बनाएं।

## कौशल

| कौशल | कवर |
|---|---|
| `nexy-principles` | कार्य का क्रम, कोड नियम, लेखन नियम |
| `nexy-ux-audit` | किसी भी दृश्य से पहले चलने वाला अनुभव और सूचना-वास्तुकला ऑडिट |
| `nexy-project` | मोड, फ़ोल्डर, फ़ाइल कन्वेंशन, कॉन्फ़िगरेशन, कमांड |
| `nexy-file` | `.nexy` पेज, प्रॉप्स, हुक, आइलैंड्स |
| `nexy-markdown` | `.md` और `.mdx` सामग्री |
| `nexy-react`, `nexy-preact`, `nexy-solid`, `nexy-vue`, `nexy-svelte` | क्लाइंट फ्रेमवर्क के लिए मुहावरेदार कोड |
| `nexy-styling` | टेलविंड, यूनोसीएसएस या सादा सीएसएस, और डिज़ाइन टोकन |
| `nexy-backend` | एपीआई हैंडलर, क्रियाएं, वेबसॉकेट, आईएसआर, मिडलवेयर |
| `nexy-modular` | मॉड्यूलर राउटर के नियंत्रक, मॉड्यूल, इंजेक्शन और गार्ड |
| `nexy-security` | निर्भरताएं, इनपुट, सत्र, प्राधिकरण, रहस्य |
| `nexy-testing` | परीक्षण-पहला लूप और गेट्स |
| `nexy-framework-dev` | नेक्सी के साथ निर्मित प्रोजेक्ट के बजाय नेक्सी को ही बदल रहा है |

वे जो नियम लागू करते हैं: एक दृश्य बनाने से पहले अनुभव का ऑडिट करें, पहले असफल परीक्षण लिखें,
एक कार्य एक उपचार करता है, एक वर्ग एक उद्देश्य रखता है, एक फ़ोल्डर एक सेट रखता है
संबंधित इरादे, कोई इमोजी नहीं, वास्तविक एसवीजी आइकन, लोगों के लिए लिखा गया सादा पाठ और कोई हस्तलिखित नहीं
React, Vue, Svelte, Solid या Preact में DOM स्क्रिप्ट।

## उन्हें किसी मौजूदा प्रोजेक्ट में जोड़ें

```bash
nx skills
```

इसे प्रोजेक्ट के मूल में चलाएँ। यह स्टैक ढूंढने के लिए `nexyconfig.py` और `package.json` पढ़ता है,
मिलान कौशल की प्रतिलिपि बनाता है, और जब वे गायब होते हैं तो `AGENTS.md` और `CLAUDE.md` लिखता है।

यह आपके द्वारा लिखी गई फ़ाइल को कभी भी अधिलेखित नहीं करता है: एक मौजूदा `AGENTS.md` या `CLAUDE.md` रखा जाता है, और
आदेश आपको ऐसा बताता है. यदि आप चाहते हैं तो कौशल सूची को अपनी फ़ाइल में हाथ से जोड़ें। का एक कौशल
`.claude/skills/` या `.agents/skills/` में आपका अपना अकेला छोड़ दिया गया है; केवल `nexy-*` कौशल ही हैं
ताज़ा

कॉपियों को ताज़ा करने के लिए नेक्सी को अपग्रेड करने के बाद `nx skills` को फिर से चलाएँ, और परिणाम को प्रतिबद्ध करें
पूरी टीम इसे साझा करती है।

## एक एजेंट उन्हें कैसे ढूंढता है

- `AGENTS.md` (या `CLAUDE.md`, जो इसे आयात करता है) प्रत्येक सत्र की शुरुआत में पढ़ा जाता है। यह नाम देता है
  कौशल.
- प्रत्येक कौशल एक नाम और विवरण से शुरू होता है जो बताता है कि इसमें क्या शामिल है और इसे कब लोड करना है। द
  एजेंट पहले उन्हें पढ़ता है और कार्य से मेल खाने पर ही कोई कौशल खोलता है।

कौशल खुले [एजेंट कौशल प्रारूप](https://agentskills.io/specification) का अनुसरण करते हैं, इसलिए अन्य
जो एजेंट `SKILL.md` फ़ोल्डर पढ़ते हैं, वे भी उनका उपयोग कर सकते हैं।

## वे क्या नहीं करते

कौशल एक एजेंट को बताते हैं कि कैसे काम करना है; वे इसके आउटपुट को सही नहीं बनाते हैं. अपने स्वयं के चेक रखें:

- पढ़ें कि एजेंट ने क्या बदला।
- `nx check`, `nx test` और `nx build` चलाएँ। कौशल इसके लिए और आउटपुट के लिए पूछते हैं
  रिपोर्ट किया गया, सारांशित नहीं किया गया।
- एजेंट ऑडिट निर्भरता जोड़ता है (`nexy-security` बताता है कि कैसे)।

कौशल में उदाहरणों को नेक्सी के स्वयं के परीक्षणों द्वारा जांचा जाता है: आयात मौजूद हैं, कॉन्फ़िगरेशन
फ़ील्ड मौजूद हैं, कमांड मौजूद हैं, पायथन पार्स करता है। यह बहाव को पकड़ता है, गलत निर्णय को नहीं।

## परियोजना अपरिवर्तनीय

1. `__nexy__/` उत्पन्न होता है। इसे कभी संपादित न करें, इसे कभी प्रतिबद्ध न करें। साफ़ निर्माण के लिए इसे हटाएँ।
2. प्रति यूआरएल एक फ़ाइल। `index.nexy` और `index.py` एक ही पथ के लिए एक बग है, प्राथमिकता नियम नहीं।
3. `src/routes/` के अंदर आरक्षित नाम: `layout.nexy`, `loading.nexy`, `errors.nexy`,
   `notfound.nexy`, `dependencies.py`, `__init__.py`। सामग्री के लिए उनका उपयोग न करें.
4. `.nexy` फ्रंटमैटर पायथन है जो प्रति अनुरोध चलता है। कोई मॉड्यूल-स्तरीय साइड इफेक्ट नहीं: कोई फ़ाइल नहीं
   हैंडल, कोई डेटाबेस कनेक्शन नहीं, आयात पर कोई नेटवर्क कॉल नहीं।
5. `.py` में `src/routes/` एक एपीआई हैंडलर है। विधियाँ फ़ंक्शन नाम हैं (`GET`, `POST`, ...)।
6. कॉन्फ़िगरेशन `nexyconfig.py` में रहता है, न कि पर्यावरण चर में और न ही बिखरे हुए में
   स्थिरांक
7. `.nexy` टेम्प्लेट में ऑटोस्केपिंग बंद है: `| e` के साथ अविश्वसनीय मानों से बचें।

```bash
nx dev      # development
nx build    # production build
nx start    # production server
nx test     # pytest, --client adds vitest
```

जब दस्तावेज़ और कोड असहमत हों, तो कोड पर भरोसा करें और ऐसा कहें: `nexy/core/config.py` प्रत्येक को धारण करता है
विकल्प, `nexy/modules/routers/fbrouter/` रूटिंग नियम, `nexy/modules/compiler/` कैसे `.nexy`
फ़ाइलें मॉड्यूल बन जाती हैं।
