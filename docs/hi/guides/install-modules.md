# मैं रजिस्ट्री से मॉड्यूल कैसे स्थापित करूं?

मॉड्यूल रजिस्ट्री से एक रिलीज़ डाउनलोड करने, उसकी जाँच करने और उसके घोषित परिवर्तनों को लागू करने के लिए नेक्सी प्रोजेक्ट में `nx add @scope/name` चलाएँ। सटीक संस्करण पिन करने के लिए `@1.2.0` जोड़ें।

## एक मॉड्यूल स्थापित करें

नेक्सी प्रोजेक्ट के मूल से:

```bash
nx add @acme/auth
nx add @acme/auth@1.2.0
```

`nx add` `useModuleRegistry` से रिलीज मेटाडेटा और संग्रह को पढ़ता है, SHA-256 चेकसम की जांच करता है, और मॉड्यूल की `nexy` और `python` संगतता श्रेणियों की जांच करता है। इसके बाद यह केवल वही फ़ाइलें लिखता है जो मेनिफेस्ट घोषित करता है, घोषित Python पैकेज को `uv add` के साथ जोड़ता है, प्रोजेक्ट के पैकेज मैनेजर के साथ नोड पैकेज जोड़ता है, और कॉन्फिग हुक को `nexyconfig.py` और `package.json` पर लागू करता है। मौजूदा सेटिंग्स और फ़ाइलें वैसे ही रहती हैं: एक घोषित फ़ाइल जो पहले से मौजूद है उसे `warning:` लाइन के साथ छोड़ दिया जाता है।

प्रत्येक सफल इंस्टालेशन `.nexy/modules.json` में दर्ज किया जाता है। उस फ़ाइल को प्रतिबद्ध करें ताकि टीम के साथी को समान मॉड्यूल संस्करण मिल सके।

## एक मॉड्यूल अपग्रेड करें

अपग्रेड करने के लिए, रजिस्ट्री में नई रिलीज़ होने के बाद `nx add @acme/auth` को फिर से चलाएँ, या `@acme/auth@1.3.0` जैसा नया पिन सेट करें। एक अनपिन किया गया नाम रजिस्ट्री की `/versions` प्रतिक्रिया से नवीनतम संस्करण का चयन करता है। उसी संस्करण को दोबारा चलाने से `is already installed` प्रिंट होता है और कुछ भी नहीं बदलता है।

## एक संस्करण पिन करें

एक पिन सटीक है: `nx add @acme/auth@1.2.0` इंस्टॉल करता है `1.2.0` और कोई अन्य रिलीज़ नहीं। सीआई और प्रतिबद्ध `.nexy/modules.json` में एक पिन का उपयोग करें ताकि प्रत्येक चेकआउट एक ही कोड स्थापित करे। पिन के बिना, एक नई रिलीज़ अगली इंस्टॉल को बदल देती है।

## माइग्रेशन चलाएँ

माइग्रेशन डिफ़ॉल्ट रूप से बंद हैं. जब आप चाहते हैं कि किसी रिलीज़ के घोषित कमांड उसकी फ़ाइलों और निर्भरताओं के ठीक होने के बाद चलें, तो `--migrate` जोड़ें:

```bash
nx add @acme/auth@1.2.0 --migrate
```

प्रत्येक कमांड चलने से पहले मुद्रित होता है। किसी मॉड्यूल को घोषित करने से पहले प्रोजेक्ट को अपने माइग्रेशन टूल को स्थापित करने की आवश्यकता होती है।

## रजिस्ट्री और उसके ट्रस्ट नियम निर्धारित करें

डिफ़ॉल्ट `nexyconfig.py` में रहते हैं:

```python filename="nexyconfig.py"
class NexyConfig(NexyConfigModel):
    useModuleRegistry = "https://registry.nexypy.dev"
    useRequireSignedModules = False
```

`useModuleRegistry` वह आधार यूआरएल है जिसे सीएलआई पढ़ता है। विकास के दौरान स्थानीय रजिस्ट्री के लिए लूपबैक http को छोड़कर, केवल https यूआरएल स्वीकार किए जाते हैं। `useRequireSignedModules = True` एक अहस्ताक्षरित रिलीज से इनकार करता है। एक हस्ताक्षर युक्त विज्ञप्ति को तब तक अस्वीकार कर दिया जाता है जब तक कोई सत्यापनकर्ता उपलब्ध न हो; एक बार जब कोई इसे सत्यापित कर लेता है, तो `nx add` हस्ताक्षरकर्ता की पहचान के साथ `Verified by` प्रिंट करता है। केवल उन रजिस्ट्रियों के लिए डिफ़ॉल्ट `False` रखें जिन पर आपको भरोसा है।
