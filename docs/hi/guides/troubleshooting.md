# समस्या निवारण

लोग सबसे पहले जिन समस्याओं से जूझते हैं, वे हैं आप क्या देखते हैं और क्या करना है। प्रत्येक व्यक्ति वास्तविक दौड़ से आता है।

## एक पृष्ठ का उत्तर 404 है लेकिन इसकी फ़ाइल मौजूद है

उस टर्मिनल को देखें जो `nx dev` या `nx start` चलाता है। जब कोई पृष्ठ आयात नहीं किया जा सकता, तो Nexy रिपोर्ट करती है
इसकी फ़ाइल और लाइन में त्रुटि, और मार्ग पंजीकृत नहीं है:

```text
nexy » error __nexy__/src/routes/index.py:18  ImportError: cannot import name 'FrameworkLogo' ...
```

वहां नामित आयात को ठीक करें। सामान्य कारण एक घटक है जिसका फ़ंक्शन नाम मेल नहीं खाता है
आप क्या आयात करते हैं (अगला आइटम देखें) और पथ में एक टाइपो।

## एक `.nexy` पृष्ठ संकलित नहीं होता: "तर्क पार्स त्रुटि"

```text
src/components/live-panel.nexy - Logic Parse Error: invalid syntax
```

एक `.nexy` घटक को पायथन मॉड्यूल के रूप में आयात किया जाता है, इसलिए इसका फ़ाइल नाम एक वैध नाम होना चाहिए। एक हाइफ़न
नहीं है. इसे पास्कलकेस में नाम दें, `LivePanel.nexy`, और इसे उसी नाम से आयात करें:

```nexy
from "@/components/LivePanel.nexy" import LivePanel
```

## एक घटक अपने बच्चों को पाठ के रूप में प्रस्तुत करता है `<slot />`

एक `.nexy` घटक अपने बच्चों को `<Slot />` के साथ बड़े अक्षर एस के साथ रखता है। एक छोटा अक्षर `<slot />` है
जैसा है वैसा ही पृष्ठ में छोड़ दें। Vue, जिसका अपना `<slot />` है, प्रभावित नहीं होता है।

## एक प्रोप वेरिएबल का नाम दिखाता है

```nexy
<Icon path=icon />          renders: icon
<Icon path="{{ icon }}" />  renders: the value of icon
```

बिना ब्रेसिज़ वाला एक गुण टेक्स्ट है। कंप्यूटेड को पास करने के लिए जिन्जा एक्सप्रेशन को विशेषता में रखें
मूल्य.

## `{{ ... }}` में एक मान खाली हो जाता है

Jinja2 एक अपरिभाषित चर छुपाता है। आपके द्वारा उपयोग की जाने वाली प्रत्येक संपत्ति की घोषणा फ्रंटमैटर में करें
(`title: prop[str] = ""`), और वर्तनी की जाँच करें।

## उपयोगिता कक्षाओं का `.nexy` पृष्ठ (यूनोसीएसएस) में कोई प्रभाव नहीं पड़ता है

UnoCSS किसी फ़ाइल को तभी पढ़ता है जब उसका एक्सटेंशन उसकी सामग्री पाइपलाइन में होता है। एक सर्वर प्रोजेक्ट बनाया गया
`nx new` द्वारा UnoCSS पहले से ही सूचीबद्ध है `.nexy`; एक वृद्ध को इसकी आवश्यकता है `uno.config.ts`:

```ts
content: {
  filesystem: ['src/**/*.nexy'],
  pipeline: { include: [/\.(vue|svelte|[jt]sx|mdx?|astro|html|nexy)($|\?)/] },
},
```

टेलविंड स्वयं `.nexy` फ़ाइलें ढूंढता है।

## एक `.mdx` पेज पैकेज मांगता है

```text
[nexy] MDX support requires optional packages that are not installed.
```

उन्हें प्रोजेक्ट में स्थापित करें: `@mdx-js/rollup`, `remark-gfm` और `@mdx-js/react` (प्लस
`@mdx-js/esbuild` के लिए `nx build`)। एमडीएक्स को `useFF` में रिएक्ट या प्रीएक्ट की आवश्यकता है। ग्राहक ढांचे के बिना,
पृष्ठ को `.md` के रूप में लिखें। [मार्कडाउन और एमडीएक्स](../views/nexy/markdown.md) देखें।

## `No module named 'sqlmodel'` (या कोई पैकेज) जब कोई कमांड शुरू होता है

```text
nexy » nexyconfig.py cannot be loaded: No module named 'sqlmodel'. If it is a package, install it
in this Python (...) or activate the project's virtual environment.
```

आदेश गलत पायथन में चला। आपके प्रोजेक्ट के पैकेज (आपका ओआरएम, आपकी लाइब्रेरी) अंदर हैं
इसका `.venv`, और `uvx nexy` या एक वैश्विक `nexy` अपने स्वयं के वातावरण में चलता है जिसमें कुछ भी नहीं है
उन्हें.

प्रोजेक्ट फ़ोल्डर से प्रोजेक्ट के वर्चुअल वातावरण को सक्रिय करें, फिर कमांड फिर से चलाएँ:

```bash
.venv\Scripts\activate    # Windows; on macOS and Linux: source .venv/bin/activate
nexy dev
```

सक्रिय होने पर प्रॉम्प्ट `(.venv)` से शुरू होता है। या इसके साथ सक्रियण छोड़ें
`uv run nexy dev`. यदि पैकेज वास्तव में प्रोजेक्ट से गायब है, तो इसे `uv add sqlmodel` के साथ जोड़ें।

## `nx dev` एक त्रुटि दिखाता है और प्रतीक्षा करता है

जब आपका एप्लिकेशन प्रारंभ नहीं हो पाता है, `nx dev` रिपोर्ट करता है कि क्यों और अगले फ़ाइल परिवर्तन की प्रतीक्षा करता है; यह होता है
बाहर नहीं निकलना. फ़ाइल को ठीक करें और सहेजें. केवल Ctrl+C ही इसे रोकता है।

## बंदरगाह व्यस्त है

`nx dev` अगला मुफ़्त पोर्ट लेता है और उसे प्रिंट करता है। किसी एक को चुनने के लिए, `--port` का उपयोग करें या `usePort` को सेट करें
`nexyconfig.py`.

## विषय एक अंधेरे पृष्ठ पर सफेद रंग में चमकता है

सहेजी गई थीम को पहले पेंट से पहले लागू किया जाना चाहिए। स्टार्टर की छोटी स्क्रिप्ट को इसमें रखें
`<head>` रूट लेआउट का, और रिएक्ट में `suppressHydrationWarning` को `<html>` पर रखें।
