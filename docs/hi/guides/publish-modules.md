# मैं नेक्सी रजिस्ट्री में एक मॉड्यूल कैसे प्रकाशित करूं?

एक वैध `nx.toml`, एक रजिस्ट्री टोकन और मेनिफेस्ट द्वारा घोषित प्रत्येक फ़ाइल के साथ मॉड्यूल निर्देशिका से `nx publish` चलाएँ; कमांड रिलीज़ की जाँच करता है, एक संग्रह बनाता है, और एक अपरिवर्तनीय संस्करण अपलोड करता है।

## मैनिफ़ेस्ट तैयार करें

एक स्रोत मॉड्यूल अपने द्वारा भेजी जाने वाली प्रत्येक फ़ाइल को सूचीबद्ध करता है। संग्रह में `nx.toml` और बिल्कुल वही फ़ाइलें हैं।

```toml filename="nx.toml"
name = "@acme/auth"
version = "1.2.0"
kind = "source"

[compatibility]
nexy = ">=2.0.0"
python = ">=3.12"

[dependencies]
python = []
node = []

[source]
files = ["src/auth.py", "src/helpers.py"]
```

`name` फ़ील्ड को लोअरकेस `@scope/name` होना चाहिए। `version` फ़ील्ड में बिंदुओं द्वारा अलग की गई तीन संख्याएँ होनी चाहिए। फ़ाइलें मॉड्यूल के अंदर सापेक्ष पथ होनी चाहिए। एक पैकेज मॉड्यूल `source.files` के बजाय `source.package` घोषित करता है।

## अपलोड करने से पहले जांच लें

मेनिफेस्ट को सत्यापित करने, घोषित फ़ाइलों को संग्रहित करने और अपलोड किए बिना चेकसम प्रिंट करने के लिए `--dry-run` का उपयोग करें:

```bash
nx publish --dry-run
```

ड्राई रन के लिए टोकन की आवश्यकता नहीं होती है। यह प्रत्येक सापेक्ष आयात के लिए एक `warning:` लाइन प्रिंट करता है जो उस फ़ाइल की ओर इशारा करता है जिसे मेनिफेस्ट घोषित नहीं करता है। उदाहरण के लिए, `from .helpers import token` को `src/auth.py` में `src/helpers.py` को `source.files` में चाहिए, अन्यथा किसी इंस्टाल को टूटा हुआ आयात मिलेगा।

## टोकन सेट करें

`nx publish` पढ़ता है `NEXY_REGISTRY_TOKEN`, फिर `~/.config/nexy/registry-token`। टोकन `Authorization` हेडर में भेजा जाता है और कभी मुद्रित नहीं होता है।

```bash
export NEXY_REGISTRY_TOKEN="your-token"
nx publish
```

टोकन फ़ाइल भविष्य में `nx login` को वही क्रेडेंशियल लिखने देती है। किसी भी स्रोत के बिना, कमांड `error: No registry token` प्रिंट करता है और स्थिति 1 के साथ बाहर निकलता है।

## प्रकाशित करें

```bash
nx publish
```

कमांड उसके द्वारा प्रकाशित रिलीज़ का नाम, संस्करण और SHA-256 चेकसम प्रिंट करता है। एक नाम और संस्करण जोड़ी अपरिवर्तनीय है: इसे दोबारा प्रकाशित करने से एक संघर्ष त्रुटि प्रिंट होती है। इसके बजाय एक नया संस्करण प्रकाशित करें.

## किसी अन्य रजिस्ट्री का उपयोग करें

डिफ़ॉल्ट रूप से कमांड `https://registry.nexypy.dev` पर पोस्ट होता है। किसी अन्य रजिस्ट्री के लिए `--registry` का उपयोग करें, उदाहरण के लिए विकास के दौरान एक स्थानीय रजिस्ट्री:

```bash
nx publish --registry http://localhost:8000
```

केवल https यूआरएल स्वीकार किए जाते हैं, साथ ही `localhost`, `127.0.0.1` और `::1` पर सादा http भी स्वीकार किया जाता है। क्षणिक `429` और `5xx` उत्तर दो बार पुनः प्रयास किए जाते हैं; ख़राब मेनिफेस्ट, गुम टोकन या विरोध का दोबारा प्रयास नहीं किया जाता है।

## रिलीज़ सत्यापित करें

```bash
nx add @acme/auth@1.2.0
```

अपग्रेड, पिन और ट्रस्ट सेटिंग्स के लिए [इंस्टॉल मॉड्यूल](install-modules.md) देखें।
