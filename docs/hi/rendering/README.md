# प्रतिपादन

प्रतिपादन एक प्रश्न का उत्तर देता है: **एचटीएमएल कौन बनाता है, और कब**। नेक्सी के पास चार उत्तर हैं और एक
डिफ़ॉल्ट.

**निश्चित नहीं? एसएसआर रखें।** कोई पेज तभी बदलें जब आप कारण बता सकें: ऐसी सामग्री जो शायद ही कभी बदलती हो
(आईएसआर), एक विजेट जिसे ब्राउज़र (द्वीप), या ऐप-जैसे नेविगेशन (सीएसआर) की आवश्यकता होती है।

## यह कैसे काम करता है

```diagram filename="HTML का निर्माण कौन करता है, और कब करता है"
SSR       request ──► server renders ────────────────► HTML ──► browser
ISR       request ──► cached HTML? ──► browser, regenerated in the background
CSR       request ──► document rendered by the server ──► browser takes over navigation
Islands   request ──► server renders the page ──► one widget hydrates on demand
```

## चार मोड

| | एसएसआर | आईएसआर | सीएसआर | द्वीप समूह |
|---|---|---|---|---|
| डेटा पढ़ा जाता है | प्रत्येक अनुरोध पर | प्रत्येक पुनर्जनन पर | ब्राउज़र में | प्रत्येक अनुरोध पर |
| HTML | सर्वर से आता है | सर्वर, फिर कैशे | पहले दस्तावेज़ के लिए सर्वर, बाद में ब्राउज़र | सर्वर |
| जावास्क्रिप्ट | केवल द्वीपों के लिए | केवल द्वीपों के लिए | फ्रेमवर्क बंडल | केवल द्वीप के लिए |
| हाइड्रेशन | कोई नहीं | कोई नहीं | संपूर्ण दस्तावेज़ | द्वीप |
| कैश | कोई नहीं | प्रति यूआरएल, मेमोरी में | कोई नहीं | कोई नहीं |
| | डिफॉल्ट | `revalidate = N` पेज में | `useCSR = True` प्रोजेक्ट में | `directive` घटक पर निर्णय लिया गया |
| अनाज | पृष्ठ | पृष्ठ | **परियोजना** | घटक |

## जीवनचक्र का प्रतिपादन

दो तथ्य सबसे अधिक आश्चर्य की व्याख्या करते हैं।

1. **एक प्रोजेक्ट एक मोड में है।** `useCSR` सर्वर मोड (एसएसआर, आईएसआर, द्वीप, `.nexy`, के बीच चयन करता है।
   `.md`, `.mdx` रूट) और क्लाइंट मोड (फ्रेमवर्क रूट और एक क्लाइंट राउटर)। दोनों नहीं हो सकते
   मिश्रित: [सर्वर मोड और क्लाइंट मोड](../routing/fbr/modes.md) देखें।
2. **सर्वर मोड के अंदर, मोड प्रति पेज है।** एक पेज को `revalidate` से कैश किया जा सकता है, दूसरे को
   एक द्वीप पर कब्ज़ा कर सकता है, तीसरा कुछ भी नहीं कर सकता।

क्लाइंट मोड अभी भी एक वास्तविक दस्तावेज़ भेजता है: नेक्सी इसे पहली प्रतिक्रिया के लिए नोड में प्रस्तुत करता है, फिर
ब्राउज़र नेविगेशन का कार्यभार संभाल लेता है. सीएसआर पृष्ठ किसी बंडल की प्रतीक्षा करने वाला कोई खाली पृष्ठ नहीं है।

## कब उपयोग करें

- **सामग्री, मार्केटिंग, दस्तावेज़ीकरण**: एसएसआर, प्लस आईएसआर जब सामग्री शायद ही कभी बदलती है।
- **एक इंटरैक्टिव विजेट के साथ एक अधिकतर स्थिर पृष्ठ**: एक द्वीप के साथ एसएसआर।
- **डैशबोर्ड, संपादक, ऐप जैसा नेविगेशन**: सीएसआर।
- **एक पृष्ठ लगातार पढ़ा जाता है और शायद ही कभी बदला जाता है**: आईएसआर।

## कॉन्फ़िगरेशन

| मोड | जहां |
|---|---|
| एसएसआर | कहीं नहीं: यह डिफ़ॉल्ट है |
| आईएसआर | `revalidate = 60` `.nexy` पेज के फ्रंटमैटर में |
| सीएसआर | `useCSR = True` में `nexyconfig.py`, `useFF` सेट के साथ |
| द्वीप समूह | `directive="client:visible"` घटक टैग पर |

## उदाहरण

```nexy filename="src/routes/blog/index.nexy"
---
revalidate = 60
---
<h1>Rendered at most once per minute</h1>
```

फ्रंटमैटर लाइन के बिना वही पेज SSR है।

## सीमाएँ

- **कोई एसएसजी मोड नहीं है।** नेक्सी बिल्ड टाइम पर HTML प्रीरेंडर करता है (घटक HTML, क्लाइंट दस्तावेज़),
  लेकिन हमेशा इसे सर्वर के माध्यम से वापस पढ़ता है: कोई निर्यात आदेश नहीं, होस्ट करने के लिए कोई स्टैंडअलोन फ़ोल्डर नहीं
  स्थैतिक रूप से। जमे हुए सामग्री के लिए, लंबी विंडो वाले ISR का उपयोग करें।
- **आईएसआर एक सीडीएन नहीं है।** कैश उस प्रक्रिया में रहता है जो पेज को प्रस्तुत करता है; कई कार्यकर्ता रखते हैं
  कई कैश. [आईएसआर](isr.md) देखें।
- **सीएसआर एक परियोजना निर्णय है।** आप एक पृष्ठ सीएसआर नहीं बना सकते हैं और शेष एसएसआर नहीं रख सकते हैं।
- **द्वीप द्वीप को हाइड्रेट करते हैं, पेज को नहीं।** एक ऐसा पेज जिसके सभी द्वीप एक-दूसरे पर निर्भर हैं
  छद्मवेशी सीएसआर पृष्ठ।
