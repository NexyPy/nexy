# द्वीप और जलयोजन

## परिभाषा

एक द्वीप एक ग्राहक घटक है - रिएक्ट, व्यू, स्वेल्ट, सॉलिड या प्रीएक्ट - को `.nexy` में आयात किया जाता है
पेज. सर्वर अपना HTML प्रस्तुत करता है; ब्राउज़र उस एक घटक को इंटरैक्टिव बनाता है। शेष
पेज HTML रहता है.

द्वीप सर्वर मोड में मौजूद हैं। क्लाइंट मोड में घटक पृष्ठ *हैं*: [सीएसआर](csr.md) देखें।

## यह कैसे काम करता है

```nexy filename="src/routes/index.nexy"
---
from "@/components/Counter.tsx" import Counter
---
<h1>Static heading</h1>
<Counter directive="client:visible" />
```

नेक्सी निर्माण के समय घटक को प्रस्तुत करता है, उसका HTML संग्रहीत करता है, और उसे पृष्ठ के अंदर रखता है। पेज
प्रतिक्रिया में HTML प्लस प्रॉप्स को JSON विशेषता के रूप में शामिल किया गया है। ब्राउज़र में, आइलैंड रनटाइम
घटक को लोड करता है और कंटेनर को अपने कब्जे में ले लेता है।

`directive` निर्णय लेता है **कब** ऐसा होता है। इसके बिना, द्वीप अपने रनटाइम के साथ ही हाइड्रेट हो जाता है
तैयार है.

## जीवनचक्र का प्रतिपादन

1. निर्माण के समय, प्रत्येक क्लाइंट घटक को HTML में प्रस्तुत किया जाता है और `__nexy__/client/static/` के अंतर्गत लिखा जाता है।
2. एक अनुरोध `.nexy` पृष्ठ प्रस्तुत करता है; टैग के स्थान पर द्वीप का HTML डाला गया है।
3. प्रतिक्रिया में विशेषताओं के रूप में HTML, प्रॉप्स और निर्देश शामिल हैं।
4. ब्राउज़र में, रनटाइम निर्देश के अनुसार हाइड्रेशन शेड्यूल करता है।
5. हाइड्रेशन स्थिर HTML को लाइव घटक से बदल देता है; शेष पृष्ठ अछूता है.

विकास में कोई बिल्ड स्नैपशॉट नहीं है: कंटेनर खाली है और घटक इसमें प्रस्तुत होता है
ब्राउज़र. पेज एक जैसा दिखता है, लेकिन पहला पेंट उत्पादन से अलग है।

## कब उपयोग करें

- एक पृष्ठ जिसमें अधिकतर सामग्री होती है और जिसमें एक या दो इंटरैक्टिव स्पॉट होते हैं।
- एक विजेट जो क्रॉलर्स के लिए HTML में मौजूद होना चाहिए और अभी भी काम करता है।
- एक घटक जिसे ब्राउज़र की आवश्यकता है लेकिन क्लाइंट रेंडरिंग में पूरे पृष्ठ को नहीं खींचना चाहिए।

## विन्यास

| निर्देश | हाइड्रेट्स |
|---|---|
| कोई नहीं, या `client:load` | तुरंत |
| `client:idle` | जब ब्राउज़र निष्क्रिय हो (`requestIdleCallback`, 2 सेकंड का समय समाप्त) |
| `client:visible` | जब द्वीप व्यूपोर्ट में प्रवेश करता है, 200 पिक्सल जल्दी |
| `client:media` | जब कोई मीडिया क्वेरी मेल खाती है; इसे `media` प्रोप | के साथ सेट करें

```nexy
<Chart directive="client:media" media="(min-width: 768px)" />
```

`client:media` डिफ़ॉल्ट रूप से `(min-width: 768px)` होता है जब `media` अनुपस्थित होता है, और एक बार हाइड्रेट होता है। ए पर
`IntersectionObserver`, `client:visible` के बिना ब्राउज़र निष्क्रिय हो जाता है।

`directive` और `media` का उपभोग नेक्सी द्वारा किया जाता है: वे आपके घटक तक नहीं पहुंचते हैं।

## उदाहरण

```tsx filename="src/components/Counter.tsx"
import { useState } from "react"

export default function Counter({ start = 0 }: { start?: number }) {
  const [count, setCount] = useState(start)
  return <button onClick={() => setCount(count + 1)}>{count}</button>
}
```

```nexy filename="src/routes/index.nexy"
---
from "@/components/Counter.tsx" import Counter
---
<h1>Count</h1>
<Counter start=3 directive="client:idle" />
```

## सीमाएँ

- **`client:only` कभी हाइड्रेट नहीं होता।** यह स्वीकार किया जाता है, लेकिन रनटाइम इसे छोड़ देता है, इसलिए सर्वर HTML बना रहता है
  जड़. जब कोई घटक सर्वर पर प्रस्तुत नहीं हो सकता तो क्लाइंट रूट ([सीएसआर](csr.md)) का उपयोग करें।
- **`client:manual` का कोई सार्वजनिक ट्रिगर नहीं है।** इसे स्वचालित रूप से छोड़ दिया जाता है, और जो हैंडल
  बायोडाटा यह आंतरिक है।
- **प्रॉप्स JSON होने चाहिए।** वे `json.dumps` के साथ क्रमबद्ध हैं; एक मान जिसे क्रमबद्ध नहीं किया जा सकता है
  गिरा दिया गया, और द्वीप को `{}` प्राप्त हुआ - चुपचाप।
- **एक द्वीप साझा राज्य वाला ग्राहक घटक नहीं है।** दो द्वीप बिना राज्य साझा नहीं करते हैं
  तंत्र आप स्वयं जोड़ें।
- **द्वीप को सर्वर द्वारा दोबारा प्रस्तुत नहीं किया गया है।** इसका HTML बिल्ड स्नैपशॉट है, साथ ही जो भी हो
  घटक एक बार हाइड्रेटेड हो जाता है।
- **द्वीपों का एक पृष्ठ प्रच्छन्न रूप से एक सीएसआर पृष्ठ है।** यदि प्रत्येक ब्लॉक को एक-दूसरे से बात करने की आवश्यकता है, तो चुनें
  इसके बजाय क्लाइंट मोड।
