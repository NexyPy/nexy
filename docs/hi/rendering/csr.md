# सीएसआर (क्लाइंट-साइड रेंडरिंग)

## परिभाषा

सीएसआर ब्राउज़र को नेविगेशन सौंपता है: पहले दस्तावेज़ के बाद, पृष्ठों के बीच जाना अब नहीं पूछता है
HTML के लिए सर्वर. नेक्सी में यह एक **प्रोजेक्ट** निर्णय है, न कि एक पृष्ठ - `useCSR = True` बदल जाता है
संपूर्ण एप्लिकेशन क्लाइंट-रूटेड।

## यह कैसे काम करता है

```python filename="nexyconfig.py"
from nexy.core.models import NexyConfigModel
from nexy.frontend import react


class NexyConfig(NexyConfigModel):
    useFF = react()
    useCSR = True
```

फिर प्रोजेक्ट का आकार बदल जाता है:

| | सर्वर मोड (`False`) | क्लाइंट मोड (`True`) |
|---|---|---|
| मार्ग | `.nexy`, `.md`, `.mdx` | `.tsx`, `.jsx`, `.vue`, `.svelte` |
| दस्तावेज़ | `layout.nexy` | मूल `layout.tsx` / `.vue` / `.svelte` का मालिक है `<html>`, `<head>`, `<body>` |
| ग्राहक घटक | एक पृष्ठ के अंदर द्वीप | पृष्ठ स्वयं |
| `.nexy` `src/routes/` | के अंतर्गत पृष्ठ प्रारूप | को `nx dev`, `nx start` और `nx build` | से पहले खारिज कर दिया गया था।
| नेविगेशन | प्रति लिंक एक पूर्ण अनुरोध | क्लाइंट राउटर |

`.md` और `.mdx` वैध रहें: नेक्सी उन्हें क्लाइंट लेआउट के अंदर सर्वर पर प्रस्तुत करता है, और
क्लाइंट राउटर वहां से काम लेता है। `.py` हैंडलर मार्गों के बगल में बैठते हैं और उन्हें फास्टएपीआई द्वारा सेवा दी जाती है।

## जीवनचक्र का प्रतिपादन

1. अनुरोध फ़ाइल-आधारित राउटर तक पहुंचता है, जो मिलान मार्ग और उसके लेआउट को ढूंढता है।
2. रूट लेआउट नोड में **संपूर्ण दस्तावेज़** प्रस्तुत करता है - पहली प्रतिक्रिया पहले से ही मौजूद है
   वास्तविक `<html>`, कोई खाली खोल नहीं।
3. नेक्सी क्लाइंट संपत्तियों और पृष्ठ का एक JSON विवरण `</body>` से पहले इंजेक्ट करता है।
4. ब्राउज़र उस दस्तावेज़ को हाइड्रेट करता है। नेस्टेड लेआउट तब से अपनी स्थिति बनाए रखते हैं।
5. किसी अन्य रूट का लिंक क्लाइंट राउटर द्वारा नियंत्रित किया जाता है: कोई दस्तावेज़ अनुरोध नहीं, पेज है
   ब्राउज़र में प्रस्तुत किया गया।

विकास में दस्तावेज़ को वाइट डेव सर्वर द्वारा मांग पर प्रस्तुत किया जाता है। उत्पादन में यह है
निर्माण के समय एक बार प्रस्तुत किया गया: एक स्थिर मार्ग को अपना दस्तावेज़ मिलता है, एक गतिशील मार्ग को प्रति घोषित एक मिलता है
स्थैतिक पैरामीटर, या एक शेल - एक खाली पृष्ठ के चारों ओर लेआउट - जब यह कोई घोषित नहीं करता है।

## कब उपयोग करें

- डैशबोर्ड, संपादक, कुछ भी जो एक एप्लिकेशन की तरह व्यवहार करता है।
-  शीर्ष पर क्लाइंट एप्लिकेशन के साथ एक पायथन एपीआई।
- एक ऐसा पेज जहां हर बातचीत स्थानीय होगी और एक राउंड ट्रिप का अहसास होगा।

## कॉन्फ़िगरेशन

| सेटिंग | मान |
|---|---|
| `useFF` | आवश्यक: `useCSR` ग्राहक ढांचे के बिना अस्वीकार कर दिया जाता है |
| `useCSR` | `True` |
| `useRouter` | को बंद रहना चाहिए: मॉड्यूलर राउटर क्लाइंट मोड में अस्वीकार कर दिया गया है |

`_` या `.` से शुरू होने वाली फ़ाइलों और फ़ोल्डरों को इन जांचों द्वारा अनदेखा कर दिया जाता है।

## उदाहरण

```tsx filename="src/routes/layout.tsx"
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <head><title>My app</title></head>
      <body>{children}</body>
    </html>
  )
}
```

```tsx filename="src/routes/index.tsx"
export default function Home() {
  return <h1>Home</h1>
}
```

## सीमाएँ

- **पूरा प्रोजेक्ट।** आप एक सीएसआर पेज को सर्वर-मोड प्रोजेक्ट में नहीं मिला सकते: इसके लिए मोड चुनें
  एप्लिकेशन, फिर सर्वर-मोड पेज के इंटरैक्टिव भागों के लिए [द्वीप](islands.md) का उपयोग करें।
- **कोई `.nexy` मार्ग नहीं। ** आपने `.nexy` में जो कुछ भी लिखा है, उसे एक रूपरेखा घटक बनना होगा।
- **सर्वर डेटा एंडपॉइंट से होकर गुजरता है।** एक क्लाइंट रूट रेंडर समय पर डेटाबेस को नहीं पढ़ सकता है; यह
  `.py` हैंडलर या [एक्शन](../guides/actions.md) को कॉल करता है।
- **एक गतिशील मार्ग को एक घोषित स्थिर पैरामीटर की आवश्यकता होती है, या यह एक शेल से शुरू होता है।** निर्यात करें
  `getStaticParams()` पेज से - नेक्स्ट.जेएस नाम `getStaticPaths` और `generateStaticParams`
  यह भी स्वीकार किया जाता है - प्रति मूल्य एक दस्तावेज़ होना। इसके बिना, शेल लेआउट और ले जाता है
  पृष्ठ नहीं: ब्राउज़र चलने के बाद पृष्ठ प्रकट होता है।
- **सीएसआर एक खाली पृष्ठ नहीं है, और एसपीए भी नहीं है।** पहला दस्तावेज़ सर्वर द्वारा प्रस्तुत किया गया है; यह
  वह नेविगेशन है जो ब्राउज़र में होता है।
