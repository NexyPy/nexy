# स्थापना

## आवश्यकताएँ

| आवश्यकता | क्यों |
|---|---|
| पायथन 3.12+ | `requires-python` में `pyproject.toml` |
| [यूवी](https://docs.astral.sh/uv/) | प्रोजेक्ट बनाता है, उसके पैकेज इंस्टॉल करता है और नेक्सी चलाता है |
| नोड.जेएस 18+ | केवल क्लाइंट फ्रेमवर्क के लिए (रिएक्ट, व्यू, स्वेल्ट, सॉलिड, प्रीएक्ट) |

क्लाइंट फ्रेमवर्क के बिना किसी प्रोजेक्ट को Node.js की बिल्कुल भी आवश्यकता नहीं है।

## पहले यूवी इंस्टॉल करें

`uvx` कोई अलग उपकरण नहीं है: यह यूवी के साथ आता है, इसलिए किसी भी चीज़ से पहले यूवी इंस्टॉल करें।

```bash
# macOS and Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

इसे `uv --version` और `uvx --version` से जांचें।

## एक प्रोजेक्ट बनाएं

```bash
uvx nexy new my-app
```

`uvx` नेक्सी को एक अस्थायी वातावरण में चलाता है और पीछे कुछ भी नहीं छोड़ता है। यह **बनाने** के लिए पर्याप्त है
परियोजना (`new`, `init`) और कुछ नहीं: अस्थायी वातावरण में नेक्सी है और कोई अन्य नहीं
पैकेज. `nexy new` परियोजना का अपना आभासी वातावरण बनाता है, `.venv`, और इसके पैकेज स्थापित करता है
वहाँ.

`nexy new my-app` चार प्रश्न पूछता है: राउटर (फ़ाइल-आधारित या मॉड्यूलर), प्रोजेक्ट प्रकार (वेब या एपीआई),
क्लाइंट फ्रेमवर्क, ओआरएम। फिर पायथन और नोड निर्भरता की स्थापना एक पंक्ति प्रति के साथ चलती है
चरण और उसकी अवधि. [सीएलआई](../reference/cli.md) देखें।

पंजीकृत टेम्पलेट के साथ संकेतों को छोड़ें:

```bash
uvx nexy new my-app --template <name>
```

## परियोजना के आभासी वातावरण के अंदर काम करें

प्रत्येक अन्य कमांड (`nexy dev`, `nexy build`, `nexy migrate`...) को प्रोजेक्ट के अंदर ** चलना चाहिए
आभासी वातावरण**. यहीं पर आपके अपने पैकेज रहते हैं: आपका ORM, आपकी लाइब्रेरी और Nexy
परियोजना के साथ बनाया गया था. इसके बाहर, जिस प्रोजेक्ट को `sqlmodel` की आवश्यकता होती है वह विफल हो जाता है
`ModuleNotFoundError: No module named 'sqlmodel'`.

इसे प्रोजेक्ट फ़ोल्डर से प्रति टर्मिनल एक बार सक्रिय करें:

| शेल | कमांड |
|---|---|
| पॉवरशेल, सीएमडी (विंडोज़) | `.venv\Scripts\activate` |
| मैकओएस, लिनक्स | `source .venv/bin/activate` |

फिर संकेत `(.venv)` से शुरू होता है। वहां से:

```bash
cd my-app
.venv\Scripts\activate    # Windows; on macOS and Linux: source .venv/bin/activate
nexy dev
```

<http://localhost:3000> खोलें।

सक्रियण को छोड़ने के लिए, यूवी को इसे एक कमांड के लिए करने दें: `uv run nexy dev`।

> [!नोट]
> `nexy` और `nx` एक ही बाइनरी हैं। `यूवी टूल इंस्टॉल' के साथ स्थापित एक प्रति
> nexy` lives in its own environment, like `uvx`, इसलिए प्रोजेक्ट बनाने और सब कुछ चलाने के लिए इसका उपयोग करें
> अन्यथा परियोजना के परिवेश से।

## नेक्सी को किसी मौजूदा प्रोजेक्ट में जोड़ें

इसे प्रोजेक्ट के वर्चुअल वातावरण से चलाएं, इसके पैकेजों में नेक्सी भी शामिल है (`uv add nexy`):

```bash
nexy init
```
