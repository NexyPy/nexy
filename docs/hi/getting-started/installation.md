# स्थापना

## आवश्यकताएँ

| आवश्यकता | क्यों |
|---|---|
| Python 3.12+ | `requires-python` में `pyproject.toml` |
| [uv](https://docs.astral.sh/uv/) | प्रोजेक्ट बनाता है, उसके पैकेज स्थापित करता है और नेक्सी चलाता है |
| Node.js 18+ | केवल क्लाइंट फ्रेमवर्क के लिए (React, Vue, Svelte, Solid, Preact) |

क्लाइंट फ्रेमवर्क के बिना किसी प्रोजेक्ट को किसी Node.js की आवश्यकता नहीं है।

## पहले uv इंस्टॉल करें

`uvx` कोई अलग टूल नहीं है: यह uv के साथ आता है, इसलिए किसी भी अन्य चीज़ से पहले uv इंस्टॉल करें।

```bash
# macOS and Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

इसे `uv --version` और `uvx --version` से जांचें।

## एक प्रोजेक्ट बनाएं

```bash
uvx nexy new my-app
```

`uvx` नेक्सी को एक अस्थायी वातावरण में चलाता है और पीछे कुछ भी नहीं छोड़ता है। यह **एक परियोजना बनाने** के लिए पर्याप्त है (`new`, `init`) और इससे अधिक कुछ नहीं: अस्थायी वातावरण में नेक्सी है और कोई अन्य पैकेज नहीं है। `nexy new` प्रोजेक्ट का अपना वर्चुअल वातावरण बनाता है, `.venv`, और वहां अपने पैकेज स्थापित करता है।

`nexy new my-app` चार प्रश्न पूछता है: राउटर (फ़ाइल-आधारित या मॉड्यूलर), प्रोजेक्ट प्रकार (वेब ​​या एपीआई), क्लाइंट फ्रेमवर्क, ओआरएम। Python और नोड निर्भरता की स्थापना फिर प्रति चरण एक पंक्ति और उसकी अवधि के साथ चलती है। [सीएलआई](../reference/cli.md) देखें।

पंजीकृत टेम्पलेट के साथ संकेतों को छोड़ें:

```bash
uvx nexy new my-app --template <name>
```

## प्रोजेक्ट के आभासी वातावरण के अंदर काम करें

प्रत्येक अन्य कमांड (`nexy dev`, `nexy build`, `nexy migrate`...) को प्रोजेक्ट के वर्चुअल वातावरण **के अंदर** चलना चाहिए। यहीं पर आपके अपने पैकेज रहते हैं: आपका ORM, आपकी लाइब्रेरी, और Nexy जिसके साथ प्रोजेक्ट बनाया गया था। इसके बाहर, जिस प्रोजेक्ट को `sqlmodel` की आवश्यकता होती है वह `ModuleNotFoundError: No module named 'sqlmodel'` के साथ विफल हो जाता है।

इसे प्रोजेक्ट फ़ोल्डर से प्रति टर्मिनल एक बार सक्रिय करें:

| शेल | कमांड |
|---|---|
| पॉवरशेल, सीएमडी (विंडोज़) | `.venv\Scripts\activate` |
| मैकओएस, लिनक्स | `source .venv/bin/activate` |

फिर संकेत `(.venv)` से शुरू होता है। वहां से:

```bash
cd my-app
.venv\Scripts\activate    # Windows; on macOS and Linux: source .venv/bin/activate
nexy dev
```

<http://localhost:3000> खोलें।

सक्रियण को छोड़ने के लिए, uv को इसे एक आदेश के लिए करने दें: `uv run nexy dev`।

> [!NOTE]
> `nexy` और `nx` एक ही बाइनरी हैं। `uv tool install nexy` के साथ स्थापित एक प्रति अपने स्वयं के वातावरण में रहती है, जैसे `uvx`, इसलिए इसका उपयोग प्रोजेक्ट बनाने और प्रोजेक्ट के वातावरण से बाकी सब कुछ चलाने के लिए करें।

## किसी मौजूदा प्रोजेक्ट में Nexy जोड़ें

इसे प्रोजेक्ट के वर्चुअल वातावरण से चलाएं, इसके पैकेजों में नेक्सी भी शामिल है (`uv add nexy`):

```bash
nexy init
```
