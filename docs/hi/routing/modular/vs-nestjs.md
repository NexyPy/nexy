# नेक्सी और नेस्टजेएस

मॉड्यूलर राउटर NestJS से प्रेरित है: नियंत्रक, मॉड्यूल और कंस्ट्रक्टर इंजेक्शन। यह एक है
फास्टएपीआई पर पतली परत है, इसलिए यह सभी NestJS को पुन: उत्पन्न करने का प्रयास नहीं करता है। यह पृष्ठ दोनों पक्षों को सूचीबद्ध करता है।

## क्या मेल खाता है

| नेस्टजेएस | नेक्सी |
|---|---|
| `@Controller('users')` | `@Controller(prefix="/users")` |
| `@Module({ controllers, providers, imports, exports })` | `@Module()` समान चार वर्ग विशेषताओं के साथ |
| `@Injectable()` | `@Injectable()` |
| कंस्ट्रक्टर इंजेक्शन | `__init__` टाइप एनोटेशन से पैरामीटर हल किए गए |
| सिंगलटन, अनुरोध और क्षणिक दायरे | `Scope.SINGLETON`, `Scope.REQUEST`, `Scope.TRANSIENT` |
| `@UseGuards(AuthGuard)` | `@UseGuard(guard)` (एक फास्टएपीआई निर्भरता) |
| `@ApiOperation`, `@ApiResponse` (स्वैगर) | `@UseRoute`, `@UseResponse` (ओपनएपीआई, `/docs` पर परोसा गया) |
| वेबसॉकेट गेटवे | `async def SOCKET(...)` एक नियंत्रक पर |
| डीटीओ सत्यापन (`class-validator`) | पाइडेंटिक मॉडल, फास्टएपीआई के मूल निवासी |
| परिपत्र निर्भरता का पता लगाना | `RecursionError` वर्ग का नामकरण |

## क्या अलग है

- हैंडलर HTTP क्रिया के नाम पर रखी गई विधियां हैं (`get`, `post`...), प्रति नियंत्रक एक।
- गार्ड और मिडलवेयर डेकोरेटर फास्टएपीआई `Depends` हैं, न कि `canActivate` वाली कक्षाएं।
- पैरामीटर (`@Body`, `@Param`, `@Query`) फास्टएपीआई पैरामीटर हैं: एनोटेशन टाइप करें, `Query`, `Path`,
  `Body`.
- पाइप पाइडेंटिक सत्यापन और फास्टएपीआई निर्भरताएं हैं।

## क्या कमी है

| नेस्टजेएस सुविधा | नेक्सी में स्थिति |
|---|---|
| कस्टम प्रदाता (`useValue`, `useFactory`, `useClass`, स्ट्रिंग टोकन) | उपलब्ध नहीं: केवल `@Injectable()` कक्षाएं |
| इंटरफ़ेस या अमूर्त वर्ग द्वारा इंजेक्शन लगाना | उपलब्ध नहीं है |
| मॉड्यूल एनकैप्सुलेशन | लागू नहीं किया गया: कंटेनर प्रक्रिया-व्यापी है, `exports` केवल उत्सुक रिज़ॉल्यूशन को नियंत्रित करता है |
| गतिशील और वैश्विक मॉड्यूल (`forRoot`, `@Global`) | उपलब्ध नहीं है |
| जीवनचक्र हुक (`onModuleInit`, `onApplicationShutdown`) | उपलब्ध नहीं है |
| इंटरसेप्टर | एएसजीआई मिडलवेयर (`useMiddlewares`) या निर्भरता | का उपयोग करते हैं
| अपवाद फ़िल्टर | फास्टएपीआई अपवाद हैंडलर का उपयोग करते हैं |
| प्रदाता के साथ परीक्षण मॉड्यूल ओवरराइड करता है | कोई सार्वजनिक एपीआई नहीं; फास्टएपीआई `dependency_overrides` और `TestClient` | का उपयोग करें
| कॉन्फिग मॉड्यूल, शेड्यूलिंग, क्यू, सीक्यूआरएस, माइक्रोसर्विसेज, कैशिंग | नेक्सी का हिस्सा नहीं है; पायथन पारिस्थितिकी तंत्र का उपयोग करें |

## इसे कब चुनना है

जब आप बड़े एपीआई के लिए इंजेक्शन के साथ क्लास-आधारित संरचना चाहते हैं तो मॉड्यूलर राउटर चुनें।
जब यूआरएल संरचना आयोजन सिद्धांत हो तो फ़ाइल-आधारित राउटर चुनें। दोनों मचान हैं
`nx new` द्वारा, एक ही फास्टएपीआई एप्लिकेशन पर चलता है, और सह-अस्तित्व में रह सकता है।

> [!नोट]
> उपरोक्त गायब वस्तुएं ईमानदार अंतर हैं। यदि आपको `useFactory` प्रदाताओं की आवश्यकता है
> या आज परीक्षणों में अत्यधिक प्रदाता, तर्क को सादे कार्यों और फास्टएपीआई में रखें
> `Depends`, जो स्वाभाविक रूप से बनाते और ओवरराइड करते हैं।
