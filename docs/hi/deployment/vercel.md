# मैं वर्सेल पर नेक्सी ऐप कैसे तैनात करूं?

`nx add vercel` चलाएँ, जेनरेट की गई फ़ाइलों को अपने `nx build` आउटपुट के साथ सबमिट करें, और वर्सेल Python रनटाइम को `src/server.py:app` पर इंगित करें।

## प्लेटफ़ॉर्म फ़ाइलें जोड़ें

नेक्सी प्रोजेक्ट के मूल से:

```bash
nx add vercel
nx build
```

`nx add vercel` `src/server.py` और `vercel.json` लिखते हैं। इसमें उन फ़ाइलों के लिए अनदेखा नियम भी जोड़े गए हैं जो ऐप चलने के दौरान बदलते हैं: `__nexy__/build-cache.json`, `__nexy__/server.port`, `__nexy__/.temp/` और `__pycache__/`। कमांड को फिर से चलाने से वे फ़ाइलें बनी रहती हैं जो पहले से मौजूद हैं और अनदेखा नियमों की नकल नहीं करती हैं।

## ऐप पर वर्सेल को इंगित करें

वर्सेल प्रोजेक्ट सेटिंग्स में, Python रनटाइम का चयन करें और प्रवेश बिंदु के रूप में `src/server.py:app` का उपयोग करें। वर्सेल को उस मॉड्यूल में `app` नाम का पता चलता है; `nx start` शामिल नहीं है।

जेनरेट किया गया `src/server.py` कार्यशील फ़ोल्डर तैयार करने के बाद आलसी `nexy.app.app` को आयात करता है। आप स्थानीय स्तर पर `uvicorn src.server:app` के साथ समान प्रवेश बिंदु का उपयोग कर सकते हैं।

## बिल्ड आउटपुट प्रतिबद्ध करें

जब वर्सेल के पास कोई बिल्ड कमांड नहीं है, तो उसे केवल वही प्राप्त होता है जो रिपॉजिटरी में होता है। प्रतिबद्ध `__nexy__/` प्रत्येक `nx build` के बाद, संकलित मार्गों के साथ, क्लाइंट बंडल `__nexy__/client/` के अंतर्गत होता है और मेनिफेस्ट `__nexy__/client/.vite/manifest.json` पर होता है।

`vite.config.ts` को प्रोजेक्ट रूट पर रखें और प्रतिबद्ध करें। उत्पादन में नेक्सी स्टाइलशीट और स्क्रिप्ट टैग लिखने के लिए Vite मेनिफेस्ट को पढ़ता है, लेकिन यह उन टैग को केवल तभी उत्सर्जित करता है जब `vite.config.ts` मौजूद होता है। उस फ़ाइल के बिना पेज अभी भी 200 उत्तर देता है और सीएसएस या क्लाइंट के बिना आता है JavaScript।

`__nexy__/build-cache.json` प्रतिबद्ध न करें: इसमें बिल्ड चलाने वाली मशीन से पूर्ण पथ शामिल हैं। `__nexy__/server.port` `nx start` से संबंधित है, और `__nexy__/.temp/` स्क्रैच स्पेस है।

## केवल-पढ़ने योग्य फ़ाइल सिस्टम स्वीकार करें

Python एप्लिकेशन शुरू होने पर वर्सेल प्रोजेक्ट को केवल-पढ़ने के लिए माउंट करता है। नेक्सी स्टार्टअप के दौरान जेनरेट की गई फ़ाइलें लिखता है, इसलिए एक खाली `from nexy.app import app` `OSError: [Errno 30] Read-only file system` के साथ विफल हो सकता है।

उत्पन्न प्रविष्टि बिंदु ऐप आयात करने से पहले छह प्रोजेक्ट आइटम को एक लिखने योग्य अस्थायी फ़ोल्डर में कॉपी करता है: `src`, `__nexy__`, `public`, `nexyconfig.py`, `pyproject.toml` और `vite.config.ts`। यह कार्यशील निर्देशिका को बदलता है और प्रतिलिपि को पहले `sys.path` पर रखता है, क्योंकि नेक्सी वर्तमान निर्देशिका से मार्गों का समाधान करता है। आपका ऐप रनटाइम पर जो भी फ़ाइल पढ़ता है उसे हाथ से उस सूची में जोड़ें।

## स्थिर संपत्तियों को कैश करें

उत्पन्न `vercel.json` में दो कैश नियम शामिल हैं जिनका उपयोग एक तैनात नेक्सी साइट करती है: `/assets/` के अंतर्गत फ़ाइलें एक वर्ष के लिए अपरिवर्तनीय होती हैं, और `public/` के अंतर्गत छवियां और फ़ॉन्ट एक सप्ताह की पुरानी-जबकि-पुनर्मूल्यांकन विंडो के साथ एक दिन के लिए ताज़ा रहते हैं। यदि आपके प्रोजेक्ट को अन्य नियमों की आवश्यकता है तो उसी फ़ाइल में जोड़ें।

## परिनियोजन की जाँच करें

पुश करने से पहले, प्रवेश बिंदु आयात करें और उससे एक पृष्ठ मांगें:

```bash
uv run python -c "from src.server import app; print(type(app).__name__)"
uv run uvicorn src.server:app
```

फिर `/`, एक जेनरेटेड रूट और `/assets/` के अंतर्गत एक फ़ाइल खोलें। स्थानीय स्तर पर प्रतिक्रिया की तुलना `nx start` से करें: स्थिति, सामग्री प्रकार और आकार मेल खाना चाहिए। एक पृष्ठ जो स्थानीय पृष्ठ से बिल्कुल दो क्लाइंट टैग से छोटा है, इसका मतलब है कि `vite.config.ts` कॉपी किए गए प्रोजेक्ट से गायब था।
