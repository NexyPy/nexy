# सुरक्षा

नेक्सी अपनी हमले की सतह को कैसे छोटा रखती है, उसे किन संस्करणों की आवश्यकता है, और किसी प्रोजेक्ट की जांच कैसे करें।

## संस्करण फर्श

नेक्सी फास्टएपीआई, स्टारलेट, जिंजा2, वाइट और रिएक्ट पर निर्भर है। एक मंजिल नेक्सी का सबसे निचला संस्करण है
अनुमति देता है; प्रत्येक व्यक्ति एक प्रकाशित सलाह का उत्तर देता है।

| पैकेज | मंजिल | क्यों |
|---|---|---|
| `starlette` | 1.0.1 | सीवीई-2026-48710 (बैडहोस्ट): एक तैयार किया गया `Host` हेडर स्टारलेट रिपोर्ट के पथ को मिडलवेयर में बदल देता है, जो `request.url.path` पर लिखे प्राधिकरण को दरकिनार कर देता है। सीआईएसए द्वारा शोषित के रूप में सूचीबद्ध। |
| `fastapi` | 0.133.0 | पहली रिलीज जो एक निश्चित स्टारलेट को स्वीकार करती है |
| `jinja2` | 3.1.6 | सैंडबॉक्स से `attr` फ़िल्टर (सीवीई-2025-27516) | के माध्यम से निकलना
| `vite` (मचान वाली परियोजनाएं) | 6.4.3 | `server.fs.deny` विंडोज़ वैकल्पिक पथों पर बाईपास (सीवीई-2026-53571); पहले वाला क्वेरी-स्ट्रिंग बाईपास (CVE-2026-39364) केवल Vite 7.1-7.3.1 और 8.0.0-8.0.4 को प्रभावित करता है |
| `react`, `react-dom` | 19.2.5 | 2026 रिएक्ट सलाह `react-server-dom-*` पैकेजों से संबंधित है, जिनका नेक्सी उपयोग नहीं करता है; फर्श लाइन को पैच करके रखता है |

अपने हल किए गए संस्करण जांचें:

```bash
uv pip list | grep -i -E "starlette|fastapi|jinja2"
npm ls vite
```

## नेक्सी जिन नियमों का पालन करती है

- **पथों के लिए होस्ट हेडर पर कभी भरोसा न करें।** नेक्सी `scope["path"]` पढ़ता है, `request.url.path` नहीं,
  इसका अपना मिडलवेयर (निर्देशिका मिडलवेयर) है। अपने में भी वैसा ही करो.
- **जो HTML तक पहुंचता है उससे बचें।** प्रॉप्स क्लाइंट घटकों को दिए गए, `Link` विशेषताएँ, `Image`,
  `Audio` और `Video` विशेषताएँ, सामग्री तालिका एंकर और `HTTPException` विवरण सभी हैं
  HTML से बच गया। `| safe` टेम्पलेट में इसे बंद कर दिया जाता है: इसे उपयोगकर्ता इनपुट पर कभी भी उपयोग न करें।
- **डेवलपर एंडपॉइंट केवल लूपबैक और संकीर्ण हैं।** डेव एंडपॉइंट रेंडर करता है
  (`/__nexy__/render`) केवल `src/routes/` के अंतर्गत `.tsx` या `.jsx` एक्सटेंशन वाली फ़ाइलें स्वीकार करता है, और
  केवल डेव सर्वर के माध्यम से पहुंच योग्य है, जो विदेशी `Host` हेडर को अस्वीकार कर देता है।
- **त्रुटि विवरण लीक नहीं होते।** एक त्रुटि पृष्ठ जो स्वयं विफल रहता है वह केवल स्थिति कोड दिखाता है।
- **प्रोडक्शन उत्तरों में सुरक्षित हेडर होते हैं।** `X-Content-Type-Options: nosniff` और
  `Referrer-Policy: strict-origin-when-cross-origin`, जब तक कि आपका कोड स्वयं सेट न हो जाए। `Server`
  हेडर नहीं भेजा गया है. अपने में `Strict-Transport-Security` और एक `Content-Security-Policy` जोड़ें
  प्रॉक्सी या मिडलवेयर: वे आपके डोमेन पर निर्भर करते हैं।
- **क्रैश एक संदर्भ दिखाता है, त्रुटि नहीं।** [त्रुटि पृष्ठ](../routing/fbr/errors/README.md#unhandled-exceptions) देखें।
- **नेक्सी के पायथन कोड में कोई `eval` और कोई `shell=True` नहीं।** बाहरी प्रोग्राम एक तर्क सूची के साथ चलते हैं।

## ऑडिट चलाना

```bash
python scripts/audit_dependencies.py        # Python dependencies against the lock
npm audit                                    # in a scaffolded project
uv run bandit -r nexy -c .bandit             # static analysis of Nexy itself
```

नेक्सी का अपना भंडार अपने चेक में पहला और तीसरा चलाता है। ऊपर एक मंजिल पर एक नई एडवाइजरी को बढ़ाकर संभाला जाता है
`pyproject.toml` में फर्श या मचान में `package.json`, फिर ताले को पुनर्जीवित करना।

## सुरक्षित रूप से तैनाती

- अपने डोमेन पर `useTrustedHost` सेट करें: यह किसी भी रूट से पहले अप्रत्याशित `Host` हेडर को अस्वीकार कर देता है।
- विटे देव सर्वर को उजागर न करें: `nx dev` इसे नेक्सी मूल के पीछे लूपबैक पर रखता है।
- यदि एपीआई स्कीमा सार्वजनिक नहीं होनी चाहिए तो `useDocs = False` सेट करें।

[मिडिलवेयर और सुरक्षा](../guides/middleware-and-security.md) देखें।
