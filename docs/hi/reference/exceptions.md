# अपवाद और त्रुटियां

एक अनुरोध चार स्थानों पर विफल हो सकता है, और नेक्सी प्रत्येक का अलग-अलग उत्तर देता है। यह पृष्ठ अनुक्रमणिका है:
जो स्थिति आप देख रहे हैं उसे ढूंढें, फिर वह पंक्ति जिसने इसे बनाया, फिर वह फ़ाइल जो मुख्य भाग का निर्णय करती है।

> [!नोट]
> तीन चीजें अलग-अलग हैं और उन्हें मिलाना आसान है: **HTTP उत्तर** (एक स्थिति और एक निकाय), द
> **त्रुटि पृष्ठ** (`notfound.nexy`, `errors.nexy`), और **लॉग लाइन** (आपने इसमें क्या पढ़ा है)
> टर्मिनल)। पृष्ठ बदलने से स्थिति नहीं बदलती है, और पृष्ठ को अनुकूलित करने से स्थिति छिपती नहीं है
> लॉग।

## संक्षिप्त संस्करण

| क्या हुआ | स्थिति | ब्राउज़र देखता है | एपीआई क्लाइंट देखता है |
|---|---|---|---|
| कोई भी मार्ग यूआरएल से मेल नहीं खाता है | `404` | `notfound.nexy`, अन्यथा अंतर्निहित पृष्ठ | `{"detail": "Not Found"}` |
| एक पथ खंड इसके एनोटेशन में फिट नहीं होता है | `404` | एक ही पृष्ठ | `{"detail": "Not Found"}` |
| एक क्वेरी, हेडर, कुकी या बॉडी फ़ील्ड गायब या अमान्य है | `422` | फास्टएपीआई की JSON बॉडी | फास्टएपीआई की JSON बॉडी |
| `notFound()` | `404` | पेज | `{"detail": ...}` |
| `unauthorized()` | `401` | अंतर्निहित पृष्ठ | `{"detail": ...}` |
| `forbidden()` | `403` | अंतर्निर्मित पृष्ठ | `{"detail": ...}` |
| `raise HTTPException(409, ...)` | `409` | अंतर्निर्मित पृष्ठ | `{"detail": ...}` |
| एक अपवाद कुछ भी पकड़ में नहीं आया | `500` | `errors.nexy`, अन्यथा अंतर्निहित पृष्ठ | `{"detail", "reference"}` |
| `redirect(url)` | `307` | गंतव्य, कोई पृष्ठ नहीं | गंतव्य, कोई शरीर नहीं |
| `permanentRedirect(url)` | `308` | गंतव्य, कोई पृष्ठ नहीं | गंतव्य |

एपीआई क्लाइंट एक अनुरोध है जिसका `Accept` हेडर JSON मांगता है न कि कोई पेज:

```bash
curl -H "Accept: application/json" http://localhost:3000/api/items/500
# {"detail":"Out of range"}
```

> [!चेतावनी]
> `curl` डिफ़ॉल्ट रूप से `Accept: */*` भेजता है, जिसे HTML पेज मिलता है। जोड़ें
> `-H "Accept: application/json"` जब आप JSON आकार का परीक्षण करते हैं। ब्राउज़रों को पेज मिलते रहते हैं.

## असफलता कहां से आती है

```diagram filename="एक अनुरोध, चार निकास"
Browser ──► Middleware ──► Router ──► Page or handler
                 │            │             │
                 │            │             ├─ return ───────────► 200
                 │            │             ├─ HTTPException ────► its status
                 │            │             └─ other exception ───► 500
                 │            └─ no match ────────────────────────► 404
                 └─ raises ──────────────────────────────────────► 500
```

| चरण | क्या असफल हो सकता है | उत्तर |
|---|---|---|
| मिडलवेयर | आपका `middleware.py`, सीओआरएस, सत्र | अपवाद की स्थिति, अन्यथा `500` |
| राउटर | यूआरएल किसी फ़ाइल से मेल नहीं खाता | `404` |
| सत्यापन | एक पथ खंड को परिवर्तित नहीं किया जा सकता है | `404` |
| सत्यापन | एक क्वेरी, हेडर, कुकी या बॉडी फ़ील्ड | `422` |
| पेज, हैंडलर, एक्शन, गार्ड | `HTTPException` | इसकी स्थिति |
| पेज, हैंडलर, एक्शन, गार्ड | कुछ और | `500` |

## कहीं से भी निकलें

`redirect`, `permanentRedirect`, `notFound`, `forbidden` और `unauthorized` एक HTTP अपवाद उठाते हैं,
तो वही कॉल एक `.nexy` पेज, एक एपीआई हैंडलर, एक मॉड्यूलर नियंत्रक, एक गार्ड, एक में काम करता है
`dependencies.py` और एक क्रिया।

```python filename="src/routes/posts/[slug].py"
from nexy import notFound, redirect

from src.posts import find


async def GET(slug: str):
    post = find(slug)
    if post is None:
        notFound("No such post")
    if post.moved_to:
        redirect(post.moved_to)
    return post
```

| कॉल करें | उत्तर दें | जब |
|---|---|---|
| `notFound(detail=None)` | `404` | संसाधन मौजूद नहीं है |
| `unauthorized(detail=None, scheme=None)` | `401` | आगंतुक को पहले साइन इन करना होगा |
| `forbidden(detail=None)` | `403` | आगंतुक को पता है लेकिन वह इसे नहीं देख सकता है |
| `redirect(url, status=307)` | `307` | विधि रखते हुए उन्हें अन्यत्र भेजें |
| `redirect(url, status=303)` | `303` | एक फॉर्म के बाद: अगला अनुरोध एक `GET` | है
| `permanentRedirect(url)` | `308` | एक स्थानांतरित पृष्ठ जिसे खोज इंजनों को याद रखना चाहिए |

मंजिल का निर्माण उन मूल्यों से करें जिन पर आप भरोसा करते हैं। `redirect(request.query_params["next"])` आगंतुकों को भेजता है
जहाँ भी लिंक कहता है; यह एक खुला रीडायरेक्ट है. जिस गंतव्य पर लाइन ब्रेक होता है उसे अस्वीकार कर दिया जाता है।

## सत्यापन: 422, या 404

हैंडलर पैरामीटर्स को उनके एनोटेशन के विरुद्ध फास्टएपीआई द्वारा मान्य किया जाता है।

```python filename="src/routes/api/search.py"
from nexy.http import Header


async def GET(q: str, limit: int = 10, x_token: str = Header(...)):
    return {"q": q, "limit": limit}
```

| समस्या | स्थिति | क्यों |
|---|---|---|
| गुम या अमान्य क्वेरी, हेडर, कुकी या बॉडी फ़ील्ड | `422` | अनुरोध हैंडलर तक पहुंच गया, डेटा गलत है |
| अमान्य पथ खंड (`/api/users/abc` के लिए `id: int`) | `404` | फ़ोल्डर में गैर-संख्या के लिए कोई मार्ग नहीं है, इसलिए यूआरएल मौजूद नहीं है |

`422` बॉडी फास्टएपीआई का मानक आकार है, इसलिए क्लाइंट और जेनरेट किए गए एसडीके काम करते रहते हैं:

```json
{"detail": [{"loc": ["query", "q"], "msg": "Field required", "type": "missing"}]}
```

किसी फॉर्म या कार्रवाई के लिए, ग्राहक को `status` और `detail` के साथ एक `ActionError` प्राप्त होता है; एक `422`
`error.fields` को प्रति फ़ील्ड एक संदेश से भी भरता है। [क्रियाएँ](../guides/actions.md#errors-and-failures) देखें।

> [!टिप]
> हस्ताक्षर में मान्य करें जब नियम एक फ़ील्ड के बारे में हो (`limit: int = 10`)। में मान्य करें
> बॉडी जब नियम को डेटाबेस या किसी अन्य फ़ील्ड की आवश्यकता होती है ("यह ईमेल पहले से ही उपयोग किया गया है"): बढ़ाएँ
> `HTTPException(409)` और ग्राहक के लिए संदेश रखें।

## कस्टम त्रुटि पृष्ठ

```nexy filename="src/routes/notfound.nexy"
<h1>Page not found</h1>
<p>The link may be old. <a href="/">Start from the home page</a>.</p>
```

```nexy filename="src/routes/errors.nexy"
<h1>Something went wrong</h1>
<p>Try again in a moment.</p>
```

| फ़ाइल | स्थिति | दायरा |
|---|---|---|
| `src/routes/notfound.nexy` | `404` | परियोजना का प्रत्येक मार्ग |
| `src/routes/errors.nexy` | `500` | परियोजना का प्रत्येक मार्ग |
| `src/routes/forbidden.nexy` | `403` | परियोजना का प्रत्येक मार्ग |
| `src/routes/unauthorized.nexy` | `401` | परियोजना का प्रत्येक मार्ग |
| `src/routes/blog/notfound.nexy` | `404` | `/blog` और नीचे |
| `src/routes/blog/errors.nexy` | `500` | `/blog` और नीचे |
| `src/routes/loading.nexy` | - | आरक्षित, अभी तक कोई रनटाइम प्रभाव नहीं |

मार्गों में कहीं एक फ़ाइल अपनी स्थिति के लिए उत्तर स्थापित करती है: रूट पर एक प्रति उत्तर देती है
संपूर्ण प्रोजेक्ट, एक फ़ोल्डर में एक प्रति उस फ़ोल्डर का उत्तर देती है, और सबसे गहरी फ़ाइल जो URL से मेल खाती है
जीतता है. प्रत्येक प्रतिलिपि के बाहर एक यूआरएल, और बिना किसी फ़ाइल वाली स्थिति, अंतर्निहित स्टाइल वाले पृष्ठ प्राप्त करते हैं।
[प्रति फ़ोल्डर त्रुटि पृष्ठ](../routing/fbr/errors/folder-pages.md) देखें।

> [!महत्वपूर्ण]
> एक `errors.nexy` पृष्ठ, `500` पृष्ठ का स्थान लेता है; यह अपवाद को पकड़ नहीं पाता है और न ही पकड़ता है
> लॉग लाइन बदलें। यदि उठाया गया हैंडलर स्वयं पृष्ठ है, तो पृष्ठ अपना स्वयं का नहीं दिखा सकता है
> त्रुटि विवरण: `errors.nexy` को सरल और स्वतंत्र रखें।

## अनचाहे अपवाद

एक अपवाद यह है कि जो कुछ भी पकड़ा गया है उसे एक बार लॉग किया जाता है, इसके संदर्भ के साथ, यह कहां से आया है और कोड के साथ
इसके चारों ओर. स्थिति `500` है, और शरीर पर्यावरण पर निर्भर करता है।

| | `nexy dev` | `nexy build` फिर `nexy start` |
|---|---|---|
| ब्राउज़र | त्रुटि, आपके कोड की पंक्तियाँ और ट्रेसबैक | `errors.nexy`, अन्यथा अंतर्निहित पृष्ठ, एक संदर्भ के साथ |
| एपीआई क्लाइंट | `{"detail", "reference", "error"}` | `{"detail", "reference"}` |
| टर्मिनल | अपवाद और आपके कोड की पंक्तियाँ | अपवाद, संपूर्ण ट्रेसबैक और संदर्भ |

```text
  x ZeroDivisionError: division by zero  GET /boom  ref fe6a5217
    at src/routes/boom.py:2 in GET
       1 | def GET():
       2 |     return {"a": 1 / 0}
```

संदर्भ आठ वर्णों का है, प्रत्येक विफलता के लिए नया। एक आगंतुक इसे उद्धृत कर सकता है, और आप उसे ढूंढ लेते हैं
इसके लिए लॉग खोजकर ट्रेसबैक करें। न तो अपवाद और न ही कोड विज़िटर तक पहुंचता है
उत्पादन।

> [!सावधानी]
> उत्पादन में किसी आगंतुक को ट्रेसबैक न लौटाएं, और किसी त्रुटि में रहस्य न डालें
> संदेश: `HTTPException` का `detail` क्लाइंट को भेजा जाता है, HTML-एस्केप्ड। राज अंदर डालो
> लॉग, उत्तर में नहीं।

## कार्य और रूप

एक क्रिया एक उत्पन्न पथ के साथ एक `POST` समापन बिंदु है। इसकी विफलताएँ उन्हीं नियमों का पालन करती हैं:

| स्थिति | स्थिति | ग्राहक |
|---|---|---|
| एक फ़ील्ड गायब है या अमान्य है | `422` | `ActionError` के साथ `fields` |
| `HTTPException(403)` कार्रवाई में उठाया गया | `403` | `ActionError` के साथ `status` और `detail` |
| एक हैंडल न किया गया अपवाद | `500` | `ActionError`; संदर्भ सर्वर लॉग में है |
| `Origin` हेडर एक अन्य साइट है | `403` | ने कार्रवाई चलने से पहले इनकार कर दिया |

जावास्क्रिप्ट के बिना एक फॉर्म क्रिया पथ पर पोस्ट होता है; एक सफलता उत्तर देती है `303` पृष्ठ पर वापस, ए
विफलता त्रुटि पृष्ठ दिखाती है. [क्रियाएँ](../guides/actions.md#forms-without-javascript) देखें।
## एक चेकलिस्ट जब कोई पेज गलत उत्तर देता है

1. **स्थिति देखें**, पृष्ठ नहीं। एक प्रथा `notfound.nexy` अभी भी `404` का उत्तर देती है।
2. **टर्मिनल पढ़ें।** एक पृष्ठ जो आयात करने में विफल रहता है वह पंजीकृत नहीं है, इसलिए इसका यूआरएल उत्तर देता है `404`
   जबकि फ़ाइल मौजूद है. आयात त्रुटि लॉग में है.
3. **एक्सटेंशन की जांच करें।** `useCSR = True` के साथ, `.nexy` पेज सर्वर मोड से संबंधित हैं; में एक पेज
   ग़लत मोड कोई मार्ग नहीं है.
4. **गहराई की जाँच करें।** एक `notfound.nexy` या `errors.nexy` केवल तभी काम करता है जब रूट कॉपी मौजूद हो।
5. **आकृति देखने के लिए `Accept: application/json` के साथ JSON** मांगें आपका एपीआई क्लाइंट प्राप्त करता है।
6. **संदर्भ उद्धृत करें** जब आप कोई समस्या खोलते हैं या लॉग खोजते हैं तो `500` का।
