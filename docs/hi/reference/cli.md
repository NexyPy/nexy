# सीएलआई

बाइनरी `nx` है (`nexy` के रूप में भी स्थापित है)। `uvx nexy new` एक प्रोजेक्ट बनाता है (`uvx` के साथ आता है
यूवी). प्रोजेक्ट के वर्चुअल वातावरण के अंदर, या `uv run` के माध्यम से, हर दूसरे कमांड को चलाएँ
उदाहरण `uv run nexy dev`: यहीं आपके अपने पैकेज हैं।

## आदेश

| कमांड | उपनाम | यह क्या करता है |
|---|---|---|
| `nx dev` | `nx d` | विकास सर्वर: परिवर्तन पर संकलन, वाइट, एचएमआर |
| `nx start` | `nx s` | संकलित आउटपुट पर उत्पादन सर्वर |
| `nx build` | `nx b` | उत्पादन निर्माण |
| `nx new` | `nx n` | एक परियोजना का मचान |
| `nx init` | `nx i` | नेक्सी को मौजूदा प्रोजेक्ट में जोड़ें |
| `nx add` | - | रजिस्ट्री से एक यूआई घटक या `src/components/ui` | में एक यूआरएल जोड़ें
| `nx migrate` | `nx m` | एलेम्बिक या एरिच के साथ डेटाबेस माइग्रेशन बनाएं या लागू करें |
| `nx check` | `nx c` | टाइप-चेक: पायथन पर मायपी, `tsc` टाइपस्क्रिप्ट पर |
| `nx format` | `nx f` | प्रारूप पायथन (रफ), जेएस/टीएस (सुंदर), `.nexy` फ़ाइलें |
| `nx test` | - | पाइटेस्ट चलाएँ; `--client` विटेस्ट जोड़ता है |
| `nx skills` | - | कोडिंग एजेंटों के लिए कौशल जोड़ें या ताज़ा करें, `AGENTS.md` और `CLAUDE.md` |

## झंडे

| कमांड | ध्वज | डिफ़ॉल्ट |
|---|---|---|
| `dev`, `start` | `--port` | `usePort`, `3000` |
| `dev`, `start` | `--host` | `useHost`, `0.0.0.0` |
| `build` | `--check` | बंद - निर्माण के बाद रफ और मायपी चलता है |
| `format` | `--check` | बंद - दोबारा लिखने के बजाय रिपोर्ट करें |
| `test` | `--client` | बंद - अकेले पाइटेस्ट के बजाय विटेस्ट भी चलाएं |
| `test` | `--no-server` | चालू - जब आप केवल क्लाइंट परीक्षण चाहते हैं तो पाइटेस्ट छोड़ें |
| `new` | `--template`, `-t` | कोई नहीं - संकेतों के बिना एक पंजीकृत टेम्पलेट को क्लोन करें |
| `new` | `--no-agents` | एजेंट चालू - छोड़ें `AGENTS.md` और एजेंट कौशल |
| `add` | `--ui`, `--url` | बंद - रजिस्ट्री नाम या यूआरएल अस्पष्ट होने पर बाध्य करें |
| `add` | `--all`, `-a` | बंद - रजिस्ट्री के प्रत्येक घटक को जोड़ें |
| `add` | `--sha256` | कोई नहीं - एक दूरस्थ घटक का अपेक्षित डाइजेस्ट; एक बेमेल विवाह समाप्त हो जाता है |
| `migrate` | `--init` | बंद - एलेम्बिक या एरिच सेटअप लिखें |
| `migrate` | `--upgrade`, `-u` | बंद - नया लिखने के बजाय माइग्रेशन लागू करें |
| `migrate` | `--message`, `-m` | खाली - नए संशोधन का नाम |

## आउटपुट

लंबे चरण (पैकेज स्थापित करना, संकलन करना, बंडल करना) बीते हुए समय के साथ एक स्पिनर दिखाते हैं
एक पंक्ति पीछे छोड़ें: `✔ uv sync .venv  1.4s`। चरणों का एक समूह (`nx new` की स्थापना) एक दिखाता है
पूर्ण चरणों की संख्या के साथ प्रगति पट्टी, `━━━━────  2/5`; एक एकल चरण (`nx add`) दिखाता है
जब यह चलता है तो उस स्पंदन को रोकें। अनुरोधों के लिए देव लॉग `GET » /about 200 in 12ms` पढ़ते हैं
`vite » ...` विटे के लिए। एक असफल चरण अंतिम प्रिंट करता है
कमांड के आउटपुट को छिपाने के बजाय उसकी पंक्तियाँ। वे टर्मिनल जो यूनिकोड प्रस्तुत नहीं कर सकते, प्राप्त करते हैं
`+` और `x`।

## `nx dev` चलने के दौरान त्रुटियाँ

टूटी हुई फ़ाइल को सहेजने से सर्वर कभी बंद नहीं होता। एक `.py` फ़ाइल को सिंटैक्स त्रुटि के साथ रिपोर्ट किया गया है
फ़ाइल और लाइन, और जब तक आप इसे ठीक नहीं कर लेते, सर्वर अंतिम कार्यशील संस्करण प्रस्तुत करता रहता है:

```text
  nexy » error  src/routes/users.py:3
  SyntaxError: invalid syntax

    1 | import json
    2 |
  > 3 | def GET(:
                ^
    4 |     x = 1
    5 |     return {"v": 2}

  Fix it and save: the server keeps its last working version.
```

एक फ़ाइल जो पार्स करती है लेकिन एप्लिकेशन लोड होने पर विफल हो जाती है (एक अनुपलब्ध आयात, मॉड्यूल में एक त्रुटि
लेवल) को उसी तरह रिपोर्ट किया जाता है और `nx dev` आपके अगले सेव की प्रतीक्षा करता है; तक कुछ भी नहीं परोसा जाता
एप्लिकेशन पुनः लोड होता है. सर्वर पुनः लोड होने पर एक वैध सेव `nexy » update <file>` पढ़ता है। मार्कडाउन फ़ाइलें बाहर
`src/routes`, जैसे कि `README.md`, पेज नहीं हैं और कुछ भी ट्रिगर नहीं करते हैं।
`nx start` सख्त है: यह कोड 1 के साथ बाहर निकलता है, और कुछ भी शुरू नहीं करता है, अगर रूट फ़ाइल लोड नहीं हो पाती है।

## `nx new` के प्रश्न

`nx new` इस क्रम में पूछता है: फ़ाइल-आधारित राउटर, प्रोजेक्ट प्रकार (वेब या एपीआई), क्लाइंट-साइड रूटिंग,
क्लाइंट फ्रेमवर्क, ऐप को कैसे स्टाइल करें, उपनाम आयात करें, ओआरएम, डेटाबेस और डेटाबेस यूआरएल। प्रत्येक विकल्प में एक लघुता होती है
विवरण और वर्तमान को हाइलाइट किया गया है। जो प्रश्न लागू नहीं होते उन्हें छोड़ दिया जाता है (एक एपीआई
परियोजना की कोई रूपरेखा या शैली नहीं है; **कोई डेटाबेस नहीं** चुनना क्योंकि ओआरएम डेटाबेस और यूआरएल को छोड़ देता है)।
तीर कुंजी (या `j`/`k`, या एक संख्या) के साथ आगे बढ़ें, `enter` के साथ पुष्टि करें, पिछले पर वापस जाएं
`←` या `esc` के साथ प्रश्न करें, `ctrl+c` के साथ छोड़ें।

| प्रश्न | विकल्प |
|---|---|
| आयात उपनाम | `@` (`@/components/...` `src/` को इंगित करता है), या कोई अन्य उपसर्ग जैसे `~` या `#app` |
| शैली | टेलविंड सीएसएस, यूनोसीएसएस, वेनिला सीएसएस, अन्य (कोई सीएसएस उपकरण नहीं, वेनिला के समान सादा स्टाइलशीट) |
| ORM | SQLModel, SQLAlchemy, Tortoise-ORM, कोई डेटाबेस नहीं |
| डेटाबेस (एक ORM के साथ) | SQLite, PostgreSQL, नियॉन, MySQL / MariaDB, अन्य (आप URL टाइप करें) |

चुने गए ORM के लिए डेटाबेस ड्राइवर इसके साथ स्थापित है (`psycopg`, `pymysql`, `asyncpg` या
`aiomysql`), और यूआरएल `.env` पर लिखा गया है।

पैकेज स्थापित करने से पहले, `nx new` कनेक्शन की जाँच करता है। इसके बिना, यह इंस्टॉल को छोड़ देता है और
आपको `uv sync` चलाने और आपके पैकेज मैनेजर को बाद में इंस्टॉल करने के लिए कहता है। एक के साथ, यह प्रिंट करता है
विलंबता और डाउनलोड गति, और कनेक्शन धीमा होने पर चेतावनी देता है (400 एमएस से अधिक या उससे कम)।
100 केबी/एस)। उदाहरण के लिए, प्रत्येक इंस्टॉल लाइन टूल और उसके द्वारा भरे जाने वाले फ़ोल्डर को नाम देती है
`pnpm install node_modules` या `uv sync .venv`।

## क्या `dev`, `build` और `start` बनाते हैं

चलने से पहले, तीन कमांड `src/` और प्रत्येक फ़ोल्डर में एक खाली `__init__.py` बनाते हैं
इसके अंतर्गत एक `.py` या `.nexy` फ़ाइल होती है, इसलिए `src/routes/users.py` जैसा मार्ग आयात करता है
उन सभी में एक ही तरह से. मौजूदा फ़ाइलों को कभी नहीं छुआ जाता है, और `nx dev` जब भी दोबारा ऐसा करता है
आप एक फ़ोल्डर जोड़ें. पायथन बाइटकोड `__nexy__/__pycache__` पर जाता है, इसलिए कोई `__pycache__` फ़ोल्डर नहीं
आपके स्रोतों के बगल में दिखाई देता है.

## भाषा

कमांड लाइन अंग्रेजी, चीनी, हिंदी, स्पेनिश, पुर्तगाली, फ्रेंच, जर्मन, जापानी, बोलती है
रूसी, कोरियाई, इंडोनेशियाई और अरबी। यह इनमें से पहले का उपयोग करता है जिसका वह समर्थन करता है:

1. `NEXY_LANG` पर्यावरण चर (`NEXY_LANG=ja nx dev`);
2. आपके शेल के स्थानीय चर (`LC_ALL`, `LC_MESSAGES`, `LANG`, फिर `LANGUAGE`);
3. आपके ऑपरेटिंग सिस्टम की भाषा।

बाकी सभी चीजें अंग्रेजी हैं, और ऐसा कोई भी संदेश जो किसी भाषा में अभी तक नहीं है। केवल क्या `nx`
प्रिंट्स का अनुवाद किया गया है: कंपाइलर त्रुटियां, ट्रेसबैक और इसके द्वारा चलाए जाने वाले टूल का आउटपुट वैसे ही रहता है
हैं. अनुवादों की अभी तक देशी वक्ताओं द्वारा समीक्षा नहीं की गई है:
`nexy/modules/i18n/<language>.json` पर पुल अनुरोध के रूप में सुधारों का स्वागत है।

## व्यवहार बनाएं

`nx build` मार्गों को संकलित करता है, फिर `useVite` चालू होने पर क्लाइंट को बंडल करता है।

> [!नोट]
> कोई `--static` झंडा नहीं है। स्टेटिक होस्टिंग एक परिनियोजन विकल्प है, निर्माण नहीं
> मोड - देखें [तैनाती](../deployment/README.md)।

## नेक्सी पर ही काम कर रहा हूं

इस भंडार के अंदर द्वार हैं:

```bash
python scripts/verify.py             # lint, format, typecheck, tests
python scripts/audit_dependencies.py # supply-chain audit against the lock
```
