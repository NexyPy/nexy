# दृश्य

फ़ाइल प्रारूप चुनने से पहले, यह अंतर करना महत्वपूर्ण है कि नेक्सी संसाधनों को कैसे संभालती है और उन्हें कैसे प्रस्तुत करती है।

| शब्द | परिभाषा |
|---|---|
| **पेज** | एप्लिकेशन का एक यूआरएल-एड्रेसेबल संसाधन। इसे `src/routes/` के अंतर्गत एक फ़ाइल द्वारा परिभाषित किया गया है। |
| **देखें** | एक पृष्ठ के लिए प्रतिक्रिया निकाय तैयार करने की प्रक्रिया। एक दृश्य तर्क और डेटा को HTML या JSON में बदल देता है। |
| **घटक** | एक पुन: प्रयोज्य यूआई बिल्डिंग ब्लॉक का उपयोग दृश्य बनाने के लिए किया जाता है। घटक मूल नेक्सी सहायक या फ्रेमवर्क-विशिष्ट (रिएक्ट, वीयू, आदि) हो सकते हैं। |
| **रूट हैंडलर** | एक पायथन फ़ंक्शन जो एक विशिष्ट विधि के लिए HTTP अनुरोध को संभालता है (उदाहरण के लिए, `GET`, `POST`)। |
| **एंडपॉइंट** | एक यूआरएल और एक HTTP विधि का अनूठा संयोजन जो एक रूट हैंडलर उत्तर देता है। |

**निश्चित नहीं? एक `.nexy` फ़ाइल लिखें। ** इसके लिए किसी क्लाइंट फ्रेमवर्क की आवश्यकता नहीं है, और आप बाद में एक द्वीप के रूप में इसके अंदर एक रिएक्ट, व्यू, स्वेल्ट, सॉलिड या प्रीएक्ट घटक जोड़ सकते हैं।

```diagram filename="किस पेज के लिए कौन सी फ़ाइल"
server logic + HTML          →  .nexy      (Python frontmatter + Jinja2)
prose that changes rarely    →  .md        (GitHub-flavoured Markdown)
prose + components           →  .mdx       (React or Preact)
app-like page, client router →  .tsx .vue .svelte (framework files)
API handler                  →  .py        (GET, POST, …)
```

## प्रारूप

| प्रारूप | फ़ाइल | सर्वर रेंडर | क्लाइंट फ्रेमवर्क | नोट्स |
|---|---|---|---|---|
| `.nexy` | [.नेक्सी फ़ाइलें](nexy/README.md) | जिंजा2 + पायथन लॉजिक, स्ट्रीम किया गया | वैकल्पिक | नेटिव नेक्सी पेज प्रारूप |
| `.md` | [मार्कडाउन और एमडीएक्स](nexy/markdown.md) | अनुरोध समय पर सीएमआरकेजीएफएम | लेआउट के माध्यम से वैकल्पिक | शुद्ध मार्कडाउन, जीएफएम, लेआउट-लिपटे |
| `.mdx` | [मार्कडाउन और एमडीएक्स](nexy/markdown.md) | फ्रेमवर्क एसएसआर | रिएक्ट या प्रीएक्ट | घटकों के साथ मार्कडाउन |
| `.tsx` | [रिएक्ट](react/differences.md), [सॉलिड](solid/differences.md) या [प्रीएक्ट](preact/differences.md) | क्लाइंट मोड: फ्रेमवर्क, नोड में रेंडर किया गया | रिएक्ट, सॉलिड या प्रीएक्ट | कंपोनेंट रूट्स |
| `.vue` | [Vue](vue/differences.md) | क्लाइंट मोड: फ्रेमवर्क, नोड में प्रस्तुत किया गया | Vue | SFC मार्ग |
| `.svelte` | [स्वेल्टे](svelte/differences.md) | क्लाइंट मोड: फ्रेमवर्क, नोड में प्रस्तुत किया गया | स्वेल्टे | एसएफसी मार्ग |

अंतर्निहित `Image`, `Link`, `Audio`, `Video` और `Import` सहायक: [घटक](nexy/components.md)।

## प्रारूपों का मिश्रण

आप एक ही प्रोजेक्ट में विभिन्न तकनीकों को मिला सकते हैं:
- **द्वीप**: आप `.nexy` पेज के अंदर एक रिएक्ट या व्यू घटक आयात कर सकते हैं। सर्वर शेल को प्रस्तुत करता है, और फ्रेमवर्क क्लाइंट पर घटक को हाइड्रेट करता है।
- **साझा तर्क**: `.py` फ़ाइलों में रूट हैंडलर साझा एप्लिकेशन स्थिति या एपीआई कॉल के माध्यम से किसी भी प्रारूप में पृष्ठों को डेटा प्रदान कर सकते हैं।

## एक रूपरेखा सक्षम करें

`nexyconfig.py` में `useFF` सेट करें और निर्भरताएँ जोड़ने के लिए `nexy new` चलाएँ:

```python filename="nexyconfig.py"
from nexy.core.models import NexyConfigModel
from nexy.frontend import react


class NexyConfig(NexyConfigModel):
    useFF = react()
```

फ़्रेमवर्क सक्षम होने पर, Vite अपने क्लाइंट बंडलों को संभालता है। क्लाइंट मोड में इसके एक्सटेंशन बन जाते हैं
मार्ग; सर्वर मोड में वही फ़ाइलें घटक हैं जिन्हें आप द्वीपों के रूप में आयात करते हैं - एक फ़्रेमवर्क फ़ाइल के अंतर्गत
`src/routes/` को वहां खारिज कर दिया गया है। [सर्वर मोड और क्लाइंट मोड](../routing/fbr/modes.md) देखें।

> [!नोट]
> [सीएसआर](../rendering/csr.md) मोड में, केवल फ्रेमवर्क रूट फ़ाइलें ही नेविगेशन योग्य हैं
> क्लाइंट-साइड।
