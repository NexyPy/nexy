# Markdown और MDX

सामग्री पृष्ठों के लिए दो प्रारूप: `.md` जब आपको केवल Markdown की आवश्यकता होती है, `.mdx` जब आपको घटकों की आवश्यकता होती है।

## `.md`: शुद्ध Markdown

एक `.md` फ़ाइल शुद्ध सामग्री है। नेक्सी इसे `cmarkgfm` (जीएफएम) के साथ प्रस्तुत करता है, शीर्षक आईडी जोड़ता है, सामग्री की एक तालिका प्राप्त करता है, और इसे निकटतम `layout.*` में लपेटता है।

```md filename="src/routes/about.md"
# About

Nexy is a fullstack Python meta-framework.
```

- `.md` में फ्रंटमैटर का उपयोग Python तर्क के रूप में नहीं किया जाता है। यदि आपको सर्वर तर्क की आवश्यकता है, तो `.nexy` का उपयोग करें।
- लेआउट रैपिंग, त्रुटि पृष्ठ और डायनामिक सेगमेंट अन्य पृष्ठों की तरह ही काम करते हैं।

## `.mdx`: Markdown घटकों के साथ

`.mdx` फ़ाइलें **Vite**, फ्रेमवर्क रूट पाइपलाइन (React या Preact) के माध्यम से संकलित की जाती हैं। Python केवल पतला आवरण लिखता है जो मार्ग का कार्य करता है; यह कभी भी स्वयं को संकलित या प्रस्तुत नहीं करता है MDX। घटकों को फ्रेमवर्क द्वारा प्रस्तुत किया जाता है, अन्य घटक मार्गों की तरह सर्वर-रेंडर किया जाता है, और `nx build` द्वारा HTML में पूर्व-रेंडर किया जाता है।

- `useFF` का React या Preact होना आवश्यक है।
- निर्माण के लिए वैकल्पिक पैकेज `@mdx-js/rollup`, `remark-gfm` और `@mdx-js/react` (और `@mdx-js/esbuild`) की आवश्यकता है। Vite आपको बताता है कि कौन सा गायब है।
- फ़्रेमवर्क को आयात से स्वतः पता लगाया जाता है: Preact जब फ़ाइल आयात होती है `preact`, React अन्यथा।

> [!NOTE]
> यदि आपको फ्रंटमैटर में Python तर्क की आवश्यकता है तो `.nexy` का उपयोग करें।
