# 建筑

## 定义

Nexy 有五层，每一层都有其他人不做的工作。了解边界可以回答大多数“为什么它会这样工作”的问题：缓慢的页面是渲染器问题，错误的页面是路由器问题，从未出现的页面是客户端问题。

此页面供编写应用程序的人员使用。 Nexy 本身的包及其背后的机制在存储库根目录的 `ARCHITECTURE.md` 中为贡献者进行了描述。

## 各层

```diagram filename="一个请求，五层"
Browser
   │
   ▼
Uvicorn ───── ASGI transport
   │
   ▼
Middleware ── sessions, CORS, gzip, trusted hosts, your own
   │
   ▼
Router ────── FBR | Modular | Custom ── picks the file that answers
   │
   ▼
Renderer ──── HTML (Jinja2, Markdown, Node) or JSON
   │
   ▼
Response
```

| 层 | 责任 | 不 |
|---|---|---|
| Uvicorn | 接受连接，讲 ASGI | 知道页面是什么 |
| 中间件 | 装饰请求：会话、CORS、gzip、可信主机、HTTPS 重定向、您的 | 选择路由 |
| 路由器 | 将 URL 与文件及其布局、依赖项和错误页面 | 匹配，生成内容 |
| 渲染器 | 运行页面并将其结果转换为 HTML 或 JSON | 获取您的数据 |
| 客户端 | Vite 和你的框架：捆绑、水合作用、客户端导航 | 应答服务器请求 |

## 谁建造什么

| 演员 | 拥有 | 不拥有 |
|---|---|---|
| Nexy | 路由、服务器渲染、操作、`.nexy` 编译、同源 | 组件、反应性、数据 |
| Vite | 客户端捆绑包、开发服务器、热重载 | 路由、服务器渲染、操作 |
| 您的框架 | 组件、反应性、生态系统 | 路由、文档（Nexy 询问其布局）|
| 您的应用程序 | 数据、身份验证、授权、业务规则 | 传输、渲染 |

表背后的规则：**Nexy 构建它拥有的内容，并且从不编译 Vite 编译的内容。** 对于组件路由，Python 编写指向该文件的瘦包装模块。

## 决定请求的地方

1. 中间件运行，并且可能会更改请求或停止它。
2. 路由器选择一个文件及其周围的布局。
3. 渲染器使用它自己读取的数据运行该文件。
4. 响应返回，如果页面有 JavaScript，则客户端层接管。

每个步骤，以及路由器之间的确切优先级和 `nx dev` 的顺序，都在 [Nexy 的工作原理 ](getting-started/how-nexy-works.md) 中。本页不再重复。

## 开发生产

相同的五层，组装两次：

| 图层 | `nx dev` | `nx build` 然后 `nx start` |
|---|---|---|
| 编译器 | 在您保存 | 时运行，提前 | 运行一次
| Vite | 开发服务器，热重载，通过 Nexy 的源代理 | 捆绑包写入 `__nexy__/client/`，无开发服务器 |
| 节点 | 按需渲染客户端文档 | 在构建时渲染它们，而不是在服务时渲染它们 |
| 观察者 | 在更改 | 缺席 | 时重新启动 uvicorn
| 始发地 | 一个端口 | 一个端口 |

改变的是工作“何时”发生，而不是“谁”做。两者之间行为不同的页面是页面中的错误，而不是模式的属性。

## 边界

Nexy 故意停在您的应用程序边缘：

| 关注 | Nexy 提供什么 | 你写什么 |
|---|---|---|
| 身份验证 | 会话中间件，`AuthenticationMiddleware` 启用后 | 登录、用户查找、cookie 策略 |
| 授权 | `dependencies.py`、防护、每个文件夹继承 | 规则本身 |
| 数据库 | 没有：没有 ORM，没有迁移 | 模型层 ([数据库](guides/databases.md)) |
| 国际化 | 您的页面没有任何内容；仅 CLI 被翻译 | 库和消息 ([i18n](guides/i18n.md)) |
| 后台作业 | 没有：没有队列，没有调度程序 | 工作进程 |
| 电子邮件、付款、搜索 | 无 | 您选择的服务 |

对于所有六个来说，原因都是相同的：选择 ORM 或身份验证库的框架决定只有您的应用程序才能决定的事情。成本是明确的：没有任何东西可以为您接线，上面的指南页面说明了每个插头的插入位置。
