# SSR（服务器渲染）

## 定义

SSR 是默认设置：服务器针对每个请求将页面呈现为 HTML。没有什么能够实现它，并且
没有标志将其关闭 - 服务器模式项目会在每个请求上呈现，除非页面声明
`revalidate`。

## 它是如何工作的

| 路由文件 | 生成 HTML 的条件 | 何时 |
|---|---|---|
| `.nexy` | 编译后的Python模块，通过Jinja2 |每个请求|
| `.md` | `cmarkgfm`，则每个请求的最近布局 | |
| `.mdx`、`.tsx`、`.vue`、`.svelte` | 框架，当路由没有布局时在构建时在 Node | 中渲染，否则在浏览器中渲染 |
| `.py` | 什么也没有：它返回 JSON 或 `Response` | - |

组件路由是需要第二句话的一种情况。在生产中，组件路线
**没有**布局由构建时生成的 HTML 提供，并且组件将其水化。与
布局，或者在开发中，容器是空的并且组件在浏览器中呈现 -
那么页面就是一个自我填充的外壳。

## 渲染生命周期

1. 请求到达基于文件的路由器。路径匹配，动态段被转换为
   组件声明的类型。
2. 该组件运行。等待节点（客户端文档）的一个在线程池中运行，因此它
   不会停止事件循环。
3. 正文作为`text/html`进行流式传输。生成块的组件在生成时流式传输它们
   他们。
4. 浏览器接收 HTML。岛屿根据其[指令](islands.md)进行水合。

当项目有一个错误时，`errors.nexy` 将渲染时引发的错误转换为页面：请参阅
[错误页面](../routing/fbr/errors/README.md)。

## 何时使用

- 该页面显示读者拥有的东西：会话、帐户、购物车。
- 每次加载时数据都必须是最新的。
- 对于不运行 JavaScript 的爬网程序，内容必须位于 HTML 中。
- 该页面的渲染成本很低：一个查询，一个模板。

## 配置

没有。有两种出路，而且它们的粒度不同：

| 将 SSR 留给 | 执行此操作 | 谷物 |
|---|---|---|
| 一页，其前面有一个缓存 | `revalidate = 60` → [ISR](isr.md) | 页 |
| 整个项目，客户端路由 | `useCSR = True` 在 `nexyconfig.py` → [CSR](csr.md) | 项目 |

## 示例

```nexy filename="src/routes/blog/[slug].nexy"
---
slug: prop[str] = "untitled"
---
<h1>{{ slug }}</h1>
```

`GET /blog/hello` 运行此模板一次，并将 `slug` 设置为 `hello`。第二个请求运行它
再次强调：两人之间没有任何保留。查询字符串不是一个 prop - 用钩子读取它
[导航](../routing/fbr/navigation/hooks.md)。

## 局限性

- **每个请求一次渲染。**同一秒内的两个访问者分别为渲染和渲染付费
  其背后的查询。
- **没有缓存。**没有要预热的共享响应缓存：[ISR](isr.md)为每个 URL 添加一个。
- **流式传输仅帮助产生收益的组件。**页面顶部的缓慢查询仍然会延迟
  第一个字节。
- **没有静态输出。**在服务器模式下，构建时没有任何内容被冻结：没有 SSG 模式，也没有
  导出命令。请参阅[渲染](README.md)。
- **`.nexy` 模板中的自动转义已关闭**。使用 `| e` 转义不受信任的值。
