# ISR (باسی-جب کہ-دوبارہ جائز)

## تعریف

ISR فی یو آر ایل، ایک صفحے کے HTML کو کیش کرتا ہے، اور اس کی ونڈو کی میعاد ختم ہونے تک اسے پیش کرتا ہے۔ میعاد ختم ہونے والی کاپی اب بھی پیش کی جاتی ہے جب کہ پس منظر میں ایک نئی پیش کی جاتی ہے: وہ ہے *Stale-while-Revalidate*۔

## یہ کیسے کام کرتا ہے۔

ایک `.nexy` صفحہ کے فرنٹ میٹر میں `revalidate = N` اسے آن کر دیتا ہے۔ `N` سیکنڈ کا ایک عدد ہے۔ ایک غائب، صفر یا منفی قدر کا مطلب ہے کہ کوئی کیش بالکل نہیں ہے۔

کیشے کی کلید صرف **درخواست کا راستہ ہے** - `request.scope["path"]`۔ استفسار کی تار اس کا حصہ نہیں ہے۔

| کیا | قدر |
|---|---|
| چابی | URL کا راستہ (`/blog/hello`) |
| ذخیرہ | منتخب کردہ بذریعہ `useISRCache`: میموری بذریعہ ڈیفالٹ، فائل، ریڈیس، یا حسب ضرورت اسٹور |
| پابند | میموری اسٹور کے لیے 256 اندراجات، کم از کم حال ہی میں استعمال شدہ بے دخل؛ فائل اور ریڈیس اندراجات کو اس وقت تک برقرار رکھتے ہیں جب تک کہ باطل نہ ہوجائے |
| رسپانس ہیڈر | `cache-control: public, s-maxage=N, stale-while-revalidate=N` |

ہر ISR جواب میں وہ ہیڈر ہوتا ہے، بشمول اسٹور کے بند ہونے پر پہلا رینڈر اور فال بیک رینڈر۔ ایک CDN اسے اسی عوامی URL کی اپنی کاپی رکھنے کے لیے استعمال کر سکتا ہے۔

## رینڈرنگ لائف سائیکل

1. ایک ایسے صفحے کے لیے درخواست آتی ہے جو کہ `revalidate` کا اعلان کرتا ہے۔
2. ابھی تک کوئی اندراج نہیں: صفحہ پیش کیا گیا، ذخیرہ کیا گیا اور واپس کر دیا گیا۔
3. `N` سیکنڈ سے چھوٹی اندراج: جیسا ہے واپس کیا گیا، صفحہ رینڈر نہیں کیا گیا ہے۔
4. `N` سیکنڈ سے زیادہ پرانا اندراج: **باسی** اندراج کو فوری طور پر واپس کر دیا جاتا ہے، اور ایک پس منظر کا کام ایک تازہ پیش کرتا ہے۔
5. اگر وہ بیک گراؤنڈ رینڈر ناکام ہوجاتا ہے تو، باسی اندراج برقرار رہتا ہے اور اگلی باسی درخواست دوبارہ کوشش کرتی ہے۔
6. اگر اسٹور ناکام ہوجاتا ہے، تو صفحہ رینڈر کیا جاتا ہے اور بغیر کیش شدہ اندراج کے واپس کردیا جاتا ہے۔ درخواست اب بھی کامیاب ہے۔

## کب استعمال کرنا ہے۔

- ہر آنے والے کے لیے ایک ہی HTML: ایک بلاگ پوسٹ، ایک پروڈکٹ کا صفحہ، ایک دستاویزی صفحہ۔
- صفحہ اکثر پڑھا جاتا ہے اور شاذ و نادر ہی تبدیل ہوتا ہے۔
- ڈیٹا چند سیکنڈ پرانا ہو سکتا ہے بغیر کسی کے نوٹس کیے۔

## کنفیگریشن

```nexy filename="src/routes/blog/index.nexy"
---
revalidate = 60
---
<h1>Rendered at most once per minute</h1>
```

`N` ایک سادہ عدد ہے۔ کسی اور جگہ کوئی فی روٹ اوور رائڈ نہیں ہے، اور `.py` ہینڈلرز صفحات نہیں ہیں: وہ کبھی بھی اس کیش میں داخل نہیں ہوتے ہیں۔

## ایک اسٹور کا انتخاب کریں۔

`nexyconfig.py` میں `useISRCache` سیٹ کریں:

```python filename="nexyconfig.py"
from nexy.core.models import NexyConfigModel


class NexyConfig(NexyConfigModel):
    useISRCache = "file"
```

| قدر | اسٹور | کے ذریعہ اشتراک کردہ |
|---|---|---|
| سیٹ نہیں، `None`، یا `"memory"` | پروسیس میموری، 256 اندراجات تک محدود | ایک کارکن |
| `"file"` | `.nexy/isr` میں JSON فائلیں | ایک میزبان پر کارکنان |
| `{"type": "file", "directory": ".cache/isr"}` | دی گئی ڈائرکٹری میں JSON فائلیں۔ | ایک میزبان پر کارکنان |
| `"redis"` | Redis at `redis://localhost:6379/0` | کوئی بھی کارکن جو سرور تک پہنچتا ہے۔ |
| `{"type": "redis", "url": "redis://cache:6379/0"}` | اس URL پر دوبارہ کریں۔ | کوئی بھی کارکن جو سرور تک پہنچتا ہے۔ |
| `{"type": "redis", "client": client}` | Redis کلائنٹ جسے آپ پاس کرتے ہیں۔ | کوئی بھی کارکن جو سرور تک پہنچتا ہے۔ |
| `get`، `set` اور `invalidate` والی چیز | آپ کی اپنی دکان | جو کچھ بھی شیئر کرتا ہے۔ |

ریڈیس اسٹور کو کلائنٹ پیکج کی ضرورت ہے: `uv add redis`۔ یہ Nexy کے ساتھ انسٹال نہیں ہے۔ ایک کسٹم اسٹور `ISRCache` پروٹوکول کو `nexy.modules.runtime.cache` سے نافذ کرتا ہے۔ اس کا `get` ایک `CacheEntry` یا `None` لوٹاتا ہے۔

فائل کے اندراجات جوہری طور پر لکھے جاتے ہیں، لہذا ایک کارکن کبھی بھی آدھا لکھا ہوا صفحہ نہیں پڑھتا ہے۔ ورکرز جو ایک ہی ڈائرکٹری یا وہی Redis سرور استعمال کرتے ہیں وہی اندراج پڑھتے ہیں۔ ایک ٹوٹا ہوا اسٹور صرف ایک رینڈر کی لاگت کرتا ہے: یہ کبھی بھی غلطی کے ساتھ درخواست کا جواب نہیں دیتا ہے۔

## مثال

ایک بلاگ پوسٹ جو ڈیٹا بیس کو پڑھتی ہے:

```nexy filename="src/routes/blog/[slug].nexy"
---
revalidate = 300
slug: prop[str] = "untitled"
posts = {"hello": {"title": "Hello"}, "other": {"title": "Other"}}
post = posts.get(slug, {"title": "Untitled"})
---
<h1>{{ post.title }}</h1>
```

پہلی درخواست `/blog/hello` رینڈرز اور اسٹورز۔ اگلے 300 سیکنڈز منتخب اسٹور سے پیش کیے جاتے ہیں۔ `/blog/other` ایک الگ اندراج ہے، جو اپنے طور پر پیش اور ذخیرہ کیا گیا ہے۔ ایک حقیقی پروجیکٹ میں `posts` ڈیٹا بیس یا سروس سے آتا ہے، جسے ایک بار فی تخلیق نو کہا جاتا ہے۔

## CDN کیا شئیر کر سکتا ہے اور کیا نہیں کر سکتا

ایک CDN جو `cache-control` کا احترام کرتا ہے وہ `/blog/hello` کی ایک کاپی کو `s-maxage` سیکنڈ کے لیے رکھ سکتا ہے اور اسے دوبارہ درست ہونے تک پیش کر سکتا ہے۔ یہ اس کاپی کو زائرین اور کارکنوں کے درمیان شیئر کرتا ہے کیونکہ جواب کہتا ہے `public`۔

ایک CDN Nexy اسٹور کو نہیں جانتا ہے۔ `revalidate()` ایک [ایکشن](../guides/actions.md) میں کنفیگرڈ Nexy اسٹور سے اندراج کو ہٹاتا ہے، لیکن یہ CDN کو صاف نہیں کرتا ہے۔ CDN اس کی کاپی اس وقت تک رکھتا ہے جب تک کہ اس کی اپنی ونڈو ختم نہ ہو جائے، یا جب تک کہ آپ اسے صاف نہ کر لیں۔

سی ڈی این کو ایسا صفحہ نہ دیں جس کا ایچ ٹی ایم ایل وزیٹر پر منحصر ہو۔ جواب کہتا ہے `public`، اور Nexy کی کلید اکیلے راستہ ہے: ایک راستے پر دو استفسار کے تار ایک اندراج کا اشتراک کرتے ہیں۔ ایچ ٹی ایم ایل میں ایک سیشن، ایک کوکی، یا صارف کی شناخت کسی دوسرے وزیٹر کو پیش کی جا سکتی ہے۔

## حدود

**Nexy ضمانت دیتا ہے** cache کلید راستہ ہے، باسی کاپی تخلیق نو کے دوران پیش کی جاتی ہے، اور سٹور کی ناکامی رینڈر پر واپس آتی ہے۔

**کنونشن کے مطابق**، ایک صفحہ جو اعلان کرتا ہے کہ `revalidate` عوامی مواد ہے۔ اسے اس طرح لکھیں جیسے ہر آنے والا ایک ہی HTML دیکھتا ہے۔

**آپ کی درخواست** باقی تمام چیزوں کے لیے ذمہ دار ہے:

| حد | اس کا کیا مطلب ہے۔ |
|---|---|
| استفسار کی تار کو نظر انداز کر دیا گیا۔ | `/search?q=a` اور `/search?q=b` ایک اندراج کا اشتراک کرتے ہیں۔ تلاش کے صفحے کو کیش نہ کریں۔ |
| سیشن الگ تھلگ نہیں ہے۔ | جواب میں کہا گیا ہے `public`، اور پہلے وزیٹر کا HTML سب کو پیش کیا جاتا ہے۔ سیشن کو کسی صفحہ میں `revalidate` کے ساتھ کبھی نہ پڑھیں۔ |
| CDN صاف نہیں ہوا۔ | `revalidate()` Nexy اسٹور کو صاف کرتا ہے، نہ کہ CDN یا اس کے سامنے کوئی اور پراکسی۔ |
| فائل اور Redis اسٹورز میں کوئی TTL نہیں ہے۔ | اندراجات اس وقت تک رہتی ہیں جب تک کہ `revalidate()` یا آپ کی اپنی صفائی انہیں ہٹا نہیں دیتی۔ میموری اسٹور 256 کے بعد سب سے کم استعمال شدہ اندراج کو بے دخل کرتا ہے۔ |
| بیک وقت تخلیق نو | کچھ بھی ان کی نقل نہیں کرتا: دس باسی درخواستیں دس رینڈرز شروع کر سکتی ہیں۔ |
| غلطیاں خاموش ہیں۔ | ایک ناکام تخلیق نو یا اسٹور آپریشن صفحہ کی خدمت کرتا رہتا ہے۔ ناکامی واپس نہیں ہے. |
