# CSR (کلائنٹ سائیڈ رینڈرنگ)

## تعریف

سی ایس آر براؤزر کو نیویگیشن کے حوالے کرتا ہے: پہلی دستاویز کے بعد، صفحات کے درمیان منتقل ہونے سے سرور سے ایچ ٹی ایم ایل کا مطالبہ نہیں ہوتا ہے۔ Nexy میں یہ ایک **پروجیکٹ** کا فیصلہ ہے، ایک صفحہ نہیں - `useCSR = True` پوری ایپلیکیشن کو کلائنٹ روٹڈ کر دیتا ہے۔

## یہ کیسے کام کرتا ہے۔

```python filename="nexyconfig.py"
from nexy.core.models import NexyConfigModel
from nexy.frontend import react


class NexyConfig(NexyConfigModel):
    useFF = react()
    useCSR = True
```

پروجیکٹ پھر شکل بدلتا ہے:

| | سرور موڈ (`False`) | کلائنٹ موڈ (`True`) |
|---|---|---|
| راستے | `.nexy`، `.md`، `.mdx` | `.tsx`، `.jsx`، `.vue`، `.svelte` |
| دستاویز | `layout.nexy` | جڑ `layout.tsx` / `.vue` / `.svelte` کا مالک ہے `<html>`، `<head>`، `<body>` |
| کلائنٹ کے اجزاء | ایک صفحے کے اندر جزیرے۔ | صفحات خود |
| `.nexy` کے تحت `src/routes/` | صفحہ کی شکل | `nx dev`، `nx start` اور `nx build` سے پہلے مسترد |
| نیویگیشن | فی لنک ایک مکمل درخواست | کلائنٹ راؤٹر |

`.md` اور `.mdx` درست رہتے ہیں: Nexy انہیں کلائنٹ لے آؤٹ کے اندر سرور پر رینڈر کرتا ہے، اور کلائنٹ راؤٹر وہاں سے سنبھال لیتا ہے۔ `.py` ہینڈلر راستوں کے پاس بیٹھتے ہیں اور FastAPI کے ذریعہ خدمت کی جاتی ہے۔

## رینڈرنگ لائف سائیکل

1. درخواست فائل پر مبنی روٹر تک پہنچ جاتی ہے، جو مماثل روٹ اور اس کی ترتیب کو تلاش کرتا ہے۔
2. روٹ لے آؤٹ نوڈ میں **پوری دستاویز** کو پیش کرتا ہے - پہلا جواب پہلے سے ہی اصلی `<html>` رکھتا ہے، خالی خول نہیں۔
3. Nexy کلائنٹ کے اثاثوں کو انجیکشن کرتا ہے اور `</body>` سے پہلے صفحہ کی JSON تفصیل۔
4. براؤزر اس دستاویز کو ہائیڈریٹ کرتا ہے۔ نیسٹڈ لے آؤٹ تب سے اپنی حالت برقرار رکھتے ہیں۔
5. دوسرے روٹ کا لنک کلائنٹ روٹر کے ذریعے ہینڈل کیا جاتا ہے: کوئی دستاویز کی درخواست نہیں، صفحہ براؤزر میں پیش کیا جاتا ہے۔

ڈویلپمنٹ میں دستاویز کو Vite دیو سرور کی مانگ پر پیش کیا جاتا ہے۔ پروڈکشن میں یہ تعمیر کے وقت ایک بار پیش کیا جاتا ہے: ایک جامد راستہ اپنا دستاویز حاصل کرتا ہے، ایک متحرک راستے کو ایک اعلان کردہ جامد پیرم، یا ایک شیل ملتا ہے - خالی صفحے کے ارد گرد کی ترتیب - جب یہ کسی کا اعلان نہیں کرتا ہے۔

## کب استعمال کرنا ہے۔

- ڈیش بورڈز، ایڈیٹرز، کوئی بھی چیز جو ایپلیکیشن کی طرح برتاؤ کرتی ہے۔
- ایک Python API جس کے اوپر کلائنٹ ایپلیکیشن ہے۔
- ایک صفحہ جہاں ہر تعامل مقامی ہے اور ایک راؤنڈ ٹرپ محسوس کیا جائے گا۔

## کنفیگریشن

| ترتیب | قدر |
|---|---|
| `useFF` | مطلوبہ: `useCSR` کلائنٹ فریم ورک کے بغیر مسترد کر دیا جاتا ہے۔ |
| `useCSR` | `True` |
| `useRouter` | بند رہنا چاہیے: ماڈیولر روٹر کلائنٹ موڈ میں مسترد کر دیا گیا ہے۔ |

`_` یا `.` سے شروع ہونے والی فائلوں اور فولڈرز کو ان چیکس کے ذریعے نظر انداز کر دیا جاتا ہے۔

## مثال

```tsx filename="src/routes/layout.tsx"
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <head><title>My app</title></head>
      <body>{children}</body>
    </html>
  )
}
```

```tsx filename="src/routes/index.tsx"
export default function Home() {
  return <h1>Home</h1>
}
```

## ایک متحرک راستہ پہلے سے پیش کریں۔

ایک متحرک راستہ جیسا کہ `src/routes/blog/[slug].tsx` کسی بھی قدر سے میل کھاتا ہے، اس لیے بلڈ یہ نہیں جان سکتی کہ کون سے صفحات پیش کیے جائیں۔ ان کی فہرست بنانے کے لیے صفحہ سے `generateStaticParams()` برآمد کریں: `nexy build` فی اندراج ایک مکمل دستاویز پیش کرتا ہے، اور `nexy start` اس راستے کے لیے کام کرتا ہے۔ Next.js نام `getStaticPaths` اور `getStaticParams` بھی قبول ہیں، اور فعل `async` ہوسکتا ہے۔

```tsx filename="src/routes/blog/[slug].tsx"
export async function generateStaticParams() {
  return [{ slug: "hello" }, { slug: "world" }]
}

export default function Post({ slug }: { slug: string }) {
  return <h1>{slug}</h1>
}
```

ہر اندراج params کی ایک چیز ہے، یا `{ params: {...} }` جیسا کہ `getStaticPaths` انہیں واپس کرتا ہے۔ تعمیر لکھتے ہیں:

| فائل میں `__nexy__/client/static/` | کے لیے پیش کیا گیا۔ |
|---|---|
| `src/routes/blog/[slug]/blog/hello.html` | `/blog/hello` |
| `src/routes/blog/[slug]/blog/world.html` | `/blog/world` |
| `src/routes/blog/[slug].shell.html` | کوئی اور `/blog/...` |

ایک راستہ جس کا نام فہرست میں نہیں ہے وہ اب بھی کام کرتا ہے: اسے شیل ملتا ہے، خالی صفحے کے ارد گرد کی ترتیب، اور براؤزر کے چلنے کے بعد صفحہ ظاہر ہوتا ہے۔ `nexy dev` میں ہر راستہ مانگ کے مطابق پیش کیا گیا ہے، درج ہے یا نہیں۔

## حدود

- **پوری پروجیکٹ** آپ سرور موڈ پروجیکٹ میں ایک سی ایس آر صفحہ نہیں ملا سکتے: ایپلیکیشن کے لیے موڈ چنیں، پھر سرور موڈ پیج کے انٹرایکٹو حصوں کے لیے [جزیروں](islands.md) کا استعمال کریں۔
- **نہیں `.nexy` راستے** جو کچھ بھی آپ نے `.nexy` میں لکھا ہے اسے فریم ورک کا جزو بننا چاہیے۔
- **سرور کا ڈیٹا گزرتا ہے۔ اختتامی پوائنٹس** کلائنٹ کا راستہ رینڈر کے وقت ڈیٹا بیس کو نہیں پڑھ سکتا۔ اسے `.py` ہینڈلر یا [ایکشن](../guides/actions.md) کہتے ہیں۔
- **ایک متحرک راستہ شیل سے شروع ہوتا ہے جب تک کہ اس کی فہرست نہ ہو۔ params** دیکھیں [ایک متحرک راستہ پہلے سے پیش کریں](#pre-render-a-dynamic-route)۔
- **CSR ایک خالی صفحہ نہیں ہے اور نہ ہی SPA۔** پہلی دستاویز سرور کے ذریعہ پیش کی گئی ہے۔ یہ نیویگیشن ہے جو براؤزر میں ہوتی ہے۔
