# میں Nexy رجسٹری میں ماڈیول کیسے شائع کروں؟

ماڈیول ڈائرکٹری سے `nx publish` کو ایک درست `nx.toml`، ایک رجسٹری ٹوکن، اور ہر فائل کے ساتھ چلائیں جس کا مینی فیسٹ اعلان کرتا ہے۔ کمانڈ ریلیز کو چیک کرتی ہے، ایک آرکائیو بناتی ہے، اور ایک ناقابل تغیر ورژن اپ لوڈ کرتی ہے۔

## منشور تیار کریں۔

ایک ماخذ ماڈیول ہر اس فائل کی فہرست بناتا ہے جسے وہ بھیجتا ہے۔ آرکائیو میں `nx.toml` اور بالکل وہی فائلیں ہیں۔

```toml filename="nx.toml"
name = "@acme/auth"
version = "1.2.0"
kind = "source"

[compatibility]
nexy = ">=2.0.0"
python = ">=3.12"

[dependencies]
python = []
node = []

[source]
files = ["src/auth.py", "src/helpers.py"]
```

`name` فیلڈ کو چھوٹا ہونا چاہیے `@scope/name`۔ `version` فیلڈ کو نقطوں سے الگ کیا گیا تین نمبر ہونا چاہیے۔ فائلوں کو ماڈیول کے اندر رشتہ دار راستے ہونے چاہئیں۔ ایک پیکیج ماڈیول `source.files` کے بجائے `source.package` کا اعلان کرتا ہے۔

## اپ لوڈ کرنے سے پہلے چیک کریں۔

مینی فیسٹ کی توثیق کرنے کے لیے `--dry-run` کا استعمال کریں، اعلان کردہ فائلوں کو محفوظ کریں، اور چیکسم کو اپ لوڈ کیے بغیر پرنٹ کریں:

```bash
nx publish --dry-run
```

ڈرائی رن کو ٹوکن کی ضرورت نہیں ہوتی۔ یہ ہر متعلقہ درآمد کے لیے ایک `warning:` لائن پرنٹ کرتا ہے جو اس فائل کی طرف اشارہ کرتا ہے جس کا اعلان نہیں کیا جاتا۔ مثال کے طور پر، `from .helpers import token` میں `src/auth.py` کی ضرورت ہے `src/helpers.py` `source.files` میں، بصورت دیگر انسٹال کو ٹوٹا ہوا درآمد مل جائے گا۔

## ٹوکن سیٹ کریں۔

`nx publish` پڑھتا ہے `NEXY_REGISTRY_TOKEN`، پھر `~/.config/nexy/registry-token`۔ ٹوکن `Authorization` ہیڈر میں بھیجا جاتا ہے اور کبھی پرنٹ نہیں ہوتا۔

```bash
export NEXY_REGISTRY_TOKEN="your-token"
nx publish
```

ٹوکن فائل مستقبل میں `nx login` کو وہی سند لکھنے دیتی ہے۔ کسی بھی ذریعہ کے بغیر، کمانڈ پرنٹ کرتا ہے `error: No registry token` اور اسٹیٹس 1 کے ساتھ باہر نکلتا ہے۔

## شائع کریں۔

```bash
nx publish
```

کمانڈ اس کی شائع کردہ ریلیز کا نام، ورژن اور SHA-256 چیکسم پرنٹ کرتی ہے۔ ایک نام اور ورژن کا جوڑا ناقابل تغیر ہے: اسے دوبارہ شائع کرنے سے تنازعہ کی غلطی ہو جاتی ہے۔ اس کے بجائے ایک نیا ورژن شائع کریں۔

## دوسری رجسٹری استعمال کریں۔

پہلے سے طے شدہ طور پر کمانڈ `https://registry.nexypy.dev` کو پوسٹ کرتی ہے۔ دوسری رجسٹری کے لیے `--registry` استعمال کریں، مثال کے طور پر ترقی کے دوران مقامی:

```bash
nx publish --registry http://localhost:8000
```

صرف https یو آر ایل قبول کیے جاتے ہیں، نیز `localhost`، `127.0.0.1` اور `::1` پر سادہ http۔ عارضی `429` اور `5xx` جوابات کی دو بار کوشش کی جاتی ہے۔ ایک برا مینی فیسٹ، گمشدہ ٹوکن یا تنازعہ کی دوبارہ کوشش نہیں کی جاتی ہے۔

## رہائی کی تصدیق کریں۔

```bash
nx add @acme/auth@1.2.0
```

اپ گریڈ، پن اور ٹرسٹ سیٹنگز کے لیے [انسٹال ماڈیولز](install-modules.md) دیکھیں۔
