# خرابی کا سراغ لگانا

لوگوں کے مسائل سب سے پہلے، آپ کیا دیکھتے ہیں اور کیا کرنا ہے۔ ہر ایک حقیقی رن سے آتا ہے۔

## ایک صفحہ 404 کا جواب دیتا ہے لیکن اس کی فائل موجود ہے۔

`nx dev` یا `nx start` چلنے والے ٹرمینل کو دیکھیں۔ جب ایک صفحہ درآمد نہیں کیا جا سکتا ہے، Nexy اپنی فائل اور لائن کے ساتھ غلطی کی اطلاع دیتا ہے، اور راستہ رجسٹرڈ نہیں ہے:

```text
nexy » error __nexy__/src/routes/index.py:18  ImportError: cannot import name 'FrameworkLogo' ...
```

وہاں نام کی درآمد کو درست کریں۔ معمول کے اسباب ایک جز ہوتے ہیں جس کے فنکشن کا نام آپ کی درآمد کردہ چیز سے میل نہیں کھاتا (اگلی آئٹم دیکھیں) اور راستے میں ٹائپنگ۔

## ایک `.nexy` صفحہ مرتب نہیں ہوتا ہے: "منطق تجزیہ کی خرابی"

```text
src/components/live-panel.nexy - Logic Parse Error: invalid syntax
```

ایک `.nexy` جزو کو Python ماڈیول کے طور پر درآمد کیا جاتا ہے، اس لیے اس کا فائل کا نام ایک درست نام ہونا چاہیے۔ ہائفن نہیں ہے۔ اسے پاسکل کیس میں نام دیں، `LivePanel.nexy`، اور اسی نام سے درآمد کریں:

```nexy
from "@/components/LivePanel.nexy" import LivePanel
```

## ایک جزو اپنے بچوں کو متن کے طور پر پیش کرتا ہے `<slot />`

ایک `.nexy` جز اپنے بچوں کو `<Slot />` کے ساتھ رکھتا ہے، ایک کیپیٹل ایس کے ساتھ۔ ایک چھوٹا حروف `<slot />` صفحہ میں جیسا ہے چھوڑ دیا جاتا ہے۔ Vue، جس کا اپنا `<slot />` ہے، متاثر نہیں ہوتا۔

## ایک سہارا متغیر کا نام دکھاتا ہے۔

```nexy
<Icon path=icon />          renders: icon
<Icon path="{{ icon }}" />  renders: the value of icon
```

بغیر منحنی خطوط وحدانی کے ایک وصف متن ہے۔ شماری قدر کو پاس کرنے کے لیے Jinja اظہار کو وصف میں رکھیں۔

## `{{ ... }}` میں ایک قدر خالی رینڈر کرتی ہے۔

Jinja2 ایک غیر متعینہ متغیر کو چھپاتا ہے۔ فرنٹ میٹر (`title: prop[str] = ""`) میں استعمال ہونے والی ہر پراپرٹی کا اعلان کریں، اور ہجے چیک کریں۔

## `.nexy` صفحہ (UnoCSS) میں یوٹیلٹی کلاسز کا کوئی اثر نہیں ہوتا۔

UnoCSS فائل کو صرف اس وقت پڑھتا ہے جب اس کی توسیع اس کے مواد کی پائپ لائن میں ہو۔ `nx new` کے ذریعہ تخلیق کردہ ایک سرور پروجیکٹ UnoCSS کے ساتھ پہلے سے ہی فہرستیں `.nexy`؛ ایک بوڑھے کو اس کی ضرورت ہے `uno.config.ts`:

```ts
content: {
  filesystem: ['src/**/*.nexy'],
  pipeline: { include: [/\.(vue|svelte|[jt]sx|mdx?|astro|html|nexy)($|\?)/] },
},
```

Tailwind اپنے طور پر `.nexy` فائلیں تلاش کرتا ہے۔

## ایک `.mdx` صفحہ پیکجز کے لیے پوچھتا ہے۔

```text
[nexy] MDX support requires optional packages that are not installed.
```

انہیں پروجیکٹ میں انسٹال کریں: `@mdx-js/rollup`، `remark-gfm` اور `@mdx-js/react` (پلس `@mdx-js/esbuild` کے لیے `nx build`)۔ MDX ضروریات React یا Preact `useFF` میں۔ کلائنٹ فریم ورک کے بغیر صفحہ کو `.md` کے طور پر لکھیں۔ دیکھیں [Markdown اور MDX](../views/nexy/markdown.md)۔

## `No module named 'sqlmodel'` (یا کوئی پیکج) جب کمانڈ شروع ہوتا ہے۔

```text
nexy » nexyconfig.py cannot be loaded: No module named 'sqlmodel'. If it is a package, install it
in this Python (...) or activate the project's virtual environment.
```

حکم غلط Python میں چلا گیا۔ آپ کے پروجیکٹ کے پیکجز (آپ کا ORM، آپ کی لائبریریاں) اس کے `.venv`، اور `uvx nexy` یا عالمی `nexy` اپنے ماحول میں چلتے ہیں جس میں ان میں سے کوئی بھی نہیں ہے۔

پروجیکٹ فولڈر سے پروجیکٹ کے ورچوئل ماحول کو چالو کریں، پھر کمانڈ کو دوبارہ چلائیں:

```bash
.venv\Scripts\activate    # Windows; on macOS and Linux: source .venv/bin/activate
nexy dev
```

پرامپٹ `(.venv)` سے شروع ہوتا ہے جب یہ فعال ہوتا ہے۔ یا `uv run nexy dev` کے ساتھ ایکٹیویشن کو چھوڑ دیں۔ اگر پیکج واقعی پروجیکٹ سے غائب ہے تو اسے `uv add sqlmodel` کے ساتھ شامل کریں۔

## `nx dev` ایک غلطی دکھاتا ہے اور انتظار کرتا ہے۔

جب آپ کی درخواست شروع نہیں ہوسکتی ہے، `nx dev` رپورٹ کیوں کرتا ہے اور اگلی فائل میں تبدیلی کا انتظار کرتا ہے۔ یہ باہر نہیں نکلتا. فائل کو درست کریں اور محفوظ کریں۔ صرف Ctrl+C اسے روکتا ہے۔

## بندرگاہ مصروف ہے۔

`nx dev` اگلا مفت پورٹ لیتا ہے اور اسے پرنٹ کرتا ہے۔ ایک کو منتخب کرنے کے لیے، `--port` استعمال کریں یا `nexyconfig.py` میں `usePort` سیٹ کریں۔

## تھیم سیاہ صفحہ پر سفید چمکتا ہے۔

محفوظ کردہ تھیم کو پہلے پینٹ سے پہلے لاگو کیا جانا چاہیے۔ سٹارٹر کے چھوٹے اسکرپٹ کو روٹ لے آؤٹ کے `<head>` میں رکھیں، اور `suppressHydrationWarning` کو `<html>` میں React میں رکھیں۔
