# میں رجسٹری سے ماڈیول کیسے انسٹال کروں؟

ماڈیول رجسٹری سے ایک ریلیز ڈاؤن لوڈ کرنے کے لیے Nexy پروجیکٹ میں `nx add @scope/name` چلائیں، اسے چیک کریں، اور اس میں اعلان کردہ تبدیلیاں لاگو کریں۔ درست ورژن کو پن کرنے کے لیے `@1.2.0` شامل کریں۔

## ایک ماڈیول انسٹال کریں۔

Nexy پروجیکٹ کی جڑ سے:

```bash
nx add @acme/auth
nx add @acme/auth@1.2.0
```

`nx add` ریلیز میٹا ڈیٹا اور آرکائیو کو `useModuleRegistry` سے پڑھتا ہے، SHA-256 چیکسم کو چیک کرتا ہے، اور ماڈیول کی `nexy` اور `python` مطابقت کی حدود کو چیک کرتا ہے۔ اس کے بعد یہ صرف وہی فائلیں لکھتا ہے جو مینی فیسٹ کا اعلان کرتا ہے، اعلان کردہ Python پیکجوں کو `uv add` کے ساتھ شامل کرتا ہے، پروجیکٹ کے پیکیج مینیجر کے ساتھ نوڈ پیکجز کا اضافہ کرتا ہے، اور `nexyconfig.py` اور `package.json` پر کنفگ ہکس کا اطلاق کرتا ہے۔ موجودہ ترتیبات اور فائلیں جوں کی توں رہتی ہیں: ایک اعلان شدہ فائل جو پہلے سے موجود ہے کو `warning:` لائن کے ساتھ چھوڑ دیا جاتا ہے۔

ہر کامیاب انسٹال کو `.nexy/modules.json` میں ریکارڈ کیا جاتا ہے۔ اس فائل کا ارتکاب کریں تاکہ ٹیم کے ساتھی کو وہی ماڈیول ورژن ملے۔

## ماڈیول کو اپ گریڈ کریں۔

اپ گریڈ کرنے کے لیے، رجسٹری کی نئی ریلیز ہونے کے بعد دوبارہ `nx add @acme/auth` چلائیں، یا ایک نیا پن سیٹ کریں جیسے `@acme/auth@1.3.0`۔ بغیر پن کا نام رجسٹری کے `/versions` جواب سے تازہ ترین ورژن کا انتخاب کرتا ہے۔ اسی ورژن کو دوبارہ چلانے سے پرنٹ `is already installed` ہوتا ہے اور کچھ نہیں بدلتا۔

## ایک ورژن پن کریں۔

ایک پن بالکل درست ہے: `nx add @acme/auth@1.2.0` انسٹال ہوتا ہے `1.2.0` اور کوئی اور ریلیز نہیں۔ CI میں اور کمٹڈ `.nexy/modules.json` میں ایک پن استعمال کریں تاکہ ہر چیک آؤٹ ایک ہی کوڈ کو انسٹال کرے۔ پن کے بغیر، ایک نئی ریلیز اگلی انسٹال کو تبدیل کرتی ہے۔

## ہجرتیں چلائیں۔

ہجرتیں بطور ڈیفالٹ بند ہیں۔ `--migrate` شامل کریں جب آپ چاہتے ہیں کہ ریلیز کے اعلان کردہ کمانڈز اس کی فائلوں اور انحصار کی جگہ کے بعد چلیں:

```bash
nx add @acme/auth@1.2.0 --migrate
```

ہر کمانڈ کو چلنے سے پہلے پرنٹ کیا جاتا ہے۔ اس سے پہلے کہ کوئی ماڈیول اعلان کر سکے اس پراجیکٹ کو اپنا مائیگریشن ٹول انسٹال کرنے کی ضرورت ہے۔

## رجسٹری اور اس کے اعتماد کے قواعد مرتب کریں۔

پہلے سے طے شدہ `nexyconfig.py` میں رہتے ہیں:

```python filename="nexyconfig.py"
class NexyConfig(NexyConfigModel):
    useModuleRegistry = "https://registry.nexypy.dev"
    useRequireSignedModules = False
```

`useModuleRegistry` بنیادی URL ہے جسے CLI پڑھتا ہے۔ ڈویلپمنٹ کے دوران مقامی رجسٹری کے لیے لوپ بیک HTTP کے علاوہ صرف https یو آر ایل قبول کیے جاتے ہیں۔ `useRequireSignedModules = True` نے بغیر دستخط شدہ ریلیز سے انکار کیا۔ ایک ایسی ریلیز جس میں دستخط ہوتے ہیں اس سے بھی انکار کر دیا جاتا ہے جب تک کہ تصدیق کنندہ دستیاب نہ ہو۔ ایک بار جب کوئی اس کی تصدیق کرتا ہے، `nx add` پرنٹ کرتا ہے `Verified by` دستخط کنندہ کی شناخت کے ساتھ۔ پہلے سے طے شدہ `False` کو صرف ان رجسٹریوں کے لیے رکھیں جن پر آپ اعتماد کرتے ہیں۔
