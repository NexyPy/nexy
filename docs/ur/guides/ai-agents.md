# کوڈنگ ایجنٹس

`nx new` کے ساتھ بنائے گئے پروجیکٹ میں وہ اصول ہوتے ہیں جو کوڈنگ ایجنٹ کو Nexy کوڈ آپ کے طریقے سے لکھنے کے لیے درکار ہوتے ہیں: کام کی ترتیب، کوڈ اور تحریری اصول، اور فی موضوع ایک مہارت۔ یہ صفحہ بتاتا ہے کہ آپ کو کیا ملتا ہے، یہ کہاں جاتا ہے، اور اسے موجودہ کیسے رکھنا ہے۔ Nexy پر کام کرنا بذات خود ایک مختلف کام ہے: repository کی جڑ پڑھیں `AGENTS.md`۔

## کیا `nx new` جوڑتا ہے۔

| فائل | پڑھیں | ہولڈز |
|---|---|---|
| `AGENTS.md` | Codex، OpenCode | منصوبے کا ڈھیر، کام کی ترتیب، قواعد، مہارتوں کی فہرست |
| `CLAUDE.md` | Claude Code | ایک سطر، `@AGENTS.md`، تو دونوں ایک ہی عبارت پڑھیں |
| `.agents/skills/` | Codex، OpenCode | ہنر |
| `.claude/skills/` | Claude Code، OpenCode | وہی مہارتیں |

`AGENTS.md` مختصر اور موزوں ہے۔ ایک کلائنٹ روٹڈ Vue پروجیکٹ پڑھتا ہے "کلائنٹ روٹڈ، Vue، Tailwind کے ساتھ اسٹائل شدہ"؛ ایک API پروجیکٹ کو بتایا جاتا ہے کہ کوئی آراء نہیں ہیں۔ صرف وہی مہارتیں نقل کی جاتی ہیں جو فٹ ہوتی ہیں: ایک React پروجیکٹ کو `nexy-react` اور کوئی Vue مہارت نہیں ملتی، سرور پروجیکٹ کو `.nexy` اور Markdown کی مہارت ملتی ہے، ایک API پروجیکٹ کو آراء کے بارے میں کوئی مہارت حاصل نہیں ہوتی۔

اس سب کو چھوڑنے کے لیے `nx new --no-agents` کے ساتھ پروجیکٹ بنائیں۔

| مہارت | کور |
|---|---|

| `nexy-ux-audit` | کسی بھی نظارے سے پہلے چلانے کے لیے تجربہ اور معلوماتی فن تعمیر کا آڈٹ |
| `nexy-project` | موڈز، فولڈرز، فائل کنونشنز، کنفیگریشن، کمانڈز |

| `nexy-react`، `nexy-preact`، `nexy-solid`، `nexy-vue`، `nexy-svelte` | کلائنٹ کے فریم ورک کے لیے محاوراتی کوڈ |

| `nexy-backend` | API ہینڈلرز، ایکشنز، WebSocket، ISR، مڈل ویئر |

| `nexy-security` | انحصار، ان پٹ، سیشن، اجازت، راز |

وہ قوانین جو وہ نافذ کرتے ہیں: ویو بنانے سے پہلے تجربے کا آڈٹ کریں، پہلے فیلنگ ٹیسٹ لکھیں، ایک فنکشن ایک علاج کرتا ہے، ایک کلاس ایک ارادہ رکھتی ہے، ایک فولڈر میں متعلقہ ارادوں کا ایک سیٹ ہوتا ہے، کوئی ایموجی نہیں، اصلی SVG آئیکنز، سادہ متن لوگوں کے لیے لکھا جاتا ہے، اور ہاتھ سے لکھا ہوا DOM اسکرپٹ نہیں ہوتا ہے۔ React، Vue، Svelte، Solid یا Preact۔

## انہیں موجودہ پروجیکٹ میں شامل کریں۔

```bash
nx skills
```

اسے پروجیکٹ کی جڑ میں چلائیں۔ یہ اسٹیک کو تلاش کرنے کے لیے `nexyconfig.py` اور `package.json` پڑھتا ہے، مماثل مہارتوں کو نقل کرتا ہے، اور جب وہ غائب ہوتے ہیں تو `AGENTS.md` اور `CLAUDE.md` لکھتا ہے۔

یہ آپ کی لکھی ہوئی فائل کو کبھی بھی اوور رائٹ نہیں کرتا: ایک موجودہ `AGENTS.md` یا `CLAUDE.md` رکھا جاتا ہے، اور کمانڈ آپ کو ایسا بتاتی ہے۔ مہارت کی فہرست کو ہاتھ سے اپنی فائل میں شامل کریں اگر آپ اسے وہاں چاہتے ہیں۔ `.claude/skills/` یا `.agents/skills/` میں آپ کی اپنی مہارت اکیلی رہ گئی ہے۔ صرف `nexy-*` مہارتیں تازہ ہوتی ہیں۔

کاپیوں کو ریفریش کرنے کے لیے Nexy کو اپ گریڈ کرنے کے بعد دوبارہ `nx skills` چلائیں، اور نتیجہ کا ارتکاب کریں تاکہ پوری ٹیم اسے شیئر کرے۔

## ایک ایجنٹ انہیں کیسے ڈھونڈتا ہے۔

- `AGENTS.md` (یا `CLAUDE.md`، جو اسے درآمد کرتا ہے) ہر سیشن کے شروع میں پڑھا جاتا ہے۔ یہ ہنر کو نام دیتا ہے۔
- ہر ہنر ایک نام اور تفصیل سے شروع ہوتا ہے جو کہتا ہے کہ یہ کیا احاطہ کرتا ہے اور اسے کب لوڈ کرنا ہے۔ ایجنٹ سب سے پہلے ان کو پڑھتا ہے اور صرف اس وقت مہارت کھولتا ہے جب ٹاسک میچ کرتا ہے۔

ہنر کھلے [Agent Skills format](https://agentskills.io/specification) کی پیروی کرتے ہیں، اس لیے دوسرے ایجنٹ جو `SKILL.md` فولڈرز کو پڑھتے ہیں وہ بھی انہیں استعمال کر سکتے ہیں۔

## جو وہ نہیں کرتے

ہنر ایک ایجنٹ کو بتاتا ہے کہ کیسے کام کرنا ہے۔ وہ اس کی پیداوار کو درست نہیں کرتے ہیں۔ اپنے چیک خود رکھیں:

- پڑھیں ایجنٹ نے کیا بدلا۔
- چلائیں `nx check`، `nx test` اور `nx build`۔ مہارتیں اس کے لیے اور آؤٹ پٹ کو رپورٹ کرنے کے لیے پوچھتی ہیں، خلاصہ نہیں۔
- آڈٹ انحصار جو ایجنٹ شامل کرتا ہے (`nexy-security` وضاحت کرتا ہے کہ کیسے)۔

مہارتوں کی مثالیں Nexy کے اپنے ٹیسٹوں سے جانچی جاتی ہیں: درآمدات موجود ہیں، کنفیگریشن فیلڈز موجود ہیں، کمانڈز موجود ہیں، Python پارس ہیں۔ یہ بہاؤ کو پکڑتا ہے، غلط اندازہ نہیں.

## پروجیکٹ انویرینٹس

1. `__nexy__/` پیدا ہوتا ہے۔ اس میں کبھی ترمیم نہ کریں، اس کا ارتکاب نہ کریں۔ صاف تعمیر پر مجبور کرنے کے لیے اسے حذف کریں۔
2. ایک فائل فی URL۔ ایک ہی راستے کے لیے `index.nexy` اور `index.py` ایک بگ ہے، ترجیحی اصول نہیں۔
3. `src/routes/`] کے اندر محفوظ کردہ نام: `layout.nexy`، `loading.nexy`، `errors.nexy`، `notfound.nexy`، `dependencies.py`، `__init__.py`۔ انہیں مواد کے لیے استعمال نہ کریں۔
4. `.nexy` فرنٹ میٹر Python ہے جو ہر درخواست پر چلتا ہے۔ کوئی ماڈیول سطح کے ضمنی اثرات: کوئی فائل ہینڈل نہیں، کوئی ڈیٹا بیس کنکشن نہیں، درآمد پر کوئی نیٹ ورک کال نہیں ہے۔
5. `.py` `src/routes/` میں ایک API ہینڈلر ہے۔ طریقے فنکشن کے نام ہیں (`GET`، `POST`، ​​...)۔
6. کنفیگریشن `nexyconfig.py` میں رہتی ہے، نہ کہ ماحولیاتی متغیرات میں اور نہ ہی بکھرے ہوئے مستقل میں۔
7. آٹو اسکیپنگ `.nexy` ٹیمپلیٹس میں بند ہے: `| e` کے ساتھ غیر بھروسہ مند اقدار سے بچیں۔

```bash
nx dev      # development
nx build    # production build
nx start    # production server
nx test     # pytest, --client adds vitest
```

جب دستاویزات اور کوڈ متفق نہ ہوں تو کوڈ پر بھروسہ کریں اور یہ کہیں: `nexy/core/config.py` ہر آپشن رکھتا ہے، `nexy/modules/routers/fbrouter/` روٹنگ کے اصول، `nexy/modules/compiler/` کیسے `.nexy` فائلیں ماڈیول بن جاتی ہیں۔
