# میں Vercel پر Nexy ایپ کیسے تعینات کروں؟

`nx add vercel` کو چلائیں، اپنے `nx build` آؤٹ پٹ کے ساتھ تیار کردہ فائلوں کو کمٹ کریں، اور ورسل Python کے رن ٹائم کو `src/server.py:app` پر پوائنٹ کریں۔

## پلیٹ فارم فائلیں شامل کریں۔

Nexy پروجیکٹ کی جڑ سے:

```bash
nx add vercel
nx build
```

`nx add vercel` لکھتے ہیں `src/server.py` اور `vercel.json`۔ یہ ایپ کے چلنے کے دوران تبدیل ہونے والی فائلوں کے لیے نظر انداز کرنے کے اصول بھی شامل کرتا ہے: `__nexy__/build-cache.json`، `__nexy__/server.port`، `__nexy__/.temp/` اور `__pycache__/`۔ کمانڈ کو دوبارہ چلانے سے فائلیں پہلے سے موجود رہتی ہیں اور نظر انداز کرنے والے اصولوں کی نقل نہیں بنتی ہیں۔

## ایپ پر Vercel کو پوائنٹ کریں۔

Vercel پروجیکٹ کی ترتیبات میں، Python رن ٹائم کو منتخب کریں اور `src/server.py:app` کو بطور انٹری پوائنٹ استعمال کریں۔ ورسل نے اس ماڈیول میں نام `app` کو دریافت کیا۔ `nx start` شامل نہیں ہے۔

تیار کردہ `src/server.py` کام کرنے والے فولڈر کو تیار کرنے کے بعد سست `nexy.app.app` کو درآمد کرتا ہے۔ آپ اسی انٹری پوائنٹ کو مقامی طور پر `uvicorn src.server:app` کے ساتھ استعمال کر سکتے ہیں۔

## تعمیراتی پیداوار کا ارتکاب کریں۔

جب ورسل کی کوئی بلڈ کمانڈ نہیں ہوتی ہے، تو اسے صرف وہی ملتا ہے جو ریپوزٹری میں ہوتا ہے۔ کمٹ `__nexy__/` ہر `nx build` کے بعد، مرتب شدہ راستوں کے ساتھ، `__nexy__/client/` کے نیچے کلائنٹ بنڈل اور `__nexy__/client/.vite/manifest.json` پر مینی فیسٹ۔

`vite.config.ts` کو پروجیکٹ کی جڑ پر رکھیں اور اس کا ارتکاب کریں۔ پروڈکشن میں Nexy اسٹائل شیٹ اور اسکرپٹ ٹیگز لکھنے کے لیے Vite مینی فیسٹ کو پڑھتا ہے، لیکن یہ ان ٹیگز کو صرف اس وقت خارج کرتا ہے جب `vite.config.ts` موجود ہو۔ اس فائل کے بغیر صفحہ اب بھی 200 کا جواب دیتا ہے اور بغیر CSS یا کلائنٹ کے آتا ہے JavaScript۔

ارتکاب نہ کریں `__nexy__/build-cache.json`: اس میں مشین کے مطلق راستے ہیں جو تعمیر کو چلاتے ہیں۔ `__nexy__/server.port` کا تعلق `nx start` سے ہے، اور `__nexy__/.temp/` سکریچ اسپیس ہے۔

## صرف پڑھنے کے لیے فائل سسٹم کو قبول کریں۔

ورسل پروجیکٹ کو صرف پڑھنے کے لیے ماؤنٹ کرتا ہے جب ایک Python ایپلیکیشن شروع ہوتی ہے۔ Nexy سٹارٹ اپ کے دوران جنریٹڈ فائلوں کو لکھتا ہے، لہذا ایک ننگا `from nexy.app import app` `OSError: [Errno 30] Read-only file system` کے ساتھ ناکام ہو سکتا ہے۔

تیار کردہ انٹری پوائنٹ ایپ کو درآمد کرنے سے پہلے چھ پروجیکٹ آئٹمز کو قابل تحریر عارضی فولڈر میں کاپی کرتا ہے: `src`، `__nexy__`، `public`، `nexyconfig.py`، `pyproject.toml` اور `vite.config.ts`۔ یہ ورکنگ ڈائرکٹری کو تبدیل کرتا ہے اور کاپی کو پہلے `sys.path` پر رکھتا ہے، کیونکہ Nexy موجودہ ڈائرکٹری سے روٹس کو حل کرتا ہے۔ آپ کی ایپ رن ٹائم پر پڑھنے والی کوئی دوسری فائل ہاتھ سے اس فہرست میں شامل کریں۔

## جامد اثاثے کیش کریں۔

تیار کردہ `vercel.json` میں کیشے کے دو قواعد شامل ہیں جو ایک تعینات Nexy سائٹ استعمال کرتی ہے: `/assets/` کے تحت فائلیں ایک سال کے لیے ناقابل تغیر ہوتی ہیں، اور `public/` کے تحت تصاویر اور فونٹس ایک ہفتے کے اسٹال-وائل-ریویلیڈیٹ ونڈو کے ساتھ ایک دن کے لیے تازہ رہتے ہیں۔ اگر آپ کے پروجیکٹ کو ان کی ضرورت ہو تو اسی فائل میں دیگر قواعد شامل کریں۔

## تعیناتی چیک کریں۔

آگے بڑھانے سے پہلے، انٹری پوائنٹ درآمد کریں اور اس سے ایک صفحہ طلب کریں:

```bash
uv run python -c "from src.server import app; print(type(app).__name__)"
uv run uvicorn src.server:app
```

پھر کھولیں `/`، ایک تیار کردہ راستہ اور ایک فائل `/assets/` کے نیچے۔ جواب کا مقامی طور پر `nx start` سے موازنہ کریں: حیثیت، مواد کی قسم اور سائز مماثل ہونا چاہیے۔ ایک صفحہ جو مقامی سے چھوٹا ہے بالکل دو کلائنٹ ٹیگز کا مطلب ہے `vite.config.ts` کاپی شدہ پروجیکٹ سے غائب تھا۔
