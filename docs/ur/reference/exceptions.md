# مستثنیات اور غلطیاں

ایک درخواست چار جگہوں پر ناکام ہو سکتی ہے، اور Nexy ہر ایک کو مختلف طریقے سے جواب دیتا ہے۔ یہ صفحہ انڈیکس ہے: وہ اسٹیٹس تلاش کریں جو آپ دیکھتے ہیں، پھر وہ لائن جس نے اسے بنایا، پھر وہ فائل جو باڈی کا فیصلہ کرتی ہے۔

> [!نوٹ]
> تین چیزیں الگ الگ اور آسانی سے مل جاتی ہیں: **HTTP جواب** (ایک حیثیت اور ایک باڈی)، **غلطی کا صفحہ** (`notfound.nexy`، `errors.nexy`)، اور **لاگ لائن** (جو آپ ٹرمینل میں پڑھتے ہیں)۔ صفحہ تبدیل کرنے سے حیثیت نہیں بدلتی، اور صفحہ کو اپنی مرضی کے مطابق کرنے سے لاگ چھپا نہیں جاتا۔

## مختصر ورژن

| کیا ہوا | اسٹیٹس | براؤزر دیکھتا ہے | API کلائنٹ دیکھتا ہے |
|---|---|---|---|
| کوئی روٹ URL | `404` | `notfound.nexy` سے میل نہیں کھاتا، ورنہ پہلے سے موجود صفحہ | `{"detail": "Not Found"}` |
| ایک پاتھ سیگمنٹ اس کی تشریح کے مطابق نہیں ہے | `404` | ایک ہی صفحہ | `{"detail": "Not Found"}` |
| ایک سوال، ہیڈر، کوکی یا باڈی فیلڈ غائب یا غلط ہے | `422` | FastAPI کی JSON باڈی | FastAPI کی JSON باڈی |
| `notFound()` | `404` | صفحہ | `{"detail": ...}` |
| `unauthorized()` | `401` | بلٹ ان صفحہ | `{"detail": ...}` |
| `forbidden()` | `403` | بلٹ ان پیج | `{"detail": ...}` |
| `raise HTTPException(409, ...)` | `409` | بلٹ ان پیج | `{"detail": ...}` |
| ایک استثناء کچھ بھی نہیں پکڑا گیا | `500` | `errors.nexy`، ورنہ بلٹ ان پیج | `{"detail", "reference"}` |
| `redirect(url)` | `307` | منزل، کوئی صفحہ | منزل نہیں، جسم نہیں |
| `permanentRedirect(url)` | `308` | منزل، کوئی صفحہ نہیں | منزل |

API کلائنٹ ایک درخواست ہے جس کا `Accept` ہیڈر JSON کے لیے پوچھتا ہے نہ کہ کسی صفحہ کے لیے:

```bash
curl -H "Accept: application/json" http://localhost:3000/api/items/500
# {"detail":"Out of range"}
```

> [!انتباہ]
> `curl` بطور ڈیفالٹ `Accept: */*` بھیجتا ہے، جس سے HTML صفحہ ملتا ہے۔ جب آپ JSON شکل کی جانچ کرتے ہیں تو `-H "Accept: application/json"` شامل کریں۔ براؤزرز کو صفحات ملتے رہتے ہیں۔

## ناکامی کہاں سے آتی ہے۔

```diagram filename="ایک درخواست، چار اخراج"
Browser ──► Middleware ──► Router ──► Page or handler
                 │            │             │
                 │            │             ├─ return ───────────► 200
                 │            │             ├─ HTTPException ────► its status
                 │            │             └─ other exception ───► 500
                 │            └─ no match ────────────────────────► 404
                 └─ raises ──────────────────────────────────────► 500
```

| مرحلہ | کیا ناکام ہو سکتا ہے | جواب |
|---|---|---|
| مڈل ویئر | آپ کا `middleware.py`، CORS، سیشنز | استثنا کی حیثیت، ورنہ `500` |
| راؤٹر | URL کسی فائل سے میل نہیں کھاتا | `404` |
| توثیق | راستے کے حصے کو تبدیل نہیں کیا جاسکتا | `404` |
| توثیق | ایک سوال، ہیڈر، کوکی یا باڈی فیلڈ | `422` |
| صفحہ، ہینڈلر، ایکشن، گارڈ | `HTTPException` | اس کی حیثیت |
| صفحہ، ہینڈلر، ایکشن، گارڈ | اور کچھ بھی | `500` |

## کہیں سے بھی چلے جائیں۔

`redirect`، `permanentRedirect`، `notFound`، `forbidden` اور `unauthorized` ایک HTTP استثنیٰ کو بڑھاتے ہیں، اس لیے وہی کال ایک `.nexy` صفحہ، ایک API ہینڈلر، ایک ماڈیولر کنٹرولر، ایک گارڈ، ایک `dependencies.py` اور ایک کارروائی میں کام کرتی ہے۔

```python filename="src/routes/posts/[slug].py"
from nexy import notFound, redirect

from src.posts import find


async def GET(slug: str):
    post = find(slug)
    if post is None:
        notFound("No such post")
    if post.moved_to:
        redirect(post.moved_to)
    return post
```

| کال | جواب | جب |
|---|---|---|
| `notFound(detail=None)` | `404` | وسیلہ موجود نہیں ہے |
| `unauthorized(detail=None, scheme=None)` | `401` | آنے والے کو پہلے سائن ان کرنا ہوگا |
| `forbidden(detail=None)` | `403` | آنے والا جانتا ہے لیکن اسے دیکھ نہیں سکتا |
| `redirect(url, status=307)` | `307` | طریقہ کو مدنظر رکھتے ہوئے انہیں دوسری جگہ بھیجیں |
| `redirect(url, status=303)` | `303` | فارم کے بعد: اگلی درخواست ہے `GET` |
| `permanentRedirect(url)` | `308` | ایک منتقل شدہ صفحہ جسے سرچ انجنوں کو یاد رکھنا چاہئے |

ان اقدار سے منزل کی تعمیر کریں جن پر آپ اعتماد کرتے ہیں۔ `redirect(request.query_params["next"])` جہاں بھی لنک کہتا ہے وہاں زائرین بھیجتا ہے۔ یہ ایک کھلا ری ڈائریکٹ ہے۔ ایک منزل جس میں لائن بریک ہو اسے مسترد کر دیا جاتا ہے۔

## توثیق: 422، یا 404

ہینڈلر پیرامیٹرز کو ان کی تشریحات کے خلاف FastAPI کے ذریعہ توثیق کیا جاتا ہے۔

```python filename="src/routes/api/search.py"
from nexy.http import Header


async def GET(q: str, limit: int = 10, x_token: str = Header(...)):
    return {"q": q, "limit": limit}
```

| مسئلہ | حیثیت | کیوں |
|---|---|---|
| غائب یا غلط استفسار، ہیڈر، کوکی یا باڈی فیلڈ | `422` | درخواست ہینڈلر تک پہنچ گئی، ڈیٹا غلط ہے |
| غلط راستہ طبقہ (`/api/users/abc` برائے `id: int`) | `404` | فولڈر میں غیر نمبر کے لیے کوئی راستہ نہیں ہے، اس لیے URL موجود نہیں ہے |

`422` باڈی FastAPI کی معیاری شکل ہے، اس لیے کلائنٹ اور تیار کردہ SDKs کام کرتے رہتے ہیں:

```json
{"detail": [{"loc": ["query", "q"], "msg": "Field required", "type": "missing"}]}
```

کسی فارم یا ایکشن کے لیے، کلائنٹ کو `ActionError` کے ساتھ `status` اور `detail`؛ a `422` بھی `error.fields` کو فی فیلڈ ایک پیغام کے ساتھ بھرتا ہے۔ دیکھیں [اعمال](../guides/actions.md#errors-and-failures)۔

> [!ٹپ]
> جب قاعدہ ایک فیلڈ (`limit: int = 10`) کے بارے میں ہو تو دستخط میں تصدیق کریں۔ باڈی میں تصدیق کریں جب قاعدہ کو ڈیٹا بیس یا کسی اور فیلڈ کی ضرورت ہو ("یہ ای میل پہلے ہی استعمال شدہ ہے"): raise `HTTPException(409)` کریں اور کلائنٹ کے لیے پیغام رکھیں۔

## حسب ضرورت خرابی والے صفحات

```nexy filename="src/routes/notfound.nexy"
<h1>Page not found</h1>
<p>The link may be old. <a href="/">Start from the home page</a>.</p>
```

```nexy filename="src/routes/errors.nexy"
<h1>Something went wrong</h1>
<p>Try again in a moment.</p>
```

| فائل | حیثیت | دائرہ کار |
|---|---|---|
| `src/routes/notfound.nexy` | `404` | منصوبے کے ہر راستے |
| `src/routes/errors.nexy` | `500` | منصوبے کے ہر راستے |
| `src/routes/forbidden.nexy` | `403` | منصوبے کے ہر راستے |
| `src/routes/unauthorized.nexy` | `401` | منصوبے کے ہر راستے |
| `src/routes/blog/notfound.nexy` | `404` | `/blog` اور نیچے |
| `src/routes/blog/errors.nexy` | `500` | `/blog` اور نیچے |
| `src/routes/loading.nexy` | - | محفوظ، ابھی تک کوئی رن ٹائم اثر نہیں |

روٹس میں کہیں ایک فائل اپنی حیثیت کے لیے جواب انسٹال کرتی ہے: روٹ پر موجود ایک کاپی پورے پروجیکٹ کا جواب دیتی ہے، ایک فولڈر میں موجود ایک کاپی اس فولڈر کا جواب دیتی ہے، اور سب سے گہری فائل جو URL سے میل کھاتی ہے جیت جاتی ہے۔ ہر کاپی کے باہر ایک یو آر ایل، اور ایک اسٹیٹس جس میں کوئی فائل نہیں، بلٹ ان اسٹائل والے صفحات حاصل کریں۔ دیکھیں [خرابی صفحات فی فولڈر](../routing/fbr/errors/folder-pages.md)۔

> [!اہم]
> ایک `errors.nexy` صفحہ `500` صفحہ کی جگہ لے لیتا ہے۔ یہ استثناء کو نہیں پکڑتا ہے اور یہ لاگ لائن کو تبدیل نہیں کرتا ہے۔ اگر ہینڈلر جس نے اٹھایا وہ صفحہ ہی ہے، تو صفحہ اپنی غلطی کی تفصیلات نہیں دکھا سکتا: `errors.nexy` سادہ اور آزاد رکھیں۔

## غیر ہینڈل شدہ مستثنیات

ایک استثناء ہے کہ پکڑی گئی کوئی بھی چیز ایک بار لاگ ان نہیں ہوتی ہے، اس کے حوالہ کے ساتھ، یہ کہاں سے آیا ہے اور اس کے ارد گرد کوڈ۔ حیثیت `500` ہے، اور جسم کا انحصار ماحول پر ہے۔

| | `nexy dev` | `nexy build` پھر `nexy start` |
|---|---|---|
| براؤزر | خرابی، آپ کے کوڈ کی لائنیں اور ٹریس بیک | `errors.nexy`، بصورت دیگر بلٹ ان پیج، حوالہ کے ساتھ |
| API کلائنٹ | `{"detail", "reference", "error"}` | `{"detail", "reference"}` |
| ٹرمینل | استثناء اور آپ کے کوڈ کی لائنیں | استثناء، پورا ٹریس بیک اور حوالہ |

```text
  x ZeroDivisionError: division by zero  GET /boom  ref fe6a5217
    at src/routes/boom.py:2 in GET
       1 | def GET():
       2 |     return {"a": 1 / 0}
```

حوالہ آٹھ حروف ہے، ہر ناکامی کے لیے نیا۔ ایک وزیٹر اس کا حوالہ دے سکتا ہے، اور آپ اس کے لیے لاگ کو تلاش کر کے ٹریس بیک تلاش کر سکتے ہیں۔ پیداوار میں نہ تو استثناء اور نہ ہی کوڈ وزیٹر تک پہنچتا ہے۔

> [!احتیاط]
> پروڈکشن میں کسی وزیٹر کو ٹریس بیک واپس نہ کریں، اور غلطی کے پیغام میں راز نہ رکھیں: `detail` کا `HTTPException` کلائنٹ کو بھیجا جاتا ہے، HTML سے بچ جاتا ہے۔ راز کو لاگ میں رکھیں، جواب میں نہیں۔

## اعمال اور شکلیں۔

ایک عمل ایک `POST` اختتامی نقطہ ہے جس میں پیدا شدہ راستہ ہے۔ اس کی ناکامیاں انہی اصولوں پر عمل کرتی ہیں:

| صورتحال | حیثیت | کلائنٹ |
|---|---|---|
| ایک فیلڈ غائب یا غلط ہے | `422` | `ActionError` `fields` | کے ساتھ
| `HTTPException(403)` کارروائی میں اٹھایا گیا | `403` | `ActionError` `status` اور `detail` |
| ایک غیر سنبھالا ہوا استثنا | `500` | `ActionError`؛ حوالہ سرور لاگ میں ہے |
| `Origin` ہیڈر ایک اور سائٹ ہے | `403` | نے ایکشن چلنے سے پہلے انکار کر دیا |

ایک فارم بغیر JavaScript ایکشن پاتھ پر پوسٹس کے۔ ایک کامیابی صفحہ پر واپس `303` جواب دیتی ہے، ناکامی غلطی کا صفحہ دکھاتی ہے۔ دیکھیں [اعمال](../guides/actions.md#forms-without-javascript)۔

## ایک چیک لسٹ جب ایک صفحہ غلط چیز کا جواب دیتا ہے۔

1. **حالت دیکھو** صفحہ کو نہیں۔ ایک رواج `notfound.nexy` اب بھی جواب دیتا ہے `404`۔
2. **پڑھیں ٹرمینل** ایک صفحہ جو درآمد کرنے میں ناکام ہوتا ہے وہ رجسٹرڈ نہیں ہوتا، اس لیے اس کا URL جواب دیتا ہے `404` جب کہ فائل موجود ہے۔ درآمد کی خرابی لاگ میں ہے۔
3. **چیک کریں۔ توسیع** `useCSR = True` کے ساتھ، `.nexy` صفحات سرور موڈ سے تعلق رکھتے ہیں۔ غلط موڈ میں ایک صفحہ ایک راستہ نہیں ہے.
4. **چیک کریں۔ گہرائی** A `notfound.nexy` یا `errors.nexy` صرف اس وقت کام کرتا ہے جب روٹ کاپی موجود ہو۔
5. **آپ کے API کلائنٹ کو موصول ہونے والی شکل دیکھنے کے لیے `Accept: application/json` کے ساتھ JSON** کے لیے پوچھیں۔
6. **جب آپ کوئی مسئلہ کھولتے ہیں یا لاگ کو تلاش کرتے ہیں تو `500` کا حوالہ** دیں۔
