# سی ایل آئی

بائنری `nx` ہے (`nexy` کے طور پر بھی انسٹال ہے)۔ `uvx nexy new` ایک پروجیکٹ بناتا ہے (`uvx` uv کے ساتھ آتا ہے)۔ ہر دوسری کمانڈ کو پروجیکٹ کے ورچوئل ماحول کے اندر چلائیں، یا `uv run` کے ذریعے، مثال کے طور پر `uv run nexy dev`: یہ وہ جگہ ہے جہاں آپ کے اپنے پیکج ہیں۔

## احکام

| حکم | عرف | یہ کیا کرتا ہے |
|---|---|---|
| `nx dev` | `nx d` | ترقیاتی سرور: تبدیلی پر مرتب کریں، Vite، HMR |
| `nx start` | `nx s` | مرتب شدہ آؤٹ پٹ پر پروڈکشن سرور |
| `nx build` | `nx b` | پیداوار کی تعمیر |
| `nx new` | `nx n` | ایک پراجیکٹ کا سہارا بنائیں |
| `nx init` | `nx i` | Nexy کو موجودہ پروجیکٹ میں شامل کریں۔ |
| `nx add` | - | رجسٹری سے UI جزو یا یو آر ایل کو `src/components/ui` میں شامل کریں۔ |
| `nx migrate` | `nx m` | Alembic یا Aerich کے ساتھ ڈیٹا بیس کی منتقلی بنائیں یا لاگو کریں |
| `nx check` | `nx c` | type-check: mypy on Python، `tsc` on TypeScript |
| `nx format` | `nx f` | فارمیٹ Python (ruff)، JS/TS (خوبصورت)، `.nexy` فائلیں |
| `nx test` | - | چلائیں pytest؛ `--client` vitest شامل کرتا ہے۔ |
| `nx skills` | - | کوڈنگ ایجنٹوں کے لیے مہارتیں شامل کریں یا تازہ کریں، `AGENTS.md` اور `CLAUDE.md` |

## آؤٹ پٹ

لمبے مراحل (پیکیجز کو انسٹال کرنا، کمپائل کرنا، بنڈل بنانا) گزرے ہوئے وقت اور آخری لائن کے ساتھ اسپنر کو دکھاتا ہے جو کمانڈ نے پرنٹ کیا ہے، پھر ایک لائن کو پیچھے چھوڑ دیں، جیسا کہ uv کرتا ہے: `Synced .venv with uv in 1.4s`۔ مراحل کا ایک گروپ (`nx new` کی تنصیبات) بھی ایک پروگریس بار اور تکمیل شدہ مراحل کی تعداد دکھاتا ہے، `2/5`۔ ناکامی کا مرحلہ اپنی وجہ کے ساتھ ایک `error:` لائن ہے، `cause: exit 1 after 2.1s`، جس کے بعد کمانڈ کے آؤٹ پٹ کی آخری لائنیں چھپنے کے بجائے آتی ہیں۔ دیکھنے کے لیے کچھ پڑھتا ہے `warning: ...`، اور آگے کیا کرنا ہے `hint: ...`۔ دیو لاگز درخواستوں کے لیے `GET » /about 200 in 12ms` اور Vite کے لیے `vite » ...` پڑھتے ہیں۔

## خرابیاں جبکہ `nx dev` چلتا ہے۔

ٹوٹی ہوئی فائل کو محفوظ کرنے سے سرور کبھی نہیں رکتا۔ نحوی غلطی کے ساتھ ایک `.py` فائل کو اس کی فائل اور لائن کے ساتھ رپورٹ کیا جاتا ہے، اور سرور آخری ورکنگ ورژن پیش کرتا رہتا ہے جب تک کہ آپ اسے ٹھیک نہیں کر دیتے:

```text
  nexy » error  src/routes/users.py:3
  SyntaxError: invalid syntax

    1 | import json
    2 |
  > 3 | def GET(:
                ^
    4 |     x = 1
    5 |     return {"v": 2}

  Fix it and save: the server keeps its last working version.
```

ایک فائل جو تجزیہ کرتی ہے لیکن ناکام ہوجاتی ہے جب ایپلیکیشن لوڈ ہو جاتی ہے (ایک گمشدہ درآمد، ماڈیول کی سطح پر ایک خرابی) اسی طرح رپورٹ کی جاتی ہے اور `nx dev` آپ کی اگلی بچت کا انتظار کرتی ہے۔ جب تک ایپلیکیشن دوبارہ لوڈ نہیں ہو جاتی تب تک کچھ نہیں پیش کیا جاتا ہے۔ سرور کے دوبارہ لوڈ ہونے کے دوران ایک درست سیو `nexy » update <file>` پڑھتا ہے۔ Markdown فائلیں `src/routes` سے باہر، جیسے `README.md`، صفحات نہیں ہیں اور کسی چیز کو متحرک نہیں کرتی ہیں۔ `nx start` سخت ہے: یہ کوڈ 1 کے ساتھ باہر نکلتا ہے، اور کچھ بھی شروع نہیں ہوتا ہے، اگر روٹ فائل لوڈ نہیں ہوسکتی ہے یا اگر `nx build` نے ابھی تک پروجیکٹ نہیں بنایا ہے۔

## `nx new` کے سوالات

`nx new` اس ترتیب میں پوچھتا ہے: فائل پر مبنی روٹر، پروجیکٹ کی قسم (ویب یا API)، کلائنٹ سائیڈ روٹنگ، کلائنٹ فریم ورک، ایپ کو اسٹائل کرنے کا طریقہ، عرف درآمد کرنا، ORM، ڈیٹا بیس اور ڈیٹا بیس URL۔ ہر آپشن کی مختصر تفصیل ہوتی ہے اور موجودہ کو نمایاں کیا جاتا ہے۔ وہ سوالات جو لاگو نہیں ہوتے ہیں انہیں چھوڑ دیا جاتا ہے (ایک API پروجیکٹ کا کوئی فریم ورک یا اسٹائل نہیں ہوتا ہے؛ **کوئی ڈیٹا بیس** منتخب کرنے سے ORM ڈیٹا بیس اور URL کو چھوڑ دیتا ہے)۔ تیر والے بٹنوں (یا `j`/`k`، یا ایک نمبر کے ساتھ منتقل کریں، `enter` کے ساتھ تصدیق کریں، `←` یا `esc` کے ساتھ پچھلے سوال پر واپس جائیں، `ctrl+c` کے ساتھ چھوڑیں۔

| سوال | انتخاب |
|---|---|
| عرف درآمد کریں۔ | `@` (`@/components/...` `src/` کی طرف اشارہ کرتا ہے)، یا کوئی اور سابقہ جیسے `~` یا `#app` |
| انداز | Tailwind سی ایس ایس، UnoCSS، وینیلا سی ایس ایس، دیگر (کوئی سی ایس ایس ٹول نہیں، ونیلا جیسی سادہ اسٹائل شیٹ) |
| ORM | SQLModel، SQLAlchemy، کچھوا-ORM، کوئی ڈیٹا بیس نہیں۔ |
| ڈیٹا بیس (ایک ORM کے ساتھ) | SQLite، PostgreSQL، Neon، MySQL / MariaDB، دیگر (آپ URL ٹائپ کرتے ہیں) |

منتخب کردہ ORM کے لیے ڈیٹا بیس ڈرائیور اس کے ساتھ انسٹال ہوتا ہے (`psycopg`، `pymysql`، `asyncpg` یا `aiomysql`)، اور یو آر ایل کو `.env` پر لکھا جاتا ہے۔

پیکجز کو انسٹال کرنے سے پہلے، `nx new` کنکشن چیک کرتا ہے۔ ایک کے بغیر، یہ انسٹال کو چھوڑ دیتا ہے اور آپ کو `uv sync` چلانے اور آپ کے پیکیج مینیجر کے بعد میں انسٹال کرنے کو کہتا ہے۔ ایک کے ساتھ، یہ تاخیر اور ڈاؤن لوڈ کی رفتار کو پرنٹ کرتا ہے، اور کنکشن سست ہونے پر خبردار کرتا ہے (400 ms سے زیادہ، یا 100 KB/s سے کم)۔ ہر انسٹال لائن اس ٹول اور فولڈر کا نام دیتی ہے جسے یہ بھرتا ہے، مثال کے طور پر `pnpm install node_modules` یا `uv sync .venv`۔

## کیا `dev`، `build` اور `start` تخلیق کرتے ہیں۔

ان کے چلانے سے پہلے، تینوں کمانڈز `src/` اور اس کے نیچے ہر فولڈر میں ایک خالی `__init__.py` بناتی ہیں جس میں `.py` یا `.nexy` فائل ہوتی ہے، اس لیے روٹ جیسا کہ `src/routes/users.py` ان سب میں اسی طرح درآمد کرتا ہے۔ موجودہ فائلوں کو کبھی ہاتھ نہیں لگایا جاتا، اور جب آپ فولڈر شامل کرتے ہیں تو `nx dev` دوبارہ ایسا ہی کرتا ہے۔ Python بائٹ کوڈ `__nexy__/__pycache__` پر جاتا ہے، لہذا آپ کے ذرائع کے آگے کوئی `__pycache__` فولڈر ظاہر نہیں ہوتا ہے۔

## زبان

کمانڈ لائن انگریزی، چینی، ہندی، ہسپانوی، پرتگالی، فرانسیسی، جرمن، جاپانی، روسی، کورین، انڈونیشیائی اور عربی بولتی ہے۔ یہ ان میں سے پہلا استعمال کرتا ہے جس کی یہ حمایت کرتا ہے:

1. دی `NEXY_LANG` ماحولیاتی متغیر (`NEXY_LANG=ja nx dev`)؛
2. آپ کے شیل کے مقامی متغیر (`LC_ALL`، `LC_MESSAGES`، `LANG`، پھر `LANGUAGE`)؛
3. آپ کے آپریٹنگ سسٹم کی زبان۔

اور کچھ بھی انگریزی ہے، اور اسی طرح کوئی بھی پیغام ہے جس کی زبان ابھی تک نہیں ہے۔ صرف وہی جو `nx` پرنٹس کا ترجمہ کیا جاتا ہے: کمپائلر کی خرابیاں، ٹریس بیکس اور اس کے چلنے والے ٹولز کی آؤٹ پٹ جوں کی توں رہتی ہے۔ مقامی بولنے والوں کی طرف سے ابھی تک تراجم کا جائزہ نہیں لیا گیا ہے: `nexy/modules/i18n/<language>.json` کو کھینچنے کی درخواست کے طور پر تصحیح کا خیرمقدم کیا جاتا ہے۔

## طرز عمل بنائیں

`nx build` روٹس کو مرتب کرتا ہے، پھر جب `useVite` آن ہوتا ہے تو کلائنٹ کو بنڈل کرتا ہے۔

> [!NOTE]
> کوئی `--static` جھنڈا نہیں ہے۔ جامد ہوسٹنگ ایک تعیناتی کا انتخاب ہے، نہ کہ تعمیراتی طرز - دیکھیں [تعینات](../deployment/README.md)۔

## خود Nexy پر کام کرنا

اس ذخیرہ کے اندر دروازے ہیں:

```bash
python scripts/verify.py             # lint, format, typecheck, tests
python scripts/audit_dependencies.py # supply-chain audit against the lock
```
