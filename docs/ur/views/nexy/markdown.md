# Markdown اور MDX

مواد کے صفحات کے لیے دو فارمیٹس: `.md` جب آپ کو صرف Markdown کی ضرورت ہو، `.mdx` جب آپ کو اجزاء کی ضرورت ہو۔

## `.md`: خالص Markdown

ایک `.md` فائل خالص مواد ہے۔ Nexy اسے `cmarkgfm` (GFM) کے ساتھ رینڈر کرتا ہے، ہیڈنگ آئی ڈیز جوڑتا ہے، مواد کی ایک میز اخذ کرتا ہے، اور اسے قریب ترین `layout.*` میں لپیٹتا ہے۔

```md filename="src/routes/about.md"
# About

Nexy is a fullstack Python meta-framework.
```

- `.md` میں فرنٹ میٹر کو Python منطق کے طور پر استعمال نہیں کیا جاتا ہے۔ اگر آپ کو سرور منطق کی ضرورت ہے تو `.nexy` استعمال کریں۔
- لے آؤٹ ریپنگ، ایرر پیجز اور ڈائنامک سیگمنٹ دوسرے صفحات کی طرح کام کرتے ہیں۔

## `.mdx`: Markdown اجزاء کے ساتھ

`.mdx` فائلیں **Vite**، فریم ورک روٹ پائپ لائن (React یا Preact) کے ذریعے مرتب کی جاتی ہیں۔ Python صرف پتلی چادر لکھتا ہے جو راستے کی خدمت کرتا ہے۔ یہ کبھی بھی مرتب یا پیش نہیں کرتا ہے۔ MDX خود۔ اجزاء کو فریم ورک کے ذریعہ پیش کیا جاتا ہے، دوسرے اجزاء کے راستوں کی طرح سرور سے پیش کیا جاتا ہے، اور `nx build` کے ذریعہ HTML کو پہلے سے پیش کیا جاتا ہے۔

- `useFF` کا React یا Preact ہونا ضروری ہے۔
- اختیاری پیکجز کی ضرورت ہے `@mdx-js/rollup`، `remark-gfm` اور `@mdx-js/react` (اور `@mdx-js/esbuild` تعمیر کے لیے)۔ Vite آپ کو بتاتا ہے کہ کون سا غائب ہے۔
- فریم ورک کو درآمدات سے خود بخود پتہ چلا ہے: Preact جب فائل درآمد کرتی ہے `preact`، React دوسری صورت میں۔

> [!نوٹ]
> اگر آپ کو فرنٹ میٹر میں Python منطق کی ضرورت ہو تو `.nexy` استعمال کریں۔
