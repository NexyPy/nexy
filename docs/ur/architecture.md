# فن تعمیر

## تعریف

Nexy پانچ پرتوں پر مشتمل ہے، اور ہر ایک کے پاس ایک کام ہے جو دوسرے نہیں کرتے ہیں۔ باؤنڈری کو جاننے سے سب سے زیادہ "یہ اس طرح کیوں کام کرتا ہے" سوالات کا جواب دیتا ہے: ایک سست صفحہ ایک پیش کنندہ سوال ہے، ایک غلط صفحہ ایک روٹر سوال ہے، ایک صفحہ جو کبھی ظاہر نہیں ہوتا ہے ایک کلائنٹ کا سوال ہے۔

یہ صفحہ ان لوگوں کے لیے ہے جو درخواست لکھتے ہیں۔ خود Nexy کے پیکجز، اور ان کے پیچھے میکانزم، `ARCHITECTURE.md` میں ریپوزٹری روٹ میں، شراکت داروں کے لیے بیان کیے گئے ہیں۔

## تہوں

```diagram filename="ایک درخواست، پانچ پرتیں۔"
Browser
   │
   ▼
Uvicorn ───── ASGI transport
   │
   ▼
Middleware ── sessions, CORS, gzip, trusted hosts, your own
   │
   ▼
Router ────── FBR | Modular | Custom ── picks the file that answers
   │
   ▼
Renderer ──── HTML (Jinja2, Markdown, Node) or JSON
   │
   ▼
Response
```

| پرت | ذمہ داری | نہیں |
|---|---|---|
| Uvicorn | کنکشن قبول کریں، ASGI بولیں | جانتے ہیں کہ صفحہ کیا ہے |
| مڈل ویئر | درخواست کو سجائیں: سیشن، CORS، gzip، قابل اعتماد میزبان، HTTPS ری ڈائریکٹ، آپ کا | ایک راستہ منتخب کریں |
| راؤٹر | یو آر ایل کو فائل سے ملاتا ہے، اس کے لے آؤٹ، انحصار اور خرابی والے صفحات کے ساتھ | مواد تیار کرتا ہے |
| پیش کنندہ | صفحہ کو چلائیں اور اس کا نتیجہ HTML یا JSON میں بدلیں | اپنا ڈیٹا حاصل کریں |
| کلائنٹ | Vite اور آپ کا فریم ورک: بنڈلز، ہائیڈریشن، کلائنٹ نیویگیشن | سرور کی درخواست کا جواب دیں |

## کون کیا بناتا ہے۔

| اداکار | کا مالک ہے | مالک نہیں ہے |
|---|---|---|
| Nexy | روٹنگ، سرور رینڈرنگ، ایکشنز، `.nexy` تالیف، ایک اصل | اجزاء، رد عمل، ڈیٹا |
| Vite | کلائنٹ بنڈلز، دیو سرور، ہاٹ ری لوڈ | روٹنگ، سرور رینڈرنگ، ایکشن |
| آپ کا فریم ورک | اجزاء، رد عمل، ماحولیاتی نظام | روٹنگ، دستاویز (Nexy اس کے لے آؤٹ سے پوچھتا ہے) |
| آپ کی درخواست | ڈیٹا، توثیق، اجازت، کاروباری قواعد | ٹرانسپورٹ، رینڈرنگ |

ٹیبل کے پیچھے کا اصول: **Nexy اپنی ملکیت کی چیز بناتا ہے، اور کبھی بھی اسے مرتب نہیں کرتا ہے Vite compiles** ایک جزو کے راستے کے لیے، Python ایک پتلا ریپر ماڈیول لکھتا ہے جو فائل کی طرف اشارہ کرتا ہے۔

## جہاں ایک درخواست کا فیصلہ کیا جاتا ہے۔

1. مڈل ویئر چلتا ہے، اور درخواست کو تبدیل یا روک سکتا ہے۔
2. روٹر ایک فائل اور اس کے آس پاس کی ترتیب کو چنتا ہے۔
3. رینڈرر اس فائل کو اس ڈیٹا کے ساتھ چلاتا ہے جسے وہ خود پڑھتا ہے۔
4. جواب واپس چلا جاتا ہے، اور اگر صفحہ میں JavaScript ہے تو کلائنٹ کی پرت سنبھال لیتی ہے۔

ہر قدم، راؤٹرز اور `nx dev` کی ترتیب کے درمیان عین برتری کے ساتھ، [How Nexy Works](getting-started/how-nexy-works.md) میں ہے۔ یہ صفحہ اسے نہیں دہراتا۔

## ترقی اور پیداوار

وہی پانچ پرتیں، جو دو بار جمع ہوئیں:

| پرت | `nx dev` | `nx build` پھر `nx start` |
|---|---|---|
| کمپائلر | چلتا ہے جب آپ بچاتے ہیں | ایک بار، وقت سے پہلے |
| Vite | دیو سرور، ہاٹ ری لوڈ، پراکسی کے ذریعے Nexy کی اصل | بنڈل `__nexy__/client/` پر لکھا گیا، کوئی دیو سرور نہیں |
| نوڈ | کلائنٹ کے دستاویزات کو ڈیمانڈ پر پیش کرتا ہے | انہیں تعمیر کے وقت پیش کرتا ہے، پیش کرتے وقت نہیں |
| واچر | تبدیلی پر یوویکورن کو دوبارہ شروع کرتا ہے | غیر حاضر |
| اصل | ایک بندرگاہ | ایک بندرگاہ |

*جب* کام ہوتا ہے تو کیا تبدیلی آتی ہے، یہ نہیں کہ *کون* کرتا ہے۔ ایک صفحہ جو دونوں کے درمیان مختلف طریقے سے برتاؤ کرتا ہے وہ صفحہ میں ایک بگ ہے، موڈ کی خاصیت نہیں۔

## حدود

Nexy آپ کی درخواست کے کنارے پر رک جاتا ہے، جان بوجھ کر:

| تشویش | کیا Nexy فراہم کرتا ہے | جو آپ لکھتے ہیں |
|---|---|---|
| توثیق | سیشن مڈل ویئر، `AuthenticationMiddleware` جب فعال کیا جاتا ہے | لاگ ان، صارف کی تلاش، کوکی پالیسی |
| اجازت | `dependencies.py`، محافظ، فی فولڈر وراثت | خود اصول |
| ڈیٹا بیس | کچھ بھی نہیں: کوئی ORM نہیں، کوئی منتقلی نہیں | ماڈل پرت ([ڈیٹا بیسز](guides/databases.md)) |
| بین الاقوامی کاری | آپ کے صفحات کے لیے کچھ نہیں؛ صرف CLI کا ترجمہ کیا جاتا ہے | لائبریری اور پیغامات ([i18n](guides/i18n.md)) |
| پس منظر کی ملازمتیں | کچھ بھی نہیں: کوئی قطار نہیں، کوئی شیڈولر نہیں | کارکن کا عمل |
| ای میل، ادائیگی، تلاش | کچھ بھی نہیں | آپ جو خدمت منتخب کرتے ہیں |

تمام چھ کی وجہ ایک جیسی ہے: ایک فریم ورک جو آپ کے ORM یا آپ کی auth لائبریری کو چنتا ہے ان چیزوں کا فیصلہ صرف آپ کی درخواست ہی کر سکتی ہے۔ لاگت واضح ہے: آپ کے لیے کچھ بھی وائرڈ نہیں ہے، اور اوپر گائیڈ کے صفحات بتاتے ہیں کہ ہر ایک کو کہاں سے لگانا ہے۔
