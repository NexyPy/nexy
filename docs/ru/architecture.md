# Архитектура

## Определение

Nexy состоит из пяти слоев, и каждый из них выполняет свою работу, которую другие не выполняют. Знание границ отвечает на большинство вопросов
вопросы "почему это так работает": медленная страница - вопрос рендерера, неправильная страница - роутера
вопрос, страница, которая никогда не появляется, является вопросом клиента.

Эта страница предназначена для людей, пишущих приложения. Пакеты самого Nexy и механизмы
за ними описаны в `ARCHITECTURE.md` в корне репозитория для участников.

## Слои

```diagram filename="Один запрос, пять слоев"
Browser
   │
   ▼
Uvicorn ───── ASGI transport
   │
   ▼
Middleware ── sessions, CORS, gzip, trusted hosts, your own
   │
   ▼
Router ────── FBR | Modular | Custom ── picks the file that answers
   │
   ▼
Renderer ──── HTML (Jinja2, Markdown, Node) or JSON
   │
   ▼
Response
```

| Уровень | Ответственность | Не |
|---|---|---|
| Ювикорн | примите соединение, говорите на ASGI | узнайте, что такое страница |
| Промежуточное программное обеспечение | оформляем запрос: сессия, CORS, gzip, доверенные хосты, перенаправление HTTPS, ваш | выбираете маршрут |
| Маршрутизатор | сопоставляет URL-адрес с файлом с его макетами, зависимостями и страницами ошибок | создает контент |
| Рендерер | запустите страницу и преобразуйте ее результат в HTML или JSON | получите ваши данные |
| Клиент | Vite и ваш фреймворк: пакеты, гидратация, навигация по клиенту | ответ на запрос сервера |

## Кто что строит

| Актер | Владеет | Не владеет |
|---|---|---|
| Nexy | маршрутизация, серверный рендеринг, действия, `.nexy` компиляция, компоненты одного происхождения | реактивность, данные |
| Vite | клиентские пакеты, сервер разработки, горячая перезагрузка | маршрутизация, рендеринг сервера, действия |
| Ваш фреймворк, | компоненты, реактивность, экосистема, | маршрутизация, документ (Nexy запрашивает его макет) |
| Ваше приложение | данные, аутентификация, авторизация, бизнес-правила | транспорт, рендеринг |

Правило таблицы: **Nexy строит то, что ей принадлежит, и никогда не компилирует то, что компилирует Vite.** Ибо
маршрут компонента, Python пишет тонкий модуль-оболочку, указывающий на файл.

## При принятии решения по запросу

1. Промежуточное ПО запускается и может изменить запрос или остановить его.
2. Маршрутизатор выбирает один файл и макеты вокруг него.
3. Средство визуализации запускает этот файл с данными, которые он считывает сам.
4. Ответ возвращается, и клиентский уровень берет на себя управление, если на странице есть JavaScript.

Каждый шаг с точным приоритетом между маршрутизаторами и порядком `nx dev` находится в
[Как работает Nexy](getting-started/how-nexy-works.md). Эта страница не повторяет его.

## Разработка и производство

Те же пять слоев, собранных дважды:

| Слой | `nx dev` | `nx build` затем `nx start` |
|---|---|---|
| Компилятор | запускается при сохранении | запускается один раз, заранее |
| Vite | сервер разработки, горячая перезагрузка, проксирование через исходный пакет Nexy | записан на `__nexy__/client/`, нет сервера разработки |
| Узел | отображает клиентские документы по запросу | отображает их при сборке, а не во время обслуживания |
| Watcher | перезапускает uvicorn при изменении | отсутствует |
| Источник | один порт | один порт |

Что меняется, так это *когда* работа происходит, а не *кто* ее выполняет. Страница, которая ведет себя по-разному
два — это ошибка на странице, а не свойство режима.

## Границы

Nexy намеренно останавливается на границе вашего приложения:

| Забота | Что предоставляет Nexy | Что вы пишете |
|---|---|---|
| Аутентификация, | промежуточное программное обеспечение сеанса, `AuthenticationMiddleware` при включении, | вход в систему, поиск пользователя, политика использования файлов cookie |
| Авторизация | `dependencies.py`, защита, наследование для каждой папки | само правило |
| База данных | ничего: ни ORM, ни миграций | уровень модели ([Базы данных](guides/databases.md)) |
| Интернационализация | ничего для ваших страниц; транслируется только CLI | библиотека и сообщения ([i18n](guides/i18n.md)) |
| Фоновые задания | ничего: ни очереди, ни планировщика, | рабочий процесс |
| Электронная почта, платежи, поиск | ничего | выбранной вами услуги |

Причина одна и та же для всех шести: фреймворк, который выбирает ваш ORM или вашу библиотеку аутентификации, решает.
вещи, которые может решить только ваше приложение. Цена очевидна: для вас ничего не подключено, и
На страницах руководства выше указано, где подключить каждый из них.
