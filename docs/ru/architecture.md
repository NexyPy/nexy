# Архитектура

## Определение

Nexy состоит из пяти слоев, и каждый из них выполняет свою работу, которую другие не выполняют. Знание границ отвечает на большинство вопросов «почему это так работает»: медленная страница — это вопрос рендерера, неправильная страница — это вопрос маршрутизатора, страница, которая никогда не появляется, — это вопрос клиента.

Эта страница предназначена для людей, пишущих приложения. Пакеты самого Nexy и механизмы, лежащие в их основе, описаны в `ARCHITECTURE.md` в корне репозитория для участников.

## Слои

```diagram filename="Один запрос, пять слоев"
Browser
   │
   ▼
Uvicorn ───── ASGI transport
   │
   ▼
Middleware ── sessions, CORS, gzip, trusted hosts, your own
   │
   ▼
Router ────── FBR | Modular | Custom ── picks the file that answers
   │
   ▼
Renderer ──── HTML (Jinja2, Markdown, Node) or JSON
   │
   ▼
Response
```

| Уровень | Ответственность | Не |
|---|---|---|
| Uvicorn | подтвердите соединение, говорите по ASGI | узнайте, что такое страница |
| Промежуточное программное обеспечение | оформляет запрос: сессия, CORS, gzip, доверенные хосты, перенаправление HTTPS, ваш | выбирает маршрут |
| Маршрутизатор | сопоставляет URL-адрес с файлом с его макетами, зависимостями и страницами ошибок | создает контент |
| Рендерер | запускает страницу и преобразует ее результат в HTML или JSON | получает ваши данные |
| Клиент | Vite и ваш фреймворк: пакеты, гидратация, клиентская навигация | отвечают на запрос сервера |

## Кто что строит

| Актер | Владеет | Не владеет |
|---|---|---|
| Nexy | маршрутизация, серверный рендеринг, действия, `.nexy` компиляция, компоненты одного источника | реактивность, данные |
| Vite | клиентские пакеты, сервер разработки, горячая перезагрузка | маршрутизация, серверный рендеринг, действия |
| Компоненты вашего фреймворка, | реактивность, маршрутизация экосистемы, | документ (Nexy запрашивает его макет) |
| Данные вашего приложения | аутентификация, авторизация, бизнес-правила | транспорт, рендеринг |

Правило, лежащее в основе таблицы: **Nexy собирает то, что ему принадлежит, и никогда не компилирует то, что компилирует Vite.** Для маршрута компонента Python пишет тонкий модуль-оболочку, указывающий на файл.

## Где принимается решение по запросу

1. Промежуточное программное обеспечение запускается и может изменить запрос или остановить его.
2. Маршрутизатор выбирает один файл и макеты вокруг него.
3. Средство визуализации запускает этот файл с данными, которые он считывает сам.
4. Ответ возвращается, и клиентский уровень берет на себя управление, если на странице есть JavaScript.

Каждый шаг с точным приоритетом между маршрутизаторами и порядком `nx dev` описан в [Как работает Nexy](getting-started/how-nexy-works.md). Эта страница не повторяет его.

## Разработка и производство

Те же пять слоев, собранных дважды:

| Слой | `nx dev` | `nx build` затем `nx start` |
|---|---|---|
| Компилятор | запускается при сохранении | запускается один раз, заранее |
| Vite | сервер разработки, горячая перезагрузка, прокси через исходный пакет Nexy | записан на `__nexy__/client/`, нет сервера разработки |
| Узел | отображает клиентские документы по запросу | отображает их при сборке, а не во время обслуживания |
| Watcher | перезапускает uvicorn при изменении | отсутствует |
| Исходный | один порт | один порт |

Что меняется, так это *когда* работа происходит, а не *кто* ее выполняет. Страница, которая ведет себя по-разному, является ошибкой на странице, а не свойством режима.

## Границы

Nexy намеренно останавливается на границе вашего приложения:

| Забота | Что предоставляет Nexy | Что вы пишете |
|---|---|---|
| Аутентификация | промежуточное программное обеспечение сеанса, `AuthenticationMiddleware` при включении | вход в систему, поиск пользователя, политика использования файлов cookie |
| Авторизация | `dependencies.py`, защита, наследование для каждой папки | само правило |
| База данных | ничего: ни ORM, ни миграций | уровень модели ([Базы данных](guides/databases.md)) |
| Интернационализация | ничего не значит для ваших страниц; транслируется только CLI | библиотека и сообщения ([i18n](guides/i18n.md)) |
| Фоновые задания | ничего: ни очереди, ни планировщика, | рабочий процесс |
| Электронная почта, платежи, поиск | ничего | выбранной вами услуги |

Причина одна и та же для всех шести: фреймворк, который выбирает ваш ORM или вашу библиотеку аутентификации, решает то, что может решить только ваше приложение. Стоимость очевидна: для вас ничего не подключено, а на страницах руководства выше указано, куда подключать каждый из них.
