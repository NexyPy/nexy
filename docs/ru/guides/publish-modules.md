# Как опубликовать модуль в реестре Nexy?

Запустите `nx publish` из каталога модуля с действительным `nx.toml`, токеном реестра и каждым файлом, объявленным в манифесте; команда проверяет выпуск, создает один архив и загружает неизменяемую версию.

## Подготовьте манифест

Исходный модуль перечисляет каждый поставляемый файл. В архиве находятся `nx.toml` и именно эти файлы.

```toml filename="nx.toml"
name = "@acme/auth"
version = "1.2.0"
kind = "source"

[compatibility]
nexy = ">=2.0.0"
python = ">=3.12"

[dependencies]
python = []
node = []

[source]
files = ["src/auth.py", "src/helpers.py"]
```

Поле `name` должно быть написано строчными буквами `@scope/name`. Поле `version` должно содержать три числа, разделенных точками. Файлы должны иметь относительные пути внутри модуля. Модуль пакета объявляет `source.package` вместо `source.files`.

## Проверьте перед загрузкой

Используйте `--dry-run` для проверки манифеста, архивирования объявленных файлов и печати контрольной суммы без загрузки:

```bash
nx publish --dry-run
```

Пробный прогон не требует жетона. Он печатает строку `warning:` для каждого относительного импорта, указывающую на файл, который не объявлен в манифесте. Например, для `from .helpers import token` в `src/auth.py` требуется `src/helpers.py` в `source.files`, иначе при установке будет нарушен импорт.

## Установить токен

`nx publish` читается `NEXY_REGISTRY_TOKEN`, затем `~/.config/nexy/registry-token`. Токен отправляется в заголовке `Authorization` и никогда не печатается.

```bash
export NEXY_REGISTRY_TOKEN="your-token"
nx publish
```

Файл токена позволяет будущему `nx login` записать те же учетные данные. Без какого-либо источника команда печатает `error: No registry token` и завершает работу со статусом 1.

## Опубликовать

```bash
nx publish
```

Команда выводит имя, версию и контрольную сумму SHA-256 опубликованного выпуска. Пара имени и версии является неизменяемой: ее повторная публикация приведет к ошибке конфликта. Вместо этого опубликуйте новую версию.

## Используйте другой реестр

По умолчанию команда отправляет сообщения в `https://registry.nexypy.dev`. Используйте `--registry` для другого реестра, например локального во время разработки:

```bash
nx publish --registry http://localhost:8000
```

Принимаются только URL-адреса https, а также простой http на `localhost`, `127.0.0.1` и `::1`. Временные ответы `429` и `5xx` повторяются дважды; неверный манифест, отсутствующий токен или конфликт не повторяются.

## Проверьте выпуск

```bash
nx add @acme/auth@1.2.0
```

См. [Установить модули](install-modules.md) для обновлений, контактов и настроек доверия.
