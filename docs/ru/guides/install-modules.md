# Как установить модуль из реестра?

Запустите `nx add @scope/name` в проекте Nexy, чтобы загрузить одну версию из реестра модуля, проверить ее и применить заявленные изменения. Добавьте `@1.2.0`, чтобы закрепить точную версию.

## Установить модуль

Из корня проекта Nexy:

```bash
nx add @acme/auth
nx add @acme/auth@1.2.0
```

`nx add` считывает метаданные выпуска и архив из `useModuleRegistry`, проверяет контрольную сумму SHA-256 и проверяет диапазоны совместимости модуля `nexy` и `python`. Затем он записывает только те файлы, которые объявлены в манифесте, добавляет объявленные пакеты Python с помощью `uv add`, добавляет пакеты Node с помощью менеджера пакетов проекта и применяет перехватчики конфигурации к `nexyconfig.py` и `package.json`. Существующие настройки и файлы остаются такими же, как они есть: объявленный файл, который уже существует, пропускается со строкой `warning:`.

Каждая успешная установка записывается в `.nexy/modules.json`. Зафиксируйте этот файл, чтобы товарищ по команде получил ту же версию модуля.

## Обновить модуль

Для обновления запустите `nx add @acme/auth` еще раз после того, как в реестре появится более новая версия, или установите новый PIN-код, например `@acme/auth@1.3.0`. Незакрепленное имя выбирает самую новую версию из ответа реестра `/versions`. Повторный запуск той же версии выводит `is already installed` и ничего не меняет.

## Закрепить версию

Пин точен: `nx add @acme/auth@1.2.0` устанавливает `1.2.0` и никакой другой выпуск. Используйте пин-код в CI и в зафиксированном `.nexy/modules.json`, чтобы при каждой проверке устанавливался один и тот же код. Без PIN-кода новый выпуск заменяет следующую установку.

## Запуск миграции

По умолчанию миграция отключена. Добавьте `--migrate`, если вы хотите, чтобы объявленные команды релиза выполнялись после того, как его файлы и зависимости установлены:

```bash
nx add @acme/auth@1.2.0 --migrate
```

Каждая команда печатается перед выполнением. В проекте необходимо установить инструмент миграции, прежде чем модуль сможет его объявить.

## Установите реестр и его правила доверия

Значения по умолчанию находятся в `nexyconfig.py`:

```python filename="nexyconfig.py"
class NexyConfig(NexyConfigModel):
    useModuleRegistry = "https://registry.nexypy.dev"
    useRequireSignedModules = False
```

`useModuleRegistry` — это базовый URL-адрес, который читает CLI. Принимаются только URL-адреса https, за исключением HTTP обратной связи для локального реестра во время разработки. `useRequireSignedModules = True` отказывается от неподписанного релиза. Релиз, содержащий подпись, также отклоняется до тех пор, пока не будет доступен верификатор; как только кто-то это проверит, `nx add` печатает `Verified by` с идентификационными данными подписывающего лица. Оставьте значение по умолчанию `False` только для реестров, которым вы доверяете.
