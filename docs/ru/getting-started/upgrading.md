# Обновление до 2.2

Что изменится в существующем проекте при переходе с 2.1 на 2.2 и что с этим делать. Полный список можно найти в [журнал изменений](https://github.com/NexyPy/nexy/blob/main/CHANGELOG.md).

```bash
uv add "nexy>=2.2"            # or: uv tool upgrade nexy
nx build
nx test
```

## Что вам, возможно, придется изменить

| Измените | Сделайте это |
|---|---|
| **`.mdx` компилируется только Vite.** Компилятор Python больше не отображает его | Оставьте React или Preact в `useFF` и установите `@mdx-js/rollup`, `remark-gfm` и `@mdx-js/react`. Страница без компонентов может быть файлом `.md` вместо |
| **`useBadge` исчез.** Тег «Создано с помощью Nexy» больше не существует. | Удалите строку из `nexyconfig.py`. Оставшаяся строка игнорируется |
| **`nx check` больше не компилируется `.mdx`** | Ничего: Vite сообщает MDX об ошибках при сборке |

## Что остается прежним

- Ваши маршруты, макеты, действия и настройки.
- Существующие проекты сохраняют свои стартовые страницы. Новый стартовый дизайн применяется только к проектам, созданным после обновления.
- Панель инструментов разработки и `useDevTools`.

## Новое в версии 2.2

- **Файлы агентов.** `nx new` записывает `AGENTS.md`, `CLAUDE.md` и навыки кодирования агентов. Если проект у вас уже есть, запустите `nx skills`. Он никогда не перезаписывает написанный вами файл. См. [Агенты кодирования](../guides/ai-agents.md).
- **Сервер разработки, который продолжает работать.** Если ваше приложение не может запуститься, `nx dev` сообщает, почему, и вместо выхода ждет следующего изменения.
- **Новый стартовый** для каждого фреймворка в Tailwind или UnoCSS с теми же страницами и компонентами.
- **UnoCSS читает `.nexy` файлы** в серверном проекте. Если вы используете UnoCSS со страницами `.nexy`, добавьте блок `content`, показанный в [Устранение неполадок](../guides/troubleshooting.md).

## Исправленная документация

На трех страницах говорилось о том, чего код не делает. Если вы следовали им, проверьте свои файлы:

- Компонент `.nexy` размещает своих дочерних элементов с `<Slot />` (заглавной S), а не с `<slot />`.
- Файл компонента `.nexy` имеет имя в PascalCase: он импортируется как модуль Python, поэтому дефис не компилируется.
- Для `.mdx` основой является Preact, если файл импортирует `preact`, в противном случае - React.
