# Как развернуть приложение Nexy на Vercel?

Запустите `nx add vercel`, зафиксируйте сгенерированные файлы вместе с выходными данными `nx build` и укажите среде выполнения Vercel Python на `src/server.py:app`.

## Добавьте файлы платформы

Из корня проекта Nexy:

```bash
nx add vercel
nx build
```

`nx add vercel` записывает `src/server.py` и `vercel.json`. Он также добавляет правила игнорирования для файлов, которые изменяются во время работы приложения: `__nexy__/build-cache.json`, `__nexy__/server.port`, `__nexy__/.temp/` и `__pycache__/`. Повторный запуск команды сохраняет уже существующие файлы и не дублирует правила игнорирования.

## Наведите курсор на Версель в приложении.

В настройках проекта Vercel выберите среду выполнения Python и используйте `src/server.py:app` в качестве точки входа. Vercel обнаруживает имя `app` в этом модуле; `nx start` не участвует.

Сгенерированный `src/server.py` импортирует ленивый `nexy.app.app` после того, как он подготовил рабочую папку. Вы можете использовать ту же точку входа с `uvicorn src.server:app` локально.

## Зафиксировать результат сборки

Когда у Vercel нет команды сборки, он получает только то, что содержится в репозитории. Фиксируйте `__nexy__/` после каждого `nx build` с скомпилированными маршрутами, клиентским пакетом в `__nexy__/client/` и манифестом в `__nexy__/client/.vite/manifest.json`.

Сохраните `vite.config.ts` в корне проекта и зафиксируйте его. В рабочей среде Nexy читает манифест Vite для записи тегов таблицы стилей и сценария, но создает эти теги только тогда, когда `vite.config.ts` существует. Без этого файла страница по-прежнему отвечает на 200 и приходит без CSS или клиента JavaScript.

Не фиксируйте `__nexy__/build-cache.json`: он содержит абсолютные пути от компьютера, на котором выполнялась сборка. `__nexy__/server.port` принадлежит `nx start`, а `__nexy__/.temp/` — это рабочее пространство.

## Принять файловую систему только для чтения

Vercel монтирует проект только для чтения при запуске приложения Python. Nexy записывает сгенерированные файлы во время запуска, поэтому голый `from nexy.app import app` может потерпеть неудачу с `OSError: [Errno 30] Read-only file system`.

Созданная точка входа копирует шесть элементов проекта во временную папку, доступную для записи, перед импортом приложения: `src`, `__nexy__`, `public`, `nexyconfig.py`, `pyproject.toml` и `vite.config.ts`. Он меняет рабочий каталог и сначала помещает копию в `sys.path`, поскольку Nexy разрешает маршруты из текущего каталога. Добавьте в этот список вручную любой другой файл, который ваше приложение читает во время выполнения.

## Кэшировать статические ресурсы

Сгенерированный `vercel.json` содержит два правила кэширования, которые использует развернутый сайт Nexy: файлы в `/assets/` являются неизменяемыми в течение одного года, а изображения и шрифты в `public/` остаются свежими в течение одного дня с недельным окном устаревания при повторной проверке. Добавьте другие правила в тот же файл, если они нужны вашему проекту.

## Проверьте развертывание

Перед отправкой импортируйте точку входа и запросите у нее одну страницу:

```bash
uv run python -c "from src.server import app; print(type(app).__name__)"
uv run uvicorn src.server:app
```

Затем откройте `/`, один сгенерированный маршрут и один файл в `/assets/`. Сравните ответ с `nx start` локально: статус, тип и размер контента должны совпадать. Страница, которая меньше локальной ровно на два клиентских тега, означает, что `vite.config.ts` отсутствовал в скопированном проекте.
