# Маршрутизация

У Nexy два родных роутера. Вы можете выбрать по одному для каждой функции; они могут сосуществовать в одном приложении.

**Не уверен? Используйте маршрутизацию на основе файлов.** Она охватывает страницы и конечные точки API без какой-либо настройки. Добавьте модульный маршрутизатор, если серверной части нужны контроллеры, внедренные службы или средства защиты.

| Вы строите | Используйте |
|---|---|
| Страницы, контент, сайт с несколькими конечными точками | На основе файлов |
| Большой API с общими службами для разных маршрутов | Модульный |
| Оба: страницы для людей, структурированный API для машин | Файловый и модульный вместе |

```diagram filename="Файловый маршрутизатор, краткий обзор"
src/routes/index.nexy           →  /
src/routes/about.nexy           →  /about
src/routes/blog/index.nexy      →  /blog
src/routes/blog/[slug].nexy     →  /blog/:slug
src/routes/(app)/dashboard.nexy →  /dashboard
src/routes/api/users.py         →  /api/users  (GET, POST, …)
```

| Маршрутизатор | Источник | Включено |
|---|---|---|
| [На основе файлов (FBR)](fbr/README.md) | каждый файл в `src/routes/` | каталог существует |
| [Модульные](modular/README.md) | контроллеры и модули | `useRouter = AppModule` в `nexyconfig.py` |

FBR сканируется всякий раз, когда `src/routes/` существует, даже если установлен модульный маршрутизатор.

## Сосуществование и приоритеты

Вы можете комбинировать FBR, модульную и пользовательскую интеграцию. Nexy регистрирует эти маршруты в порядке их обнаружения. Если два маршрутизатора определяют один и тот же путь URL-адреса, побеждает первый зарегистрированный. 

*Примечание. Nexy в настоящее время не обеспечивает диагностику конфликтов URL-адресов; первый маршрут, претендующий на путь, просто затеняет остальные.*

## Маршрутизация на основе файлов

Маршрут — это файл. URL-адрес — это его путь в `src/routes/` без расширения. Как и Next.js, проект находится в одном из двух режимов, выбранных с помощью `useCSR`:

| | `useCSR = False` (по умолчанию) | `useCSR = True` |
|---|---|---|
| Страницы | `.nexy`, `.md`, `.mdx` | файлы вашей клиентской платформы |
| Корневая раскладка | `layout.nexy` | `layout.tsx` (React) |
| Клиентские компоненты | разрешены, как острова внутри страниц | сами страницы |
| Маршруты API | `.py` | `.py` |

См. [Режим сервера и режим клиента](fbr/modes.md).

| Раздел | Что он охватывает |
|---|---|
| [fbr/pages](fbr/pages/README.md) | страницы, [динамические маршруты](fbr/pages/dynamic-routes.md) и группы маршрутов |
| [fbr/layouts](fbr/layouts/README.md) | `layout.nexy`, `layout.tsx`, `layout.vue`, `layout.svelte` |
| [fbr/handlers](fbr/handlers/README.md) | `.py` обработчики маршрутов, [проверка и ошибки](fbr/handlers/validation-and-errors.md) |
| [fbr/dependents](fbr/dependencies/README.md) | `dependencies.py` и охранники, унаследованные каталогом |
| [fbr/middleware](fbr/middleware/README.md) | `middleware.py`, наследуется каталогом |
| [fbr/errors](fbr/errors/README.md) | `notfound.nexy`, `errors.nexy`, ошибки JSON |
| [fbr/navigation](fbr/navigation/linking-and-navigating.md) | связывание, клиентская навигация, [крючки](fbr/navigation/hooks.md) |
| [fbr/realtime](fbr/realtime/websocket.md) | WebSocket обработчики |
| [fbr/inheritance](fbr/inheritance.md) | как наследуются макеты, зависимости и страницы ошибок |
