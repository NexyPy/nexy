# Страницы внешнего интерфейса

**Страница** — это базовая единица приложения Nexy. Это ресурс с URL-адресом, определенный в файле в `src/routes/`. 

Независимо от используемой клиентской платформы, каждая страница соответствует одному и тому же универсальному жизненному циклу и архитектурным ограничениям.

## Жизненный цикл страницы

Когда пользователь переходит на страницу, Nexy выполняет следующие шаги:

1.  **Сопоставление маршрутов**: маршрутизатор идентифицирует файл, соответствующий URL-адресу.
2.  **Извлечение данных**: сервер выполняет логику страницы (Python фронтматер или загрузчик платформы) для получения необходимых данных.
3.  **Композиция**: страница заключена в ближайший к ней `layout.nexy` (или макет структуры).
4.  **Рендеринг**: результат отображается в HTML (через Jinja2, Markdown или SSR платформы).
5.  **Гидратация**: если страница использует клиентскую платформу, браузер присоединяет интерактивную логику к статическому HTML.

## Маршрутизация и URL-адреса

Маршрутизация строго файловая. URL-адрес определяется путем к файлу в разделе `src/routes/` за вычетом расширения.

### Динамические сегменты
Чтобы создать маршрут, который зависит от параметра (например, профиля пользователя), используйте квадратные скобки:
- `src/routes/user/[id].tsx` → `/user/123`

Значение сегмента (`123`) доступно странице через перехватчик `useParams()` из `@nexy/client`.

### Группы маршрутов
Папки, заключенные в круглые скобки, игнорируются маршрутизатором, но позволяют группировать файлы для организационных целей или общих макетов:
- `src/routes/(auth)/login.tsx` → `/login`

## Метаданные страницы
Каждая страница может определять метаданные (заголовок, описание, теги OpenGraph), которые Nexy вводит в оболочку документа. В файлах `.nexy` это делается во вступительной части; в файлах фреймворка он предоставляется через экспорт `metadata`.
