# Markdown и MDX

Два формата страниц контента: `.md` — когда вам нужны только Markdown, `.mdx` — когда вам нужны компоненты.

## `.md`: чистый Markdown

Файл `.md` — это чистый контент. Nexy отображает его как Markdown в стиле GitHub (таблицы, списки задач, зачеркивание, ссылки), добавляет идентификаторы заголовков, извлекает оглавление и оборачивает его в ближайший `layout.*`.

```md filename="источник/маршруты/about.md"
# About

Nexy is a fullstack Python meta-framework.
```

- Frontmatter в `.md` не используется как логика Python. Если вам нужна серверная логика, используйте `.nexy`.
- Необработанный HTML-код на странице `.md` отображается как текст и никогда не запускается. Если вам нужен HTML, используйте `.nexy`.
- Перенос макета, страницы ошибок и динамические сегменты работают так же, как и другие страницы.

## `.mdx`: Markdown с компонентами

Файлы `.mdx` компилируются **Vite** через конвейер маршрутизации платформы (React или Preact). Python записывает только тонкую оболочку, обслуживающую маршрут; он никогда не компилирует и не отображает MDX сам. Компоненты визуализируются платформой, сервером, как и другие маршруты компонентов, и предварительно визуализируются в HTML с помощью `nx build`.

- Требуется, чтобы `useFF` было React или Preact.
- Требуются дополнительные пакеты `@mdx-js/rollup`, `remark-gfm` и `@mdx-js/react` (и `@mdx-js/esbuild` для сборки). Vite сообщит вам, какой из них отсутствует.
- Платформа автоматически определяется при импорте: Preact при импорте файла, `preact` и React в противном случае.

> [!NOTE]
> используйте `.nexy`, если вам нужна логика Python во вступительной части.
