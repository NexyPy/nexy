# ISR (устаревший при повторной проверке)

## Определение

ISR кэширует HTML-код одной страницы для каждого URL-адреса и обслуживает его до истечения срока действия окна. Копия с истекшим сроком действия по-прежнему обслуживается, пока в фоновом режиме отображается новая: то есть *устаревшая при повторной проверке*.

## Как это работает

`revalidate = N` в заголовке страницы `.nexy` включает его. `N` — количество секунд; отсутствие, нулевое или отрицательное значение означает отсутствие кэша вообще.

Ключом кэша является только **путь запроса** — `request.scope["path"]`. Строка запроса не является его частью.

| Что | Значение |
|---|---|
| Ключ | URL-путь (`/blog/hello`) |
| Хранение | выбрано `useISRCache`: память по умолчанию, файл, Redis или пользовательское хранилище. |
| Связанный | 256 записей в хранилище памяти, выселены последние использованные; файл и Redis сохраняют записи до тех пор, пока они не станут недействительными. |
| Заголовок ответа | `cache-control: public, s-maxage=N, stale-while-revalidate=N` |

Каждый ответ ISR содержит этот заголовок, включая первый рендеринг и резервный рендеринг, когда хранилище не работает. CDN может использовать его для хранения собственной копии того же общедоступного URL-адреса.

## Жизненный цикл рендеринга

1. Поступает запрос на страницу, на которой объявлено `revalidate`.
2. Записей пока нет: страница отображается, сохраняется и возвращается.
3. Запись моложе `N` секунд: возвращается как есть, страница не отображается.
4. Запись старше `N` секунд: запись **stale** возвращается немедленно, а фоновая задача отображает новую.
5. Если фоновый рендеринг завершается неудачно, устаревшая запись остается, и следующий устаревший запрос повторяется.
6. В случае сбоя хранилища страница отображается и возвращается без кэшированной записи. Запрос по-прежнему выполняется.

## Когда использовать

- Один и тот же HTML-код для каждого посетителя: сообщение в блоге, страница продукта, страница документации.
- Страница читается часто и меняется редко.
- Данные могут быть датированы несколькими секундами, и никто этого не заметит.

## Конфигурация

```nexy filename="src/маршруты/блог/index.nexy"
---
revalidate = 60
---
<h1>Rendered at most once per minute</h1>
```

`N` — простое целое число. В другом месте нет переопределения для каждого маршрута, а обработчики `.py` не являются страницами: они никогда не попадают в этот кеш.

## Выберите магазин

Установите `useISRCache` в `nexyconfig.py`:

```python filename="nexyconfig.py"
from nexy.core.models import NexyConfigModel


class NexyConfig(NexyConfigModel):
    useISRCache = "file"
```

| Значение | Магазин | Поделились |
|---|---|---|
| не установлено, `None` или `"memory"` | память процесса, ограниченная 256 записями | один рабочий |
| `"file"` | Файлы JSON в `.nexy/isr` | рабочие на одном хосте |
| `{"type": "file", "directory": ".cache/isr"}` | JSON-файлы в указанном каталоге | рабочие на одном хосте |
| `"redis"` | Redis в `redis://localhost:6379/0` | любой работник, который достигает сервера |
| `{"type": "redis", "url": "redis://cache:6379/0"}` | Redis по этому URL-адресу | любой работник, который достигает сервера |
| `{"type": "redis", "client": client}` | клиент Redis, который вы передаете | любой работник, который достигает сервера |
| объект с `get`, `set` и `invalidate` | твой собственный магазин | все, что оно разделяет |

Магазину Redis нужен клиентский пакет: `uv add redis`. Не устанавливается вместе с Nexy. Пользовательское хранилище реализует протокол `ISRCache` из `nexy.modules.runtime.cache`; его `get` возвращает `CacheEntry` или `None`.

Записи файла записываются атомарно, поэтому рабочий никогда не читает наполовину написанную страницу. Работники, использующие один и тот же каталог или один и тот же сервер Redis, читают одну и ту же запись. Неработающий магазин стоит только рендера: он никогда не отвечает на запрос ошибкой.

## Пример

Сообщение в блоге, которое читает базу данных:

```nexy filename="src/маршруты/блог/[слизняк].nexy"
---
revalidate = 300
slug: prop[str] = "untitled"
posts = {"hello": {"title": "Hello"}, "other": {"title": "Other"}}
post = posts.get(slug, {"title": "Untitled"})
---
<h1>{{ post.title }}</h1>
```

Первый запрос к `/blog/hello` обрабатывается и сохраняется. Следующие 300 секунд обслуживаются из выбранного магазина. `/blog/other` — это отдельная запись, отображаемая и сохраняемая отдельно. В реальном проекте `posts` поступает из базы данных или службы, вызываемой один раз при регенерации.

## Чем CDN может и не может делиться

CDN, который учитывает `cache-control`, может хранить одну копию `/blog/hello` в течение `s-maxage` секунд и обслуживать ее во время повторной проверки. Он делится этой копией между посетителями и работниками, потому что в ответе говорится `public`.

CDN не знает магазина Nexy. `revalidate()` в [Действии](../guides/actions.md) удаляет запись из настроенного хранилища Nexy, но не очищает CDN. CDN хранит свою копию до тех пор, пока не завершится собственное окно или пока вы не настроите ее очистку.

Не предоставляйте CDN страницу, HTML которой зависит от посетителя. В ответе говорится `public`, а ключ Nexy — это только путь: две строки запроса на одном пути имеют одну запись. Сеанс, файл cookie или идентификатор пользователя в HTML могут быть переданы другому посетителю.

## Ограничения

**Nexy гарантирует, что** ключ кэша является путем, устаревшая копия обслуживается во время регенерации, а в случае сбоя хранилища возвращается к рендерингу.

**По соглашению** страница, объявляющая `revalidate` является общедоступным контентом. Напишите это так, как будто каждый посетитель видит один и тот же HTML-код.

**Ваше приложение отвечает за** всё остальное:

| Лимит | Что это значит |
|---|---|
| Строка запроса игнорируется | `/search?q=a` и `/search?q=b` имеют одну запись. Не кэшируйте страницу поиска. |
| Сессия не изолирована | В ответе говорится `public`, и HTML первого посетителя предоставляется всем. Никогда не читайте сеанс на странице с `revalidate`. |
| CDN не очищен | `revalidate()` очищает хранилище Nexy, а не CDN или другой прокси перед ним. |
| Нет TTL в файлах и хранилищах Redis | Записи остаются до тех пор, пока `revalidate()` или ваша собственная очистка не удалит их. Хранилище памяти удаляет последнюю использованную запись после 256. |
| Параллельные регенерации | Ничто не дедуплицирует их: десять устаревших запросов могут запустить десять рендеров. |
| Ошибки молчат | Неудачная операция регенерации или сохранения продолжает обслуживать страницу; отказ не возвращается. |
