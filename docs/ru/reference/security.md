# Безопасность

Как Nexy сохраняет небольшую поверхность атаки, какие версии ему требуются и как проверять проект.

## Полы версии

Nexy зависит от FastAPI, Starlette, Jinja2, Vite и React. Пол — это самая низкая версия, которую допускает Nexy; каждый отвечает на опубликованную рекомендацию.

| Пакет | Этаж | Почему |
|---|---|---|
| `starlette` | 1.3.1 | CVE-2026-48710 (BadHost, исправлено в версии 1.0.1): созданный заголовок `Host` изменяет путь, по которому Starlette сообщает промежуточному программному обеспечению, что обходит авторизацию, написанную на `request.url.path`; внесен в список эксплуатируемых CISA. CVE-2026-48817 и CVE-2026-48818 (отправка запроса, `StaticFiles` в Windows, исправлено в версии 1.1.0), CVE-2026-54282 (путь запроса не проверен, 1.3.0) и CVE-2026-54283 (ограничения `request.form()`, 1.3.1). |
| `python-dotenv` | 1.2.2 | CVE-2026-28684, в читателе файла `.env` загружается `nx migrate` |
| `fastapi` | 0.133.0 | первый выпуск, который принимает фиксированное Starlette |
| `jinja2` | 3.1.6 | Выход из песочницы через фильтр `attr` (CVE-2025-27516) |
| `vite` (проекты строительных лесов) | 6.4.5 | `server.fs.deny` обходит (CVE-2026-53571 на альтернативных путях Windows; GHSA-rq7h-c2jc-7f22, исправлено в версии 6.4.4; GHSA-8g5g-mxqh-grgj, обход запроса сам по себе добавлен в версии 6.4.4, исправлено в версии 6.4.5), и рекомендации `launch-editor` исправлены в версии 6.4.4 |
| `svelte` (проекты строительных лесов) | 5.55.7 | шесть рекомендаций XSS для рендеринга сервера с помощью атрибутов распространения, динамических имен тегов и `bind:innerText` |
| `esbuild` (проекты строительных лесов) | 0.28.1 | произвольный файл, прочитанный через сервер разработки (GHSA-g7r4-m6w7-qqqr) |

`python scripts/audit_dependencies.py` проверяет каждый этаж на соответствие OSV после блокировки, в том числе и в CI: новая рекомендация на этаже не проходит проверку.

Проверьте решенные версии:

```bash
uv pip list | grep -i -E "starlette|fastapi|jinja2"
npm ls vite
```

## Правила, которым следует Nexy

- **Никогда не доверяйте заголовку Host для путей.** Nexy читает `scope["path"]`, а не `request.url.path` в своем собственном промежуточном программном обеспечении (промежуточном программном обеспечении каталога). Сделайте то же самое в своем.
- **Экранируйте то, что достигает HTML.** Свойства, передаваемые клиентским компонентам, атрибуты `Link`, атрибуты `Image`, `Audio` и `Video`, привязки таблицы содержания и детали `HTTPException` экранируются HTML. Шаблон `.nexy` не экранируется сам по себе: записывайте `{{ value | e }}` для любого значения, поступающего от посетителя или из базы данных, и никогда не записывайте `| safe` для пользовательского ввода.
- **Конечные точки разработчика являются узкими и предназначены только для обратной связи.** Конечная точка рендеринга разработчика (`/__nexy__/render`) принимает только файлы под именем `src/routes/` с расширением `.tsx` или `.jsx` и доступна только через сервер разработки, который отказывается от внешних заголовков `Host`.
- **Подробности об ошибке не разглашаются.** Страница ошибки, которая сама по себе терпит неудачу, отображает только код состояния.
- **Производственные ответы содержат безопасные заголовки.** `X-Content-Type-Options: nosniff` и `Referrer-Policy: strict-origin-when-cross-origin`, если ваш код не устанавливает свои собственные. Заголовок `Server` не отправляется. Добавьте `Strict-Transport-Security` и `Content-Security-Policy` в свой прокси или промежуточное программное обеспечение: они зависят от вашего домена.
- **При сбое отображается ссылка, а не ошибка.** См. [Страницы ошибок](../routing/fbr/errors/README.md#unhandled-exceptions).
- **В коде Nexy Python нет `eval` и `shell=True`.** Внешние программы запускаются со списком аргументов.

## Проведение аудитов

```bash
python scripts/audit_dependencies.py        # Python dependencies against the lock
npm audit                                    # in a scaffolded project
uv run bandit -r nexy -c .bandit             # static analysis of Nexy itself
```

Собственный репозиторий Nexy в своих проверках запускает первый и третий. Новая рекомендация этажом выше обрабатывается поднятием пола в `pyproject.toml` или в лесах `package.json` и последующей регенерацией замка.

## Безопасное развертывание

- Установите `useTrustedHost` для своих доменов: он отклоняет неожиданные заголовки `Host` перед любым маршрутом.
- Не открывайте сервер разработки Vite: `nx dev` сохраняет его в режиме обратной связи за источником Nexy.
- Установите `useDocs = False`, если схема API не должна быть общедоступной.

См. [Промежуточное ПО и безопасность](../guides/middleware-and-security.md).
