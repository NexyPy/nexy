# Исключения и ошибки

Запрос может завершиться неудачей в четырех местах, и Nexy отвечает на каждый из них по-разному. Эта страница является индексом: найдите статус, который вы видите, затем строку, которая его создала, затем файл, который определяет тело.

> [!NOTE]
> Три вещи разделены и их легко спутать: **HTTP-ответ** (статус и тело), ​​**страница ошибки** (`notfound.nexy`, `errors.nexy`) и **строка журнала** (то, что вы читаете в терминале). Изменение страницы не меняет статус, а настройка страницы не скрывает журнал.

## Краткая версия

| Что произошло | Статус | Браузер видит | Клиент API видит |
|---|---|---|---|
| ни один маршрут не соответствует URL-адресу | `404` | `notfound.nexy`, иначе встроенная страница | `{"detail": "Not Found"}` |
| сегмент пути не соответствует его аннотации | `404` | та же страница | `{"detail": "Not Found"}` |
| поле запроса, заголовка, файла cookie или тела отсутствует или недействительно | `422` | FastAPI тело JSON | тело JSON FastAPI |
| `notFound()` | `404` | страница | `{"detail": ...}` |
| `unauthorized()` | `401` | встроенная страница | `{"detail": ...}` |
| `forbidden()` | `403` | встроенная страница | `{"detail": ...}` |
| `raise HTTPException(409, ...)` | `409` | встроенная страница | `{"detail": ...}` |
| исключение, ничего не перехвачено | `500` | `errors.nexy`, иначе встроенная страница | `{"detail", "reference"}` |
| `redirect(url)` | `307` | пункт назначения, без страницы | пункт назначения, без тела |
| `permanentRedirect(url)` | `308` | пункт назначения, нет страницы | пункт назначения |

Клиент API — это запрос, заголовок которого `Accept` запрашивает JSON, а не страницу:

```bash
curl -H "Accept: application/json" http://localhost:3000/api/items/500
# {"detail":"Out of range"}
```

> [!WARNING]
> `curl` по умолчанию отправляет `Accept: */*` , который получает HTML-страницу. Добавьте `-H "Accept: application/json"` при тестировании формы JSON. Браузеры продолжают получать страницы.

## Откуда берется неудача

```diagram filename="Один запрос, четыре выхода"
Browser ──► Middleware ──► Router ──► Page or handler
                 │            │             │
                 │            │             ├─ return ───────────► 200
                 │            │             ├─ HTTPException ────► its status
                 │            │             └─ other exception ───► 500
                 │            └─ no match ────────────────────────► 404
                 └─ raises ──────────────────────────────────────► 500
```

| Этап | Что может выйти из строя | Ответ |
|---|---|---|
| Промежуточное программное обеспечение | ваш `middleware.py`, CORS, сеансы | статус исключения, иначе `500` |
| Маршрутизатор | URL-адрес не соответствует ни одному файлу | `404` |
| Проверка | сегмент пути не может быть преобразован | `404` |
| Проверка | поля запроса, заголовка, файла cookie или тела | `422` |
| Страница, обработчик, действие, защита | `HTTPException` | ее статус |
| Страница, обработчик, действие, защита | что-нибудь еще | `500` |

## Уйти откуда угодно

`redirect`, `permanentRedirect`, `notFound`, `forbidden` и `unauthorized` вызывают исключение HTTP, поэтому один и тот же вызов работает на странице `.nexy`, обработчике API, модульном контроллере, защите, `dependencies.py` и действии.

```python filename="src/routes/posts/[slug].py"
from nexy import notFound, redirect

from src.posts import find


async def GET(slug: str):
    post = find(slug)
    if post is None:
        notFound("No such post")
    if post.moved_to:
        redirect(post.moved_to)
    return post
```

| Позвоните | Ответьте | Когда |
|---|---|---|
| `notFound(detail=None)` | `404` | ресурс не существует |
| `unauthorized(detail=None, scheme=None)` | `401` | посетитель должен сначала войти в систему |
| `forbidden(detail=None)` | `403` | посетитель известен, но может не видеть это |
| `redirect(url, status=307)` | `307` | отправьте их в другое место, сохраняя метод |
| `redirect(url, status=303)` | `303` | после формы: следующий запрос — это `GET` |
| `permanentRedirect(url)` | `308` | перемещенная страница, которую поисковые системы должны запомнить |

Создайте пункт назначения на основе ценностей, которым вы доверяете. `redirect(request.query_params["next"])` отправляет посетителей туда, где указано в ссылке; это открытое перенаправление. Пункт назначения, содержащий разрыв строки, отклоняется.

## Проверка: 422 или 404.

Параметры обработчика проверяются FastAPI на соответствие их аннотациям.

```python filename="src/routes/api/search.py"
from nexy.http import Header


async def GET(q: str, limit: int = 10, x_token: str = Header(...)):
    return {"q": q, "limit": limit}
```

| Проблема | Статус | Почему |
|---|---|---|
| отсутствует или недействителен запрос, заголовок, файл cookie или поле тела | `422` | запрос дошел до обработчика, данные неверны |
| неверный сегмент пути (`/api/users/abc` для `id: int`) | `404` | у папки нет маршрута для неномера, поэтому URL-адрес не существует |

Тело `422` имеет стандартную форму FastAPI, поэтому клиенты и созданные SDK продолжают работать:

```json
{"detail": [{"loc": ["query", "q"], "msg": "Field required", "type": "missing"}]}
```

Для формы или действия клиент получает `ActionError` с `status` и `detail`; `422` также заполняет `error.fields` одним сообщением в каждом поле. См. [Действия](../guides/actions.md#errors-and-failures).

> [!TIP]
> Проверьте подпись, если правило касается одного поля (`limit: int = 10`). Подтвердите в теле, когда правилу нужна база данных или другое поле («этот адрес электронной почты уже используется»): поднимите `HTTPException(409)` и сохраните сообщение для клиента.

## Пользовательские страницы ошибок

```nexy filename="источник/маршруты/notfound.nexy"
<h1>Page not found</h1>
<p>The link may be old. <a href="/">Start from the home page</a>.</p>
```

```nexy filename="src/маршруты/errors.nexy"
<h1>Something went wrong</h1>
<p>Try again in a moment.</p>
```

| Файл | Статус | Область действия |
|---|---|---|
| `src/routes/notfound.nexy` | `404` | каждый маршрут проекта |
| `src/routes/errors.nexy` | `500` | каждый маршрут проекта |
| `src/routes/forbidden.nexy` | `403` | каждый маршрут проекта |
| `src/routes/unauthorized.nexy` | `401` | каждый маршрут проекта |
| `src/routes/blog/notfound.nexy` | `404` | `/blog` и ниже |
| `src/routes/blog/errors.nexy` | `500` | `/blog` и ниже |
| `src/routes/loading.nexy` | - | зарезервировано, пока нет эффекта во время выполнения |

Один файл где-то в маршрутах устанавливает ответ на свой статус: копия в корне отвечает всему проекту, копия в папке отвечает этой папке, и побеждает самый глубокий файл, соответствующий URL-адресу. URL-адрес за пределами каждой копии и статус без файла вообще получают встроенные страницы со стилем. См. [Страниц ошибок в папке](../routing/fbr/errors/folder-pages.md).

> [!IMPORTANT]
> Страница `errors.nexy` заменяет страницу `500`; он не перехватывает исключение и не меняет строку журнала. Если вызвавший обработчик является самой страницей, страница не может отображать собственные сведения об ошибке: сохраняйте `errors.nexy` простым и независимым.

## Необработанные исключения

Исключение, когда ничего не обнаружено, записывается один раз со ссылкой на источник и код вокруг него. Статус `500`, тело зависит от окружающей среды.

| | `nexy dev` | `nexy build` затем `nexy start` |
|---|---|---|
| Браузер | ошибка, строки вашего кода и трассировка | `errors.nexy`, иначе встроенная страница со ссылкой |
| API-клиент | `{"detail", "reference", "error"}` | `{"detail", "reference"}` |
| Терминал | исключение и строки вашего кода | исключение, вся трассировка и ссылка |

```text
  x ZeroDivisionError: division by zero  GET /boom  ref fe6a5217
    at src/routes/boom.py:2 in GET
       1 | def GET():
       2 |     return {"a": 1 / 0}
```

Ссылка состоит из восьми символов, новых для каждой неудачи. Посетитель может процитировать его, и вы найдете обратную трассировку, выполнив поиск в журнале. Ни исключение, ни код не доходят до посетителя в рабочей среде.

> [!CAUTION]
> Не возвращайте обратную трассировку посетителю в рабочей среде и не помещайте секреты в сообщение об ошибке: `detail` из `HTTPException` отправляется клиенту в HTML-экранированном виде. Поместите секрет в журнал, а не в ответ.

## Действия и формы

Действие — это конечная точка `POST` со сгенерированным путем. Его неудачи подчиняются тем же правилам:

| Ситуация | Статус | Клиент |
|---|---|---|
| поле отсутствует или недействительно | `422` | `ActionError` с `fields` |
| `HTTPException(403)` поднят в иске | `403` | `ActionError` с `status` и `detail` |
| необработанное исключение | `500` | `ActionError`; ссылка есть в журнале сервера |
| заголовок `Origin` — это другой сайт, | `403` | которому было отказано до запуска действия |

Форма без JavaScript сообщений о пути действия; при успехе ответ `303` возвращается на страницу, при неудаче отображается страница с ошибкой. См. [Действия](../guides/actions.md#forms-without-javascript).

## Контрольный список, когда страница отвечает не на тот вопрос

1. **Смотрите на статус**, а не на страницу. Пользовательский `notfound.nexy` по-прежнему отвечает на `404`.
2. **Прочтите терминал.** Страница, которую не удается импортировать, не зарегистрирована, поэтому ее URL-адрес отвечает `404`, пока файл существует. Ошибка импорта есть в журнале.
3. **Проверьте расширение.** При `useCSR = True`, `.nexy` страницы относятся к режиму сервера; страница в неправильном режиме не является маршрутом.
4. **Проверьте глубину.** `notfound.nexy` или `errors.nexy` работает только при наличии корневой копии.
5. **Запросите JSON** с помощью `Accept: application/json`, чтобы увидеть форму, которую получает ваш API-клиент.
6. **Цитируйте ссылку** на `500` при открытии задачи или поиске в журнале.
