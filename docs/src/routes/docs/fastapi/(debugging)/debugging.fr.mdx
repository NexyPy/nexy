# Débogage

Les applications Nexy sont Python standard – utilisez vos outils de débogage habituels.

## `breakpoint()`

Insérez `breakpoint()` n'importe où dans votre gestionnaire de route :

```python
def GET():
    x = 42
    breakpoint()  # drops into pdb
    return {"x": x}
```

Exécutez `nx dev` et suivez l'itinéraire — le terminal tombe dans `pdb`.

## VSCode

1. Définissez des points d'arrêt dans VS Code en cliquant sur la gouttière
2. Créez un `.vscode/launch.json` :

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Nexy Dev",
            "type": "debugpy",
            "request": "launch",
            "module": "nexy.cli",
            "args": ["dev"],
            "jinja": true
        }
    ]
}
```

3. Appuyez sur `F5` pour démarrer le débogage — les points d'arrêt fonctionnent dans les fichiers `.nexy` frontmatter et `.py`.

## Débogage de l'impression

```python
---
print(f"Request params: {params}")  # appears in the terminal
---
```

## Journalisation de la console

Nexy enregistre toutes les requêtes sur le terminal par défaut. Ajoutez vos propres journaux :

```python
import logging
logger = logging.getLogger("nexy")

def GET():
    logger.info("Home page loaded")
    return {"ok": True}
```

## rechargement de la vicorne

`nx dev` exécute uvicorn avec `--reload` — les modifications apportées aux fichiers `.py`, `.nexy`, `.mdx` déclenchent un redémarrage automatique.

## Problèmes courants

| Symptôme | Cause probable |
|---------|-------------|
| L'itinéraire renvoie 405 | Mauvaise méthode HTTP ou `python-multipart` manquant |
| Le corps est `None` | Modèle Pydantic manquant ou annotation de type |
| 422 Erreur de validation | Incompatibilité de type dans les paramètres de chemin/requête |
| Module introuvable | Cache VFS obsolète — redémarrez `nx dev` |
