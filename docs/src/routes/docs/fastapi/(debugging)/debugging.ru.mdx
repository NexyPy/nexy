# Отладка

Приложения Nexy — это стандартный Python — используйте свои обычные инструменты отладки.

## `breakpoint()`

Вставьте `breakpoint()` в любое место обработчика маршрута:

```python
def GET():
    x = 42
    breakpoint()  # drops into pdb
    return {"x": x}
```

Запустите `nx dev` и выберите маршрут — терминал попадет в `pdb`.

## VS-код

1. Установите точки останова в VS Code, щелкнув переплет.
2. Создайте `.vscode/launch.json`:

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Nexy Dev",
            "type": "debugpy",
            "request": "launch",
            "module": "nexy.cli",
            "args": ["dev"],
            "jinja": true
        }
    ]
}
```

3. Нажмите `F5`, чтобы начать отладку — точки останова работают в файлах `.nexy` и файлах `.py`.

## Отладка печати

```python
---
print(f"Request params: {params}")  # appears in the terminal
---
```

## Ведение журнала консоли

Nexy по умолчанию регистрирует все запросы к терминалу. Добавьте свои собственные журналы:

```python
import logging
logger = logging.getLogger("nexy")

def GET():
    logger.info("Home page loaded")
    return {"ok": True}
```

## увикорн перезагрузка

`nx dev` запускает uvicorn с `--reload` — изменения в файлах `.py`, `.nexy`, `.mdx` вызывают автоматический перезапуск.

## Распространенные проблемы

| Симптом | Вероятная причина |
|---------|-------------|
| Маршрут возвращает 405 | Неправильный метод HTTP или отсутствует `python-multipart` |
| Тело — `None` | Отсутствует модель Pydantic или аннотация типа |
| 422 Ошибка проверки | Несоответствие типов в параметрах пути/запроса |
| Модуль не найден | Кэш VFS устарел — перезапустите `nx dev` |
