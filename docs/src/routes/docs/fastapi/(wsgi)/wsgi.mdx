# WSGI (Flask, Django)

Mount WSGI applications (Flask, Django, Pyramid) alongside Nexy routes.

## Flask

```python
# src/flask_app.py
from flask import Flask

flask_app = Flask(__name__)

"@flask_app.route("/hello")
def hello():
    return "<h1>Hello from Flask</h1>"
```

```python
# In nexyconfig.py or any startup file
from nexy import app
from src.flask_app import flask_app
from fastapi.middleware.wsgi import WSGIMiddleware

app.mount("/legacy", WSGIMiddleware(flask_app))
```

Flask routes are now available at `/legacy/hello`. All Nexy features (auth, middleware) still apply to the parent app.

## Django

```python
import os
os.environ.setdefault("DJANGO_SETTINGS_MODULE", "myapp.settings")

from django.core.wsgi import get_wsgi_application
django_app = get_wsgi_application()

from nexy import app
from fastapi.middleware.wsgi import WSGIMiddleware

app.mount("/django", WSGIMiddleware(django_app))
```

## How it works

- `WSGIMiddleware` wraps any WSGI callable as ASGI
- The sub-application runs in a thread pool — it doesn't block the event loop
- Path prefix (`/legacy`, `/django`) is stripped before reaching the WSGI app
- Nexy middleware (auth, session, CORS) does **not** apply to the mounted WSGI app — configure it there separately

## Limitations

- Request/response cycle only — WebSocket not supported
- WSGI apps can't use Nexy hooks or dependencies
- Performance is limited by the thread pool — consider migrating to native Nexy routes
