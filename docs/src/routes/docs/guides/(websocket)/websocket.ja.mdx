# リアルタイム通信

Nexy は、WebSocket、Server-Sent Events (SSE)、およびリアルタイム通信のためのロングポーリングをサポートしています。

## どれを使用するか

|特集 |最適 |方向 |
|----------|----------|----------|
| **WebSocket** |双方向、低遅延 (チャット、ゲーム、コラボレーション) |クライアント ↔ サーバー |
| **SSE** |サーバー → クライアント イベント (通知、ライブ フィード) |サーバー → クライアント |
| **ロングポーリング** |上記が利用できない場合の単純なポーリング |クライアント → サーバー |

## ウェブソケット

単一の TCP 接続を介した全二重通信。 Nexy は、`SOCKET` 関数/メソッド名を Starlette WebSocket エンドポイントにマップします。

- [FBR WebSocket](/docs/fbrouters/websocket) — ファイルベースのルーティングの例
- [Modular WebSocket](/docs/modular/websocket) — DI を使用したコントローラーベースの例

## サーバー送信イベント (SSE)

HTTP 経由の単方向サーバー → クライアント ストリーミング。サーバープッシュのみが必要な場合は、WebSocket よりも軽量です。

実装の詳細については、[SSE](/docs/fastapi/sse) を参照してください。

## いつ選択するか

- **WebSocket**: チャット アプリ、ライブ コラボレーション、ゲーム、金融ティッカー
- **SSE**: ライブ通知、フィード更新、進行状況バー、ログ ストリーミング
- **ロングポーリング**: WebSocket (企業プロキシ) をブロックする環境のフォールバック
