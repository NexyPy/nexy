# Serveraktionen

Mit Serveraktionen können Sie Python-Funktionen vom Client aus als POST-Endpunkte aufrufen – keine Routenregistrierung, kein Serialisierungs-Boilerplate.

---

## Eine Aktion definieren

Dekorieren Sie jede Funktion mit `"@Action`:

```python
# src/actions/vote.py
from nexy.decorators import Action

"@Action
def vote(post_id: str, direction: int) -> dict:
    return {"success": True, "post_id": post_id, "votes": 42}
```

Die Funktion empfängt JSON-Body-Parameter als Schlüsselwortargumente. Gibt einen beliebigen JSON-serialisierbaren Wert zurück.

---

## Wo werden Aktionsdateien abgelegt?

Aktionen können **überall** in Ihrem Projekt ausgeführt werden – `src/actions/`, `src/routes/` oder direkt im Stammverzeichnis. `ActionEngine` scannt beim Start das gesamte Projektverzeichnis.

```text
my-app/
├── src/
│   └── actions/
│       ├── vote.py        ← "@Action
│       └── comment.py     ← "@Action
├── actions/
│   ├── vote.ts            ← Generated TypeScript client
│   └── comment.ts
```

Informationen zur Funktionsweise von Erkennung und Endpunktgenerierung finden Sie unter ["@Action reference](/docs/decorators/action).

## Praxisbeispiele

### Formularübermittlung

```python
# src/actions/contact.py
from nexy.decorators import Action
from pydantic import BaseModel, EmailStr

class ContactForm(BaseModel):
    name: str
    email: EmailStr
    message: str

"@Action
def submit_contact(data: ContactForm) -> dict:
    # Save to database, send email, etc.
    return {"ok": True, "name": data.name}
```

```nexy

<form id="contact">

document.getElementById('contact').onsubmit = async (e) => {

    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(Object.fromEntries(fd))
  });
  const data = await res.json();
  if (data.ok) alert('Message sent!');
};
</script>
```

### Datenbankaktion

```python
# src/actions/create_user.py
from nexy.decorators import Action
from pydantic import BaseModel
from src.database import get_session
from src.models import User

class CreateUserBody(BaseModel):
    name: str
    email: str

"@Action
def create_user(body: CreateUserBody) -> dict:
    db = next(get_session())
    user = User(name=body.name, email=body.email)
    db.add(user)
    db.commit()
    db.refresh(user)
    return {"id": user.id, "name": user.name}
```

### Aktion mit Fehlerbehandlung

```python
# src/actions/delete_item.py
from nexy.decorators import Action
from fastapi import HTTPException
from src.database import get_session

"@Action
def delete_item(item_id: int) -> dict:
    db = next(get_session())
    item = db.get(Item, item_id)
    if not item:
        raise HTTPException(status_code=404, detail="Item not found")
    db.delete(item)
    db.commit()
    return {"deleted": item_id}
```

## Generierter TypeScript-Client

`nx build` oder `nx dev` generiert typsichere TypeScript-Wrapper in `./actions/`:

```typescript
// Generated: ./actions/vote.ts
import { transport } from '"@/nexy/client';

export const vote = async (post_id: string, direction: number): Promise<dict> => {
  return await transport.call('/_nx_a1b2c3d4e5f6', { post_id, direction });
};
```

Jede generierte Funktion spiegelt die Python-Signatur mit den richtigen TypeScript-Typen wider.

## Best Practices

- Halten Sie die Aktionsfunktionen fokussiert und idempotent
- Validieren Sie Eingaben innerhalb der Aktion – behandeln Sie sie als nicht vertrauenswürdig
- Verwenden Sie Pydantic-Modelle für komplexe Anforderungstexte
- Aktionen sind nur POST – für andere HTTP-Methoden verwenden Sie Routenhandler
- Verwenden Sie Guards oder Middleware für die Autorisierung
