# Acciones del servidor

Las acciones del servidor le permiten llamar a funciones de Python desde el cliente como puntos finales POST: sin registro de ruta ni texto estándar de serialización.

---

## Definiendo una acción

Decora cualquier función con `"@Action`:

```python
# src/actions/vote.py
from nexy.decorators import Action

"@Action
def vote(post_id: str, direction: int) -> dict:
    return {"success": True, "post_id": post_id, "votes": 42}
```

La función recibe parámetros del cuerpo JSON como argumentos de palabras clave. Devuelve cualquier valor serializable en JSON.

---

## Dónde colocar los archivos de acción

Las acciones pueden vivir **en cualquier lugar** de su proyecto: `src/actions/`, `src/routes/` o directamente en la raíz. El `ActionEngine` escanea todo el directorio del proyecto al inicio.

```text
my-app/
├── src/
│   └── actions/
│       ├── vote.py        ← "@Action
│       └── comment.py     ← "@Action
├── actions/
│   ├── vote.ts            ← Generated TypeScript client
│   └── comment.ts
```

Consulte ["@Action reference](/docs/decorators/action) para saber cómo funcionan el descubrimiento y la generación de puntos finales.

## Ejemplos prácticos

### Envío de formulario

```python
# src/actions/contact.py
from nexy.decorators import Action
from pydantic import BaseModel, EmailStr

class ContactForm(BaseModel):
    name: str
    email: EmailStr
    message: str

"@Action
def submit_contact(data: ContactForm) -> dict:
    # Save to database, send email, etc.
    return {"ok": True, "name": data.name}
```

```nexy

<form id="contact">

<script>
document.getElementById('contact').onsubmit = async (e) => {

  const fd = new FormData(e.target);
  const res = await fetch('/_nx_a1b2c3d4e5f6', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(Object.fromEntries(fd))
  });
  const data = await res.json();
  if (data.ok) alert('Message sent!');
};
</script>
```

### Acción de base de datos

```python
# src/actions/create_user.py
from nexy.decorators import Action
from pydantic import BaseModel
from src.database import get_session
from src.models import User

class CreateUserBody(BaseModel):
    name: str
    email: str

"@Action
def create_user(body: CreateUserBody) -> dict:
    db = next(get_session())
    user = User(name=body.name, email=body.email)
    db.add(user)
    db.commit()
    db.refresh(user)
    return {"id": user.id, "name": user.name}
```

### Acción con manejo de errores

```python
# src/actions/delete_item.py
from nexy.decorators import Action
from fastapi import HTTPException
from src.database import get_session

"@Action
def delete_item(item_id: int) -> dict:
    db = next(get_session())
    item = db.get(Item, item_id)
    if not item:
        raise HTTPException(status_code=404, detail="Item not found")
    db.delete(item)
    db.commit()
    return {"deleted": item_id}
```

## Cliente TypeScript generado

`nx build` o `nx dev` genera contenedores de TypeScript con seguridad de tipos en `./actions/`:

```typescript
// Generated: ./actions/vote.ts
import { transport } from '"@/nexy/client';

export const vote = async (post_id: string, direction: number): Promise<dict> => {
  return await transport.call('/_nx_a1b2c3d4e5f6', { post_id, direction });
};
```

Cada función generada refleja la firma de Python con los tipos de TypeScript adecuados.

## Mejores prácticas

- Mantener las funciones de acción enfocadas e idempotentes.
- Validar las entradas dentro de la acción: tratarlas como si no fueran de confianza.
- Utilice modelos Pydantic para cuerpos de solicitud complejos
- Las acciones son solo POST; para otros métodos HTTP, utilice controladores de ruta
- Utilice guardias o middleware para la autorización
