# Ações do Servidor

As ações do servidor permitem chamar funções Python do cliente como pontos de extremidade POST — sem registro de rota, sem padrão de serialização.

---

## Definindo uma ação

Decore qualquer função com `"@Action`:

```python
# src/actions/vote.py
from nexy.decorators import Action

"@Action
def vote(post_id: str, direction: int) -> dict:
    return {"success": True, "post_id": post_id, "votes": 42}
```

A função recebe parâmetros do corpo JSON como argumentos de palavras-chave. Retorne qualquer valor serializável JSON.

---

## Onde colocar os arquivos de ação

As ações podem estar em **qualquer lugar** do seu projeto — `src/actions/`, `src/routes/` ou diretamente na raiz. O `ActionEngine` verifica todo o diretório do projeto na inicialização.

```text
my-app/
├── src/
│   └── actions/
│       ├── vote.py        ← "@Action
│       └── comment.py     ← "@Action
├── actions/
│   ├── vote.ts            ← Generated TypeScript client
│   └── comment.ts
```

Consulte ["@Action reference](/docs/decorators/action) para saber como funcionam a descoberta e a geração de endpoint.

## Exemplos práticos

### Envio de formulário

```python
# src/actions/contact.py
from nexy.decorators import Action
from pydantic import BaseModel, EmailStr

class ContactForm(BaseModel):
    name: str
    email: EmailStr
    message: str

"@Action
def submit_contact(data: ContactForm) -> dict:
    # Save to database, send email, etc.
    return {"ok": True, "name": data.name}
```

```nexy
document.getElementById('contact').onsubmit = async (e) => {

    body: JSON.stringify(Object.fromEntries(fd))

  const data = await res.json();
  if (data.ok) alert('Message sent!');
};
</script>
```

### Ação do banco de dados

```python
# src/actions/create_user.py
from nexy.decorators import Action
from pydantic import BaseModel
from src.database import get_session
from src.models import User

class CreateUserBody(BaseModel):
    name: str
    email: str

"@Action
def create_user(body: CreateUserBody) -> dict:
    db = next(get_session())
    user = User(name=body.name, email=body.email)
    db.add(user)
    db.commit()
    db.refresh(user)
    return {"id": user.id, "name": user.name}
```

### Ação com tratamento de erros

```python
# src/actions/delete_item.py
from nexy.decorators import Action
from fastapi import HTTPException
from src.database import get_session

"@Action
def delete_item(item_id: int) -> dict:
    db = next(get_session())
    item = db.get(Item, item_id)
    if not item:
        raise HTTPException(status_code=404, detail="Item not found")
    db.delete(item)
    db.commit()
    return {"deleted": item_id}
```

## Cliente TypeScript gerado

`nx build` ou `nx dev` gera wrappers TypeScript com segurança de tipo em `./actions/`:

```typescript
// Generated: ./actions/vote.ts
import { transport } from '"@/nexy/client';

export const vote = async (post_id: string, direction: number): Promise<dict> => {
  return await transport.call('/_nx_a1b2c3d4e5f6', { post_id, direction });
};
```

Cada função gerada espelha a assinatura Python com tipos TypeScript adequados.

## Melhores práticas

- Mantenha as funções de ação focadas e idempotentes
- Valide as entradas dentro da ação – trate-as como não confiáveis
- Use modelos Pydantic para órgãos de solicitação complexos
- As ações são somente POST — para outros métodos HTTP, use manipuladores de rota
- Use guardas ou middleware para autorização
