# 从 NestJS 迁移到 Nexy

Nexy 的模块化路由器受到 NestJS 的启发——装饰器、DI、模块、防护装置、中间件。这些概念几乎是一对一地传递的。

## 概念图

| NestJS |内克西 |
|--------|------|
| `"@Controller()` | `"@Controller()` |
| `"@Injectable()` | `"@Injectable()` |
| `"@Module()` | `"@Module()` |
| `"@Get()` | `def GET(self)` |
| `"@Post()` | `def POST(self)` |
| `"@UseGuards()` | `"@UseGuard()` |
| `"@UseInterceptors()` | `"@Middleware()` |
| `constructor(private svc: Svc)` | `def __init__(self, svc: Svc)` |
| `APP_INTERCEPTOR` |配置中的 `useMiddlewares` |
| `app.module.ts` | `app_module.py` |

＃＃ 例子
```python
# NestJS equivalent
"@Controller("/users")
export class UsersController {
    constructor(private service: UserService) {}
    "@Get()
    findAll() { return this.service.findAll(); }
}

# Nexy
"@Controller("/users")
class UsersController:
    def __init__(self, service: UserService):
        self.service = service

    def GET(self):
        return self.service.find_all()
```
## 主要区别

- **方法名称定义 HTTP 动词** — 无 `"@Get`/`"@Post`/`"@Put`/`"@Delete` 装饰器
- **一个模块中的所有装饰器** — `from nexy.decorators import Controller, Module, Injectable, UseGuard, Middleware`
- **没有 `"@Global`** — 范围通过 `Injectable(scope=Scope.SINGLETON)` 处理
- **守卫和中间件是可调用的** — 无需扩展基类，只需 `__call__(self, request)`
