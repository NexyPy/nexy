# Von NestJS nach Nexy migrieren

Der modulare Router von Nexy ist von NestJS inspiriert – Dekoratoren, DI, Module, Guards, Middleware. Die Konzepte übertragen sich nahezu eins zu eins.

## Konzeptzuordnung

| NestJS | Nexy |
|--------|------|
| `"@Controller()` | `"@Controller()` |
| `"@Injectable()` | `"@Injectable()` |
| `"@Module()` | `"@Module()` |
| `"@Get()` | `def GET(self)` |
| `"@Post()` | `def POST(self)` |
| `"@UseGuards()` | `"@UseGuard()` |
| `"@UseInterceptors()` | `"@Middleware()` |
| `constructor(private svc: Svc)` | `def __init__(self, svc: Svc)` |
| `APP_INTERCEPTOR` | `useMiddlewares` in der Konfiguration |
| `app.module.ts` | `app_module.py` |

## Beispiel
```python
# NestJS equivalent
"@Controller("/users")
export class UsersController {
    constructor(private service: UserService) {}
    "@Get()
    findAll() { return this.service.findAll(); }
}

# Nexy
"@Controller("/users")
class UsersController:
    def __init__(self, service: UserService):
        self.service = service

    def GET(self):
        return self.service.find_all()
```
## Hauptunterschiede

- **Methodennamen definieren HTTP-Verben** – keine `"@Get`/`"@Post`/`"@Put`/`"@Delete` Dekoratoren
- **Alle Dekorateure in einem Modul** – `from nexy.decorators import Controller, Module, Injectable, UseGuard, Middleware`
- **Nein `"@Global`** – der Bereich wird über `Injectable(scope=Scope.SINGLETON)` verwaltet
- **Guards und Middleware sind aufrufbar** – keine Basisklasse zum Erweitern, nur `__call__(self, request)`
