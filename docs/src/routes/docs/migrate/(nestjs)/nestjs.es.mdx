# Migrar de NestJS a Nexy

El enrutador modular de Nexy está inspirado en NestJS: decoradores, DI, módulos, protecciones y middleware. Los conceptos se transfieren casi uno a uno.

## Mapeo de conceptos

| NestJS | Nexy |
|--------|------|
| `"@Controller()` | `"@Controller()` |
| `"@Injectable()` | `"@Injectable()` |
| `"@Module()` | `"@Module()` |
| `"@Get()` | `def GET(self)` |
| `"@Post()` | `def POST(self)` |
| `"@UseGuards()` | `"@UseGuard()` |
| `"@UseInterceptors()` | `"@Middleware()` |
| `constructor(private svc: Svc)` | `def __init__(self, svc: Svc)` |
| `APP_INTERCEPTOR` | `useMiddlewares` en configuración |
| `app.module.ts` | `app_module.py` |

## Ejemplo
```python
# NestJS equivalent
"@Controller("/users")
export class UsersController {
    constructor(private service: UserService) {}
    "@Get()
    findAll() { return this.service.findAll(); }
}

# Nexy
"@Controller("/users")
class UsersController:
    def __init__(self, service: UserService):
        self.service = service

    def GET(self):
        return self.service.find_all()
```
## Diferencias clave

- **Los nombres de los métodos definen verbos HTTP**: no hay decoradores `"@Get`/`"@Post`/`"@Put`/`"@Delete`
- **Todos los decoradores en un módulo** — `from nexy.decorators import Controller, Module, Injectable, UseGuard, Middleware`
- **No `"@Global`** — el alcance se maneja a través de `Injectable(scope=Scope.SINGLETON)`
- **Los guardias y el middleware son invocables**: no hay clase base que ampliar, solo `__call__(self, request)`
