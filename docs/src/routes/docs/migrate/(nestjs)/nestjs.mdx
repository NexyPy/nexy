# Migrate from NestJS to Nexy

Nexy's Modular Router is inspired by NestJS — decorators, DI, modules, guards, middleware. The concepts transfer almost one-to-one.

## Concepts mapping

| NestJS | Nexy |
|--------|------|
| `"@Controller()` | `"@Controller()` |
| `"@Injectable()` | `"@Injectable()` |
| `"@Module()` | `"@Module()` |
| `"@Get()` | `def GET(self)` |
| `"@Post()` | `def POST(self)` |
| `"@UseGuards()` | `"@UseGuard()` |
| `"@UseInterceptors()` | `"@Middleware()` |
| `constructor(private svc: Svc)` | `def __init__(self, svc: Svc)` |
| `APP_INTERCEPTOR` | `useMiddlewares` in config |
| `app.module.ts` | `app_module.py` |

## Example
```python
# NestJS equivalent
"@Controller("/users")
export class UsersController {
    constructor(private service: UserService) {}
    "@Get()
    findAll() { return this.service.findAll(); }
}

# Nexy
"@Controller("/users")
class UsersController:
    def __init__(self, service: UserService):
        self.service = service

    def GET(self):
        return self.service.find_all()
```
## Key differences

- **Method names define HTTP verbs** — no `"@Get`/`"@Post`/`"@Put`/`"@Delete` decorators
- **All decorators in one module** — `from nexy.decorators import Controller, Module, Injectable, UseGuard, Middleware`
- **No `"@Global`** — scope is handled via `Injectable(scope=Scope.SINGLETON)`
- **Guards & Middleware are callables** — no base class to extend, just `__call__(self, request)`
