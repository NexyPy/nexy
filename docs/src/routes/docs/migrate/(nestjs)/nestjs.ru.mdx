# Миграция с NestJS на Nexy

Модульный маршрутизатор Nexy вдохновлен NestJS — декораторы, DI, модули, средства защиты, промежуточное программное обеспечение. Понятия передаются практически один в один.

## Сопоставление концепций

| НестJS | Некси |
|--------|------|
| `"@Controller()` | `"@Controller()` |
| `"@Injectable()` | `"@Injectable()` |
| `"@Module()` | `"@Module()` |
| `"@Get()` | `def GET(self)` |
| `"@Post()` | `def POST(self)` |
| `"@UseGuards()` | `"@UseGuard()` |
| `"@UseInterceptors()` | `"@Middleware()` |
| `constructor(private svc: Svc)` | `def __init__(self, svc: Svc)` |
| `APP_INTERCEPTOR` | `useMiddlewares` в конфигурации |
| `app.module.ts` | `app_module.py` |

## Пример
```python
# NestJS equivalent
"@Controller("/users")
export class UsersController {
    constructor(private service: UserService) {}
    "@Get()
    findAll() { return this.service.findAll(); }
}

# Nexy
"@Controller("/users")
class UsersController:
    def __init__(self, service: UserService):
        self.service = service

    def GET(self):
        return self.service.find_all()
```
## Ключевые различия

- **Имена методов определяют HTTP-глаголы** — нет декораторов `"@Get`/`"@Post`/`"@Put`/`"@Delete`
- **Все декораторы в одном модуле** — `from nexy.decorators import Controller, Module, Injectable, UseGuard, Middleware`
- **Нет `"@Global`** — область действия обрабатывается через `Injectable(scope=Scope.SINGLETON)`
- **Guards & Middleware являются вызываемыми объектами** — нет базового класса для расширения, только `__call__(self, request)`
