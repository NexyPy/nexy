# Migrer de NestJS vers Nexy

Le routeur modulaire de Nexy s'inspire de NestJS : décorateurs, DI, modules, gardes, middleware. Les concepts sont transférés presque un à un.

## Cartographie des concepts

| NestJS | Nexy |
|--------|------|
| `"@Controller()` | `"@Controller()` |
| `"@Injectable()` | `"@Injectable()` |
| `"@Module()` | `"@Module()` |
| `"@Get()` | `def GET(self)` |
| `"@Post()` | `def POST(self)` |
| `"@UseGuards()` | `"@UseGuard()` |
| `"@UseInterceptors()` | `"@Middleware()` |
| `constructor(private svc: Svc)` | `def __init__(self, svc: Svc)` |
| `APP_INTERCEPTOR` | `useMiddlewares` dans la configuration |
| `app.module.ts` | `app_module.py` |

## Exemple
```python
# NestJS equivalent
"@Controller("/users")
export class UsersController {
    constructor(private service: UserService) {}
    "@Get()
    findAll() { return this.service.findAll(); }
}

# Nexy
"@Controller("/users")
class UsersController:
    def __init__(self, service: UserService):
        self.service = service

    def GET(self):
        return self.service.find_all()
```
## Différences clés

- **Les noms de méthodes définissent les verbes HTTP** — pas de décorateurs `"@Get`/`"@Post`/`"@Put`/`"@Delete`
- **Tous les décorateurs dans un module** — `from nexy.decorators import Controller, Module, Injectable, UseGuard, Middleware`
- **Non `"@Global`** — la portée est gérée via `Injectable(scope=Scope.SINGLETON)`
- **Les gardes et les middlewares sont appelables** — aucune classe de base à étendre, juste `__call__(self, request)`
