# الهجرة من جانغو إلى Nexy

جانغو متضمنة بالبطاريات. Nexy مركز ومعياري - فأنت تجلب ما تحتاجه.

## رسم خرائط المفاهيم

| جانجو | نكسي |
|--------|-----|
| `views.py` | `.nexy` ملفات (FBR) أو `"@Controller` (وحدات) |
| `urls.py` | شجرة الملفات (FBR) أو `"@Module` (معيارية) |
| `models.py` | SQLModel / SQLAlchemy (اختيارك) |
| `admin.py` | مستندات OpenAPI على `/docs` |
| `manage.py` | `nx` سطر الأوامر |
| `settings.py` | `nexyconfig.py` |
| جانغو أورم | SQLModel أو SQLAlchemy أو Tortoise-ORM |
| قوالب (DTL) | Jinja2 (`.nexy` ملفات) |
| وجهات النظر على أساس الطبقة | `"@Controller` (معياري) أو `.nexy` ملفات (FBR) |
| الوسيطة | `"@Middleware` أو برنامج وسيط FastAPI |
| `request.user` | `request.state.user` أو الحراس |

## خطوات الهجرة

1. **دعم مشروع Nexy جديد** — `nx new my-app`
2. **نماذج المنافذ** — ترجمة نماذج Django إلى SQLModel/SQLAlchemy
3. **طرق عرض المنفذ** — تحويل طرق عرض دالة/فئة Django إلى ملفات `.nexy` (FBR) أو `"@Controller` (وحدات)
4. **تكوينات عنوان URL للمنفذ** — تتحول أنماط `urls.py` إلى شجرة ملفات (FBR) أو `"@Module` (وحدات)
5. **قوالب المنافذ** — قوالب DTL → Jinja2 في ملفات `.nexy`
6. **البرمجيات الوسيطة للمنفذ** — البرامج الوسيطة لـ Django → Starlette `BaseHTTPMiddleware`

## لماذا التبديل

- **لا توجد إعدادات متجانسة** — قم بتكوين ما تستخدمه فقط
- **غير متزامن افتراضيًا** — FastAPI/Starlette أسفل الغطاء
- **مستندات OpenAPI** — تلقائية، لا حاجة إلى `drf-spectacular`
- **واجهة المستخدم القائمة على المكونات** — امزج Python + Jinja2 في ملف واحد
- **اختيار الإطار** — React أو Vue أو Svelte أو Solid أو Preact للواجهة الأمامية
