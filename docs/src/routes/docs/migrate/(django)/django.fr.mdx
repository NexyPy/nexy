# Migrer de Django vers Nexy

Django est livré avec des piles. Nexy est ciblé et modulaire : vous apportez ce dont vous avez besoin.

## Cartographie des concepts

| Django | Nexy |
|--------|------|
| `views.py` | Fichiers `.nexy` (FBR) ou `"@Controller` (modulaire) |
| `urls.py` | Arborescence de fichiers (FBR) ou `"@Module` (Modulaire) |
| `models.py` | SQLModel / SQLAlchemy (votre choix) |
| `admin.py` | Documents OpenAPI sur `/docs` |
| `manage.py` | `nx` CLI |
| `settings.py` | `nexyconfig.py` |
| Django ORM | SQLModel, SQLAlchemy ou Tortoise-ORM |
| Modèles (DTL) | Jinja2 (`.nexy` fichiers) |
| Vues basées sur les classes | Fichiers `"@Controller` (modulaires) ou `.nexy` (FBR) |
| Intergiciel | `"@Middleware` ou middleware FastAPI |
| `request.user` | `request.state.user` ou gardes |

## Exemple
```python
# src/routes/users/index.nexy
---
from pydantic import BaseModel

class UserOut(BaseModel):
    id: int
    name: str
    email: str

def GET():
    return {"users": [u.model_dump() for u in User.find_all()]}
---
```
```python
# Nexy Modular
from nexy.decorators import Controller

"@Controller("/users")
class UsersController:
    def GET(self):
        return {"users": [u.model_dump() for u in User.find_all()]}
```
## Étapes de migration

1. **Échafauder un nouveau projet Nexy** — `nx new my-app`
2. **Modèles de port** — traduisez les modèles Django en SQLModel/SQLAlchemy
3. **Vues de port** — convertissez les vues de fonction/classe Django en fichiers `.nexy` (FBR) ou `"@Controller` (modulaire)
4. **Configurations d'URL de port** — Les modèles `urls.py` deviennent une arborescence de fichiers (FBR) ou `"@Module` (modulaire)
5. **Modèles de port** — Modèles DTL → Jinja2 dans les fichiers `.nexy`
6. **Middleware de port** — Middleware Django → Starlette `BaseHTTPMiddleware`

## Pourquoi changer

- **Aucun paramètre monolithique** : configurez uniquement ce que vous utilisez
- **Async par défaut** — FastAPI/Starlette sous le capot
- **Documents OpenAPI** — automatique, aucun `drf-spectacular` nécessaire
- **Interface utilisateur basée sur les composants** — mélangez Python + Jinja2 dans un seul fichier
- **Choix de framework** — React, Vue, Svelte, Solid ou Preact pour le frontend
