# Migrate from Django to Nexy

Django is batteries-included. Nexy is focused and modular — you bring what you need.

## Concepts mapping

| Django | Nexy |
|--------|------|
| `views.py` | `.nexy` files (FBR) or `"@Controller` (Modular) |
| `urls.py` | File tree (FBR) or `"@Module` (Modular) |
| `models.py` | SQLModel / SQLAlchemy (your choice) |
| `admin.py` | OpenAPI docs at `/docs` |
| `manage.py` | `nx` CLI |
| `settings.py` | `nexyconfig.py` |
| Django ORM | SQLModel, SQLAlchemy, or Tortoise-ORM |
| Templates (DTL) | Jinja2 (`.nexy` files) |
| Class-based views | `"@Controller` (Modular) or `.nexy` files (FBR) |
| Middleware | `"@Middleware` or FastAPI middleware |
| `request.user` | `request.state.user` or guards |

## Example
```python
# src/routes/users/index.nexy
---
from pydantic import BaseModel

class UserOut(BaseModel):
    id: int
    name: str
    email: str

def GET():
    return {"users": [u.model_dump() for u in User.find_all()]}
---
```
```python
# Nexy Modular
from nexy.decorators import Controller

"@Controller("/users")
class UsersController:
    def GET(self):
        return {"users": [u.model_dump() for u in User.find_all()]}
```
## Migration steps

1. **Scaffold a new Nexy project** — `nx new my-app`
2. **Port models** — translate Django models to SQLModel/SQLAlchemy
3. **Port views** — convert Django function/class views to `.nexy` files (FBR) or `"@Controller` (Modular)
4. **Port URL configs** — `urls.py` patterns become file tree (FBR) or `"@Module` (Modular)
5. **Port templates** — DTL templates → Jinja2 in `.nexy` files
6. **Port middleware** — Django middleware → Starlette `BaseHTTPMiddleware`

## Why switch

- **No monolithic settings** — configure only what you use
- **Async by default** — FastAPI/Starlette under the hood
- **OpenAPI docs** — automatic, no `drf-spectacular` needed
- **Component-based UI** — mix Python + Jinja2 in one file
- **Framework choice** — React, Vue, Svelte, Solid, or Preact for the frontend
