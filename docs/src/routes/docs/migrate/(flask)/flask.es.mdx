# Migrar de Flask a Nexy

El matraz es mínimo. Nexy también es mínimo, pero con asíncrono moderno, tipos y OpenAPI integrados.

## Mapeo de conceptos

| matraz | Nexy |
|-------|------|
| `"@app.route("/")` | Archivo en `src/routes/` o `"@Controller` |
| `render_template()` | Archivo `.nexy` |
| `request.args` | Parámetros de consulta en la firma de la función |
| `request.json` | Parámetro del cuerpo en la firma de la función |
| `g` | `request.state` |
| `flask run` | `nx dev` |
| `config.py` | `nexyconfig.py` |
| Planos | Subdirectorios `"@Module` o `src/routes/` |

## Ejemplo

```python
# Flask
"@app.route("/api/users/<int:id>")
def get_user(id):
    return jsonify({"id": id})

# Nexy FBR: src/routes/api/users/[id].py
async def get(id: int):
    return {"id": id}
```

## Lo que ganas

- **Soporte asíncrono**: nativo, no mediante hacks
- **Validación de tipo** — Pydantic, errores 422 automáticos
- **Documentos OpenAPI**: no se necesita `flasgger`
- **Sistema DI**: inyecta servicios sin singletons globales
- **CLI** — `nx build`, `nx start`, `nx migrate`

## Pasos de migración

1. **Andamio** — `nx new my-app`
2. **Rutas de puerto** — `"@app.route()` → archivo en `src/routes/` o `"@Controller`
3. **Port templates** — Flask `render_template()` → `.nexy` files
4. **Manejo de solicitudes de puerto** — `request.args`/`request.json` → parámetros de función escritos
5. **Planos de puertos** → `"@Module` o subdirectorios en FBR

## Lo que queda

Rutas simples, repetición mínima, control total. Solo con Python moderno.
