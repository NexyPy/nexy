# Next.js से Nexy पर माइग्रेट करें

Next.js ने फ़ाइल-आधारित रूटिंग और सर्वर घटकों को लोकप्रिय बनाया। नेक्सी उसी DX को पायथन में लाता है।

## अवधारणाओं का मानचित्रण

| अगला.जेएस | नेक्सी |
|------|------|
| `app/` निर्देशिका | `src/routes/` निर्देशिका |
| `page.tsx` | `.nexy` या `.mdx` फ़ाइल |
| `layout.tsx` | `layout.nexy` |
| `loading.tsx` | `dependencies.py` |
| `route.ts` (एपीआई) | `.py` फ़ाइल `get()`, `post()`, आदि के साथ |
| `next.config.js` | `nexyconfig.py` |
| सर्वर क्रियाएँ | `"@Action` डेकोरेटर |
| रिएक्ट सर्वर घटक | `.nexy` घटक (पायथन + जिंजा2) |
| `getStaticProps` | `.nexy` में फ्रंटमैटर तर्क |

## उदाहरण

```python
# Next.js: app/users/[id]/page.tsx
export default async function Page({ params }) {
    const user = await db.user.findUnique(params.id);
    return <div>{user.name}</div>;
}

# Nexy: src/routes/users/[id]/index.nexy
---
user = db.user.find_unique(id)
---
<h1>{{ user.name }}</h1>
```

## प्रवास के चरण

1. **मचान** — `nx new my-app`
2. **पोर्ट पेज** - `page.tsx` → `.nexy` या `.mdx` फ़ाइलें
3. **पोर्ट लेआउट** — `layout.tsx` → `layout.nexy`
4. **पोर्ट एपीआई मार्ग** - `route.ts` → `.py` फ़ाइलें `get()`, `post()`, आदि के साथ।
5. **पोर्ट सर्वर क्रियाएँ** — सर्वर क्रियाएँ → `"@Action` डेकोरेटर

## मुख्य अंतर

- **सर्वर पर पायथन** - कोई जावास्क्रिप्ट/टाइपस्क्रिप्ट की आवश्यकता नहीं है
- **पेजों के लिए कोई निर्माण चरण नहीं** - `.nexy` फ़ाइलें डेव टाइम पर संकलित होती हैं
- **मल्टीपल फ्रंटएंड फ्रेमवर्क** - रिएक्ट, व्यू, स्वेल्ट, सॉलिड, प्रीएक्ट
- **हुड के नीचे फास्टएपीआई** - एसिंक, ओपनएपीआई, टाइप-सुरक्षित
- **दो रूटिंग रणनीतियाँ** - फ़ाइल-आधारित (जैसे Next.js पेज) या मॉड्यूलर (जैसे NestJS)
