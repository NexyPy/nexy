# وحدات التحكم

تقوم وحدات التحكم بتجميع نقاط نهاية HTTP ذات الصلة ضمن بادئة مشتركة. بدلاً من تشتيت المسارات عبر الملفات، تحتفظ وحدة التحكم بكل نقطة نهاية لمورد في فئة واحدة.

## لماذا وحدات التحكم؟

في FBR، يمكنك إنشاء `users/index.nexy`، `users/[id].nexy`، `users/create.nexy`. يعالج كل ملف عنوان URL واحدًا. يعمل ذلك حتى تحتاج إحدى الصفحات إلى بيانات من صفحة أخرى، أو تقوم بمشاركة منطق المصادقة عبر 10 مسارات للمستخدم.

تضع وحدة التحكم كافة المسارات `/users/*` في فئة واحدة. التبعيات المشتركة تذهب إلى المنشئ. المنطق الخاص بالمسار موجود في كل طريقة.

## إنشاء وحدة تحكم

تزيين الفصل بـ `"@Controller(prefix)`:

```python
from nexy.decorators import Controller

"@Controller("/users")
class UsersController:
    def GET(self):
        return [{"id": 1, "name": "Alice"}, {"id": 2, "name": "Bob"}]

    def post(self, data: dict):
        return {"id": 3, **data}
```

** تحدد أسماء الطرق طريقة HTTP. ** يقوم Nexy بوضع اسم الطريقة بأحرف كبيرة ويطابقه مع طرق HTTP القياسية. `GET` → ​​GET، `post` → POST، `Put` → PUT.

كافة المسارات في وحدة التحكم هذه موجودة عند `/users/`:
- `GET /users/` → `GET()`
- `POST /users/` → `post(data)`

**مسكتك**: يمكنك الحصول على طريقة واحدة فقط لكل طريقة HTTP لكل وحدة تحكم. `def GET(self): ... def get(self): ...` سيرفع `ValueError` عند بدء التشغيل.

## رسم خرائط طريقة الطريق

| اسم الطريقة | طريقة HTTP | مثال |
|-------------|-------------|---------|
| `GET`، `get`، `Get` | احصل على | إقرأ المصادر |
| `post`، `POST`، `Post` | مشاركة | إنشاء الموارد |
| `put`، `PUT`، `Put` | ضع | استبدال الموارد |
| `delete`، `DELETE`، `Delete` | حذف | إزالة الموارد |
| `patch`، `PATCH`، `Patch` | التصحيح | تحديث جزئي |
| `options`، `OPTIONS`، `Options` | خيارات | الاختبار المبدئي لـ CORS |
| `head`، `HEAD`، `Head` | رئيس | رؤوس الاستجابة فقط |
| `SOCKET`، `socket`، `Socket` | ويب سوكيت | التواصل في الوقت الحقيقي |

**التقليد**: استخدم الأحرف الكبيرة لعمليات القراءة (`GET`)، والأحرف الصغيرة للطفرات (`post`، `put`، `delete`). وهذا يجعل من السهل فحص وحدة التحكم - يمكنك رؤية أفعال HTTP في لمحة سريعة.

## معلمات المسار

يتم إدخال معلمات المسار في **بادئة وحدة التحكم**، وليس في الطرق الفردية:

```python
"@Controller("/users/{id}")
class UserDetailController:
    def GET(self, id: int):
        return {"id": id, "name": "Charlie"}

    def delete(self, id: int):
        return {"deleted": id}
```

يتم فرض معلمات المسار على النوع ** — يقرأ جهاز التوجيه تلميح النوع ويحول السلسلة من عنوان URL. الأنواع المدعومة: `int`، `float`، `str`، `uuid.UUID`، `datetime.datetime`.

**مسكتك**: إذا فشل الإكراه (على سبيل المثال، `GET /users/abc` حيث `id: int`)، فسيقوم جهاز التوجيه بإرجاع خطأ التحقق من الصحة 422، وليس 404. وهذا يخبر العميل بأن تنسيق المعلمة خاطئ، وليس أن المورد غير موجود.

### معلمات مسار متعددة

```python
"@Controller("/users/{userId}/posts/{postId}")
class UserPostController:
    def GET(self, userId: int, postId: int):
        return {"user": userId, "post": postId}
```

## معلمات الاستعلام

تتوفر معلمات سلسلة الاستعلام كوسيطات للكلمات الرئيسية الوظيفية مع الإعدادات الافتراضية:

```python
"@Controller("/users")
class UsersController:
    def GET(self, q: str | None = None, page: int = 1):
        return {"query": q, "page": page}
```

يعالج نظام حقن التبعية الخاص بـ FastAPI تحليل معلمات الاستعلام تلقائيًا. يتم تفسير المعلمات التي ليست معلمات مسار على أنها معلمات استعلام.

يمكنك أيضًا الوصول إلى معلمات الاستعلام عبر `request.query_params`:

```python
from fastapi import Request

"@Controller("/users")
class UsersController:
    def GET(self, request: Request):
        q = request.query_params.get("q")
        page = int(request.query_params.get("page", 1))
        return {"query": q, "page": page}
```

**مسكتك**: `useQuery` يُرجع معلمات المسار، وليس معلمات الاستعلام. بالنسبة لمعلمات الاستعلام، قم بتعريفها كوسيطات للكلمات الرئيسية الوظيفية أو استخدم `request.query_params`.

## نص الطلب

تقوم أساليب POST وPUT وPATCH تلقائيًا بتحليل نص الطلب. قم بتعريف تلميح النوع:

```python
from pydantic import BaseModel

class CreateUser(BaseModel):
    name: str
    email: str

"@Controller("/users")
class UsersController:
    def post(self, body: CreateUser):
        return {"id": 4, **body.model_dump()}
```

يتم تحليل النص كـ JSON افتراضيًا. توفر نماذج Pydantic التحقق التلقائي - تُرجع الحقول غير الصالحة 422 مع وجود أخطاء على مستوى الحقل.

**مسكتك**: إذا استخدمت `dict` كتلميح للنوع، فستفقد التحقق من الصحة. تفضل دائمًا Pydantic لنقاط النهاية التي تواجه المستخدم.

## تجاوز رموز الحالة

استخدم `"@UseResponse(status_code=...)` لتجاوز رمز الحالة الافتراضي:

```python
from nexy.decorators import Controller, UseResponse

"@Controller("/users")
class UsersController:
    "@UseResponse(status_code=201)
    def post(self, data: dict):
        return {"id": 5}
```

رموز الحالة الافتراضية: `GET` → 200، `POST` → 201، `DELETE` → 204، أخرى → 200.

يدعم `"@UseResponse` أيضًا نموذج الاستجابة وفئة الاستجابة ووصف الاستجابة والخيارات الأخرى المتوافقة مع FastAPI:

```python
from nexy.decorators import UseResponse
from fastapi.responses import HTMLResponse

"@UseResponse(
    status_code=200,
    response_class=HTMLResponse,
    response_model=None,
    response_description="User profile page",
)
def GET(self):
    ...
```

## البيانات الوصفية للطريق

أضف بيانات تعريف OpenAPI مع `"@UseRoute`:

```python
from nexy.decorators import Controller, UseRoute

"@Controller("/users")
class UsersController:
    "@UseRoute(summary="List all users", description="Returns paginated user list")
    def GET(self):
        return [...]

    "@UseRoute(summary="Create a user", deprecated=True)
    def post(self, data: dict):
        return [...]
```

`"@UseRoute` يدعم: `name`، `tags`، `summary`، `description`، `deprecated`، `include_in_schema`، `operation_id`، `openapi_extra`.

## معالجات غير متزامنة

تدعم وحدات التحكم معالجات المزامنة وغير المتزامنة:

```python
"@Controller("/users")
class UsersController:
    async def GET(self):
        users = await db.fetch_all()
        return users

    def post(self, data: dict):
        # Sync is fine for CPU-bound work
        return process_sync(data)
```

Nexy ينتظر تلقائيًا معالجات غير متزامنة. تعمل معالجات المزامنة في Threadpool. تفضل عدم المزامنة لنقاط النهاية المرتبطة بالإدخال/الإخراج (قاعدة البيانات، مكالمات HTTP).

## معالجة الأخطاء

رفع استثناءات HTTP لاستجابات الأخطاء:

```python
from starlette.exceptions import HTTPException

"@Controller("/users/{id}")
class UserDetailController:
    def GET(self, id: int):
        if id < 1:
            raise HTTPException(400, "ID must be positive")
        user = find_user(id)
        if not user:
            raise HTTPException(404, "User not found")
        return user
```

استخدم رموز حالة HTTP القياسية. تقوم Nexy بإعادة تصدير الاستثناءات من Starlette.

## وحدة تحكم واحدة، مسار واحد

القيد الأساسي: **جميع الأساليب في وحدة التحكم تشترك في نفس المسار**. يتم تحديد المسار بواسطة بادئة وحدة التحكم. لا يمكنك تحديد المسارات الفرعية لكل طريقة.

إذا كنت بحاجة إلى `/users` و`/users/{id}`، فقم بإنشاء وحدتي تحكم:

```python
"@Controller("/users")
class UsersController:
    def GET(self):
        return [...]          # GET /users/

    def post(self, data: dict):
        return {...}          # POST /users/

"@Controller("/users/{id}")
class UserDetailController:
    def GET(self, id: int):
        return {...}          # GET /users/42

    def delete(self, id: int):
        return None           # DELETE /users/42
```

يمكن أن يكون كل من وحدات التحكم في نفس الوحدة. هذا الفصل مقصود — حيث تتعامل كل وحدة تحكم مع مسار مورد واحد.

## تكامل الوحدة

يتم تسجيل وحدات التحكم في الوحدة النمطية عبر سمة الفئة `controllers`:

```python
from nexy.decorators import Module

"@Module()
class UsersModule:
    controllers = [UsersController, UserDetailController]
```

يمكن للوحدة تعيين بادئة تنطبق على جميع وحدات التحكم الخاصة بها:

```python
"@Module(prefix="/api/v1")
class UsersModule:
    controllers = [UsersController, UserDetailController]
    # → GET /api/v1/users/, DELETE /api/v1/users/42
```

## أفضل الممارسات

1. **مورد واحد لكل وحدة تحكم** — `UsersController`، `PostsController`. ليس `ApiController` واحد.
2. **حافظ على تركيز الأساليب** — كل طريقة تؤدي شيئًا واحدًا.
3. **استخدم حقن التبعية** — لا تقم بإنشاء مثيل للخدمات في نص الطريقة.
4. **تفضل Pydantic لهيئات الطلب** — `body: dict` عبارة عن رائحة رمزية.
5. **وحدات التحكم البادئة ذات معنى** — `/users`، `/posts`، `/auth`.
