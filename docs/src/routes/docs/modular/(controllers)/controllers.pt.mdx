# Controladores

Os controladores agrupam terminais HTTP relacionados sob um prefixo comum. Em vez de espalhar rotas entre arquivos, um controlador mantém cada endpoint de um recurso em uma classe.

## Por que controladores?

No FBR, você cria `users/index.nexy`, `users/[id].nexy`, `users/create.nexy`. Cada arquivo lida com um URL. Isso funciona até que uma página precise de dados de outra ou você compartilhe a lógica de autenticação em 10 rotas de usuário.

Um controlador coloca todas as rotas `/users/*` em uma classe. As dependências compartilhadas vão para o construtor. A lógica específica da rota está presente em cada método.

## Criando um controlador

Decore uma aula com `"@Controller(prefix)`:

```python
from nexy.decorators import Controller

"@Controller("/users")
class UsersController:
    def GET(self):
        return [{"id": 1, "name": "Alice"}, {"id": 2, "name": "Bob"}]

    def post(self, data: dict):
        return {"id": 3, **data}
```

**Os nomes dos métodos definem o método HTTP.** Nexy coloca o nome do método em letras maiúsculas e compara-o com os métodos HTTP padrão. `GET` → ​​OBTER, `post` → POST, `Put` → COLOCAR.

Todas as rotas neste controlador estão em `/users/`:
- `GET /users/` → `GET()`
- `POST /users/` → `post(data)`

**Entendi**: você só pode ter UM método por método HTTP por controlador. `def GET(self): ... def get(self): ...` aumentaria `ValueError` na inicialização.

## Mapeamento de método de rota

| Nome do método | Método HTTP | Exemplo |
|---------|-------------|---------|
| `GET`, `get`, `Get` | OBTER | Leia recursos |
| `post`, `POST`, `Post` | POSTAR | Criar recursos |
| `put`, `PUT`, `Put` | COLOCAR | Substituir recursos |
| `delete`, `DELETE`, `Delete` | EXCLUIR | Remover recursos |
| `patch`, `PATCH`, `Patch` | REMENDO | Atualização parcial |
| `options`, `OPTIONS`, `Options` | OPÇÕES | Pré-voo CORS |
| `head`, `HEAD`, `Head` | CABEÇA | Apenas cabeçalhos de resposta |
| `SOCKET`, `socket`, `Socket` | WebSocket | Comunicação em tempo real |

**Convenção**: Use letras maiúsculas para operações de leitura (`GET`), letras minúsculas para mutações (`post`, `put`, `delete`). Isso torna o controlador mais fácil de verificar — você vê os verbos HTTP rapidamente.

## Parâmetros de caminho

Os parâmetros do caminho vão no **prefixo do controlador**, não em métodos individuais:

```python
"@Controller("/users/{id}")
class UserDetailController:
    def GET(self, id: int):
        return {"id": id, "name": "Charlie"}

    def delete(self, id: int):
        return {"deleted": id}
```

Os parâmetros de caminho são **coagidos por tipo** — o roteador lê a dica de tipo e converte a string do URL. Tipos suportados: `int`, `float`, `str`, `uuid.UUID`, `datetime.datetime`.

**Entendi**: Se a coerção falhar (por exemplo, `GET /users/abc` onde `id: int`), o roteador retornará um erro de validação 422, não um 404. Isso informa ao cliente que o formato do parâmetro está errado, não que o recurso não existe.

### Vários parâmetros de caminho

```python
"@Controller("/users/{userId}/posts/{postId}")
class UserPostController:
    def GET(self, userId: int, postId: int):
        return {"user": userId, "post": postId}
```

## Parâmetros de consulta

Os parâmetros da string de consulta estão disponíveis como argumentos de palavra-chave de função com padrões:

```python
"@Controller("/users")
class UsersController:
    def GET(self, q: str | None = None, page: int = 1):
        return {"query": q, "page": page}
```

O sistema de injeção de dependência do FastAPI lida com a análise de parâmetros de consulta automaticamente. Os parâmetros que não são parâmetros de caminho são interpretados como parâmetros de consulta.

Você também pode acessar parâmetros de consulta via `request.query_params`:

```python
from fastapi import Request

"@Controller("/users")
class UsersController:
    def GET(self, request: Request):
        q = request.query_params.get("q")
        page = int(request.query_params.get("page", 1))
        return {"query": q, "page": page}
```

**Entendi**: `useQuery` retorna parâmetros de caminho, não parâmetros de consulta. Para parâmetros de consulta, declare-os como argumentos de palavra-chave de função ou use `request.query_params`.

## Corpo da solicitação

Os métodos POST, PUT e PATCH analisam automaticamente o corpo da solicitação. Declare uma dica de tipo:

```python
from pydantic import BaseModel

class CreateUser(BaseModel):
    name: str
    email: str

"@Controller("/users")
class UsersController:
    def post(self, body: CreateUser):
        return {"id": 4, **body.model_dump()}
```

O corpo é analisado como JSON por padrão. Os modelos Pydantic fornecem validação automática – campos inválidos retornam 422 com erros no nível do campo.

**Entendi**: Se você usar `dict` como dica de tipo, você perderá a validação. Sempre prefira Pydantic para endpoints voltados para o usuário.

## Substituindo códigos de status

Use `"@UseResponse(status_code=...)` para substituir o código de status padrão:

```python
from nexy.decorators import Controller, UseResponse

"@Controller("/users")
class UsersController:
    "@UseResponse(status_code=201)
    def post(self, data: dict):
        return {"id": 5}
```

Códigos de status padrão: `GET` → 200, `POST` → 201, `DELETE` → 204, outros → 200.

`"@UseResponse` também suporta modelo de resposta, classe de resposta, descrição de resposta e outras opções compatíveis com FastAPI:

```python
from nexy.decorators import UseResponse
from fastapi.responses import HTMLResponse

"@UseResponse(
    status_code=200,
    response_class=HTMLResponse,
    response_model=None,
    response_description="User profile page",
)
def GET(self):
    ...
```

## Metadados de rota

Adicione metadados OpenAPI com `"@UseRoute`:

```python
from nexy.decorators import Controller, UseRoute

"@Controller("/users")
class UsersController:
    "@UseRoute(summary="List all users", description="Returns paginated user list")
    def GET(self):
        return [...]

    "@UseRoute(summary="Create a user", deprecated=True)
    def post(self, data: dict):
        return [...]
```

`"@UseRoute` suporta: `name`, `tags`, `summary`, `description`, `deprecated`, `include_in_schema`, `operation_id`, `openapi_extra`.

## Manipuladores assíncronos

Os controladores suportam manipuladores sincronizados e assíncronos:

```python
"@Controller("/users")
class UsersController:
    async def GET(self):
        users = await db.fetch_all()
        return users

    def post(self, data: dict):
        # Sync is fine for CPU-bound work
        return process_sync(data)
```

Nexy aguarda automaticamente manipuladores assíncronos. Os manipuladores de sincronização são executados em um threadpool. Prefira assíncrono para endpoints vinculados a E/S (banco de dados, chamadas HTTP).

## Tratamento de erros

Gere exceções HTTP para respostas de erro:

```python
from starlette.exceptions import HTTPException

"@Controller("/users/{id}")
class UserDetailController:
    def GET(self, id: int):
        if id < 1:
            raise HTTPException(400, "ID must be positive")
        user = find_user(id)
        if not user:
            raise HTTPException(404, "User not found")
        return user
```

Use códigos de status HTTP padrão. Nexy reexporta exceções de Starlette.

## Um controlador, um caminho

Uma restrição fundamental: **todos os métodos em um controlador compartilham o mesmo caminho**. O caminho é determinado pelo prefixo do controlador. Você não pode definir subcaminhos por método.

Se você precisar de `/users` e `/users/{id}`, crie dois controladores:

```python
"@Controller("/users")
class UsersController:
    def GET(self):
        return [...]          # GET /users/

    def post(self, data: dict):
        return {...}          # POST /users/

"@Controller("/users/{id}")
class UserDetailController:
    def GET(self, id: int):
        return {...}          # GET /users/42

    def delete(self, id: int):
        return None           # DELETE /users/42
```

Ambos os controladores podem estar no mesmo módulo. Essa separação é intencional — cada controlador lida com um caminho de recurso.

## Integração de Módulo

Os controladores são registrados em um módulo através do atributo de classe `controllers`:

```python
from nexy.decorators import Module

"@Module()
class UsersModule:
    controllers = [UsersController, UserDetailController]
```

O módulo pode definir um prefixo que se aplica a todos os seus controladores:

```python
"@Module(prefix="/api/v1")
class UsersModule:
    controllers = [UsersController, UserDetailController]
    # → GET /api/v1/users/, DELETE /api/v1/users/42
```

## Melhores práticas

1. **Um recurso por controlador** — `UsersController`, `PostsController`. Nem um único `ApiController`.
2. **Mantenha o foco nos métodos** — cada método faz uma coisa.
3. **Use injeção de dependência** — não instancie serviços no corpo do método.
4. **Prefira Pydantic para corpos de solicitação** — `body: dict` é um cheiro de código.
5. **Prefixar controladores significativamente** — `/users`, `/posts`, `/auth`.
