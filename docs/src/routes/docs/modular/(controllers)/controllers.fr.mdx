# Contrôleurs

Les contrôleurs regroupent les points de terminaison HTTP associés sous un préfixe commun. Au lieu de disperser les routes entre les fichiers, un contrôleur conserve chaque point de terminaison d’une ressource dans une seule classe.

## Pourquoi des contrôleurs ?

Dans FBR, vous créez `users/index.nexy`, `users/[id].nexy`, `users/create.nexy`. Chaque fichier gère une URL. Cela fonctionne jusqu'à ce qu'une page ait besoin des données d'une autre ou que vous partagiez la logique d'authentification sur 10 routes utilisateur.

Un contrôleur place toutes les routes `/users/*` dans une seule classe. Les dépendances partagées vont dans le constructeur. La logique spécifique à l'itinéraire est présente dans chaque méthode.

## Création d'un contrôleur

Décorez une classe avec `"@Controller(prefix)` :

```python
from nexy.decorators import Controller

"@Controller("/users")
class UsersController:
    def GET(self):
        return [{"id": 1, "name": "Alice"}, {"id": 2, "name": "Bob"}]

    def post(self, data: dict):
        return {"id": 3, **data}
```

**Les noms de méthode définissent la méthode HTTP.** Nexy met en majuscule le nom de la méthode et le compare aux méthodes HTTP standard. `GET` → ​​GET, `post` → POST, `Put` → PUT.

Toutes les routes de ce contrôleur sont à `/users/` :
- `GET /users/` → `GET()`
- `POST /users/` → `post(data)`

** Gotcha ** : vous ne pouvez avoir qu'UNE seule méthode par méthode HTTP et par contrôleur. `def GET(self): ... def get(self): ...` générerait un `ValueError` au démarrage.

## Cartographie des méthodes d'itinéraire

| Nom de la méthode | Méthode HTTP | Exemple |
|-------------|-------------|---------|
| `GET`, `get`, `Get` | OBTENIR | Lire les ressources |
| `post`, `POST`, `Post` | POSTER | Créer des ressources |
| `put`, `PUT`, `Put` | METTRE | Remplacer les ressources |
| `delete`, `DELETE`, `Delete` | SUPPRIMER | Supprimer des ressources |
| `patch`, `PATCH`, `Patch` | PATCH | Mise à jour partielle |
| `options`, `OPTIONS`, `Options` | OPTIONS | Contrôle en amont CORS |
| `head`, `HEAD`, `Head` | TÊTE | En-têtes de réponse uniquement |
| `SOCKET`, `socket`, `Socket` | WebSocket | Communication en temps réel |

**Convention** : utilisez des majuscules pour les opérations de lecture (`GET`), des minuscules pour les mutations (`post`, `put`, `delete`). Cela rend le contrôleur plus facile à analyser : vous voyez les verbes HTTP en un coup d'œil.

## Paramètres du chemin

Les paramètres de chemin vont dans le **préfixe du contrôleur**, pas dans les méthodes individuelles :

```python
"@Controller("/users/{id}")
class UserDetailController:
    def GET(self, id: int):
        return {"id": id, "name": "Charlie"}

    def delete(self, id: int):
        return {"deleted": id}
```

Les paramètres de chemin sont **contraints par type** : le routeur lit l'indice de type et convertit la chaîne à partir de l'URL. Types pris en charge : `int`, `float`, `str`, `uuid.UUID`, `datetime.datetime`.

**Je vous ai eu** : si la coercition échoue (par exemple, `GET /users/abc` où `id: int`), le routeur renvoie une erreur de validation 422, et non 404. Cela indique au client que le format du paramètre est incorrect, et non que la ressource n'existe pas.

### Paramètres de chemin multiples

```python
"@Controller("/users/{userId}/posts/{postId}")
class UserPostController:
    def GET(self, userId: int, postId: int):
        return {"user": userId, "post": postId}
```

## Paramètres de requête

Les paramètres de chaîne de requête sont disponibles en tant qu'arguments de mot-clé de fonction avec les valeurs par défaut :

```python
"@Controller("/users")
class UsersController:
    def GET(self, q: str | None = None, page: int = 1):
        return {"query": q, "page": page}
```

Le système d'injection de dépendances de FastAPI gère automatiquement l'analyse des paramètres de requête. Les paramètres qui ne sont pas des paramètres de chemin sont interprétés comme des paramètres de requête.

Vous pouvez également accéder aux paramètres de requête via `request.query_params` :

```python
from fastapi import Request

"@Controller("/users")
class UsersController:
    def GET(self, request: Request):
        q = request.query_params.get("q")
        page = int(request.query_params.get("page", 1))
        return {"query": q, "page": page}
```

**Je t'ai eu** : `useQuery` renvoie les paramètres de chemin, pas les paramètres de requête. Pour les paramètres de requête, déclarez-les comme arguments de mot-clé de fonction ou utilisez `request.query_params`.

## Corps de la demande

Les méthodes POST, PUT et PATCH analysent automatiquement le corps de la requête. Déclarez un indice de type :

```python
from pydantic import BaseModel

class CreateUser(BaseModel):
    name: str
    email: str

"@Controller("/users")
class UsersController:
    def post(self, body: CreateUser):
        return {"id": 4, **body.model_dump()}
```

Le corps est analysé au format JSON par défaut. Les modèles Pydantic fournissent une validation automatique : les champs invalides renvoient un 422 avec des erreurs au niveau du champ.

**Je t'ai eu** : si vous utilisez `dict` comme indice de type, vous perdez la validation. Préférez toujours Pydantic pour les points de terminaison orientés utilisateur.

## Remplacement des codes d'état

Utilisez `"@UseResponse(status_code=...)` pour remplacer le code d'état par défaut :

```python
from nexy.decorators import Controller, UseResponse

"@Controller("/users")
class UsersController:
    "@UseResponse(status_code=201)
    def post(self, data: dict):
        return {"id": 5}
```

Codes d'état par défaut : `GET` → 200, `POST` → 201, `DELETE` → 204, autres → 200.

`"@UseResponse` prend également en charge le modèle de réponse, la classe de réponse, la description de la réponse et d'autres options compatibles FastAPI :

```python
from nexy.decorators import UseResponse
from fastapi.responses import HTMLResponse

"@UseResponse(
    status_code=200,
    response_class=HTMLResponse,
    response_model=None,
    response_description="User profile page",
)
def GET(self):
    ...
```

## Métadonnées d'itinéraire

Ajoutez des métadonnées OpenAPI avec `"@UseRoute` :

```python
from nexy.decorators import Controller, UseRoute

"@Controller("/users")
class UsersController:
    "@UseRoute(summary="List all users", description="Returns paginated user list")
    def GET(self):
        return [...]

    "@UseRoute(summary="Create a user", deprecated=True)
    def post(self, data: dict):
        return [...]
```

`"@UseRoute` prend en charge : `name`, `tags`, `summary`, `description`, `deprecated`, `include_in_schema`, `operation_id`, `openapi_extra`.

## Gestionnaires asynchrones

Les contrôleurs prennent en charge les gestionnaires de synchronisation et asynchrones :

```python
"@Controller("/users")
class UsersController:
    async def GET(self):
        users = await db.fetch_all()
        return users

    def post(self, data: dict):
        # Sync is fine for CPU-bound work
        return process_sync(data)
```

Nexy attend automatiquement les gestionnaires asynchrones. Les gestionnaires de synchronisation s'exécutent dans un pool de threads. Préférez l'asynchrone pour les points de terminaison liés aux E/S (base de données, appels HTTP).

## Gestion des erreurs

Déclenchez des exceptions HTTP pour les réponses d'erreur :

```python
from starlette.exceptions import HTTPException

"@Controller("/users/{id}")
class UserDetailController:
    def GET(self, id: int):
        if id < 1:
            raise HTTPException(400, "ID must be positive")
        user = find_user(id)
        if not user:
            raise HTTPException(404, "User not found")
        return user
```

Utilisez les codes d'état HTTP standard. Nexy réexporte les exceptions de Starlette.

## Un contrôleur, un chemin

Une contrainte fondamentale : **toutes les méthodes d'un contrôleur partagent le même chemin**. Le chemin est déterminé par le préfixe du contrôleur. Vous ne pouvez pas définir de sous-chemins par méthode.

Si vous avez besoin de `/users` et `/users/{id}`, créez deux contrôleurs :

```python
"@Controller("/users")
class UsersController:
    def GET(self):
        return [...]          # GET /users/

    def post(self, data: dict):
        return {...}          # POST /users/

"@Controller("/users/{id}")
class UserDetailController:
    def GET(self, id: int):
        return {...}          # GET /users/42

    def delete(self, id: int):
        return None           # DELETE /users/42
```

Les deux contrôleurs peuvent être dans le même module. Cette séparation est intentionnelle : chaque contrôleur gère un chemin de ressources.

## Intégration des modules

Les contrôleurs sont enregistrés dans un module via l'attribut de classe `controllers` :

```python
from nexy.decorators import Module

"@Module()
class UsersModule:
    controllers = [UsersController, UserDetailController]
```

Le module peut définir un préfixe qui s'applique à tous ses contrôleurs :

```python
"@Module(prefix="/api/v1")
class UsersModule:
    controllers = [UsersController, UserDetailController]
    # → GET /api/v1/users/, DELETE /api/v1/users/42
```

## meilleures pratiques

1. **Une ressource par contrôleur** — `UsersController`, `PostsController`. Pas un seul `ApiController`.
2. **Gardez les méthodes concentrées** — chaque méthode fait une chose.
3. **Utilisez l'injection de dépendances** — n'instancierez pas de services dans le corps de la méthode.
4. **Préférez Pydantic pour les corps de requête** — `body: dict` est une odeur de code.
5. **Préfixez les contrôleurs de manière significative** — `/users`, `/posts`, `/auth`.
