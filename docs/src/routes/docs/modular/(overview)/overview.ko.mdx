# 모듈형 라우터 - 아키텍처 개요

Modular Router는 NestJS 스타일 아키텍처를 Python에 도입합니다. 파일이 경로(FBR)가 되는 대신 코드를 **컨트롤러**, **공급자**, **모듈**, **가드** 및 **미들웨어**로 구성합니다.

## 왜 모듈러인가?

FBR(파일 기반 라우팅)은 중소형 앱에 적합합니다. 하지만 앱이 성장함에 따라 다음과 같은 상황이 발생합니다.

| 문제 | FBR | 모듈형 라우터 |
|---------|------|---|
| 교차적 우려 | 파일당 미들웨어 중복 | 컨트롤러 또는 모듈 수준의 가드/미들웨어 |
| 의존성 주입 | 모든 곳에서 수동으로 가져오기 | 자동 해결 기능을 갖춘 `"@Injectable` |
| 코드 구성 | 여러 파일에 흩어져 있음 | 기능 모듈로 그룹화됨 |
| 테스트 가능성 | 파일 경로와의 긴밀한 결합 | 컨트롤러는 주입된 종속성을 허용합니다 |
| 대규모 팀 조정 | 파일 충돌, 불분명한 경계 | 클래스 속성에 의해 시행되는 모듈 경계 |

## 건축학

```
AppModule  ("@Module)
├── AuthModule  ("@Module)
│   ├── AuthController   ("@Controller)
│   │   ├── def GET(self)       → GET /auth/
│   │   └── def post(self, ...)  → POST /auth/
│   └── AuthService      ("@Injectable)
├── UsersModule  ("@Module(prefix="/users"))
│   └── UsersController  ("@Controller)
│       ├── def GET(self)       → GET /users/
│       └── def post(self, ...)  → POST /users/
└── └── UserService      ("@Injectable)
```

### 메소드 이름은 HTTP 동사를 정의합니다.

Nexy는 **메서드 이름**을 HTTP 메소드에 매핑합니다. `"@Get`/`"@Post` 데코레이터가 필요하지 않습니다.

| 메소드 이름 | HTTP 메소드 |
|-------------|-------------|
| `GET`, `get`, `Get` | 받기 |
| `post`, `POST`, `Post` | 포스트 |
| `put`, `PUT`, `Put` | 넣어 |
| `delete`, `DELETE`, `Delete` | 삭제 |
| `patch`, `PATCH`, `Patch` | 패치 |
| `options`, `OPTIONS`, `Options` | 옵션 |
| `head`, `HEAD`, `Head` | 머리 |
| `SOCKET`, `socket`, `Socket` | 웹소켓 |

## 빠른 시작

```python
# src/apps/app_module.py
from nexy.decorators import Module, Controller

"@Controller("/ping")
class PingController:
    def GET(self):
        return {"status": "ok"}

"@Module()
class AppModule:
    controllers = [PingController]
```

`nexyconfig.py`에서 구성:

```python
from nexy import NexyConfigModel

class NexyConfig(NexyConfigModel):
    useModular = "src.apps.app_module.AppModule"
```

## FBR 대신 모듈식을 선택해야 하는 경우

**다음과 같은 경우 모듈식을 선택하세요.**
- 종속성을 공유하는 경로 파일이 5개 이상 있습니다.
- 종속성 주입이 필요합니다(서비스, 데이터베이스, 구성).
- 팀에는 뚜렷한 기능 경계(인증, 청구, 사용자)가 있습니다.

**다음과 같은 경우 FBR을 선택하세요.**
- 경로가 10개 미만입니다.
- 구성보다 컨벤션을 선호합니다.
- 대부분 정적인 사이트를 구축하고 있습니다.
- 가능한 가장 간단한 설정을 원합니다.

## 5가지 개념

| 개념 | 데코레이터 | 목적 |
|---------|------------|---------|
| 컨트롤러 | `"@Controller(prefix)` | 경로 접두사 아래의 그룹 관련 경로 |
| 공급자 | `"@Injectable()` | 컨트롤러에 주입 가능한 비즈니스 로직 |
| 모듈 | `"@Module()` | 클래스 속성을 통해 컨트롤러 및 공급자 연결 |
| 가드 | `"@UseGuard(...)` | 권한 부여 — 핸들러 이전에 실행 |
| 미들웨어 | `"@Middleware(...)` | 요청/응답 파이프라인 — 가드 이전에 실행 |
