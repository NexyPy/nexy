# جهاز التوجيه المعياري — نظرة عامة على البنية

يجلب جهاز التوجيه المعياري بنية نمط NestJS إلى Python. بدلاً من تحويل الملفات إلى مسارات (FBR)، يمكنك تنظيم التعليمات البرمجية في **وحدات التحكم**، و**الموفرين**، و**الوحدات**، و**guards**، و**middleware**.

## لماذا وحدات؟

يعد التوجيه المستند إلى الملفات (FBR) مثاليًا للتطبيقات الصغيرة والمتوسطة. ولكن مع نمو تطبيقك:

| مشكلة | فبر | جهاز التوجيه المعياري |
|---------|-----|----------------|
| المخاوف الشاملة | برامج وسيطة مكررة لكل ملف | الحرس/الوسيطة على مستوى وحدة التحكم أو الوحدة |
| حقن التبعية | الواردات اليدوية في كل مكان | `"@Injectable` مع الدقة التلقائية |
| تنظيم الكود | متناثرة عبر الملفات | مجمعة في وحدات الميزة |
| قابلية الاختبار | اقتران محكم لمسارات الملفات | تقبل وحدات التحكم التبعيات المحقونة |
| تنسيق فريق كبير | تعارضات الملفات، حدود غير واضحة | حدود الوحدة التي يتم فرضها بواسطة سمات الفئة |

## بنيان

```
AppModule  ("@Module)
├── AuthModule  ("@Module)
│   ├── AuthController   ("@Controller)
│   │   ├── def GET(self)       → GET /auth/
│   │   └── def post(self, ...)  → POST /auth/
│   └── AuthService      ("@Injectable)
├── UsersModule  ("@Module(prefix="/users"))
│   └── UsersController  ("@Controller)
│       ├── def GET(self)       → GET /users/
│       └── def post(self, ...)  → POST /users/
└── └── UserService      ("@Injectable)
```

### تحدد أسماء الطرق أفعال HTTP

يقوم Nexy بتعيين **أسماء الطرق** إلى أساليب HTTP — لا حاجة إلى أدوات تزيين `"@Get`/`"@Post`:

| اسم الطريقة | طريقة HTTP |
|-------------|-------------|
| `GET`، `get`، `Get` | احصل على |
| `post`، `POST`، `Post` | مشاركة |
| `put`، `PUT`، `Put` | ضع |
| `delete`، `DELETE`، `Delete` | حذف |
| `patch`، `PATCH`، `Patch` | التصحيح |
| `options`، `OPTIONS`، `Options` | خيارات |
| `head`، `HEAD`، `Head` | رئيس |
| `SOCKET`، `socket`، `Socket` | ويب سوكيت |

## بداية سريعة

```python
# src/apps/app_module.py
from nexy.decorators import Module, Controller

"@Controller("/ping")
class PingController:
    def GET(self):
        return {"status": "ok"}

"@Module()
class AppModule:
    controllers = [PingController]
```

تكوين في `nexyconfig.py`:

```python
from nexy import NexyConfigModel

class NexyConfig(NexyConfigModel):
    useModular = "src.apps.app_module.AppModule"
```

## متى تختار الوحدات بدلاً من FBR

**اختر نمطيًا عندما:**
- لديك أكثر من 5 ملفات توجيه تشترك في التبعيات
- أنت بحاجة إلى حقن التبعية (الخدمات، وقواعد البيانات، والتكوين)
- يتمتع فريقك بحدود مميزة للميزات (المصادقة، والفوترة، والمستخدمين)

**اختر FBR عندما:**
- لديك أقل من 10 طرق
- أنت تفضل التقليد على التكوين
- أنت تقوم ببناء موقع ثابت في الغالب
- تريد أبسط إعداد ممكن

## المفاهيم الخمسة

| المفهوم | ديكور | الغرض |
|---------|---------|---------|
| المراقب المالي | `"@Controller(prefix)` | مجموعات المسارات ذات الصلة تحت بادئة المسار |
| مقدم | `"@Injectable()` | منطق الأعمال، قابل للحقن في وحدات التحكم |
| الوحدة | `"@Module()` | وحدات تحكم الأسلاك ومقدميها عبر سمات الفئة |
| الحرس | `"@UseGuard(...)` | التفويض — يعمل قبل المعالج |
| الوسيطة | `"@Middleware(...)` | خط أنابيب الطلب/الاستجابة — يعمل قبل الحراس |
