# Модульный маршрутизатор — обзор архитектуры

Модульный маршрутизатор привносит в Python архитектуру в стиле NestJS. Вместо того, чтобы файлы превращались в маршруты (FBR), вы организуете код в **контроллеры**, **провайдеры**, **модули**, **защиты** и **промежуточное программное обеспечение**.

## Почему модульный?

Маршрутизация на основе файлов (FBR) идеально подходит для приложений малого и среднего размера. Но по мере роста вашего приложения:

| Проблема | ФБР | Модульный маршрутизатор |
|---------|-----|----------------|
| Сквозные проблемы | Дублирование промежуточного программного обеспечения для каждого файла | Guard/Middleware на уровне контроллера или модуля |
| Внедрение зависимостей | Ручной импорт везде | `"@Injectable` с автоматическим разрешением |
| Организация кода | Разбросаны по файлам | Сгруппированы в функциональные модули |
| Тестируемость | Тесная связь с путями к файлам | Контроллеры принимают внедренные зависимости |
| Координация большой команды | Конфликты файлов, неясные границы | Границы модуля определяются атрибутами класса |

## Архитектура

```
AppModule  ("@Module)
├── AuthModule  ("@Module)
│   ├── AuthController   ("@Controller)
│   │   ├── def GET(self)       → GET /auth/
│   │   └── def post(self, ...)  → POST /auth/
│   └── AuthService      ("@Injectable)
├── UsersModule  ("@Module(prefix="/users"))
│   └── UsersController  ("@Controller)
│       ├── def GET(self)       → GET /users/
│       └── def post(self, ...)  → POST /users/
└── └── UserService      ("@Injectable)
```

### Имена методов определяют HTTP-глаголы

Nexy сопоставляет **имена методов** с методами HTTP — декораторы `"@Get`/`"@Post` не требуются:

| Имя метода | HTTP-метод |
|-------------|-------------|
| `GET`, `get`, `Get` | ПОЛУЧИТЬ |
| `post`, `POST`, `Post` | ПОСТ |
| `put`, `PUT`, `Put` | ПУТЬ |
| `delete`, `DELETE`, `Delete` | УДАЛИТЬ |
| `patch`, `PATCH`, `Patch` | ПАТЧ |
| `options`, `OPTIONS`, `Options` | ОПЦИИ |
| `head`, `HEAD`, `Head` | ГОЛОВА |
| `SOCKET`, `socket`, `Socket` | Вебсокет |

## Быстрый старт

```python
# src/apps/app_module.py
from nexy.decorators import Module, Controller

"@Controller("/ping")
class PingController:
    def GET(self):
        return {"status": "ok"}

"@Module()
class AppModule:
    controllers = [PingController]
```

Настройте в `nexyconfig.py`:

```python
from nexy import NexyConfigModel

class NexyConfig(NexyConfigModel):
    useModular = "src.apps.app_module.AppModule"
```

## Когда лучше выбирать модульную систему, а не FBR

**Выбирайте модульную версию, если:**
- У вас есть более 5 файлов маршрутов, которые имеют общие зависимости.
- Вам нужна инъекция зависимостей (сервисы, базы данных, конфигурация)
– Ваша команда имеет четкие границы функций (авторизация, выставление счетов, пользователи).

**Выбирайте FBR, когда:**
- У вас меньше 10 маршрутов
- Вы предпочитаете соглашения, а не конфигурацию
- Вы создаете в основном статический сайт.
- Вам нужна максимально простая установка

## Пять концепций

| Концепция | Декоратор | Цель |
|---------|-----------|---------|
| Контроллер | `"@Controller(prefix)` | Группирует связанные маршруты по префиксу пути |
| Провайдер | `"@Injectable()` | Бизнес-логика, внедряемая в контроллеры |
| Модуль | `"@Module()` | Контроллеры и провайдеры проводов через атрибуты класса |
| Охранник | `"@UseGuard(...)` | Авторизация — выполняется перед обработчиком |
| Промежуточное ПО | `"@Middleware(...)` | Конвейер запросов/ответов — выполняется до защиты |
