# मॉड्यूलर राउटर - आर्किटेक्चर अवलोकन

मॉड्यूलर राउटर नेस्टजेएस-शैली आर्किटेक्चर को पायथन में लाता है। फ़ाइलों को रूट (FBR) बनाने के बजाय, आप कोड को **नियंत्रक**, **प्रदाता**, **मॉड्यूल**, **गार्ड**, और **मिडलवेयर** में व्यवस्थित करते हैं।

## मॉड्यूलर क्यों?

फ़ाइल-आधारित रूटिंग (FBR) छोटे-से-मध्यम ऐप्स के लिए बिल्कुल सही है। लेकिन जैसे-जैसे आपका ऐप बढ़ता है:

| समस्या | एफबीआर | मॉड्यूलर राउटर |
|---------|-----|----------------|
| क्रॉस-कटिंग चिंताएं | प्रति फ़ाइल डुप्लिकेट मिडलवेयर | नियंत्रक या मॉड्यूल स्तर पर गार्ड/मिडिलवेयर |
| निर्भरता इंजेक्शन | हर जगह मैन्युअल आयात | `"@Injectable` स्वचालित रिज़ॉल्यूशन के साथ |
| कोड संगठन | फाइलों में बिखरा हुआ | फीचर मॉड्यूल में समूहीकृत |
| परीक्षण योग्यता | फ़ाइल पथों के लिए टाइट कपलिंग | नियंत्रक इंजेक्शन निर्भरताएँ स्वीकार करते हैं |
| बड़ी टीम का समन्वय | फ़ाइल विरोध, अस्पष्ट सीमाएँ | वर्ग विशेषताओं द्वारा लागू मॉड्यूल सीमाएँ |

## वास्तुकला

```
AppModule  ("@Module)
├── AuthModule  ("@Module)
│   ├── AuthController   ("@Controller)
│   │   ├── def GET(self)       → GET /auth/
│   │   └── def post(self, ...)  → POST /auth/
│   └── AuthService      ("@Injectable)
├── UsersModule  ("@Module(prefix="/users"))
│   └── UsersController  ("@Controller)
│       ├── def GET(self)       → GET /users/
│       └── def post(self, ...)  → POST /users/
└── └── UserService      ("@Injectable)
```

### विधि नाम HTTP क्रियाओं को परिभाषित करते हैं

HTTP विधियों के लिए Nexy मानचित्र **विधि नाम** - कोई `"@Get`/`"@Post` डेकोरेटर की आवश्यकता नहीं है:

| विधि का नाम | HTTP विधि |
|---|----|
| `GET`, `get`, `Get` | प्राप्त करें |
| `post`, `POST`, `Post` | पोस्ट |
| `put`, `PUT`, `Put` | डालो |
| `delete`, `DELETE`, `Delete` | हटाएं |
| `patch`, `PATCH`, `Patch` | पैच |
| `options`, `OPTIONS`, `Options` | विकल्प |
| `head`, `HEAD`, `Head` | सिर |
| `SOCKET`, `socket`, `Socket` | वेबसॉकेट |

## त्वरित शुरुआत

```python
# src/apps/app_module.py
from nexy.decorators import Module, Controller

"@Controller("/ping")
class PingController:
    def GET(self):
        return {"status": "ok"}

"@Module()
class AppModule:
    controllers = [PingController]
```

`nexyconfig.py` में कॉन्फ़िगर करें:

```python
from nexy import NexyConfigModel

class NexyConfig(NexyConfigModel):
    useModular = "src.apps.app_module.AppModule"
```

## एफबीआर के स्थान पर मॉड्यूलर कब चुनें

**मॉड्यूलर चुनें जब:**
- आपके पास 5+ रूट फ़ाइलें हैं जो निर्भरताएँ साझा करती हैं
- आपको निर्भरता इंजेक्शन (सेवाएं, डेटाबेस, कॉन्फ़िगरेशन) की आवश्यकता है
- आपकी टीम की विशिष्ट विशेषता सीमाएँ हैं (प्रमाणीकरण, बिलिंग, उपयोगकर्ता)

**FBR चुनें जब:**
- आपके पास 10 से कम मार्ग हैं
- आप कॉन्फिगरेशन की बजाय कन्वेंशन को प्राथमिकता देते हैं
- आप अधिकतर स्थैतिक साइट बना रहे हैं
- आप यथासंभव सरलतम सेटअप चाहते हैं

## पाँच अवधारणाएँ

| संकल्पना | डेकोरेटर | उद्देश्य |
|---------|--------|---------|
| नियंत्रक | `"@Controller(prefix)` | पथ उपसर्ग के अंतर्गत संबंधित मार्गों को समूहित करें |
| प्रदाता | `"@Injectable()` | व्यावसायिक तर्क, नियंत्रकों में इंजेक्टेबल |
| मॉड्यूल | `"@Module()` | वर्ग विशेषताओं के माध्यम से तार नियंत्रकों और प्रदाताओं |
| रक्षक | `"@UseGuard(...)` | प्राधिकरण - हैंडलर से पहले चलता है |
| मिडलवेयर | `"@Middleware(...)` | अनुरोध/प्रतिक्रिया पाइपलाइन - गार्ड के सामने चलती है |

## अगले चरण

- [Modules](/docs/modular/modules) - नियंत्रकों और प्रदाताओं को फीचर मॉड्यूल में व्यवस्थित करें
- [Guards](/docs/modular/guards) - प्राधिकरण के साथ मार्गों की सुरक्षा करें
- [Middleware](/docs/modular/middleware) - हैंडलर के समक्ष अनुरोधों को रोकें
