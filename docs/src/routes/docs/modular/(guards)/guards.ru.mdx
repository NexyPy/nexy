# Охранники

Охранники определяют, должен ли запрос достичь обработчика маршрута. Они выполняются **перед методом контроллера** — идеально подходят для аутентификации, авторизации, ограничения скорости и контроля доступа.

Защитниками Nexy являются **зависимости FastAPI**. Это вызываемые объекты (классы с `__call__` или автономные функции), которые получают запрос и либо передают, либо вызывают исключение HTTPException.

## Почему охранники?

Без охранников вы бы проверяли аутентификацию в каждом методе контроллера:

```python
class AdminController:
    def GET(self):
        if not is_authenticated(request):
            raise HTTPException(401)
        return {"role": "admin"}

    def delete(self, id: int):
        if not is_authenticated(request):
            raise HTTPException(401)
        return None
```

Охранник извлекает это в вызываемый объект многократного использования:

```python
class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization")
        if not token:
            raise HTTPException(401)
```

Применяется один раз, защищает каждый маршрут в контроллере:

```python
"@Controller("/admin")
"@UseGuard(AuthGuard())
class AdminController:
    def GET(self):
        return {"role": "admin"}
```

## Создание охраны

Guard — это вызываемый объект, который принимает `Request` и возвращает `None` или повышает:

```python
from starlette.exceptions import HTTPException
from starlette.requests import Request

class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization")
        if not token or not token.startswith("Bearer "):
            raise HTTPException(401, "Missing or invalid token")
```

Охранник вызывает `HTTPException`, чтобы заблокировать запрос. Если он возвращается нормально, запрос продолжается.

**Попался**: `__call__` может быть синхронным или асинхронным — маршрутизатор обрабатывает и то, и другое. Используйте асинхронность, когда вашему охраннику необходимо вызвать базу данных или внешний API.

## Применение защиты

### Уровень контроллера — защищает все маршруты

```python
from nexy.decorators import Controller, UseGuard

"@Controller("/admin")
"@UseGuard(AuthGuard())
class AdminController:
    def GET(self):
        return {"role": "admin"}

    def delete(self, id: int):
        return None
```

### Уровень метода — защищает определенные маршруты.

```python
"@Controller("/users")
class UsersController:
    "@UseGuard(AuthGuard())
    def GET(self):
        return {"email": "user"@example.com"}

    # No guard on public routes
    def post(self, data: dict):
        return {"message": "No auth required"}
```

### Несколько охранников — все должны пройти

```python
"@Controller("/admin")
"@UseGuard(AuthGuard(), RateLimitGuard())
class AdminController:
    ...
```

Охранники казнят в том порядке, в котором они перечислены. Если `AuthGuard` повышает ставку, `RateLimitGuard` никогда не запускается.

**Попался**: меры защиты на уровне метода срабатывают ПОСЛЕ защиты уровня контроллера — и только в том случае, если меры защиты уровня контроллера пройдены.

## Охранники с параметрами

Создайте фабрику охранников для параметризованных охранников:

```python
class RoleGuard:
    def __init__(self, required_role: str):
        self.required_role = required_role

    async def __call__(self, request: Request):
        user_role = request.headers.get("X-Role", "guest")
        if user_role != self.required_role:
            raise HTTPException(403, f"Requires {self.required_role} role")
```

Применить с аргументами:

```python
"@Controller("/admin")
"@UseGuard(RoleGuard("admin"))
class AdminController:
    def GET(self):
        return {"role": "admin"}
```

## Охранники как функции

Простые охранники могут быть самостоятельными функциями:

```python
async def rate_limit(request: Request):
    client_ip = request.client.host if request.client else "unknown"
    if is_rate_limited(client_ip):
        raise HTTPException(429, "Too many requests")

"@Controller("/api")
"@UseGuard(rate_limit)
class ApiController:
    def GET(self):
        return {"data": [...]}
```

## Контекст защиты

Охранники получают полный объект Starlette `Request`, предоставляющий доступ к заголовкам, параметрам запроса, сеансу и т. д.

Установите состояние запроса в защите для последующего использования:

```python
class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization", "").removeprefix("Bearer ")
        user = await verify_token(token)
        if not user:
            raise HTTPException(401)
        request.state.user = user

# In the controller:
class UsersController:
    def GET(self, request: Request):
        return {"user": request.state.user}
```

## Защита против промежуточного программного обеспечения

| Аспект | Охранник | Промежуточное ПО |
|--------|-------|------------|
| Выполняет | До обработчика, после промежуточного программного обеспечения | Перед охранниками и проводником |
| Цель | Аутентификация, авторизация, контроль доступа | Ведение журнала, манипулирование заголовками, CORS |
| Вернуться | `None` или поднимите `HTTPException` | `None` или поднимите `HTTPException` |
| Запросить доступ | Полное через параметр `Request` | Полное через параметр `Request` |

**Когда выбирать защитное или промежуточное программное обеспечение**: если логика определяет, «должен ли этот запрос продолжаться?» (аутентификация, проверка роли, ограничение скорости), используйте защиту. Если логика независимо изменяет запрос/ответ (ведение журнала, CORS), используйте промежуточное программное обеспечение.

## Лучшие практики

1. **Один охранник на группу** — `AuthGuard`, `RoleGuard`, `RateLimitGuard`. Не `SecurityGuard`, который делает все.
2. **Используйте описательные коды состояния** — 401 для отсутствующей/недействительной аутентификации, 403 для недостаточных разрешений, 429 для ограничения скорости.
3. **Избегайте побочных эффектов** — охранники должны проверять разрешения, а не изменять состояние (кроме `request.state`).
4. **Кэширование дорогостоящих проверок** — одноэлементные экземпляры защиты с кэшами в памяти.
5. **Протестируйте охранников изолированно** — создайте макет `Request`, вызовите охранника и подтвердите, что он поднимает или пасует.
