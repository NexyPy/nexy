# 警備員

ガードは、リクエストがルート ハンドラーに到達する必要があるかどうかを決定します。これらは **コントローラー メソッドの前**に実行され、認証、認可、レート制限、およびアクセス制御に最適です。

Nexy のガードは **FastAPI の依存関係**です。これらは、リクエストを受け取り、HTTPException を渡すか、HTTPException を発生させる呼び出し可能オブジェクト (`__call__` を持つクラスまたはスタンドアロン関数) です。

## なぜ警備員なのか?

ガードがなければ、すべてのコントローラー メソッドで認証をチェックすることになります。

```python
class AdminController:
    def GET(self):
        if not is_authenticated(request):
            raise HTTPException(401)
        return {"role": "admin"}

    def delete(self, id: int):
        if not is_authenticated(request):
            raise HTTPException(401)
        return None
```

ガードはこれを再利用可能な呼び出し可能ファイルに抽出します。

```python
class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization")
        if not token:
            raise HTTPException(401)
```

一度適用すると、コントローラー内のすべてのルートが保護されます。

```python
"@Controller("/admin")
"@UseGuard(AuthGuard())
class AdminController:
    def GET(self):
        return {"role": "admin"}
```

## ガードの作成

ガードは、`Request` を受け取り、`None` を返すか、以下を発生させる呼び出し可能です。

```python
from starlette.exceptions import HTTPException
from starlette.requests import Request

class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization")
        if not token or not token.startswith("Bearer "):
            raise HTTPException(401, "Missing or invalid token")
```

ガードは `HTTPException` を発生させてリクエストをブロックします。正常に返された場合、リクエストは続行されます。

**注意事項**: `__call__` は同期または非同期にすることができます。ルーターは両方を処理します。ガードがデータベースまたは外部 API を呼び出す必要がある場合は、async を使用します。

## ガードの適用

### コントローラーレベル — すべてのルートを保護します

```python
from nexy.decorators import Controller, UseGuard

"@Controller("/admin")
"@UseGuard(AuthGuard())
class AdminController:
    def GET(self):
        return {"role": "admin"}

    def delete(self, id: int):
        return None
```

### メソッドレベル — 特定のルートを保護します

```python
"@Controller("/users")
class UsersController:
    "@UseGuard(AuthGuard())
    def GET(self):
        return {"email": "user"@example.com"}

    # No guard on public routes
    def post(self, data: dict):
        return {"message": "No auth required"}
```

### 複数の警備員 - 全員が通過する必要がある

```python
"@Controller("/admin")
"@UseGuard(AuthGuard(), RateLimitGuard())
class AdminController:
    ...
```

ガードはリストされている順序で実行されます。 `AuthGuard` が発生すると、`RateLimitGuard` は実行されません。

**注意事項**: メソッド レベルのガードは、コントローラー レベルのガードの後に​​実行されます。ただし、コントローラー レベルのガードが合格した場合に限ります。

## パラメータ付きのガード

パラメータ化されたガードのガード ファクトリを作成します。

```python
class RoleGuard:
    def __init__(self, required_role: str):
        self.required_role = required_role

    async def __call__(self, request: Request):
        user_role = request.headers.get("X-Role", "guest")
        if user_role != self.required_role:
            raise HTTPException(403, f"Requires {self.required_role} role")
```

引数を指定して適用します。

```python
"@Controller("/admin")
"@UseGuard(RoleGuard("admin"))
class AdminController:
    def GET(self):
        return {"role": "admin"}
```

## 関数としてのガード

単純なガードはスタンドアロン関数にすることができます。

```python
async def rate_limit(request: Request):
    client_ip = request.client.host if request.client else "unknown"
    if is_rate_limited(client_ip):
        raise HTTPException(429, "Too many requests")

"@Controller("/api")
"@UseGuard(rate_limit)
class ApiController:
    def GET(self):
        return {"data": [...]}
```

## ガードコンテキスト

ガードは完全な Starlette `Request` オブジェクトを受け取り、ヘッダー、クエリ パラメーター、セッションなどへのアクセスを許可します。

ダウンストリームで使用するためにガードにリクエスト状態を設定します。

```python
class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization", "").removeprefix("Bearer ")
        user = await verify_token(token)
        if not user:
            raise HTTPException(401)
        request.state.user = user

# In the controller:
class UsersController:
    def GET(self, request: Request):
        return {"user": request.state.user}
```

## ガード対ミドルウェア

|側面 |ガード |ミドルウェア |
|----------|----------|---------------|
|実行します |ハンドラー前、ミドルウェア後 |ガードとハンドラーの前 |
|目的 |認証、承認、アクセス制御 |ロギング、ヘッダー操作、CORS |
|戻る | `None` または値を上げる `HTTPException` | `None` または値を上げる `HTTPException` |
|アクセス権のリクエスト | `Request` パラメータ経由のフル | `Request` パラメータ経由のフル |

**ガードとミドルウェアを選択する場合**: ロジックが「このリクエストを続行すべきか?」と判断した場合。 (認証、ロールチェック、レート制限)、ガードを使用します。ロジックが (ロギング、CORS) に関係なくリクエスト/レスポンスを変更する場合は、ミドルウェアを使用してください。

## ベストプラクティス

1. **懸念事項ごとに 1 つのガード** — `AuthGuard`、`RoleGuard`、`RateLimitGuard`。 `SecurityGuard` がすべてを行うわけではありません。
2. **説明的なステータス コードを使用します** — 欠落または無効な認証の場合は 401、不十分な権限の場合は 403、レート制限の場合は 429。
3. **副作用を避ける** — ガードは状態を変更するのではなく、アクセス許可をチェックする必要があります (`request.state` を除く)。
4. **高価なチェックをキャッシュする** — メモリ内キャッシュを備えたシングルトン ガード インスタンス。
5. **ガードを分離してテスト** — モック `Request` を作成し、ガードを呼び出し、レイズまたはパスをアサートします。
