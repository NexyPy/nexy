# guardias

Los guardias determinan si una solicitud debe llegar al controlador de ruta. Se ejecutan **antes del método del controlador**: perfecto para autenticación, autorización, limitación de velocidad y control de acceso.

Los guardias de Nexy son **dependencias de FastAPI**. Son invocables (clases con `__call__` o funciones independientes) que reciben la solicitud y pasan o generan una excepción HTTP.

## ¿Por qué guardias?

Sin guardias, verificarías la autenticación en cada método del controlador:

```python
class AdminController:
    def GET(self):
        if not is_authenticated(request):
            raise HTTPException(401)
        return {"role": "admin"}

    def delete(self, id: int):
        if not is_authenticated(request):
            raise HTTPException(401)
        return None
```

Un guardia extrae esto en un invocable reutilizable:

```python
class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization")
        if not token:
            raise HTTPException(401)
```

Aplicado una vez, protege todas las rutas en el controlador:

```python
"@Controller("/admin")
"@UseGuard(AuthGuard())
class AdminController:
    def GET(self):
        return {"role": "admin"}
```

## Creando una guardia

Un guardia es un callable que toma un `Request` y devuelve `None` o sube:

```python
from starlette.exceptions import HTTPException
from starlette.requests import Request

class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization")
        if not token or not token.startswith("Bearer "):
            raise HTTPException(401, "Missing or invalid token")
```

El guardia levanta `HTTPException` para bloquear la solicitud. Si regresa normalmente, la solicitud continúa.

**Te tengo**: `__call__` puede ser sincronizado o asíncrono; el enrutador maneja ambos. Utilice async cuando su guardia necesite llamar a una base de datos o API externa.

## Aplicar guardias

### Nivel de controlador: protege todas las rutas

```python
from nexy.decorators import Controller, UseGuard

"@Controller("/admin")
"@UseGuard(AuthGuard())
class AdminController:
    def GET(self):
        return {"role": "admin"}

    def delete(self, id: int):
        return None
```

### Nivel de método: protege rutas específicas

```python
"@Controller("/users")
class UsersController:
    "@UseGuard(AuthGuard())
    def GET(self):
        return {"email": "user"@example.com"}

    # No guard on public routes
    def post(self, data: dict):
        return {"message": "No auth required"}
```

### Varios guardias: todos deben pasar

```python
"@Controller("/admin")
"@UseGuard(AuthGuard(), RateLimitGuard())
class AdminController:
    ...
```

Los guardias ejecutan en el orden en que aparecen. Si `AuthGuard` aumenta, `RateLimitGuard` nunca se ejecuta.

**Te tengo**: Los guardias de nivel de método se ejecutan DESPUÉS de los guardias de nivel de controlador, y solo si los guardias de nivel de controlador pasan.

## Guardias con parámetros

Cree una fábrica de guardias para guardias parametrizadas:

```python
class RoleGuard:
    def __init__(self, required_role: str):
        self.required_role = required_role

    async def __call__(self, request: Request):
        user_role = request.headers.get("X-Role", "guest")
        if user_role != self.required_role:
            raise HTTPException(403, f"Requires {self.required_role} role")
```

Aplicar con argumentos:

```python
"@Controller("/admin")
"@UseGuard(RoleGuard("admin"))
class AdminController:
    def GET(self):
        return {"role": "admin"}
```

## Guardias como funciones

Las protecciones simples pueden ser funciones independientes:

```python
async def rate_limit(request: Request):
    client_ip = request.client.host if request.client else "unknown"
    if is_rate_limited(client_ip):
        raise HTTPException(429, "Too many requests")

"@Controller("/api")
"@UseGuard(rate_limit)
class ApiController:
    def GET(self):
        return {"data": [...]}
```

## Contexto de guardia

Los guardias reciben el objeto Starlette `Request` completo, lo que les brinda acceso a encabezados, parámetros de consulta, sesión y más.

Establecer el estado de la solicitud en una guardia para uso posterior:

```python
class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization", "").removeprefix("Bearer ")
        user = await verify_token(token)
        if not user:
            raise HTTPException(401)
        request.state.user = user

# In the controller:
class UsersController:
    def GET(self, request: Request):
        return {"user": request.state.user}
```

## Guardia frente a middleware

| Aspecto | Guardia | Software intermedio |
|--------|-------|------------|
| Ejecuta | Antes del controlador, después del middleware | Ante guardias y manejador |
| Propósito | Autenticación, autorización, control de acceso | Registro, manipulación de encabezados, CORS |
| Volver | `None` o aumentar `HTTPException` | `None` o aumentar `HTTPException` |
| Solicitar acceso | Completo mediante el parámetro `Request` | Completo mediante el parámetro `Request` |

**Cuándo elegir una protección frente a un middleware**: si la lógica determina "¿debería continuar esta solicitud?" (autenticación, verificación de rol, límite de velocidad), use un guardia. Si la lógica modifica la solicitud/respuesta independientemente (registro, CORS), utilice middleware.

## Mejores prácticas

1. **Un guardia por preocupación** — `AuthGuard`, `RoleGuard`, `RateLimitGuard`. No `SecurityGuard` que lo hace todo.
2. **Utilice códigos de estado descriptivos**: 401 para autenticación faltante o no válida, 403 para permisos insuficientes, 429 para limitación de velocidad.
3. **Evite efectos secundarios**: los guardias deben verificar los permisos, no modificar el estado (excepto `request.state`).
4. **Caché de comprobaciones costosas**: instancias de protección única con cachés en memoria.
5. **Prueba a los guardias de forma aislada**: crea un `Request` simulado, llama al guardia, afirma que sube o pasa.
