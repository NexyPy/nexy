# Gardes

Les gardes déterminent si une demande doit parvenir au gestionnaire d'itinéraire. Ils s'exécutent **avant la méthode du contrôleur** — parfaits pour l'authentification, l'autorisation, la limitation de débit et le contrôle d'accès.

Les gardes de Nexy sont des **dépendances FastAPI**. Ce sont des appelables (classes avec `__call__` ou fonctions autonomes) qui reçoivent la requête et transmettent ou déclenchent une HTTPException.

## Pourquoi des gardes ?

Sans gardes, vous vérifieriez l'authentification dans chaque méthode de contrôleur :

```python
class AdminController:
    def GET(self):
        if not is_authenticated(request):
            raise HTTPException(401)
        return {"role": "admin"}

    def delete(self, id: int):
        if not is_authenticated(request):
            raise HTTPException(401)
        return None
```

Un garde extrait ceci dans un callable réutilisable :

```python
class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization")
        if not token:
            raise HTTPException(401)
```

Appliqué une fois, protège chaque itinéraire du contrôleur :

```python
"@Controller("/admin")
"@UseGuard(AuthGuard())
class AdminController:
    def GET(self):
        return {"role": "admin"}
```

## Créer un garde

Un garde est un callable qui prend un `Request` et renvoie `None` ou relance :

```python
from starlette.exceptions import HTTPException
from starlette.requests import Request

class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization")
        if not token or not token.startswith("Bearer "):
            raise HTTPException(401, "Missing or invalid token")
```

Le garde lève `HTTPException` pour bloquer la demande. S'il revient normalement, la demande se poursuit.

**Je vous ai eu** : `__call__` peut être synchronisé ou asynchrone – le routeur gère les deux. Utilisez async lorsque votre garde doit appeler une base de données ou une API externe.

## Application de gardes

### Au niveau du contrôleur : protège toutes les routes

```python
from nexy.decorators import Controller, UseGuard

"@Controller("/admin")
"@UseGuard(AuthGuard())
class AdminController:
    def GET(self):
        return {"role": "admin"}

    def delete(self, id: int):
        return None
```

### Au niveau de la méthode : protège des itinéraires spécifiques

```python
"@Controller("/users")
class UsersController:
    "@UseGuard(AuthGuard())
    def GET(self):
        return {"email": "user"@example.com"}

    # No guard on public routes
    def post(self, data: dict):
        return {"message": "No auth required"}
```

### Plusieurs gardes – tous doivent passer

```python
"@Controller("/admin")
"@UseGuard(AuthGuard(), RateLimitGuard())
class AdminController:
    ...
```

Les gardes exécutent dans l'ordre dans lequel ils sont répertoriés. Si `AuthGuard` augmente, `RateLimitGuard` ne s'exécute jamais.

**Je vous ai eu** : les gardes au niveau de la méthode s'exécutent APRÈS les gardes au niveau du contrôleur - et uniquement si les gardes au niveau du contrôleur réussissent.

## Gardes avec paramètres

Créez une fabrique de gardes pour les gardes paramétrées :

```python
class RoleGuard:
    def __init__(self, required_role: str):
        self.required_role = required_role

    async def __call__(self, request: Request):
        user_role = request.headers.get("X-Role", "guest")
        if user_role != self.required_role:
            raise HTTPException(403, f"Requires {self.required_role} role")
```

Appliquer avec des arguments :

```python
"@Controller("/admin")
"@UseGuard(RoleGuard("admin"))
class AdminController:
    def GET(self):
        return {"role": "admin"}
```

## Gardes comme fonctions

Les gardes simples peuvent être des fonctions autonomes :

```python
async def rate_limit(request: Request):
    client_ip = request.client.host if request.client else "unknown"
    if is_rate_limited(client_ip):
        raise HTTPException(429, "Too many requests")

"@Controller("/api")
"@UseGuard(rate_limit)
class ApiController:
    def GET(self):
        return {"data": [...]}
```

## Contexte de garde

Les gardes reçoivent l'objet Starlette `Request` complet, donnant accès aux en-têtes, aux paramètres de requête, à la session, etc.

Définir l'état de la demande dans une garde pour une utilisation en aval :

```python
class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization", "").removeprefix("Bearer ")
        user = await verify_token(token)
        if not user:
            raise HTTPException(401)
        request.state.user = user

# In the controller:
class UsersController:
    def GET(self, request: Request):
        return {"user": request.state.user}
```

## Garde contre Middleware

| Aspects | Garde | Intergiciel |
|--------|-------|------------|
| Exécute | Avant le gestionnaire, après le middleware | Devant les gardes et le gestionnaire |
| Objectif | Authentification, autorisation, contrôle d'accès | Journalisation, manipulation d'en-tête, CORS |
| Retour | `None` ou augmenter `HTTPException` | `None` ou augmenter `HTTPException` |
| Demander un accès | Complet via le paramètre `Request` | Complet via le paramètre `Request` |

**Quand choisir un garde ou un middleware** : Si la logique détermine « cette demande doit-elle être exécutée ? » (authentification, vérification de rôle, limite de débit), utilisez un garde. Si la logique modifie malgré tout la demande/réponse (journalisation, CORS), utilisez un middleware.

## meilleures pratiques

1. **Un garde par préoccupation** — `AuthGuard`, `RoleGuard`, `RateLimitGuard`. Pas `SecurityGuard` qui fait tout.
2. **Utilisez des codes d'état descriptifs** — 401 pour une authentification manquante/invalide, 403 pour des autorisations insuffisantes, 429 pour une limitation de débit.
3. **Évitez les effets secondaires** — les gardes doivent vérifier les autorisations et non modifier l'état (sauf `request.state`).
4. **Cache les contrôles coûteux** — instances de garde singleton avec caches en mémoire.
5. **Testez les gardes en isolement** — créez un `Request` simulé, appelez le garde, affirmez qu'il augmente ou passe.
