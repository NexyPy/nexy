# Wachen

Guards bestimmen, ob eine Anfrage den Routenhandler erreichen soll. Sie werden **vor der Controller-Methode** ausgeführt – perfekt für Authentifizierung, Autorisierung, Ratenbegrenzung und Zugriffskontrolle.

Nexys Wächter sind **FastAPI-Abhängigkeiten**. Es handelt sich um aufrufbare Elemente (Klassen mit `__call__` oder eigenständige Funktionen), die die Anforderung empfangen und entweder eine HTTPException übergeben oder auslösen.

## Warum Wachen?

Ohne Guards würden Sie die Authentifizierung in jeder Controller-Methode überprüfen:

```python
class AdminController:
    def GET(self):
        if not is_authenticated(request):
            raise HTTPException(401)
        return {"role": "admin"}

    def delete(self, id: int):
        if not is_authenticated(request):
            raise HTTPException(401)
        return None
```

Ein Wächter extrahiert dies in ein wiederverwendbares Callable:

```python
class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization")
        if not token:
            raise HTTPException(401)
```

Einmal angewendet, schützt jede Route im Controller:

```python
"@Controller("/admin")
"@UseGuard(AuthGuard())
class AdminController:
    def GET(self):
        return {"role": "admin"}
```

## Einen Wächter erstellen

Ein Guard ist ein Callable, der ein `Request` annimmt und `None` zurückgibt oder Folgendes auslöst:

```python
from starlette.exceptions import HTTPException
from starlette.requests import Request

class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization")
        if not token or not token.startswith("Bearer "):
            raise HTTPException(401, "Missing or invalid token")
```

Der Wächter löst `HTTPException` aus, um die Anfrage zu blockieren. Wenn es normal zurückkehrt, wird die Anfrage fortgesetzt.

**Verstanden**: `__call__` kann synchron oder asynchron sein – der Router verarbeitet beides. Verwenden Sie async, wenn Ihr Guard eine Datenbank oder eine externe API aufrufen muss.

## Anwenden von Schutzmaßnahmen

### Controller-Ebene – schützt alle Routen

```python
from nexy.decorators import Controller, UseGuard

"@Controller("/admin")
"@UseGuard(AuthGuard())
class AdminController:
    def GET(self):
        return {"role": "admin"}

    def delete(self, id: int):
        return None
```

### Methodenebene – schützt bestimmte Routen

```python
"@Controller("/users")
class UsersController:
    "@UseGuard(AuthGuard())
    def GET(self):
        return {"email": "user"@example.com"}

    # No guard on public routes
    def post(self, data: dict):
        return {"message": "No auth required"}
```

### Mehrere Wachen – alle müssen passieren

```python
"@Controller("/admin")
"@UseGuard(AuthGuard(), RateLimitGuard())
class AdminController:
    ...
```

Die Wachen werden in der aufgeführten Reihenfolge ausgeführt. Wenn `AuthGuard` erhöht wird, wird `RateLimitGuard` nie ausgeführt.

**Gotcha**: Guards auf Methodenebene laufen NACH Guards auf Controller-Ebene – und nur, wenn Guards auf Controller-Ebene bestehen.

## Guards mit Parametern

Erstellen Sie eine Guard-Factory für parametrisierte Guards:

```python
class RoleGuard:
    def __init__(self, required_role: str):
        self.required_role = required_role

    async def __call__(self, request: Request):
        user_role = request.headers.get("X-Role", "guest")
        if user_role != self.required_role:
            raise HTTPException(403, f"Requires {self.required_role} role")
```

Bewerben Sie sich mit Argumenten:

```python
"@Controller("/admin")
"@UseGuard(RoleGuard("admin"))
class AdminController:
    def GET(self):
        return {"role": "admin"}
```

## Wachen als Funktionen

Einfache Wachen können eigenständige Funktionen sein:

```python
async def rate_limit(request: Request):
    client_ip = request.client.host if request.client else "unknown"
    if is_rate_limited(client_ip):
        raise HTTPException(429, "Too many requests")

"@Controller("/api")
"@UseGuard(rate_limit)
class ApiController:
    def GET(self):
        return {"data": [...]}
```

## Kontext schützen

Guards erhalten das vollständige Starlette-Objekt `Request` und gewähren Zugriff auf Header, Abfrageparameter, Sitzung und mehr.

Legen Sie den Anforderungsstatus in einem Guard für die Downstream-Verwendung fest:

```python
class AuthGuard:
    async def __call__(self, request: Request):
        token = request.headers.get("Authorization", "").removeprefix("Bearer ")
        user = await verify_token(token)
        if not user:
            raise HTTPException(401)
        request.state.user = user

# In the controller:
class UsersController:
    def GET(self, request: Request):
        return {"user": request.state.user}
```

## Guard vs. Middleware

| Aspekt | Wache | Middleware |
|--------|-------|------------|
| Führt aus | Vor dem Handler, nach der Middleware | Vor Wachen und Hundeführer |
| Zweck | Authentifizierung, Autorisierung, Zugriffskontrolle | Protokollierung, Header-Manipulation, CORS |
| Zurück | `None` oder `HTTPException` erhöhen | `None` oder `HTTPException` erhöhen |
| Zugriff anfordern | Vollständig über den Parameter `Request` | Vollständig über den Parameter `Request` |

**Wann sollte man einen Wächter vs. Middleware wählen**: Wenn die Logik bestimmt, „sollte diese Anfrage fortgesetzt werden?“ (Authentifizierung, Rollenprüfung, Ratenbegrenzung), verwenden Sie einen Schutz. Wenn die Logik die Anfrage/Antwort unabhängig davon ändert (Protokollierung, CORS), verwenden Sie Middleware.

## Best Practices

1. **Ein Wachmann pro Anliegen** – `AuthGuard`, `RoleGuard`, `RateLimitGuard`. Nicht `SecurityGuard`, das alles macht.
2. **Verwenden Sie beschreibende Statuscodes** – 401 für fehlende/ungültige Authentifizierung, 403 für unzureichende Berechtigungen, 429 für Ratenbegrenzung.
3. **Nebenwirkungen vermeiden** – Wächter sollten Berechtigungen prüfen, nicht den Status ändern (außer `request.state`).
4. **Cache-kostspielige Prüfungen** – Singleton-Guard-Instanzen mit In-Memory-Caches.
5. **Wächter isoliert testen** – Erstellen Sie einen simulierten `Request`, rufen Sie den Wächter auf und stellen Sie sicher, dass er aktiviert oder bestanden wird.
