# Обзор файловой маршрутизации

Файловая маршрутизация Nexy (FBR) автоматически создает маршруты из вашего файлового дерева в `src/routes/`. Каждый файл `.nexy`, `.mdx` и `.py` становится HTTP-маршрутом — регистрация маршрута не требуется.

Если вы работали с маршрутизатором страниц Next.js, PHP или статическим HTML-сервером, концепция вам знакома: путь к файлу — это путь URL-адреса.

---

## Как это работает

```
src/routes/
├── index.nexy          →  /
├── about.nexy          →  /about
├── blog/
│   ├── index.nexy      →  /blog
│   ├── [slug].nexy     →  /blog/{slug}
│   └── layout.nexy     →  (shared layout, not routed)
└── api/
    └── users.py        →  /api/users (REST handler)
```

Каждый файл сопоставляется с URL-путем путем удаления префикса `src/routes/` и расширения файла. Файлы с именем `index` служат корнем каталога, а `/blog/index.nexy` — `/blog`.

---

## Зарезервированные имена файлов

Некоторые имена файлов имеют особое поведение и не рассматриваются как маршруты:

| Файл | Цель |
|------|---------|
| `layout.nexy` | Общий макет для родственных и дочерних маршрутов |
| `dependencies.py` | Общая инъекция зависимостей |
| `__init__.py` | Маркер пакета Python |

---

## Приоритет маршрута

Если вы создаете несколько файлов по одному и тому же пути в разных форматах, Nexy определяет приоритет следующим образом: `.py` > `.nexy` > `.mdx`.

```
routes/
├── index.nexy    →  served
├── index.py      →  overrides index.nexy
└── index.mdx     →  ignored (lowest priority)
```
