# المزامنة والتزامن (FBR)

تم بناء Nexy على FastAPI الذي يدعم كلاً من معالجات التوجيه `async` و`def`.

## `async def` مقابل `def`

| نوع المعالج | تنفيذ | متى تستخدم |
|-------------|-----------|-------------|
| `def` | تجمع الخيوط (الحظر) | عمل وحدة المعالجة المركزية، ومزامنة مكالمات قاعدة البيانات، وحظر الإدخال/الإخراج |
| `async def` | حلقة الحدث | قاعدة بيانات غير متزامنة، ومكالمات HTTP، وWebSocket، والاستقصاء الطويل |

## طريق غير متزامن

```python
# src/routes/proxy.py
import httpx

async def GET():
    async with httpx.AsyncClient() as client:
        resp = await client.get("https://api.example.com/data")
        return resp.json()
```

## مزامنة مختلطة وغير متزامنة في ملف واحد

```python
def GET():             # runs in thread pool
    return {"type": "sync"}

async def GET():       # runs in event loop
    return {"type": "async"}
```

## مهام الخلفية

بالنسبة إلى عمل "أطلق وانسى" بعد الرد، استخدم `BackgroundTasks`. للحصول على عمل غير متزامن في الخلفية، استخدم `asyncio.create_task`.

##محاذير

- لا تستدعي وظائف `async` من معالجات `def` مع `await` — استخدم `asyncio.run()` أو اجعل المعالج `async def`
- لا تستدعي وظائف الحظر (`time.sleep()`، `requests.get()`) من `async def` — استخدم `asyncio.sleep()`، `httpx.AsyncClient`
- يقوم `nx dev` الخاص بـ Nexy بتشغيل عامل uvicorn واحدًا افتراضيًا - تتألق المعالجات غير المتزامنة هنا
- بالنسبة للإنتاج، استخدم عدة عاملين (`nx start --workers 4`) لمعالجات المزامنة
