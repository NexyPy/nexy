# Tareas en segundo plano (FBR)

Ejecute el código *después* de enviar la respuesta: para registro, notificaciones y calentamiento de caché.

```python
from fastapi import BackgroundTasks
```

## Tarea única

```python
# src/routes/log.py
from fastapi import BackgroundTasks

def write_log(message: str):
    with open("app.log", "a") as f:
        f.write(message + "\n")

def GET(tasks: BackgroundTasks):
    tasks.add_task(write_log, "Page visited")
    return {"status": "ok"}
```

## Múltiples tareas

```python
from fastapi import BackgroundTasks

def GET(tasks: BackgroundTasks):
    tasks.add_task(log_visit)
    tasks.add_task(notify_admin)
    tasks.add_task(warm_cache)
    return {"ok": True}
```

## Tarea con dependencias

```python
from fastapi import BackgroundTasks, Depends
from src.db import get_db

def cleanup_old_records(db=Depends(get_db)):
    db.query(Log).delete()

def GET(tasks: BackgroundTasks):
    tasks.add_task(cleanup_old_records)
    return {"status": "cleaning"}
```

## Importante

- Las tareas se ejecutan **después** de enviar la respuesta: el cliente no espera
- Se ejecutan en el mismo proceso: las tareas largas bloquean el bucle de eventos
- Para trabajos pesados, utilice una cola de tareas (Apio, ARQ, RQ, etc.)
- Los errores en las tareas se tragan silenciosamente: agregue try/except dentro de la función de tarea
- Las tareas reciben **copias** de objetos mutables; las mutaciones no afectarán la respuesta
