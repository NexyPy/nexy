# Tâches en arrière-plan (FBR)

Exécutez le code *après* l'envoi de la réponse - pour la journalisation, les notifications et le réchauffement du cache.

```python
from fastapi import BackgroundTasks
```

## Tâche unique

```python
# src/routes/log.py
from fastapi import BackgroundTasks

def write_log(message: str):
    with open("app.log", "a") as f:
        f.write(message + "\n")

def GET(tasks: BackgroundTasks):
    tasks.add_task(write_log, "Page visited")
    return {"status": "ok"}
```

## Tâches multiples

```python
from fastapi import BackgroundTasks

def GET(tasks: BackgroundTasks):
    tasks.add_task(log_visit)
    tasks.add_task(notify_admin)
    tasks.add_task(warm_cache)
    return {"ok": True}
```

## Tâche avec dépendances

```python
from fastapi import BackgroundTasks, Depends
from src.db import get_db

def cleanup_old_records(db=Depends(get_db)):
    db.query(Log).delete()

def GET(tasks: BackgroundTasks):
    tasks.add_task(cleanup_old_records)
    return {"status": "cleaning"}
```

##Important

- Les tâches s'exécutent **après** l'envoi de la réponse — le client n'attend pas
- Ils s'exécutent dans le même processus : les tâches longues bloquent la boucle d'événements
- Pour les travaux lourds, utilisez une file d'attente de tâches (Céleri, ARQ, RQ, etc.)
- Les erreurs dans les tâches sont avalées silencieusement — ajoutez try/sauf dans la fonction de tâche
- Les tâches reçoivent des **copies** d'objets mutables — les mutations n'affecteront pas la réponse
