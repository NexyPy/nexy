# Структура проекта

На этой странице представлен обзор соглашений о файлах и папках Nexy, а также способы организации вашего проекта.

```text
my-app/
├── .venv/
├── node_modules/          (optional — client framework only)
├── public/
├── src/
│   ├── components/
│   ├── routes/            (FBR) — or apps/ (Modular)
│   └── layout.nexy
├── .gitignore
├── nexyconfig.py
├── pyproject.toml
├── package.json           (optional)
├── vite.config.ts         (optional)
└── tsconfig.json          (optional)
```

---

## Каталоги верхнего уровня

### `public/`

Размещенные здесь статические ресурсы обслуживаются по корневому URL-адресу `/`. Изображения, шрифты, значки, robots.txt — все, что вы хотите сделать общедоступным без маршрута.

### `src/`

Здесь находится исходный код вашего приложения. Nexy отслеживает `src/` изменений в разработке и компилирует все отсюда в производство.

---

## Внутри `src/`

```text
src/
├── components/     — reusable Nexy components (optional)
├── routes/         — FBR: file-based routing tree
├── apps/           — Modular: controllers, modules, providers
├── layout.nexy     — root layout (optional, FBR only)
└── global.css      — global styles (optional)
```

### `src/components/`

Необязательный каталог для повторно используемых компонентов `.nexy`. Nexy не требует определенного каталога компонентов — вы можете использовать любое имя или структуру. Компоненты импортируются с помощью `from "@components/..." import ...`.

### `src/routes/` (маршрутизация на основе файлов)

Каждый файл `.py`, `.nexy` и `.mdx` в `src/routes/` становится HTTP-маршрутом, за исключением специальных имен файлов:

| Файл | Поведение |
|------|----------|
| `index.nexy` / `index.py` / `index.mdx` | Обслуживается по родительскому пути (`/users/index.nexy` → `/users`) |
| `layout.nexy` | Общий макет для одноуровневых и дочерних маршрутов (не маршрутизируемых) |
| `__init__.py` | Маркер пакета Python (не маршрутизируемый) |
| `dependencies.py` | Общие зависимости (не маршрутизируемые) |

```text
routes/
├── index.nexy          →  /
├── about.nexy          →  /about
├── blog/
│   ├── index.nexy      →  /blog
│   ├── [slug].nexy     →  /blog/{slug}
│   └── layout.nexy     —  shared layout for /blog/*
└── api/
    └── users.py        →  /api/users (GET, POST, etc.)
```

### `src/apps/` (модульная маршрутизация)

При использовании модульного маршрутизатора код вашего приложения организован в функциональные модули:

```text
apps/
├── app_module.py       →  "@Module(root module)
├── app_controller.py   →  "@Controller("/")
├── app_view.nexy       →  template
├── users/
│   ├── user_module.py
│   ├── user_controller.py
│   └── user_service.py
└── layout.nexy         →  shared layout
```

## Файлы конфигурации

| Файл | Цель |
|------|---------|
| `nexyconfig.py` | Основная конфигурация Nexy: роутер, плагины, настройки приложения |
| `pyproject.toml` | Метаданные проекта Python, зависимости, система сборки |
| `package.json` | Зависимости JavaScript (присутствуют при использовании клиентской платформы) |
| `vite.config.ts` | Конфигурация Vite для объединения клиентского кода |
| `tsconfig.json` | Параметры компилятора TypeScript |
| `.gitignore` | Файлы и каталоги, которые следует исключить из контроля версий |

---

## Организация вашего проекта

Помимо приведенных выше соглашений, Nexy не имеет никакого мнения о том, как вы структурируете исходный код. Некоторые шаблоны, которые хорошо работают:

- **Папки функций**: группируйте связанные страницы, компоненты и утилиты по функциям.
- **Общие компоненты**: сохраняйте по-настоящему повторно используемые компоненты в `src/components/`.
- **Группы маршрутов**: вложите каталоги в `src/routes/`, чтобы отразить структуру URL-адресов.
- **Monorepo**: модули `src/apps/` рассматриваются как независимо развертываемые единицы.

Важно то, что каждый файл в `src/routes/` (FBR) или на который ссылается `"@Module` (модульный) соответствует приведенным выше соглашениям об именах.
