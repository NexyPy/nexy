# 프로젝트 구조

이 페이지에서는 Nexy의 파일 및 폴더 규칙에 대한 개요와 프로젝트 구성 방법을 제공합니다.

```text
my-app/
├── .venv/
├── node_modules/          (optional — client framework only)
├── public/
├── src/
│   ├── components/
│   ├── routes/            (FBR) — or apps/ (Modular)
│   └── layout.nexy
├── .gitignore
├── nexyconfig.py
├── pyproject.toml
├── package.json           (optional)
├── vite.config.ts         (optional)
└── tsconfig.json          (optional)
```

---

## 최상위 디렉토리

### `public/`

여기에 배치된 정적 자산은 루트 `/` URL에서 제공됩니다. 이미지, 글꼴, 파비콘, robots.txt 등 경로 없이 공개적으로 액세스할 수 있는 모든 항목.

### `src/`

귀하의 애플리케이션 소스 코드가 여기에 있습니다. Nexy는 `src/` 개발 변경 사항을 감시하고 여기에서 프로덕션 단계까지 모든 것을 컴파일합니다.

---

## `src/` 내부

```text
src/
├── components/     — reusable Nexy components (optional)
├── routes/         — FBR: file-based routing tree
├── apps/           — Modular: controllers, modules, providers
├── layout.nexy     — root layout (optional, FBR only)
└── global.css      — global styles (optional)
```

### `src/components/`

재사용 가능한 `.nexy` 구성 요소에 대한 선택적 디렉터리입니다. Nexy는 특정 구성요소 디렉토리를 강제하지 않습니다. 임의의 이름이나 구조를 사용할 수 있습니다. 구성 요소는 `from "@components/..." import ...`를 사용하여 가져옵니다.

### `src/routes/`(파일 기반 라우팅)

`src/routes/` 아래의 모든 `.py`, `.nexy` 및 `.mdx` 파일은 특수 파일 이름을 제외하고 HTTP 경로가 됩니다.

| 파일 | 행동 |
|------|----------|
| `index.nexy` / `index.py` / `index.mdx` | 상위 경로에서 제공됨(`/users/index.nexy` → `/users`) |
| `layout.nexy` | 형제 및 하위 경로에 대한 공유 레이아웃(라우팅할 수 없음) |
| `__init__.py` | Python 패키지 마커(라우팅할 수 없음) |
| `dependencies.py` | 공유 종속성(라우팅할 수 없음) |

```text
routes/
├── index.nexy          →  /
├── about.nexy          →  /about
├── blog/
│   ├── index.nexy      →  /blog
│   ├── [slug].nexy     →  /blog/{slug}
│   └── layout.nexy     —  shared layout for /blog/*
└── api/
    └── users.py        →  /api/users (GET, POST, etc.)
```

### `src/apps/`(모듈식 라우팅)

모듈형 라우터를 사용할 때 애플리케이션 코드는 기능 모듈로 구성됩니다.

```text
apps/
├── app_module.py       →  "@Module(root module)
├── app_controller.py   →  "@Controller("/")
├── app_view.nexy       →  template
├── users/
│   ├── user_module.py
│   ├── user_controller.py
│   └── user_service.py
└── layout.nexy         →  shared layout
```

---

## 구성 파일

| 파일 | 목적 |
|------|---------|
| `nexyconfig.py` | 주요 Nexy 구성: 라우터, 플러그인, 앱 설정 |
| `pyproject.toml` | Python 프로젝트 메타데이터, 종속성, 빌드 시스템 |
| `package.json` | JavaScript 종속성(클라이언트 프레임워크를 사용할 때 존재함) |
| `vite.config.ts` | 클라이언트 측 코드 번들링을 위한 Vite 구성 |
| `tsconfig.json` | TypeScript 컴파일러 옵션 |
| `.gitignore` | 버전 제어에서 제외할 파일 및 디렉터리 |

---

## 프로젝트 구성

위의 규칙 외에 Nexy는 소스 코드를 어떻게 구성하는지에 대한 의견이 없습니다. 잘 작동하는 몇 가지 패턴은 다음과 같습니다.

- **기능 폴더**: 기능별로 관련 페이지, 구성 요소 및 유틸리티를 그룹화합니다.
- **공유 구성요소**: 재사용 가능한 구성요소를 `src/components/`에 보관하세요.
- **경로 그룹**: URL 구조를 미러링하기 위해 `src/routes/`에 디렉터리를 중첩합니다.
- **Monorepo**: `src/apps/` 모듈을 독립적으로 배포 가능한 단위로 처리합니다.

중요한 것은 `src/routes/`(FBR) 아래에 있거나 `"@Module`(모듈식)에 의해 참조되는 모든 파일이 위의 명명 규칙을 따른다는 것입니다.
