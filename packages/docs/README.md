# Nexy Documentation (`packages/docs`)

Static, multi-page documentation site for the **Nexy** framework. Bilingual (English + French).

- **SEO-friendly multipage**: every page is a real `…/index.html` with its own `<title>`, meta description, canonical URL and `hreflang` alternates.
- **Soft navigation**: clicking an internal link fetches the target page and swaps the content - no full reload - while keeping every page fully crawlable.
- **Fuzzy search**: tolerant to typos. Search `roate` and it will suggest `route`. Includes a "did you mean" panel and keyboard navigation (`Ctrl K` / `⌘ K`).
- Modern responsive design, dark/light theme, on-this-page TOC, previous/next pager, copy buttons, mobile sidebar.

## Quick start

```bash
cd packages/docs
node js/build.mjs          # regenerate all HTML pages from js/content.js
```

The generated output (`index.html`, `404.html`, `en/**/index.html`, `js/search-index.js`,
`sitemap.xml`, `robots.txt`) is gitignored: only sources are tracked, so rebuild before
publishing the folder to a `gh-pages` branch.

Open `index.html`, or serve the folder:

```bash
npx serve .
```

## Editing content

All documentation lives in **`js/content.js`**. To add a page, add one object to the
relevant section's `pages` array (or create a new section). No other file needs editing.

```js
{
  id: "my-page",                                // URL: <locale>/<section>/my-page/
  title: { en: "My Page", fr: "Ma page" },
  keywords: { en: ["seo", "words"], fr: ["mots"] },
  content: {
    en: [
      ["p", "A paragraph with `inline code` and a [[link|#/en/routing/overview]]."],
      ["h2", "A heading"],
      ["code", "python", "print('hi')"],
      ["callout", "tip", "A tip box"],
    ],
    fr: [ /* same structure, French */ ],
  },
}
```

### Content block types

| Block | Form |
|-------|------|
| `["lead", text]` | big intro paragraph |
| `["p", text]` | paragraph (`\`code\``, `[[label\|#/path]]`) |
| `["h2"\|"h3", text]` | heading (auto-TOC) |
| `["ul", [...]` / `["ol", [...]]` | lists |
| `["code", "lang", "text"]` | code block (python, bash, json, js, text) |
| `["callout", "tip\|note\|warn\|danger", text]` | callout |
| `["quote", text]` | blockquote |
| `["table", [headers], [[rows]]]` | table |

After editing `content.js`, rebuild:

```bash
node js/build.mjs
```

## Deploying to GitHub Pages

All internal links are **relative**, so the site works from any sub-path. Two options:

1. **Repo root GitHub Pages**: copy/push the contents of `packages/docs/` to the branch
   or folder you host on Pages (Settings → Pages → Source).
2. **Sub-folder deploy**: the relative links keep working even under `/repo-name/`.

Set the canonical domain (for SEO) when generating:

```bash
SITE_URL=https://mydocs.dev node js/build.mjs
```

## Notes

- Soft navigation uses `fetch`, which is unavailable on `file://`. Opening via `file://`
  still works - pages just navigate normally. Serve the folder to get the smooth
  soft-navigation and the search palette.
- The fuzzy search maps typos to real terms via a Damerau–Levenshtein distance ≤ 2 and
  bigram similarity, so common misspellings still surface the right page.
